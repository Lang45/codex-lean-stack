# 5.2.13 full-chain audit

This audit starts from `8a39eb73a40a40c4b060dc736dcda8a44f98bec0`, the merged English README revision. Fixes are proposed as `5.2.14` on `audit/full-chain-5.2.13-20260917`; this report is not an installation or live-host acceptance receipt.

## Plan and preservation boundary

Trace the entry points, delegation decisions, shared execution rules, parallel-write ownership, specialist discovery, persistence, experience updates, outcome recording, cleanup, installation, and version maintenance. Establish the existing test baseline, reproduce concrete failures in temporary homes, then add behavioral regressions and make local fixes. Review navigation and public descriptions separately from executable code.

Keep both skills independent. Preserve the four-model routing policy, explicit model/effort arguments, bounded context, visible task-card declarations, source reuse, writable parallelism, retained specialists, corrections, compaction, migrations, outcome association, dashboard, and cleanup rules. Do not replace these features with a simpler implementation or weaken ownership, permission, schema, or hash checks to make tests pass.

All script probes use temporary directories. Installer tests substitute a subprocess and never install Codex. The Windows probe starts real PowerShell/Python processes on a CI runner; it does **not** pass through a user's Codex `exec` tool.

## Confirmed findings and changes

| ID | Area | Failure before the fix | Change and regression evidence |
| --- | --- | --- | --- |
| A01 | Installation | An explicit `--codex-home` selected the activation file, but the child installer retained another `CODEX_HOME`. | Forward the same resolved home to the subprocess. A fake installer captures its actual environment. |
| A02 | Activation | A non-empty `AGENTS.override.md` made the edited `AGENTS.md` inactive. A changed selection during installation could also produce a false success. | Select the active file under the existing home-level lock; preserve the inactive base. Fail explicitly if selection changes. Test empty, non-empty, malformed and newly created overrides. |
| A03 | Activation | A fenced example or HTML comment was treated as an active requirement. Insertion after the first line could place the new rule inside the example. | Exclude examples/comments from detection and insert outside the opening block. Preserve original bytes, BOM, newline style and idempotence. |
| A04 | Registry ownership | `Path.exists()` skipped a dangling database symlink, allowing SQLite to create its external target. Database hard links were not rejected either. | Inspect the directory entry with `lstat` before opening SQLite and require one hard link. Regressions verify that external data is not created or modified. |
| A05 | Experience reuse | A valid 3,000-character / 9,000-byte first lesson was saved, but did not fit the 4 KiB prompt window. `recall`, routing status and subsequent result recording then failed. | Distinguish saved-but-unloaded experience from missing/corrupt experience. Keep raw events, report deferred compaction, and do not fabricate a loaded-experience digest. Accept the old empty-window representation read-only. Exercise save → recall → route → record → compact → recall → associate/replay an outcome. |
| A06 | Compaction | The trigger counted pending lesson bytes without the existing summary and labels; a new lesson could be excluded without requesting compaction. The returned task mentioned only a character limit. | Calculate the complete rendered UTF-8 budget, state both limits, and avoid empty compaction batches. Original events remain intact. |
| A07 | Persistence rollback | The TOML file could be replaced before a failing ledger update, count query or compaction calculation. The caller had not yet received the rollback bytes, so SQL rolled back while the file remained changed. | Complete fallible bookkeeping before the replacement; return replacement bytes immediately. Inject ledger, count, compaction and commit failures through both `improve` and `complete-run`, checking exact file and table restoration. |
| A08 | Persistent inputs | POSIX/UNC locations bypassed the path filter. Non-string domains were coerced to strings; control characters could become escaped JSON before inspection. | Check raw contract values and recognizable rooted paths before persistence. Keep relative paths and terms such as `I/O` and `SQLite/TOML` valid. No stored data is automatically deleted. |
| A09 | README contract | The earlier English README change left a test requiring the Chinese title on the first line. This was the single original baseline failure. | Check the English title and retained Chinese display heading separately; retain stable plugin/skill identifier and display-name checks. |
| A10 | Documentation routing | Two fragment links led to no heading: conditional validation and the configuration/context section. File-existence tests did not detect this. | Correct both anchors and add a heading-fragment regression over the README and skill documentation. |
| A11 | Host API explanation | References incorrectly said full-history forks cannot override model and reasoning effort. | Keep the plugin's existing prohibition on full-history inheritance, but explain it as a context policy, not a missing host capability. Explicit argument and bounded-context gates remain. |
| A12 | Installation instructions | The release guide showed an obsolete activation sentence rather than the line written by the helper. | Synchronize the sentence and document home/override selection. Test the guide against the actual constant. |
| A13 | Cost maintenance | Two concurrent writers using the same old state hash could both report success. A synchronized two-thread probe reproduced two successful writers. | Hold an exclusive, non-blocking record lock across comparison and replacement. The competing attempt safely skips; there is no retry loop, scheduler or service. |
| A14 | Cost state recovery | An interrupted first write could leave a partial state file that prevented later reads/records. | On failure remove only the inode created by that operation; preserve replacements owned by another writer. Test a partial write followed by a successful fresh record. |

A01, A02, A04, A05 and A07 affect activation, ownership or availability of the persistence chain. The documentation/test findings are not represented as observed failures of a live model.

## Validation

The original suite ran **184 tests with one failure** on both Linux and Windows. The failure was A09, introduced by the preceding README-only change.

The proposed suite contains **203 tests**: all 184 original tests plus 19 new behavioral, documentation and Windows-probe tests. Two existing assertions were updated to reflect the English title and corrected fork explanation; neither test was removed. Local Linux execution passes with one intentional skip for the Windows-native probe. The branch's CI records the actual Windows result and the exact tested commit; consult those checks rather than reusing earlier test counts.


The public CLI commands, database schema version 6, existing migration formats, model/effort sets and persistent ownership identities are retained. The source-only patch version is `5.2.14+codex.20260916162253`. No cache refresh or release publication is implied.

## Size and remaining risks

The large registry module includes current migration and data-protection code, not just dispatch logic. It was not split, stripped of compatibility, or given a general execution framework merely to reduce its line count. New production code addresses reproduced defects; most added lines are targeted tests. Prompt loading still has a substantial first-read cost (the two entry files together are about 41 KiB before this audit). That cost needs a fresh-host measurement before changing mandatory entry behavior.

Further acceptance requires an authorized fresh Codex installation/session: observe actual tool availability and model allowlists, early delegation, child task-card output, result delivery and reuse. Concurrent completion of one retained identity, abrupt process termination during persistence and hostile file replacement between validation and system calls also need dedicated stress/fault testing. Passing this suite is not proof that those boundaries are defect-free.
