# PR #2 follow-up: cost locking and front matter

This follow-up starts at PR head `aa44374f3558baf7d3f91ec697af4fd7f423d639`.
It corrects two defects in the proposed 5.2.14 changes. The version stays
`5.2.14+codex.20260916162253`; this is not a new release or installation.
The earlier [full-chain audit](5.2.13-full-chain.md) remains the record of the
first pass; its 203-test results predate this follow-up.

## A15: a dead cost writer left a permanent busy marker

Reproduction: exit a child with `os._exit(91)` inside `record_lock`; its empty
`.cost-check-v1.json.lock` remains and every subsequent record attempt fails.
The previous `O_EXCL` marker depended on Python `finally` running.

The cost writer now holds a non-blocking OS lock for the entire compare/write
section: `msvcrt.locking(..., LK_NBLCK, 1)` on Windows and `fcntl.flock` on Unix.
The anchor file deliberately remains in place. Its existence is not evidence
of an active writer; unlinking an unlocked anchor could split simultaneous
openers across different inodes. No PID guessing, age-based deletion, wait
loop, background cleanup or extra dependency is introduced. Linked, non-regular
or replaced anchors are rejected before entering the critical section.

Tests use real processes to cover a live competing writer, `os._exit`, forced
termination, reacquisition and unchanged state. Existing same-hash concurrency
and caught partial-write regressions remain. All competing writers must use
the updated lock protocol; running old and new helper versions against one
home is not a supported concurrency test. Other install/release marker locks
are unchanged. This does not prove crash-atomic state publication or recovery
from power loss during the first write.

## A16: activation insertion displaced YAML metadata

Reproduction: activation was prepended before a leading `---` block, so front
matter was no longer first in the document. The helper now shares one boundary
scan between detection and insertion, preserves the metadata bytes at the
start (including an existing BOM), and inserts an independent paragraph after
the closing delimiter. YAML is not parsed and reserialized. Indented delimiter
text inside scalar content cannot close the header. Unclosed opening blocks
are rejected before the installer subprocess runs, without changing the file.

Tests cover LF/CRLF/CR, BOM/no BOM, `---`/`...` endings, empty headers, closing
at EOF, scalar examples, existing active body instructions and repeated use.
The ordinary fenced-example/comment and effective-override tests remain.

## Verification and scope

Twelve new tests bring discovery to 215 methods. The new cases were first run
against the old PR source and reproduced failures. Local Linux passes 214
methods and intentionally skips the Windows-native execution probe. Consult
the latest PR checks for the exact Windows/Linux commit and final CI results;
do not reuse the previous 203-test run as evidence of these changes.

No public CLI command, stored JSON schema, agent lifecycle behavior or model
routing rule is removed. No real Codex installation, user-global edit, cache
refresh or live-host acceptance is claimed.
