## Findings reproduced and corrected

### A17 — rooted persistent inputs

The previous predicate accepted `/`, `/foo`, `//server/share` and Windows
root-relative paths. A separator starting a path token is now rejected without
requiring a second path segment. Embedded separators in `I/O`, `SQLite/TOML`,
`src/module.py`, `./module.py`, `../src/module.py` and relative Windows paths
remain valid. Tests cover raw and JSON contracts, every contract field, public
improve/complete-run dispatch, ensure, and the migration contract/instruction/
correction inputs. Invalid requests must preserve the files and ledger rows.

All contract fields are checked before serialization. A redundant check of
the generated JSON was removed: JSON quoting introduces backslash syntax that
must not be mistaken for machine locations. Quoted, legitimate text is tested
through normalization, saving, recall, routing and completion.

This is a syntactic policy for identifiable rooted path tokens, not a proof
that arbitrary free text contains no machine-specific information.

### A18 — install/update and release lock death

A real child exiting inside the installer update lock with `os._exit(91)` left
an O_EXCL marker and blocked preflight. The release lock had the same defect
and was independently reproduced. Both now use process-lifetime, non-blocking
kernel locks, sharing the implementation with cost maintenance in
`_maintenance_lock.py`. Stable empty anchors are retained, not deleted after
unlock. The three public wrappers and command-line entry points remain.

Real subprocess tests cover live contention, normal release, abrupt exit and
forced termination. A subsequent preflight/activation or version operation
must succeed without modifying the protected file during the interruption.
Caught-exception recovery and existing failure/rollback tests remain.

**Legacy marker boundary:** nonempty install/release markers written by older
versions are not silently stolen, truncated or deleted. They require explicit
inspection after older helpers have stopped. New helpers leave empty anchors;
process death releases the actual lock automatically. Mixed old/new writers
are not a supported concurrency protocol. Kernel-lock recovery does not prove
recovery or cancellation of an external installer child that outlives its
parent.

### A19 — real POSIX anchor-replacement race

On the old code, one subprocess held `record_lock` while its anchor was
replaced with `os.replace`. A second subprocess then ran the real `record`
CLI and returned exit code 0, entering an allegedly exclusive write interval.
This reproduced the report's POSIX risk rather than inferring it from Windows.

On POSIX, the shared lock now holds a verified containing-directory flock for
the whole critical section, in addition to the existing anchor flock. The
same replacement probe now returns the existing busy/skip code 2 and preserves
the state bytes; recording succeeds after the original holder exits. A
separate pre-open swap test checks that an already-inspected anchor cannot be
silently replaced during acquisition. Linked and non-regular anchors remain
rejected. The Windows backend retains non-blocking byte-range locking.

The directory must remain stable. Arbitrary replacement of the containing
directory, non-cooperating writers, concurrent older protocols and network
filesystems are outside this guarantee. Repeated lstat checks are not described
as an atomic security barrier against a process able to replace arbitrary
parent directories. No polling, lock stealing, background service or new
third-party dependency was added.

### A20 — completion replay after the returned SHA changes

New completion events use a deterministic UUID derived from the run ID and a
versioned constant, not from the mutable TOML SHA. First writes still require
the exact caller CAS. For already-completed runs, the bound event digest,
correction target, specialist identity, invocation kind, outcome and loaded
experience evidence must match. Live file ownership and its hash against the
ledger are still checked. Original and returned SHA retries do not add events,
change files or increment attempts; correction replay is covered as well.

An event created by an earlier improve operation cannot be retroactively
claimed by a new completion. Changed payloads, different identities, file
drift and a stale CAS on a new run remain errors.

**Legacy replay boundary:** old CAS-derived event IDs retain exact-original-
request compatibility. The old schema did not store an independent run-to-
event binding or the initial CAS, so an old completion supplied only with a
new SHA cannot be safely associated by matching lesson text or timestamps.
That case continues to fail with an explicit original-CAS requirement. No
historical rows are guessed, rewritten or duplicated and schema remains 6.

## Validation

The original snapshot discovers 215 tests: local Linux passes 214 and skips
the Windows-native argument ABI probe. The 19 added review regressions were
run on that exact old snapshot before being run on the patched source. The
old source fails the substantive rooted-input, dead-lock, anchor-replacement
and returned-SHA scenarios; the patched source passes all 19 review tests.
Failure counts in the old run include subtests and cascading assertions and
must not be reported as a count of distinct product defects.

The final local full-suite result is 234 tests discovered, 233 passed and one
Windows-native probe intentionally skipped, with no failures or errors. All
215 pre-existing test methods remain. Old assertions were updated only where
they required deletion of a now-stable anchor or a CAS-derived new event UUID;
actual reacquisition and old-event compatibility are tested instead.

Validation commands:

```sh
python -X utf8 -B -m unittest discover -s tests -p test_pr2_independent_review.py -v
python -X utf8 -B -m unittest discover -s tests -v
git diff --check
```

The three helper CLIs were also invoked with `--help` from an unrelated
working directory, proving sibling resolution does not depend on the caller's
working directory. Their shared file is loaded by exact sibling path without
changing sys.path. Public command/option sets and existing stored schema/model
constants were compared with the frozen baseline.

## Not validated here

At preparation time, this patch had not yet been run on Windows or in a new
GitHub Actions run. Those platform checks subsequently completed in the linked
234-test CI run above, including Windows installation/release lock death,
native byte-range locking and the exec argument probe. The earlier Windows
215-test run remains evidence for `98be304` only. The POSIX rename probe is
intentionally Unix-only.

Real Codex automatic plugin loading, model allowlists and native dispatch,
user exec wrapping, real marketplace/UAC behavior, external installer children,
network filesystems, containing-directory replacement, power-loss atomicity
and crash consistency across SQLite and TOML remain separate targets.
The user's report established a native host probe, not automatic loading of
the PR's 5.2.14 rules; this patch does not change that evidence boundary.
