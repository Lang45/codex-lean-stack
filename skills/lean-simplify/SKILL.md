# Codex 主任务精简

## 职责与触发

主任务启动仅由项目主父代理执行；被明确指定的局部协作父只在获准范围内应用所需的阶段方法，
仍沿用子代理开场，不接管根项目交接。普通子代理
按[执行身份](../lean-stack/SKILL.md#执行身份与适用范围)从任务卡直接开工，不因新子线程或恢复
而重跑主父开场、根项目交接或整套主任务准备。若本文件本身是受托审查的源码或指定证据，
只按任务范围核对；必须的专业/操作技能照常使用，不由读取动作扩大职责。

本入口决定非平凡主任务需要哪些步骤、做到什么范围和何时停止；与 `$lean-stack` 子代理调用平行、
独立且互不前置。调查、实现、测试、复核、发布或文档维护命中本入口；无需工具的一次性答复和
单个确定性工具动作默认直接完成；用户已指定委派或执行者时先按[用户明确指令优先](../lean-stack/SKILL.md#用户明确指令优先)执行。
`$lean-stack` 对未指定部分独立判断委派，任何一方都不等待、阻断或代证另一方。

新项目或新会话不无条件读取两个入口。非平凡主任务命中时才读取已加载目录中的本 `SKILL.md`；
已读且入口未变化时直接复用。只读取并应用当前实际动作命中的入口，不预读 `$lean-stack` 或完整
`references`。本入口与其他适用技能的用途说明合并到主父唯一启动说明；读取后的下一次工具调用
立即开始实际任务，不插入第二段前言、无关扫描或版本解释。

本入口负责主任务方法，持续派遣的执行检查由[运行期主线覆盖](../lean-stack/references/runtime-coverage.md)接入已信任的宿主钩子。
两者都不提供额外权限。修改、外部操作、创建任务和不可逆
影响仍以用户当前要求与更高层规则为准；始终保留安全、权限、数据完整性和诚实证据边界。
工具与 PowerShell 路径精简共同遵守
[Windows exec 稳健性契约](../lean-stack/references/windows-exec.md#windows-exec-与-powershell)。
Computer Use 的实际操作按[父代理指导、按任务选配](../lean-stack/SKILL.md#computer-use父代理指导按任务选配)
分工；按用户明确要求分别落实操作者和工具。本入口收窄目标与阶段，操作简单或只有一个工具动作时仍沿用该分工。

## 多目标推进与逐项交付

主任务包含用户全部仍有效的结果要求。最早一个尚未完成或尚未交付的要求是优先锚点，
不把其他活动项串行锁住。精简针对达到结果的方法，不缩掉目标、关键上下文或必要取证操作。
单项任务直接推进；多目标任务复用已有清单、计划或交接当前快照，按用户可辨认的名称保留：
每项要交付的结果与验收、当前证据和授权、负责人的完整工作包、下一实际动作或具名依赖。
已完成但未回复交付的项仍待交付；已交付事项退出活动清单，不复活未受影响的历史。
这是当前任务的轻量状态，不另建数据库、后台队列或重复清单，也不要求为每个工具动作写表。

研究用于取得能改变后续操作的知识与证据。按问题需要使用来源阅读、实验、实际运行、调试、
逆向、隔离副本及研究工装修改；“研究”本身不等于只读网页或只写报告。用户要求持续搜索时，
保留广泛发现，将影响现有目标的发现或关键依赖并入相应活动项，范围外发现只作候选；
已经明确的工作按其有效授权继续。
用户明确先研究后实施时遵守该顺序，研究中为取得信息所必需且已授权的操作仍应执行。
生产修改、设备写入、许可和其他外部影响分别核对权限；某个动作受限只阻该动作，不能自行
推出整个项目停工。工具、样本或权限确实缺失时说明影响与解除条件，继续独立部分。

工作包围绕一个可交付结果或能解除具名依赖的证据，带齐相关调用链、状态、失败分支与验收。
不能把整个领域泛派给一个执行者，也不能为了“最窄”压成脱离上下文的单键、单来源或单次搜索。
证据足够后接实际操作、实现或验收；继续深挖应能补一个会改变目标的缺口，不原样重派已完成题目。

父代理在成果返回、实际操作产生证据、依赖解除或用户纠正时，更新受影响目标并立即接续：
核对满足了哪个验收条件、还缺什么，把可采用结果交给下一实际消费者并执行或派发就绪工作。
明确派遣沿用 `$lean-stack` 的[用户明确指令](../lean-stack/SKILL.md#用户明确指令优先)直接落实，不回默认是否委派判断；
结果按原采用入口接续，父代理同时推进适合自己的实质工作。
用户要求持续派遣时，该要求覆盖后续接续：每次结果解锁、输入就绪或容量释放后继续补派，
不以首批完成、当前代理交稿或阶段切换为停止条件；真实依赖只阻对应项，不等用户再次催促。
完整切片通过验收后及时向用户逐项交付，不等其他主线全部完成；交付后只继续剩余项。
报告、保护开关、派发成功和测试数量仅证明各自范围，不能替代用户要求的功能或实际操作。
用户纠正只改实际受影响的目标、顺序或权限；助手建议不写成用户要求或用户指定优先级。

压缩与恢复使用[长任务的当前快照](../lean-stack/references/long-running.md)：恢复全部未交付目标及各自
下一动作、执行者或依赖，优先锚点不替代全体；较新明确要求覆盖相冲突的旧阶段安排。

## 最小完整方法

先理解真实调用流、用户可见结果和受保护边界，再选择第一个完整满足要求的选项：

1. 不实现当前要求不需要的行为；
2. 复用现有工具、类型、约定或帮助函数；
3. 优先标准库、平台原生能力、官方支持的扩展点、项目已有适用依赖，以及维护、安全、许可和
   兼容性可接受的成熟开源库；
4. 优先删除、内联、合并或一个聚焦改动；
5. 前述均不满足时才增加最少的新代码和文件。

按[多目标推进与逐项交付](#多目标推进与逐项交付)确定完整目标与当前工作包。动手前
写清要改变的行为、必须保持的行为，以及
哪一个最窄检查能区分对错；不预造用户未要求的产物、复核、升版、安装或发布。

在当前已授权修复范围内，必需的定位、代码修改、构建和最窄必要验收直接推进，即使预计耗时
较长，也不因“长任务”重新索要同意。说明可信进展、预计耗时及其依据即可，不把说明变成开工
审批；必要的离线构建、目标架构/格式检查和修复回归也适用。数秒内、低成本的必要验证同样
直接执行，不额外询问。

必要性对应当前用户的完成条件、真实阻断或具体风险：缺少该步骤就无法完成已授权修复、确认
该修复实际成立，或守住该动作不可省略的安全边界，且没有已有充分证据或等效的更窄方法。
“更保险”、工具默认流程、助手自设的完整恢复目标或一句“这是必要的”都不能替代上述依据。
复用有效证据；有等效更窄路径就采用，不把模块修复扩大成全系统重建或全量恢复工程。

仅对非必要、附加或边缘的长时间步骤，以及明显扩大读写量的附加步骤，先询问用户；常见包括
额外整卡备份、全量扫描、重复回读和扩大的保险性验证。说明具体动作、范围、可选收益、预计
耗时及依据；无法估时就明说。没有同意不启动，不能先后台执行再解释；未回答就跳过，不执行、
不排队，也不卡住其余已授权修复。已确认无收益或重复的工作直接不做，不为它另加审批。
已明确同意同一具体附加动作与范围时沿用授权，不重复询问；笼统“继续”或写入目标不自动授权
助手追加这些非必要长步骤。跳过的验证如实标为未执行，不声称已验证。

工具内部附带的备份、整盘复核或回读也按同一必要性和范围判断，不能藏在提交命令里绕过询问，
也不能把所有回读都自动当作必需。未获同意的附加阶段无法分离时，先选合适的可分离入口；
没有合规入口就说明该组合动作的具体冲突，不暗中执行附带步骤或绕过真实安全约束。
目标身份、授权范围、写入边界及当前动作不可省略的完整性依据仍须保留。实际超出已授权范围、
新增外部副作用或确实缺少所需权限时，仍先取得对应授权；“修复必需”不能自授权限。

本插件采用用户明确给定的升级默认：当前任务确实需要升级运行时、依赖或随项目交付的组件
（如 ARM Python）时，及时提出基于兼容要求选择的目标版本、升级原因、兼容影响及预计耗时。
使用非阻塞提问并继续独立工作，给用户合理的答复机会后，未回答即按这项预先授权升级当前项目
或交付物范围内的相应组件，不因无人答复停滞；明确拒绝、延期或指定版本优先。
这项用户已给的条件授权适用于本插件后续任务的同一范围，必要组件升级不因耗时长停下来等同意；
不能把沉默普遍解释为许可。它不扩展到全局系统升级、设备刷写或附加备份回读，实际权限与
不能满足的兼容条件仍须说明。

已能确认重复或超出实际目标、受影响范围，且无必要交付、验证、安全或恢复依据的长时步骤，
禁止启动或继续排队；已经开始时，在安全边界及时停止或缩窄，不继续沿同一路线堆叠步骤。
无法安全停止的在途外部操作依下方长任务分支保留原请求和恢复责任。字节数增加不自动证明方法合理；按任务目标和剩余缺口判断
有效推进。必要修复或已同意的附加步骤都不能无限续等；实际工作量或等待明显扩大时，先按
安全边界重评方法并说明变化。新增非必要长步骤或需要扩大授权时才另行取得同意，不因必要
修复仍需时间而重复请示。发现当前方法不能解除具名缺口、观察反复不变，或存在等效且明显更短的可验证路线时，
及时要求当前执行者重新核对目标、实际工作量和有效证据，改变下一动作，不靠继续等待或追加
同类核对拖延。这里要求简短的决定与依据，不展示思维过程、不另建评分或审批；必要验证和安全
停止条件保留，在途外部操作按[长任务的阶段与退出边界](../lean-stack/references/long-running.md)处理。

## 追加要求的作用范围

用户追加限制时，先按对象、动作和生效时间判断哪些当前要求被覆盖。“以后、下次、新一轮”
的限制指向后续任务，且本轮仍有明确授权并要求继续时，记录后续约束并继续当前任务；不能据此
自行取消在途准备、回滚、恢复旧状态或重启已完成阶段。任务复杂或有外部副作用不改变这一区分。
明确要求“本轮停止、现在取消、从现在起不再执行”的当前撤权，以及已证实的危险、权限缺口和
安全停止条件，仍立即按实际阶段处理。作用范围确实无法判定且会改变外部动作时，只澄清该项，
不自行选择取消或恢复作为默认；不受影响的已授权工作继续。

上下文压缩、重置或阶段切换后，恢复的是最新仍有效要求及其适用范围，同时保留已撤回或已到期的
临时例外。用户已恢复三原则后，旧的“不计成本、全用专家、持续顶满”不得重新生效；新派发按当前
规则判断。人数本身不证明违令或提速，依据实际分工、配置和结果说明，不把历史计划当成当前授权。

不能为少代码或少步骤删掉用户要求、错误处理、可访问性、安全、隐私、权限、数据完整性、真实
外部系统的不确定性处理或能捕获非平凡回归的低成本检查。完成条件来自用户可见结果；只读、方案、
暂停和审阅按指定边界停止，源码、静态文字、编译或子代理自报不能冒充真实运行。

按整项任务的完成时间收窄方法；用户明确指定是否委派、人数或协作方式时，先按[用户明确指令优先](../lean-stack/SKILL.md#用户明确指令优先)落实，
不以最少步骤或父代理实质工作要求缩减人数。默认增派也按 `$lean-stack` 的一次快判随进度进行；
多开或不限人数不自动改变成本优先级，各项特殊安排分别按用户实际要求执行。
已知多项就绪独立工作各需持续模型判断时，在逐项深入前读取或复用 `$lean-stack` 快判；
其余分工沿用其[一次快判](../lean-stack/SKILL.md#先判断是否委派再选模型与复用)，
立即派出有收益的就绪切片，父代理继续适合自己的实质工作，不等完整拆分或另做路线论证。
独立重算可以由父代理用工具完成，不自动增加一轮模型复核。

## 可选准备动作触发器

父代理已经理解目标，却准备执行一个不能直接产生首个可验证主任务结果、也不能解除已命名阻断的
可选准备动作时，及时应用本入口一次，只回答“当前代码、证据和授权内，哪条最短路径能产生首个
可验证结果”，随后立即执行第一项实际动作。

主父第一条说明给出当前理解、立即动作和必要限制，并合并本轮其他技能用途；不再为每个入口或分支
重复前言，也不重复发两份前言。能直接答完的请求由最终答案本身完成。

新会话额外预读或前言、目标与验收未定前的批量编辑、决定性验收通过后的同类复验都命中；正在
运行的必要工具、唯一权威读取、权限或安全检查和解除已命名阻断的动作不命中。本触发器不计时、
不创建脚本、Hook、持久状态或新子代理，也不得延后 `$lean-stack`。

## 进展说明与等待

执行期间及时说明已确认的进展、当前动作、变化和问题；相同状态不重复叙述，不以重复前言、纯确认或准备说明阻塞首个可验证结果。
收到“快点”、剩余时间、恢复默认或其他改变当前优先级的消息，能响应时立即简短说明怎样应用、
当前真实状态和紧接着的实际动作，再继续工具或派发；不等一整批工作完成才回应，也不先追加无关
读取或审查。工具阻塞期间尚不能处理时，恢复响应后据实交代限制与调整，不虚报已启动或已改路。
进入等待时说明最后可信状态和下一项可判断的信号。新的阶段、产物或回执、错误或阻断、估算或
下一动作因新证据改变，以及需要用户处理的事项，才构成等待期间的新进展。没有这些变化时，
不换措辞反复发送“仍在等待、原事务继续收口、没有新增操作”，也不为发消息反复查询同一事实。
连接仍为 `ESTABLISHED` 或一次查询正常返回，不等于任务已推进。用户主动问状态或宿主明确
要求可见说明时据实简答；实际有进展、风险或需要介入时及时说明，不把本段解释为默认静默。
等待连续十分钟没有上述实质变化时，必须介入：依据最后可信进展时间，做能区分原因的最窄诊断，
重新核对阶段、必要性和实际工作量，选择能解除缺口的不同下一动作；需要时及时要求当前执行者
重评并改路。十分钟是最迟介入点，不是必须先等满，也不由重复连接查询或心跳重置。
没有安全取消或可执行替代时，明确具体限制、仍可做的诊断和需要用户决定的继续/退出边界；
不能把同一路线原样再等一轮当成改路，不能为赶时限盲目强杀或重发有副作用的操作。
长时入口尽量保留可收取结果的句柄和可观测阶段，使停滞能被识别；不另建后台轮询或通用计时器。
同一根因的首次决定性失败后先修真实根因，再做一次能区分修复前后的复验；目标条件已覆盖就
停止。新证据、依赖、公共约定或风险范围变化时才扩大检查。

## 条件路由

按当前状态和下一项实际动作判断，不按用户是否写出条件名称判断。入口先完成快速判断，只保留会
改变下一动作的目标、步骤、风险、验证和停止条件；确认命中具体功能分支后，才读取其最小权威
段落。未命中分支不读取，也不批量预读可能稍后使用的分支。分支读取不再产生第二段技能用途说明；
读取后下一次工具调用执行该分支的实际操作。同一任务可以随实际动作依次命中多个分支；每个分支
在真正开始对应动作时读取，不能预先成批加载，也不能因拆分而跳过后继触发。
