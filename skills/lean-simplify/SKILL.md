# Codex 主任务精简

这是 `codex-lean-stack` 的主任务精简入口，与 `$lean-stack` 子代理调用并行。它决定主任务需要
哪些步骤、做到什么范围和何时停止；工具与 PowerShell 路径由两个入口共同收窄，只有步骤需要
模型或子代理时，才同时由 `$lean-stack` 决定调用路线。任何一个功能都不能用自己的运行记录
替代另一个功能的成功证据。

只要主任务需要调查、实现、测试、复核、发布或文档维护，就先使用本入口，不等待用户再次说
“精简”。无需工具的一次性答复和单个确定性工具动作直接完成，不为加载技能增加重复前言或步骤。

本入口是提示驱动的执行合同，不声称存在自动删除器、后台消融服务或宿主调用前 Hook。当前
任务是否允许修改、创建独立任务、运行外部操作或产生不可逆影响，仍由用户要求和更高层规则决定。

工具与 PowerShell 路径精简是两个入口共同遵守的执行底座。主任务优先直接使用足够的确定性
工具，多个独立短命令用一次工具调用并发；多层引号、JSON、正则或多行 PowerShell 逻辑及时
改用任务专属脚本，不为精简任务增加多余包装、重试器或通用执行层。只有需要持续模型判断时，
才由 `$lean-stack` 继续选择模型和子代理。

两个入口都必须保留用户要求的结果、当前授权、安全、权限、数据完整性和与结论匹配的证据，
并且不得因本次双入口拆分恢复历史上已经删除的大规模中间机制。详细判断只由
[反 AI 过度工程](../lean-stack/references/anti-overengineering.md)承载，不在两个入口重复维护清单。

## 最小完整任务方法

先理解真实调用流、用户可见结果和需要保留的边界，再停在第一个能完整满足要求的选项：

1. 不实现当前要求不需要的行为；
2. 复用仓库现有工具、类型、约定或帮助函数；
3. 优先语言标准库；
4. 优先平台原生能力；
5. 优先已经安装且适用的依赖；
6. 优先删除、内联、合并或一个聚焦改动，而不是增加新层；
7. 只有前面都不满足时，才增加最少的新代码和文件。

不能为减少代码或步骤而删掉信任边界验证、防止数据丢失或静默损坏所需的错误处理、安全、
隐私、权限、可访问性、用户明确要求、真实硬件/外部系统的不确定性处理，或能捕获非平凡回归的
低成本检查。精简修复落在共同根因，不在可见症状周围堆叠补丁。

## 主任务状态和沟通收窄

- 从最早尚未完成或尚未交付的当前要求继续；纠正只重开受影响项，已交付事项和无关历史待办
  不复活。会话内只保留轻量活动清单，不建立后台状态机。
- 每条新要求先简短说明理解、立即动作和必要限制，随后继续；过程中只报告会改变后续动作的
  进展、阻断和结果，最终回复独立交付新完成内容、证据范围与真实缺口。无需工具的一次性简单
  回复中，最终答案本身就是首条快速说明，不额外发送重复前言。
- 从用户可见结果确定完成条件。实现继续到当前授权内的最窄运行、检查和失败修补；只读、方案、
  暂停或审阅任务按用户指定边界停止。初版代码、静态文本或子代理自报都不等于完成。

## 主任务工作链

本入口只决定主任务步骤与范围；详细手册各保留一个权威来源，不复制成新的固定流程。

| 主任务精简面 | 最小执行合同 |
| --- | --- |
| 调查、实现和任务手册 | 只选当前需要的[调查](../lean-stack/references/investigation.md)、[缺陷修复](../lean-stack/references/bug-fix.md)、[构建](../lean-stack/references/build.md)或[审查](../lean-stack/references/review.md)；只有真实多阶段依赖才读取[长任务](../lean-stack/references/long-running.md) |
| 测试、复核和重验 | 先确定会发现真实错误的最窄检查、预期来源和受影响范围；不能从仓库现有测试文件数、测试函数数、历史全套命令或“发布”标签反推本轮范围；不因“全面”而运行无关套件，也不删掉安全、权限、数据完整性或真实回归需要的检查 |
| 条件性语义复核与最终验证链 | 只有代码、配置、公共行为或高风险范围变化时，才按[条件性验证](../lean-stack/references/execution-routing.md#七条件性验证)做会推动修改的语义复核与必要最终检查 |
| 失败后的最窄重验链 | 只修真实原因，只重跑失败项和受影响项；来源与风险未变化的通过证据继续复用 |
| 发布、安装和文档维护 | 只更新不改就会作出错误承诺的表面；获授权发布或安装时才读取[版本与发布](../lean-stack/references/versioning.md)，同轮已有版本收据时不重复升版 |

`迭代测试链` 属于 `$lean-stack` 子代理调用：它负责在迭代中选择直接工具还是有收益的验证
子代理并收集结果。本入口只确定主任务应测什么、预期来自哪里和受影响范围，并消费该链结果。
`精确删除与否定重做` 同样属于 `$lean-stack` 的角色、经验与生命周期清理；主任务消融中的
删除、内联或合并不能替代角色资料的所有权、任务尝试、哈希和失败次数等资格。

完整链路图只用于说明归属，见[中文链路图](../lean-stack/references/flowcharts-zh.md)；真实执行仍以
制品变化、工具输出、宿主子代理调用记录和匹配风险的验收结果为证。

## 三种使用强度

先区分三种强度，不把普通任务步骤或预防性检查自动升级为正式消融：

1. **主任务精简。** 主任务进行时持续选择刚好足够的调查、实现、验证、重验和收口步骤；
   不把全部手册、全部检查或全部子代理链设成固定必经流程，也不因追求少步骤而省略决定性证据。
2. **预防反过度工程。** 当前实现、兼容层、验证、迁移或规则可能扩大维护面时，完整读取
   [反 AI 过度工程](../lean-stack/references/anti-overengineering.md)。先找真实消费者、实际数据
   变化、触发动作和可核验证据；没有现实消费者的内部新功能不预造兼容层、第二事实源或重复
   验证。验证强度按真实风险决定，不由“迁移”“全面”或“安全”等标签自动放大。
3. **显式消融（正式消融实验）。** 只有用户明确要求“进行消融实验”、精简当前代码或设计、去掉不必要
   抽象或同义操作时，完整读取
   [消融反馈循环](../lean-stack/references/ablation-loop.md)。普通设计、实现、重构、审查或测试
   完成不自动启动，也不例行询问。

## 采用标准

主任务精简以更少且足够的动作完成用户结果，并取得与当前风险匹配的决定性证据；删掉一个
必要步骤不算精简，增加不改变下一动作或结论的调查、规则、测试、复核与重复验证也不算完整。

正式消融先冻结核心功能、用户设计意图、公共约定、安全、权限和数据完整性边界，并记录
`ABLATION_BASELINE`。一次只真实删除、内联或合并一个候选；改名、移动、别名和转发包装不算。
使用同一组最窄相关验收比较前后，只有功能与受保护边界不回退、维护面确实减少时才采用，最后
形成 `ABLATION_REPORT`。不能完成独立上下文或同一验收时，只能交付候选与缺口，不能宣称完成
正式消融实验。

预防性检查的完成证据是删去或避免了没有真实消费者的维护面，并保留当前任务所需功能与相称
验证；仅新增一条规则、通过静态关键词断言或压缩文字长度都不是充分证据。

## 与子代理调用的关系

主任务始终用本入口关注精简；只有步骤涉及模型或子代理时，才同时进入 `$lean-stack` 的质量 →
成本 → 时间路线判断是否委派。该顺序只决定执行路线，不决定步骤是否必要或精简候选是否采用。
调用过子代理、生成过
角色 TOML、写入过 SQLite 经验或完成过摘要压缩，都不能替代真实结构变化和前后验收。

`skills/lean-stack/scripts/agents.py` 只维护子代理角色、运行、经验和有界提示摘要；它不会启动
子代理，不会删除或内联源码，也不是精简执行器。实际派发必须有宿主 `spawn_agent` 或
`followup_task` 证据，实际消融必须有本节所述结构变化和验收证据，两类结论分别报告。

同一卷内只改变路径的移动、改名或重新挂接目录不属于内容迁移：按上述反过度工程规则验证精确
源/目标、卷、重解析点、路径映射和结果结构，不默认建立迁移前后整树逐文件长度与 SHA-256
清单。实际字节复制、正式发布或安装清单、安全关键完整性约定，以及用户明确要求逐字节核验
时，仍对预先声明的范围做相称验证。
