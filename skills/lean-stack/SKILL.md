# Codex子代理调用与精简流程

让主任务在守住高价值质量的前提下以更低总成本完成。代理管理、经验、验证和版本是辅助能力，
不能拖延交付。
所有模型与思考程度的父代理均须使用本插件规则；已加载且未变化的规则直接复用。
本入口保留共同决策与必要边界；只在进入相应操作时读取所链接的细则，不预读全部参考文档。
普通子代理从任务说明、已加载角色和指定证据直接开始；本入口的项目接手、选配、发布与经验
管理由父代理负责。子代理不因新线程或上下文重置自行全文读取交接、整套技能或搜索插件缓存；
仅在分配的职责需要或用户明确要求时读取相关部分，更高层明确读取要求仍须遵守。

## 三项原则

1. **高价值工作质量优先。** 先守住正确性和决定性证据；可靠性达标后先比较总成本，成本相近
   才比较完成时间。
2. **质量达标后总成本优先。** 比较父子输入输出、分派、交流、核验、返工和新增服务费用，
   选择全任务总成本更低的路线。
3. **成本相近时再比速度。** 只有当前用户明确速度或期限要求时才提高速度权重；没有相应质量
   收益时，不为单纯提速大幅增费。

安全、权限、数据完整性、明确验收条件和诚实证据始终是底线；委派不增加权限。
三原则对调用、选配、拆分和核验起决定作用。高价值的必要质量收益可以承担成本；质量和决定性
证据达标后先比较父子合计总成本，成本相近才比较总完成时间。用户明确的当前期限或速度偏好
参与权衡，但不能省略质量底线或必要核验。
用户最新明确要求优先于技能建议与历史交接，更高层指令及实际工具约定仍须遵守。

## 主任务与用户沟通

主任务从最早一个尚未完成或尚未通过用户可见回复交付的要求继续。新要求、纠正和补充验收
累加到对应活动项；明确取消或替换只作用于指定项。完成且已交付的要求立即退出，不等待再次
确认；后续“继续”只恢复剩余项，无关历史待办不复活。只维护会话内轻量清单，不建后台状态机。

### 首条快速说明

每条新要求先简短说明当前理解、立即动作和必要边界，随后继续。首次选路说明工具或子代理
怎样帮助本任务即可；最终答案本身就是首条快速说明时，不重复前言。
持续实现、调试与等待中，及时报告具体进展、采用的发现、未决问题和下一动作。内部子代理消息
的有限配额不限制面向用户的说明，不把父代理“无异议沉默”外推到用户沟通。

### 完成标准与停止边界

从用户目标确定可观察的完成结果。实现任务通常包含实现、已授权的最窄运行或测试、检查结果、
修复本次引起的失败，以及交付实际入口；初版代码或子代理报告只是中间结果。用户明确只读、
只提交方案或先停在审阅点时，以该边界为准，不擅自扩成实现。
用户明确选定的技术栈、架构边界和数据处理方式属于验收约束；简化、优化、修复或上下文压缩
不授权替换它们。委派和恢复时携带相关约束及来源，现有实现漂移不能反过来证明变更已获准；
具体检查见[构建中的既定决策](references/build.md#既定决策与改动范围)。
构建先明确变化、保留行为与判别检查；修补依据新证据，验收预期独立于实现。细则分别由
[构建](references/build.md)、[缺陷修复](references/bug-fix.md)与[条件性验证](references/execution-routing.md#七、条件性验证)
承载，UI 同时需要相关的实际交互证据，不以首次通过省略必要验证。
已授权的本地可逆工作、相关隔离测试与失败修补连续推进，不逐步重新申请同一授权。缺失信息
确实影响目标或安全时才询问；等待后续动作的授权期间，先完成仍获准且可独立进行的准备。
被阻止时只停止受影响动作，不能换工具绕过边界；用户撤回或调整授权后及时纠正执行者，迟到
结果不能恢复旧授权。技能导致暂停或未完成时，链接实际读取的文件、引用关键原句，区分明确
要求与自己的解释，并先检查本会话是否已有授权。

最终说明独立交付本次新完成结果、必要原因、实际文件或入口、验证对象与覆盖边界，以及剩余
影响和最窄下一步；不以“已调用”或过程记录代替结果，不重复已交付历史。源码、静态检查、
编译、真实运行、安装缓存与正式交付分别说明；验收达到后停止扩张，必要验收未完成时不能报全部完成。

## 一次调用判断

父代理先判定具体任务类型。确定性短工作直接用工具；独立短命令工具级并发，长而确定的命令
使用持续终端或后台。不为凑数委派，也不让子代理只运行命令回报退出码。

需要持续模型判断时，只做一次正向判断：是否已有就绪、边界明确、可安全独立推进且符合三原则的
子任务？必要质量收益，或质量达标时的全任务总成本优势，都可构成调用收益；成本相近时再看
总完成时间，用户明确当前期限或速度要求时按该要求调整权重。
正向寻找能替代父代理实际阅读、实现或分析工作的切片；能独立端到端完成并自检的任务也是候选，
不把子代理局限在边角工作、只读审查或最终复核。有则立即调用，不等待用户重复要求。输入未就绪、缺少真实工具或权限、
写入无法隔离、重复已有工作，或大幅增费而无必要质量收益时不调用。收益按任务形状判断，不做评分表。

持续的多工作流任务一旦出现多个互不依赖、已就绪且能替代父代理实际研究、实现或验收的切片，
默认在父代理深入读取额外来源族或开始实现前，尽早派发全部当前有收益且互不冲突的 GPT-5.6 切片。
调用数量随真实工作流、边际收益与运行容量变化，不设最低数量，也不要求逐片量化节省；无法
精确量化本身不能否决调用。输入未就绪、严格依赖、权限不足、写入冲突、重复已有工作、容量
不足，或大幅增费而无必要质量收益等明确阻断才停止相应派发。只在后期增加一次复核不能替代
前面的实际工作。父代理保留交接全文、关键约束、共享热点、整合与必要验收；新要求改变工作流
时立即按新任务形状重新判断。
在适用指令允许的范围内使用本插件判断，不额外套用官方默认调用触发规则；任务类型组、已有
保留角色、持久创建和经验写入都不是当前调用前置条件。父代理同步推进不重叠的主任务，
只在真实依赖点汇合，不为收齐非必要结果而等待全部。
按主任务剩余时间选择切片：短小确定性核对直接批量工具处理；必要复核保留独立性，非必要
调查不能成为交付门槛。父代理发现预读偏离、重复证据或成功条件已达到时及时收窄并收口，
不靠增加并发补救无收益拆分，见[委派替代工作](references/execution-routing.md#让委派替代工作)。

确定调用后，先按可复用能力族及兼容的工具、权限、风险和证据形状确定任务类型组，再匹配
可见保留子代理；有则复用，没有则定制本次运行时子代理。同一能力族内的调查、诊断、实现、
修复、测试或验收，只要没有跨越角色的写入权限、专用工具、安全边界和决定性证据边界，就按
同一种活匹配；具体项目、框架、动作动词、交付名称、成功条件或需要不同档位本身不构成新
领域。只读角色仍不能借“范围放宽”获得写权限，工具、权限、风险或证据形状不兼容时才拆分。
运行时定制不等于持久创建，不等待热加载。
描述不足、可能遗漏复用，或准备因无匹配而新建角色且尚未查目录时，按[保留子代理经验](references/specialist-memory.md)从已加载技能的
绝对目录执行一次 `scripts/agents.py status --for-routing`，复用当前结果，不例行遍历台账。
角色未加载或配置需适配时，用 `recall --name` 有界取得同角色职责与经验后适配本次调用；
职责部分匹配就只分配合适切片，不因名称或档位不同放弃已有专长，也不为复用率强行委派。

并发以运行环境当前可用槽位与计数口径为准；`agents.max_concurrent_threads_per_session`
的名字不证明是否计入协调者。容量是上限，不是调用目标，不另外设置插件调用次数限制。
单会话累计调用次数不设插件上限；每次调用仍按三原则判断，运行环境的并发容量与累计次数分开。

有收益的委派尽量发生在父代理，尤其是昂贵父代理，大量预读或生成之前；工具先定位，子代理完成
可替代的阅读、生成或独立判断。父代理保持用户选定的配置，负责约束、冲突、必要核验与整合，
不完整重做子代理已经完成且证据充分的工作。把启动、父子输入输出、核验和返工合计
考虑，不以主代理 token 减少冒充总成本下降；操作细则见[执行路由](references/execution-routing.md#让委派替代工作)。

## 选配与上下文

保持用户选定的父代理配置。子任务联合选择 `模型 + 思考程度 + 速度`，不能机械继承昂贵配置、
按模型固定思考档位或为分布均衡混配。`gpt-5.6-luna`、`gpt-5.6-terra` 与 `gpt-5.6-sol`
是通常候选：普通窄任务优先 Luna，可靠语义判断优先 Terra，Sol 可端到端承担复杂高价值实现、
分析与自检。Astra 只在相对这些候选有额外决定性质量，或能以更少返工、token 等使全任务总成本
更低时考虑，不能只凭更快选择。新选配默认标准速度，包括 Luna；只有当前用户明确速度或期限
要求，且完整路线有收益时才用快速。已有显式快速配置保留真实值；复用不适配时只调整本次调用，
不批量重配。更强配置可直接选择，不强制廉价模型逐级试错。

独立、范围窄的任务优先 `fork_turns="none"` 和自包含任务说明；依赖前面决策时才给有限历史，
确需完整历史且继承组合合理时才用 `"all"`。任务专属工具限制、安全边界、写入范围与停止条件
必须显式放进新上下文任务说明；继承历史也不能代替当前边界。历史里的父级编排指令不授权
普通子代理另开主线或下游。读证据、普通执行与复杂推理可分别考虑 low、medium、high 等档位，
这只是起点，仍按任务风险、歧义、模型能力及实际支持的组合判断。

能用来源定位、当前约束和未决问题自包含说明的研究、实现或验收切片，不因父代理已经拥有长
历史、使用 Astra、发生过上下文压缩或读过大工具输出而继承 `"all"`；这一最小上下文原则沿
协作父代理、复制与下游逐层适用。只有完整历史中存在无法由有限摘录或来源快照保留、又直接
关系正确性、权限或决定性证据的输入时才使用 `"all"`，并在任务说明中点明该输入和覆盖边界。
已完成子代理结果、完整工具输出和父级编排过程本身都不是全量继承理由。
Astra 对这些上下文读取、传播、结果复用和增量补缺规则没有例外。

父代理首次采用子代理结果后，在当前会话保留结果身份、来源快照或覆盖范围、已满足成功条件
和剩余决定性缺口组成的轻量收据；上下文压缩后复用这份收据，不重新读取已交付结果。只有
来源变化、覆盖不完整、结果与当前事实冲突或必要验收仍有具体缺口时，才定向补读、补验或
增量追问；没有具体缺口就停止收取和追问。必要的接口、安全、权限与数据完整性核验仍保留。

实际工具 schema 决定可选字段；当前 `spawn_agent` 没有独立速度参数，角色 TOML 的
`service_tier` 可提供已加载配置。不能把任务卡文字或四行声明当作选速成功、计费或测速证明。
选配、上下文覆盖或执行路线确有疑问时读[执行路由](references/execution-routing.md)；
需比较配置或维护费率时读[成本预估](references/cost-baseline.md)，不逐任务联网查价。

## 委派与收口入口

首次实际派发前读取[子代理委派](references/delegation.md)，当前上下文复用。任务说明必须给出
来源、具体职责、父代理规范任务名、写入所有权或只读限制、工具与外部影响边界、成功条件、
停止条件和有限关键步骤（可为“无”）。关键步骤只有真实依赖需要中途结果时才设置。实现者必须
知道共享目录还有其他代理，不得回退他人修改。固定四行实际配置在子代理 commentary 公开，
最终回复保留配置抬头；普通任务不再向父代理重复发送相同四行，也不索要确认。

同一团队中，子代理只在发现真正解锁队友或父代理下一动作的证据、需要输入纠偏，或出现风险、
阻断时，用 `collaboration.send_message` 向已知接收者发送有来源的短消息。正常过程随最终回复
交付，不重复发送。消息不授权改写对方职责；范围调整、冲突与共享写入仍交父代理裁决。
普通子代理各自交付结果，不代交或隐藏队友结果，不用跨任务工具冒充内部消息。
父代理保持用户沟通、避免重复调查、整合结果；只在有收益且任务说明明确允许的子项目内
启用协作父代理，下游及跨任务细节见[协作父代理与父代理之间](references/collaboration.md)。
跨任务动作须符合当前工具要求；技能或任务卡不能代替工具要求的用户明确新建任务授权。

同类额外子任务复制组内子代理；只有复制前确认改进空间时才形成变体，比较完整配置组合。
各结果先独立核验采用，竞争只选择未来保留者。用户否定的子代理立即停止，其结果与经验候选
失效；共享修改只按明确归属撤销，不能整树回退。并行写入、热点与恢复细节在涉及写入时读
[可写子代理并行](references/write-parallelism.md)。

每个任务类型组结果核验采用后，先形成可跨项目复用的全局领域合同，再按
[保留子代理经验](references/specialist-memory.md)默认各有界尝试一次 `ensure` 和 `improve`。
每个全局领域组只保留一个休眠配置，没有项目保留层；保留不延长运行线程。
保留身份启动前分配 UUID `run_id`；任务完成且父代理取得明确最终判断后才幂等
`record-run --outcome success|failure`。成功必须达到成功条件、核验采用且 Done；失败必须是整个任务已明确
失败。运行中、中断、未采用、用户停止或否定、工具缺失后停止及结果未定都不记为失败。累计
两次明确任务失败时，永久移除该角色 TOML、身份、全部成功/失败运行、原始经验、纠正事件与
摘要；不保留退役身份、收据或恢复入口。权限、锁、结构、身份或 CAS 失败时零写入跳过，说明原因；
不重试或等待维护。经验准备只在预计能降低后续全任务总成本或提供必要质量收益时提前进行，不因
空闲槽位单独启动，也不是提交前置条件。经验维护完成或
安全跳过后，其他候选退出；普通手动删除资格不因精简提示而放宽。最终按组简述角色和
经验保存回执，不新造同领域记录或保存来源项目及敏感内容。
需要查看聚合时，`status --for-dashboard` 做一次只读快照；加 `--watch-seconds 1..3600` 后在
前台逐行输出周期快照，`Ctrl+C` 结束。它不创建后台任务，也不冒充 Codex 插件卡自动刷新。

## 项目交接与文件边界

新会话检查项目根 `Jiao-Jie.md`：有则父代理只读当前用户要求，以及会改变当前下一动作的
重要片段——最新快照、最早活动项、最后可信状态、相关稳定决定、来源定位与授权边界；无则
创建。工作上下文重置后（包括压缩或切换上下文窗口）按同一边界恢复，不重读已交付历史、
旧快照、大日志、已采用子代理结果或无关稳定规则；只有重要片段标明缺口、冲突或来源变化时
才定向展开对应段落。随后简短告知已读范围与接续事项，普通后续轮次复用，不为补通知重复读取。

上下文重置后的插件规则只读取一次本 `SKILL.md` 入口；当前活动项实际进入某项操作、对应
reference 尚未加载或已经变化时，才按入口定向读取那一份。入口和未变细则在当前工作中复用，
实际调用子代理时不得再为“调用插件”重读一次，也不顺带重读全部 references、子线程或工具
