# Codex 子代理调用

## 何时使用

本入口负责判断是否委派、选择模型与思考程度、复用子代理、限定上下文和采用结果。首次准备
`collaboration.spawn_agent`，或准备让现有子代理承担新的相关子任务时读取；本轮已经读取且文件
未变化时直接复用。`$lean-stack` 与 `$lean-simplify` 平行、独立，互不构成前置条件。

确定性短工作直接使用工具。切片就绪、边界清楚且可独立推进时，按场景使用三项原则：

1. 高价值工作质量优先，守住正确性；当遇到困难时派遣专家协助。
2. 普通工作可靠性相当后，总成本优先。
3. 总成本处于可接受成本带时，为加快父任务完成速度，增加或并发派遣子代理来节省时间是可取的。

三项不是每次调用必须同时获益的硬门槛，提速也不是每次委派的必要条件。总成本同时计入
父代理独做与委派后的启动、交流、整合和核验。调用数量本身不是目标，也不是错误；
多个互不冲突的切片各有真实收益时可按上述原则并发。安全、权限、数据完整性和诚实证据
始终优先。

## 模型与思考程度

| 模型 | 适用任务 |
| --- | --- |
| `gpt-6-luna` | 规格清楚、证据已定位、结果容易核验 |
| `gpt-6-sol` | 跨来源或模块因果、复杂实现与验证 |
| `gpt-6-astra` | 相对最强可行 Sol 仍有决定性质量收益的专家问题 |

思考程度从 `medium` 起，按任务选 `high` 或 `xhigh`；Astra 的 `xhigh` 是上限，不是默认值。
Sol 的 `max`、`ultra` 仅按[首次派发](references/dispatch-start.md#模型与思考程度)
中的质量条件选用；普通任务不因模型名称或任务标签升级。

## 同一能力族优先复用

决定委派后，依次选择兼容的 live child、已加载 `agent_type`、最小运行时子代理。能力族按职责、
输入、交付、权限、安全风险和证据要求判断；完成状态本身不妨碍续用 live child，同任务继续
只发送新增目标、证据或纠偏。真实模型须为上述三款且思考程度不低于 `medium`；同身份配置
可经核验用 CAS 安全重配，当前宿主已加载的旧配置须由新任务验证。执行者选择、一次有界
`recall`、失败改派与任务卡细节见[首次派发](references/dispatch-start.md#选择同一能力族的执行者)。

## 原生调用与任务卡

每次 `spawn_agent` 显式传实际 `model`、`reasoning_effort` 和 `fork_turns="none"` 或有限
正整数；禁止 `fork_turns="all"`，TOML 和任务卡不能代替原生参数。已加载保留类型须与原生目录
固定配置一致。五行真实开场与 final 三行的唯一详细规则见
[首次派发](references/dispatch-start.md#任务卡上下文与所有权)；缺少实际状态先内部补齐，
不向用户显示占位语。保留 TOML 的经验已在 `developer_instructions` 原生注入，召回成功后
任务卡只传五行状态，不复制经验正文；子代理读已注入经验一次即开始任务。

## 执行、结果和可选保留

派发后父代理继续未分配主线，以 final 或等价结果收据采用结果；进展说明不构成交付。
结果核验后主任务立即继续。新能力族的跨任务价值经核验后可按需 `ensure`，无新增经验
也无需 `run_id`；成功结果只有新增可复用经验才 `complete-run`，已核验保留身份的明确
失败可不带 `--lesson` 记录。普通派发不进行成本、迁移或摘要巡检。身份、CAS、经验与
第二次明确失败的写入边界见[保留子代理经验](references/specialist-memory.md)。

## 条件路由

只在下一动作真正需要时读取对应最小分支：

| 下一动作 | 权威入口 |
| --- | --- |
| 选择执行者、模型、思考程度、任务卡或调用参数 | [首次派发](references/dispatch-start.md) |
| 分配长来源、复用证据包或补具名缺口 | [来源所有权与结果收据](references/source-results.md) |
| 准备运行时复制、配置变体、结果比较或处理用户否定 | [任务类型组、复制与变体](references/agent-groups.md) |
| 接收中间消息、最终结果、等待或停止 | [子代理结果与汇合](references/agent-results.md) |
| 两个或更多执行者写入文件或共享状态 | [可写子代理并行](references/write-parallelism.md) |
| 当前子代理将再派下游，或与其他 Codex 任务协作 | [协作父代理](references/collaboration.md) |
| 创建或重配保留身份、读取经验、记录结果、迁移或删除 | [保留子代理经验](references/specialist-memory.md) |
| 选择直接工具或验证子代理，或失败后最窄重验 | [条件性验证](references/verification.md) |
| 维护官方费率或插件成本基线 | [成本预估](references/cost-baseline.md) |
| 用户明确调用流程图并要求检查或解释 | [中文链路图](references/flowcharts-zh.md) |

下一步属于主任务调查、实现、复核、消融或发布时，独立使用
[$lean-simplify](../lean-simplify/SKILL.md)。未命中分支不读取，不把 reference 变成普通调用前置。

## 正式宿主证据边界

静态文案、模板测试、源码读取、安装成功或缓存相等不能证明真实宿主采用了本路线。正式验收需要
在安装后的新任务中观察原生调用参数、子线程开场和最终结果；子代理进展说明是否显示还需单独用
用户实际界面确认。辅助脚本维护身份和经验，不启动子代理，也不证明宿主加载了经验。
