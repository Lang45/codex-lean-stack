# Codex 子代理调用

## 何时使用

本入口负责判断是否委派、选择模型与思考程度、复用子代理、限定上下文和采用结果。Computer Use
操作前独立触发，含只读界面观察、应用清单；不等到已经决定委派才读取。其余首次准备
`collaboration.spawn_agent`，或准备让现有子代理承担新的相关子任务时读取；本轮已经读取且文件
未变化时直接复用。`$lean-stack` 与 `$lean-simplify` 平行、独立，互不构成前置条件。

## 用户明确指令优先

先落实用户对当前任务是否委派、子代理人数、并行方式、模型与思考程度、工具或操作者及具体分工的明确要求；三项原则只决定
用户未指定的选配与执行细节。不得用默认成本收益判断、工具优先、线程复用偏好或父代理实质
工作要求否决、缩减或延后这些明确要求；用户说“不派子代理”时也不得按默认原则自行派发。

明确要求某个切片由专家执行时，直接在[专家路线](#模型与思考程度)选配。
明确要求增开、不限数量、持续顶满或不计成本时，按[持续并行提速](#用户要求持续并行提速)
分别落实人数安排、补派和成本约束，不把人数要求自动解释为不计成本。

- 用户说“启动十个代理”“开 10 个并行”等，人数就是当前任务要落实的目标，不能解释为上限、
  可选建议或“有收益时再开几个”。立即按真实任务划分不同职责，先派已就绪切片并尽早补足；
  不等父代理深入做完、全部拆分完或下一轮提醒。用户明确要求新启动时不能用旧线程冒充。
- 数量以真实原生调用和当前状态为据：父代理、已完成或关闭的历史子线程、只等待未就绪输入
  的线程，以及发送消息的次数，都不能充作正在并行工作的子代理。汇报区分已启动、正在运行、
  已完成和受阻；未达到人数时说明真实缺口，不把“会扩到十路”写成已经落实。
- 只有更高优先级要求、安全、权限、实际宿主容量、真实依赖或共享写入冲突能限制执行；须说明
  具体阻断、实际可运行数量与最窄替代，并继续不受阻的工作，不能以“成本高”“可能不划算”
  或一般效率偏好代替阻断。单个界面保持一个操作者，其他代理可负责独立实现、事实核对与验证，
  不能把单操作者限制泛化为整个任务只能少派。不得虚构任务、空转占位或绕过真实容量。
- 用户要求边执行边看到结果时，已就绪的完整切片及时进入实际交付入口；补足队伍和落地成果
  共同推进，不等全体结果齐备。补丁就绪、计划或派发成功不等于用户已看到实际变化。

明确要求沿用到用户撤回、覆盖、停止或当前主任务交付；压缩或交接后仍按未完成要求恢复，
不得重置为默认人数；恢复前同时核对已撤回或已到期的临时例外，不能重新启用旧的不计成本、
全用专家或顶满模式。用户已恢复三原则时按当前规则派发，具体生效范围依
[追加要求的作用范围](../lean-simplify/SKILL.md#追加要求的作用范围)。只使用当前任务的轻量状态，
不新增全局调度器、配额或后台状态机。

用户未指定时，确定性短工作直接使用工具；已确定需要界面操作的 Computer Use 按[父代理指导、按任务选配](#computer-use父代理指导按任务选配)执行。
在用户未明确改变的选配范围内，切片就绪、边界清楚且可独立推进，按场景使用三项原则：

1. 高价值工作质量优先，守住正确性；当遇到困难时派遣专家协助。
2. 普通工作可靠性相当后，总成本优先。
3. 总成本处于可接受成本带时，为加快父任务完成速度，增加或并发派遣子代理来节省时间是可取的。

三项不是每次调用必须同时获益的硬门槛，提速也不是每次委派的必要条件；必要质量或真实总成本
收益可以支持较慢的路线，但必须对照整项主任务判断。总成本同时计入父代理独做与委派后的
启动、上下文、交流、等待、整合和核验，不能只比较子模型单价或父代理减少的工作。
用户未指定人数时，调用数量本身不是目标，也不是错误；多个互不冲突的切片各有真实收益时可按上述原则并发。
三项原则不对应三名代理或三路并行，也没有默认人数定额；实际人数由当前独立工作、必要质量、
父子合计成本与整项完成时间决定，不由首批人数、保留身份数量或历史小队规模决定。
安全、权限、数据完整性和诚实证据始终优先。

## 先判断是否委派，再选模型与复用

本节只补足[用户明确指令](#用户明确指令优先)未指定的部分，不再次审议已指定的人数与协作方式。
根据已知目标、输入、风险和当前分工做一次简短判断，结论明确就立即行动。整项完成时间与父子
合计成本是判断视角，不要求展开三条完整路线、量化收益或逐项写论证；不为普通委派查价、试跑
或额外收集成本数据，也不把判断交给另一个代理。

- 平均值、汇总、格式转换、哈希比较、已定义公式的计算和现有脚本可完成的核对，由父代理直接
  用工具完成并批量处理。同一规则下的多轮原始事件可以集中解析；“独立重算”“补核”“审核”
  等名称不自动产生调用另一模型的必要性。用户明确指定某项交给子代理或 Computer Use 分工除外；
  泛指“多派”不等于指定这些计算也要委派；明确人数仍须按优先节落实，父工具计算不构成缩减队伍的理由。
- 切片需要持续模型判断、输入足够、边界清楚且可独立推进，按任务形状合理预期有质量、合计
  成本或整项时间收益，就直接选执行者并派发；不等待收益被量化证明。公共接口、安全、迁移、
  数据完整性等必要独立复核直接按风险安排，不重做节省论证；常规核对不因此升级成逐轮模型复核。
- 分工时同时保留适合父代理直接推进的实现、研究或独立验收主线，立即派出其他有收益的就绪
  切片；不等待整项任务拆完、其他输入就绪或父代理先动手。有适合父代理的实质工作时直接推进，
  不为“多派”把它也外包；运行已有检查、维护版本/交接和最终汇总本身不能替代这条主线。
  实际依赖、必要复杂验收或缺少适合父代理的切片时可以专门协调，不设写代码配额或重复劳动。
- 同一任务阶段沿用已作分工；纠偏、解锁和语义增量直接续用兼容线程，不逐条消息、点击或工具
  步骤重判。新增确定性核算由父工具处理，新的独立语义切片只做上述快判；目标、质量、权限、
  依赖或成本预期实质变化时才重新选路。已有熟悉代理本身不构成委派理由。

默认三原则也随进度增派，不等待用户再次要求“多开”。首批分工、新独立输入就绪、已有结果解除
依赖或运行容量释放时，只看尚未分配且可独立完成的工作，沿用上述快判：必要质量、父子合计
成本收益，或可接受成本带内缩短整项完成时间，支持新增一路时立即派发；仍有这样的切片就继续。
没有新的有益切片，或存在真实依赖、权限、写入冲突与容量限制时才停止本次增派，受影响项之外
继续推进。沿用已有分工不等于冻结队伍；现有人数不是停止理由，也不能为增派制造任务。
同一能力族可承担多个独立切片，复用一个身份不等于只允许一个运行线程。父代理同时推进主线，
不重新评审已经分配且条件未变的工作，不增加打分、定时轮询、逐次审批或固定批次。

收益不明的零碎工作直接完成；只有会改变当前选路的具体质量、权限、依赖、冲突或显著成本疑问
才补查该缺口，不挡住其他已就绪切片。快判不生成评分表、计时器、固定路线收据或调用配额，
也不替代必要的安全、权限、数据完整性和工具可用性检查。

## 用户要求持续并行提速

先分清用户具体改变了什么，以下要求可以组合，只在指定当轮或任务范围内生效：

- “并行数量不限、取消人数限制”：取消预设人数，不改变三原则或成本约束，也不要求占满槽位。
- “多开、继续加开”：立即落实新增并行工作及后续就绪切片的补派，不自动放宽模型、思考程度或成本。
- “不计成本”：在当前范围跳过成本比较和成本否决，仍按必要质量与整项完成时间选路；不自动要求满载。
- “高负载时持续顶满”：就绪独立切片充足时持续填满实际可用容量，槽位释放后继续补派；
  这是明确并行安排，未同时放宽的模型、思考程度和其他成本约束继续有效。

明确人数、上限与协作方式按[用户明确指令优先](#用户明确指令优先)落实；未指定的部分沿用
上节默认增派快判。父代理同时推进适合自己的实质主线，不另等全面比较或统一批准，
“所有”只指可委派的就绪独立工作，不把父主线全部转出。实际容量以工具能力和真实运行状态确认，
不得用固定人数或配置数字代替；同一保留 `agent_type` 可启动多个独立线程。

安全、权限、实际工具容量、依赖、写入冲突和必要质量继续约束派发；不为空转或填满槽位制造工作，
不因成本放宽自动全部采用 Astra 或 `xhigh`。模型与思考程度仍按当前切片的必要质量选择。
各项安排持续到用户限定范围结束、撤回或用新要求覆盖该项，或当前主任务交付完毕或被替换；
恢复成本约束不自动增加人数上限，取消顶满也不禁止三原则下有收益的增派。普通顺序调整和局部
要求变化不自动终止其他仍有效项，不扩展到无关未来任务；
不自行增加固定人数、时限、脚本调度器、后台状态机或全局持久模式；用户明确指定人数按优先节执行。各分支中的默认成本与线程复用
条款只在用户实际改变的范围服从本节，未指定部分仍按原三项原则执行。

## 模型与思考程度

用户已明确指定且当前宿主真实支持的配置，先按[用户明确指令优先](#用户明确指令优先)执行；
以下任务分档、思考程度和默认上限仅补足未指定部分。指定配置不可用时说明具体能力缺口，
不擅自替换型号，也不修改固定保留角色的已加载配置冒充生效；权限与必要保护继续保留。

| 模型 | 适用任务 |
| --- | --- |
| `gpt-6.1-terra` | 速度优先、范围明确且验收直接的简单工作：有界读取、结构化提取、事实总结、文字整理和局部小修改；以及父代理指导的常规、低风险 Computer Use |
| `gpt-6.2-sol` | 有限歧义、跨来源或模块因果，常规复杂实现、审查与验证；以及复杂或高风险的 Computer Use |
| `gpt-6.2-astra` | 相对最强可行 `gpt-6.2-sol` 仍有决定性质量收益的专家问题 |

前两档都是常规子代理路线；只有 `gpt-6.2-astra` 是专家路线。三项原则中的“派遣专家”只指
这条 Astra 路线。未指定由专家执行的切片按上述决定性质量差距判断。

上表是本插件按任务分工的路线，不是所有任务的通用能力排名，也不保证各型号都能作为当前宿主的运行时覆盖值。运行时 `model` 必须存在于当前
公开覆盖目录；所需 Terra 不在该目录时，普通任务选择当前可用且质量足够的 Sol，不猜别名、不发错误调用试探。
Computer Use 的执行者按下节核对，不能以工具优先绕过操作者选配；用户明确指定仍优先。
固定保留角色仅按其已加载固定配置调用；某角色的型号可用，不证明通用运行时角色也能覆盖为该型号，
不得为此擅自修改角色 TOML。

思考程度从 `medium` 起，按任务选 `high` 或 `xhigh`；Astra 的 `xhigh` 是上限，不是默认值，
同时适用于历史 `gpt-6-astra` 和当前 `gpt-6.2-astra`。
Sol 的 `max`、`ultra` 仅按[首次派发](references/dispatch-start.md#模型与思考程度)
中的质量条件选用；普通任务不因模型名称或任务标签升级。
Terra 通常使用 `medium`，仅有少量局部歧义时可用 `high`；以输入清楚、风险低、有直接验收点为前提，
不为简单工作追求最高质量而增加推理。复杂取舍、跨模块因果、合规或安全判断、高风险修改及最终审查结论
至少使用合适的 Sol；出现这些条件时重新选路，不仅提高 Terra 的思考程度。已保留身份也不能绕过这条质量下限。
旧 Luna、`gpt-6.1-sol` 和 `gpt-6-astra` 保留资料可读取；新建或显式重配使用本表型号。
`ensure` 接受旧 `gpt-6.1-sol`、`gpt-6-astra` 输入，分别规范化为 `gpt-6.2-sol`、
`gpt-6.2-astra` 后继续处理，思考程度及质量约束保留；历史读取不改写型号。
已有身份升级仍按 CAS 重配同一身份，保留权限与经验，并在新任务核对宿主加载；
已加载的旧配置不能冒充新型号，本机模型缓存也不能代替当前会话公开覆盖目录或固定角色配置。

选择 6.2 Sol/Astra 的任务卡须消费[6.2 调用防错](references/dispatch-start.md#62-调用防错)：
核对决定性未知，保持关键要求完整，如实报告阻断，用新证据推进并交付可核验结果；结果采用时
核对相应证据。仅按实际执行型号触发，旧别名先规范化；详细条件与随型号退出清单在该节维护，
完整随卡执行句见本入口“原生调用与任务卡”；不能保证模型零错误，不自动套到后继型号。

## Computer Use：父代理指导，按任务选配

按[用户明确指令优先](#用户明确指令优先)分别落实操作者和工具。用户只指定工具时，仍按本节选择
能够使用该工具的操作者；用户只指定操作者时，仍按当前任务和权限选择工具。

已经确定需要通过桌面或浏览器界面操作的 Computer Use 任务，由父代理指导子代理实际执行：
目标和输入清楚、风险低、验收直接的常规操作默认 `gpt-6.1-terra`；界面状态复杂、存在难判断的
多步依赖或高风险变更时至少使用 `gpt-6.2-sol`。整体业务复杂不自动升级简单界面步骤，复杂业务
分析、取舍和最终审查仍留给父代理或合适的 Sol/Astra。此分工同样覆盖只读界面观察，
不因操作很短就由父代理自行代操。
当前默认依据 2026-11-19 同工具、同任务的 Edge 快速对照；每模型一轮，仅支持这类明确界面操作的
速度选配，不作为全部 Windows 应用的通用性能排名，复杂或高风险操作保持 Sol 质量下限。
已有适用连接器、API 或 CLI 的任务继续按对应工具规则处理，不为套用此分工改成界面操作。
Computer Use 工具自身的应用/窗口清单、UI 树和截图等只读观察也属于本节；不能因接口名是 API、
操作确定或只有一次调用，就由父代理直接执行或绕过本入口。普通业务连接器、API 和 CLI 的原分工保持。

- **父代理指导与验收：**任务卡给出目标应用或页面、已知当前状态、已授权操作范围、当前阶段
  的目标、可观察完成条件及必要的停止或恢复要求；父代理负责整体判断、具名纠偏与最终验收。
- **执行者操作与反馈：**先核对自己的工具可用性；有对应且适用的 Computer Use 技能时读取或复用，
  并遵守实际工具说明，以当前返回的界面对象和观察为依据执行。按可验证阶段反馈实际操作、结果和剩余状态；出现范围外决定、
  权限缺口或界面偏离时返回父代理，不自行扩大目标。父代理用 `followup_task` 发送增量指导，
  不要求每次点击往返，也不把发出点击命令当作已保存或已完成。
- **操作所有权：**同一桌面、窗口或标签页保持一个操作者；父代理不与执行者交错输入。
  只有界面和会话状态确实隔离、工具支持且互不冲突时，才并行其他界面操作。
- **能力与权限：**模型和工具须在执行子代理中真实可用，父会话的工具句柄不等于子会话可用对象。
  委派不扩大现有授权，确认要求仍按当前用户授权和工具技能执行。默认 Terra 的固定角色和运行时
  路线均无法使用所需工具时，可选用实际可用且质量足够的 Sol 并明示回退；用户明确指定的操作者、型号或所需工具不可用时，报告具体缺口，
  不擅改明确指定。继续不依赖界面的工作，不得把父代理代操、其他模型操作或文字方案说成指定执行者已操作。

## 同一能力族优先复用

用户明确要求新建、指定可用执行者或不复用时，先按[用户明确指令优先](#用户明确指令优先)落实，
下述默认复用顺序不构成二次否决；所有权、固定角色真实配置和工具可用性仍须核对。

决定委派后，同一任务的小补充直接继续使用兼容的当前子代理，只发送新增目标、证据或纠偏；完成
状态本身不妨碍续用。这指仍需模型判断的增量，沿用已有分工，不重复论证必要性；新增确定性
计算直接由父工具处理。决定为一个新的能力类型调用子代理且没有适合继续使用的当前子代理时，只做
一次快速、有界台账查询。满足以下条件的保留子代理会被复用：

- 当前会话已经加载；
- 属于同一能力族；
- 质量兼容。

符合条件的保留子代理优先于通用角色或最小运行时角色。目录查询失败但当前会话已加载类型中已有
符合三项条件的明确候选时，仍只读取该候选一次；读取成功就复用，不要求所有无关保留身份都健康。
只有没有可核对候选或读取保留子代理失败时，本次才改用最小运行时角色继续。不得把查询失败当成
空台账用于新建保留身份。查询结果和候选条件未变化时复用本轮结果，不重复查。能力族按职责和预期交付判断；输入形式与证据使用规则
写进任务卡，模型档位按本次任务的质量和当前用户优先级选择，不另设复用条件。当前子代理与台账保留
子代理都可用时，按[当前用户优先级](#用户明确指令优先)和[持续并行提速](#用户要求持续并行提速)选择线程；
默认在质量达到要求后比较父子合计总成本，选择更低成本的一条，不为统计台账复用强制换线程。模型与思考程度由本次任务的质量条件
统一决定，不另设为复用门槛。同身份配置可经核验用 CAS 安全
重配，当前宿主已加载的旧配置须由新任务验证。执行者选择、一次有界
读取保留子代理、失败改派与任务卡细节见[首次派发](references/dispatch-start.md#选择同一能力族的执行者)。
台账复用只指调用现有 `lean_*` 保留 `agent_type`；当前子代理的 `followup_task` 是当前会话上下文
复用，不得计入台账复用。

只有用户优先级、并行需求、任务类型、质量门槛、权限或证据边界、专家必要性、预计成本发生实质变化时才重新选路；同一
任务的小补充直接继续，不重复评估。历史使用的模型不锁定未来模型。需要重新选路时，先判断当前
切片是否仍由用户指定专家或质量仍需 Astra；仍需时再独立选择旧线程或另一条兼容
Astra 路线，旧线程上下文无边际价值不能触发降级。已完成且采用、验收满足的 Astra 在没有新要求、新证据、未满足验收或明确
纠错时停止，详细停止与续用条件见[首次派发](references/dispatch-start.md#增量切片与-astra-停止条件)。

## 原生调用与任务卡

选择 `gpt-6.2-sol` 或 `gpt-6.2-astra` 时，必须把以下完整执行句原样随任务卡交给执行者，
不能只给未读取的链接或关键词命中行；这是随最后一款 6.2 退出而移除的专属附加指令，详细触发与退出条件由
[6.2 调用防错](references/dispatch-start.md#62-调用防错)承载：

```text
按关键要求给出结果与对应证据，保留数量、边界和例外；未知事实先核对。工具失败或阻断如实报告失败动作、实际错误及影响，不伪报测试或完成。以用户可观察的完成条件收尾；常规实现选择自行推进，缺决定性事实或权限时报告局部缺口并继续独立部分。审查发现附触发条件并核对严重性；视觉结果逐项检查关键细节与真实交互。无新增证据时停止原样循环，改做决定性检查或返回具名缺口。最终说明面向用户重写，先用清楚语言说明实际结果、原因、证据与未覆盖项。
```

当前宿主所有 `spawn_agent` 调用显式传 `fork_turns="none"`，不得省略历史参数而采用默认全量继承；禁止 `fork_turns="all"`。
通用运行时角色显式传实际 `model`、`reasoning_effort`，型号取当前公开覆盖目录；固定保留角色沿用工具
已加载固定配置，不传模型或思考程度覆盖参数，任务卡核对实际配置。TOML 和任务卡不能代替原生参数，
不得通过错误调用试探或擅改 TOML 绕过工具合同。五行真实开场与最终回复三行的唯一详细规则见
[首次派发](references/dispatch-start.md#任务卡上下文与所有权)；缺少实际状态先内部补齐，
不向用户显示占位语。复用当前子代理但没有已核验的保留子代理读取状态时，经验行只写
“经验：复用当前线程上下文”；不得显示“未核验持久化经验”。保留 TOML 的经验已在
`developer_instructions` 原生注入，读取保留子代理成功后
任务卡只传五行状态，不复制经验正文；子代理读已注入经验一次即开始任务。
任务卡须直接传递[条件性经验候选合同](references/agent-results.md#最终结果)：将本次已验证、可跨任务复用且
当前身份尚未承载的具体做法、反例或证据边界随最终结果返回；无价值或已承载则省略。

## 执行、结果和保留

派发后父代理继续未分配主线，以最终回复或等价结果收据采用结果；进展说明不构成交付。
子代理执行期间正常提供用户可见进展说明，任务卡不得要求默认静默；减少重复的父子内部消息不限制途中说明。进展、内部消息和父代理汇合的具体边界见[子代理结果与汇合](references/agent-results.md)。
核验采用结果时，按[父代理采用](references/agent-results.md#父代理采用)自动完成能力族与新增经验的两项判断，
符合条件即执行现有命令并回读，再继续主任务；采用触发与失败处理以该节为唯一说明。
身份保留无新增经验也无需 `run_id`；成功结果只有新增可复用经验才 `complete-run`，已核验保留身份的明确
失败可不带 `--lesson` 记录。普通派发不进行成本、迁移或摘要巡检。身份、CAS、经验与
第二次明确失败的写入边界见[保留子代理经验](references/specialist-memory.md)。

## 正式宿主证据边界

静态文案、模板测试、源码读取、安装成功或缓存相等不能证明真实宿主采用了本路线。正式验收需要
在安装后的新任务中观察原生调用参数、子线程开场和最终结果；子代理进展说明是否显示还需单独用
用户实际界面确认。辅助脚本维护身份和经验，不启动子代理，也不证明宿主加载了经验。
