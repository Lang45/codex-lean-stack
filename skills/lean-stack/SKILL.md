# Codex 子代理调用

## 职责与触发

本入口负责工具/子代理调用判断、模型与思考程度选配、最小上下文、结果采用及必要收口。安装本
插件的项目和新会话保持主动委派：出现符合质量、成本、时间三项原则且能独立推进的切片时立即
调用，不等待用户逐次重申，也不设机械调用配额。代理管理和经验只能服务主任务，不能拖延交付。

新项目或新会话不因进入会话而预读本入口。首次准备调用 `collaboration.spawn_agent`，或用
`followup_task` 启动新当前子任务时，才实际读取已加载目录中的本 `SKILL.md`；已读且入口未变化
时直接复用。只读取并应用当前实际动作命中的入口，不预读 `$lean-simplify` 或完整 `references`。本入口与
其他适用技能的用途说明合并到唯一启动说明；读取后的下一次工具调用立即开始实际任务。

普通子代理从任务卡和指定证据开始，不自行扩读未分配的项目资料、整套技能或插件缓存。首次派发
只识别技能名称、口头声明、项目交接或猜测路径都不算已读；工具明确截断时只补缺失段。

## 每次原生调用的派发硬门

每次 `collaboration.spawn_agent` 调用前都重新检查，且原生参数必须同时包含：

- 当前切片实际选择的 `model`；
- 当前切片实际选择的 `reasoning_effort`；
- `fork_turns="none"` 或有限正整数，禁止 `fork_turns="all"`。

任何层级和任何 `agent_type` 都不得用任务卡文字、TOML 或“继承”占位替代原生参数。具名保留
子代理的模型与思考程度必须与已加载 TOML 完全一致；不合规时换用合规子代理，不覆盖 TOML。
`followup_task` 没有选模参数，但任务卡仍写现有子代理的真实模型、思考程度和 `MODEL_ROUTE`。

每个 `spawn_agent` 或新当前子任务的 `followup_task` 内部任务卡必须以下列五行实际值开头：

1. 子代理名称；
2. 模型；
3. 思考程度；
4. 存活轮次；
5. 经验。

五行之后必须写当前切片的 `MODEL_ROUTE`，说明实际选择、必要质量、相称成本和对父任务完成速度
的正贡献；缺失时不得调用。

名称使用用户语言；中文会话不能用技术 `task_name` 代替中文名称。五行只由子代理本人在自己的
第一条可见 commentary 原样宣读，五行前不写计划、运行 ID 或其他说明；父代理仅写内部任务卡，
不得在父代理自己的用户可见 commentary 或最终回复中代为展示或重复。该硬门沿 parent → child → grandchild
递归；缺字段、占位值或错误可见所有权时不得调用。

普通 UI、视觉和简单审计不得使用 Sol `ultra`。Sol `ultra` 只用于高价值复杂边界，且须说明
`xhigh` 与 `max` 为何都不足；Astra 仅在最强可行 GPT-5.6 仍有决定性质量差距时使用，最高 `xhigh`。
完整选配规则按需读取
[一次确定模型与思考程度](references/dispatch-start.md#一一次确定模型与思考程度)。

## 两个独立入口

插件只提供 `$lean-stack` 与 `$lean-simplify` 两个并行技能入口，二者平行、独立且互不前置：本入口命中时直接完成调用判断与派发，
不等待主任务精简；主任务精简也不得阻断、延后或减少符合三项原则的委派。两边共同保留用户
要求、当前授权、安全、权限、数据完整性和匹配结论的证据，并共同遵守工具与 PowerShell 路径精简及
[Windows exec 稳健性契约](references/windows-exec.md#windows-exec-与-powershell)。

调用子代理不能证明主任务已经精简，静态精简规则也不能证明子代理实际运行。`scripts/agents.py`
只维护子代理、运行和经验，不启动子代理，也不是主任务精简执行器；两项功能分别验收。

## 三项原则与一次判断

选路固定按 **质量 → 成本 → 时间** 执行：

1. **质量。** 模型与思考程度联合达到必要质量并能给出决定性证据；质量不足的组合不合格。
2. **成本。** 在质量充分的模型与思考程度组合中选择与任务相称的成本，不只计算子代理启动成本。
3. **时间。** 委派必须并行推进或替代父代理尚未完成的模型工作，实际加快父任务完成。

调用数量本身不是成本结论；多个调用只要分别通过三项原则就可同时成立，不能按调用总数倒推
成本错误。

确定性短工作直接用工具；独立短命令做工具级并发。需要持续模型判断时，只问是否已有就绪、范围
明确、可安全独立推进且通过三项原则的切片；有则立即调用，多个互不冲突的合格切片可并发。
未通过三项原则时继续主任务；不读取分支、不创建任务，也不查询 `status --for-routing` 或
`recall` 来证明能够委派。

### 持续多工作流任务的早期派发

持续任务中出现多个互不依赖、能推进实际研究、调查、实现或验收的已就绪独立切片时，在父代理继续大块来源读取、
实现或长链诊断前，为每个切片写任务卡并尽早派发全部分别通过三项原则且互不冲突的 GPT-5.6
切片：模型与思考程度联合达到该切片的必要质量，在质量充分的组合中选择与任务相称的成本，且
该委派对父任务实际完成速度有正贡献。调用数量随真实工作流和容量变化；为提高父任务完成速度，
可以同时派发多个子代理。不设置同时调用数字，
也不设置主任务累计调用数字。只在后期增加一次复核不能替代前面的实际工作。

新要求、来源范围、具体困难或上下文切换使任务形状改变并出现新的已就绪切片时，在继续大规模
读取、实现或长链诊断前立即重新判断受影响的任务形状；没有变化则复用原决定，不按固定时间、
文件数量或轮次机械重判；没有这些变化时复用原决定。并发只使用运行环境实际可用的并发槽位。

只有具体阻断才直接处理或停止相应派发：属于确定性短工具工作、真实前置未就绪或严格依赖、
重复工作、写入冲突无法隔离、能力或权限缺失、运行环境容量不足、没有质量充分且成本相称的
模型与思考程度组合，或委派对父任务完成速度没有正贡献。
不使用评分表、固定百分比或机械配额，也不为证明插件能委派而制造任务。

安全、权限、数据完整性、明确验收与诚实证据始终是底线，委派不扩大权限。

入口内的四模型快判保留普通派发所需判断，不要求先读详细 reference：

| 模型 | 快速判断 |
| --- | --- |
| `gpt-5.6-luna` | 规格清楚、证据已定位、推理直接、输出短且容易核验的普通切片 |
| `gpt-5.6-terra` | 有限语义歧义、少量关联来源或局部实现风险，Luna 难以守住必要质量 |
| `gpt-5.6-sol` | 跨来源或跨模块因果、竞争假设、隐藏不变量，或复杂实现、测试与自检 |
| `gpt-6-astra` | 有实际输入和验收点，且相对最强可行 GPT-5.6 存在会改变决定的质量差距 |

思考程度同样按当前切片的推理深度选择：直接事实可用 `low`，少量依赖或局部歧义用 `medium`，
多层因果、竞争假设、接口或安全边界用 `high`，密集冲突且高价值的未决关系用 `xhigh`；Sol
`max` 可按复杂度正常选择。只有边界仍不清楚、考虑 Astra 或 Sol `ultra` 时，才读取上面的完整
选配段落。

## 选配与上下文底线

正向委派决定完成后，先确定具体任务类型和兼容任务类型组，再匹配已经加载的轻量路由目录；目录
尚未加载时最多执行一次有界 `status --for-routing`，命中候选后才 `recall`。目录、SQLite、候选或
配置不可用时立即改用合规运行时子代理，不重试。任务类型组、查询、保留和经验写入都不能反向
成为“是否调用”的前置条件。

独立窄任务优先 `fork_turns="none"` 和自包含任务卡；确需先前决策时才给有限历史。
`followup_task` 不以旧上下文不可替代为前提；持续对话、澄清、纠偏、迭代验证或父代理遥控
能具体改善质量、速度或总成本时，可以继续使用 `followup_task`。无关、已经结束或能自包含的新切片
则新建 `spawn_agent(fork_turns="none")`。任务卡明确职责、来源、写入所有权或只读限制、外部影响、
成功/停止条件和必要关键步骤。父代理同步推进不重叠主线，只在真实依赖点汇合，不完整重做已核验证据。

每次派发前指定唯一来源所有者或不重叠责任范围；子代理负责的来源发现、完整读取、实现或验收
范围内，父代理不得并行重做该范围。父代理的下一动作必须属于未分配主线、整合或真实依赖；只有
来源快照变化、覆盖不完整、结果冲突或必要高风险事实复核时，才定向重开具名缺口。

子代理 commentary 只是进展，不是可采用交付；必须取得其明确最终回复或等价结果收据。只在来源
变化、冲突或具名缺口时定向补读或补问一次，不循环索取全文。每个结果经必要核验并被父代理采用后，
都进入一次非阻塞保留收口判断：已有保留子代理记录本次完成；临时子代理能形成全局领域规则时，
先保存为保留子代理再记录完成；只有明确排除项才跳过并留下保存回执。具体命令只在保留分支中读取，该侧支
不能阻塞已经就绪的主任务动作或交付。

## 条件路由

按当前状态和下一项实际动作判断，不按用户是否写出条件名称判断。入口先完成快速判断，只保留会
改变是否调用、调用谁和如何交付的规则；确认命中具体功能分支后，才读取其最小权威段落。未命中
分支不读取，也不批量预读可能稍后使用的分支。分支读取不再产生第二段技能用途说明；读取后下一次
工具调用执行该分支的实际操作。普通首次派发先读首次派发分支；同一任务可以随实际动作依次命中
多个分支；每个分支在真正开始对应动作时读取，不能预先成批加载，也不能因拆分而跳过后继触发。

| 条件 | 权威入口 |

| 入口快判仍不能确定模型与思考程度，或正在考虑 Astra / Sol `ultra` | [一次确定模型与思考程度](references/dispatch-start.md#一一次确定模型与思考程度) |

## 正式宿主证据边界

静态合同、当前源码读取、手工加载候选、安装成功或缓存相等都不能证明新会话真实采用本路线。
若要证明，必须在获授权正式安装后，用全新项目目录创建独立父代理任务，只依赖自动加载的全局
入口和正式缓存；观察真实 `subAgentActivity` 或等价事件，并从原生调用记录核对实际 `model`、
`reasoning_effort`、非全量 `fork_turns` 及子线程首条五行后立即停止探针。内部阻断只能说明验收
未完成，不能替代真实派发；该探针也不证明业务质量或插件其他功能。
