# Codex 子代理调用

让主任务按质量、成本、时间三项原则决定委派：模型与思考程度联合达到必要质量，在质量充分的
组合中选择成本相称的配置，并确认该委派对父任务实际完成速度有正贡献。代理管理、经验和调用
验证只能服务主任务，不能拖延交付。
用户已明确要求安装本插件的项目和新会话不得临时关闭主动委派；本入口是持续有效的明确委派请求。
父代理识别出符合三项原则、可独立推进的切片时主动调用子代理，不等待用户逐次重申，也不以调用
数量限制派发；为提高父任务完成速度，可以在实际并发容量内同时派发多个子代理。
所有模型与思考程度的父代理均须使用本插件规则；已加载且未变化的规则直接复用。
本入口只保留子代理调用决策与必要限制；进入相应操作时才读取所链接的细则，不预读全部参考文档。
普通子代理从任务说明、已加载子代理和指定证据直接开始；本入口的选配与经验管理由父代理
负责。子代理不因新线程或上下文重置自行扩读未分配的项目资料、整套技能或插件缓存；仅在分配
的职责需要或用户明确要求时读取相关部分，更高层明确读取要求仍须遵守。

新项目或新会话在同一次启动热路径中，快速实际读取已加载技能目录里的 `$lean-simplify` 与
`$lean-stack` 两个按需入口，并立即开始当前实际动作；只读两份 `SKILL.md`，不预读它们链接的
完整参考细则，也不为插件再增加第二段初始化前言。无关记忆扫描、保留子代理目录、委派或不委派
解释、版本解释不能阻塞主任务。两个入口不互相要求先完成或取得对方结果；读取完成后各自按实际
情形独立触发，也可并行触发，同一会话入口未变化时后续轮次直接复用。
入口存在、交接存在与否、直接工具路线、不委派和不升版都不是需要单独报告的进展；首条说明后
不能在第一个实际任务操作前再发第二段启动说明。互不依赖的必要读取与第一个确定性命令放进同一
次工具调用。

首次准备调用 `collaboration.spawn_agent` 或用 `followup_task` 启动新当前子任务时，父代理必须先
实际读取已加载技能目录中的本入口；只识别技能名称、口头声明已经采用、读取项目交接或猜测技能
路径都不算调用。读取路径以当前技能目录提供的位置为准，不从其他项目或用户目录猜路径。
普通派发只完整读取本入口一次；若已在当前会话启动热路径读过且版本未变化则直接复用，并立即进入调用判断，不统计行数、分段重读
本入口，也不在派发前通读 `references/delegation.md`、`references/execution-routing.md` 或
`references/specialist-memory.md`。只有本入口无法解决的具名配置、并行写入、复制/变体、生命周期
或阻断问题，才读取对应参考文档的最小相关段落；参考资料读取不得代替或延后已经就绪的派发。

派发硬门在每次原生调用前重新生效：`collaboration.spawn_agent` 的参数必须同时包含 `model`、
`reasoning_effort` 和合法的 `fork_turns`，任务卡必须以子代理名称、模型、思考程度、存活轮次、
经验五行实际值开头，并明确要求子代理在第一条可见 commentary 原样先输出这五行。可见的
子代理名称必须使用用户语言；中文会话使用中文名称，不能照抄只供工具调用的技术 `task_name`。
缺少任一字段、使用任何“继承”占位，或给普通 UI、视觉、简单审计选择
Sol `ultra`，都属于无效调用；父代理必须先补正，不能发出工具调用。此前读取过入口不能替代这个
调用时检查。

新项目和新会话首次派发也必须直接执行以下热路径合同：任何层级、任何 `agent_type`，包括通用
`default`、`explorer`、`worker` 与具名保留子代理，每次原生 `collaboration.spawn_agent` 都显式传入
`model` 和 `reasoning_effort`。具名保留子代理传入的两个值必须与已加载 TOML 完全一致；不能省略为
继承，也不能临时覆盖。新派发只用 `fork_turns="none"` 或有限正整数历史；`fork_turns="all"`
因不能同时显式覆盖模型和思考程度而禁止使用。保留子代理 TOML 的其他宿主预配置只在进入配置
或生命周期操作时，按[保留子代理经验](references/specialist-memory.md#保留子代理-toml-的宿主预配置)
处理；不进入本次模型与思考程度选配、任务卡、`MODEL_ROUTE` 或可见声明。
普通 UI、视觉和简单审计不得使用 Sol `ultra`。Sol `max` 可按任务复杂度、必要质量和相称思考深度正常
联合选择；只有 Sol `ultra` 需要高价值复杂边界，且 `MODEL_ROUTE` 必须具体解释 `xhigh` 与 `max`
为何都不足。Astra 仍最高 `xhigh`，且只有 Astra 称为高成本专家路线。已加载保留子代理的固定组合若违反当前任务的
模型或思考程度边界，不复用也不覆盖该 TOML；改选合规保留子代理，或显式配置运行时子代理。
`followup_task` 没有选模参数，其任务卡仍必须携带现有子代理的真实模型、思考程度、五行开场和
`MODEL_ROUTE`；不能使用“任务卡未提供”、“未揭露”或“继承父级”等占位。上述派发硬门沿
parent → child → grandchild 逐层递归；每个新当前子任务的第一条可见 commentary 严格复现任务卡
开头五行。面向用户主任务的交接启动句只由直接处理用户主任务的父代理使用；
子代理接到新子任务后不输出该启动句，直接以五行声明开场。

## 两个并行功能的边界

`codex-lean-stack` 在一个插件内提供两个并行技能入口，并共享一项执行底座：

- 两个入口都遵守工具与 PowerShell 路径精简：确定性短工作优先直接工具，多个独立短命令用一次
  工具调用并发，复杂 PowerShell 转义及时改用任务专属脚本，不制造多余包装、重试器或执行层。
- `$lean-stack` 负责调用判断与模型、成本、时间选配，上下文、来源和结果复用，内部交流与子代理
  结果收口，子代理、经验和生命周期表面精简，以及迭代测试链。
- `$lean-simplify` 是“主任务精简”：负责最小完整任务方法，主任务状态与沟通收窄，调查、实现
  和任务手册精简，测试、复核和重验范围，反过度工程与维护面，显式消融，发布、安装和文档
  维护，以及条件性语义复核与最终验证链、失败后的最窄重验链。

两个入口按各自职责独立触发和执行，不互相要求先加载、先完成或取得对方结果。命中本入口时
直接完成调用判断与派发，不等待 `$lean-simplify`；命中 `$lean-simplify` 时也不能阻断、延后或
减少符合三项原则的子代理调用。两个入口都采用共享的最窄工具与 PowerShell 路径，并可在同一
任务中并行工作。两个功能各自验收，不能用“调用了子代理”证明步骤已经精简或消融完成，也不能
用静态精简规则证明子代理实际运行。精简任务若确有质量、成本或时间收益，可以由 `$lean-stack`
委派独立实验，但委派只是一种执行路线。
`scripts/agents.py` 的子代理、运行、经验和摘要维护属于子代理生命周期，不是主任务精简执行器。
“精确删除与否定重做”完整属于子代理任务类型组与保留子代理清理，不归主任务精简功能。
两个入口都必须保留用户要求的结果、当前授权、安全、权限、数据完整性和与结论匹配的证据；
也不得因本次拆分恢复历史上已经删除的大规模中间机制。详细判断只由
[反 AI 过度工程](references/anti-overengineering.md)承载。

## 三项原则

本节只决定工具、模型和子代理路线；精简候选是否采用，由真实消费者、受保护核心、维护面变化
以及同一组前后验收决定。

1. **质量。** 模型与思考程度联合达到该切片的必要质量，并能给出所需决定性证据；质量不足的
   便宜或快速组合不合格。
2. **成本。** 在质量充分的模型与思考程度组合中，选择与任务相称的成本，不因父代理档位更高、
   希望少调用或追求更强配置而无依据增费。
3. **时间。** 该委派必须与父代理并行推进或替代父代理尚未完成的模型工作，对父任务实际完成
   速度有正贡献。

调用数量只描述委派拓扑和并发形状，本身不构成成本错误；
每个新增调用只按这三项直接判断，多个分别通过三项原则的调用可以同时成立。其他执行规则不组成
新增调用的第二套成本清单或否决轴。

安全、权限、数据完整性、明确验收条件和诚实证据始终是底线；委派不增加权限。以下选路固定按
**质量 → 成本 → 时间** 执行；期限不省略质量或必要核验。
用户最新明确要求优先于技能建议与历史交接，更高层指令及实际工具约定仍须遵守。

## 一次调用判断

父代理先判定具体任务类型。确定性短工作直接用工具；独立短命令工具级并发，长而确定的命令
使用持续终端或后台。三项原则成立且有多个独立切片时可为父任务速度多派子代理；子代理不能
只运行命令回报退出码。

需要持续模型判断时，只做一次正向判断：是否已有就绪、范围明确、可安全独立推进的切片，能为它
选择达到必要质量且成本相称的模型与思考程度组合，并对父任务实际完成速度有正贡献？符合这三项就默认立即调用，
不等待用户重复要求。能独立端到端完成并自检的任务同样是候选，不把子代理局限在边角工作、
只读审查或最终复核。

只有命中具体阻断才由父代理直接处理：确定性短工具；真实前置尚未就绪或存在严格依赖；重复已有
工作；写入冲突无法隔离；缺少所需能力、工具或权限；运行容量不足；没有达到必要质量且成本相称
的模型与思考程度组合；或委派对父任务完成速度没有正贡献。这些是内部选路硬条件，不产生向用户说明阻断
的义务，也不能作为新会话行为验收的替代通过结果。不做评分表或固定百分比阈值。

这里的“一次”只约束当前任务形状，不能把直接处理决定固化到整个长任务。新要求引入不同系统或
证据范围、具体困难或失败暴露可独立诊断的切片，或者上下文重置后剩余工作出现多个独立就绪
工作流时，原判断失效；父代理在继续大段阅读、实现或诊断前，立即按变化后的形状重新做一次
正向判断并派发新出现的有收益切片。没有新切片、只有确定性工具或严格依赖时继续当前路线，
不为重新判断制造调用。

持续的多工作流任务一旦出现多个互不依赖、已就绪且能替代父代理实际研究、实现或验收的切片，
默认在父代理深入读取额外来源族或开始实现前，尽早派发全部当前取得正向收益判定且互不冲突的
GPT-5.6 切片。
这些切片必须已经由用户当前要求或实现中的真实依赖产生；不得为了证明插件能委派而预造任务、
规范文件、汇总文件、固定数量的分支或额外验收工作。
调用数量随真实工作流和容量变化，并由三项原则决定；三项原则成立时，为提高父任务完成速度，
可以同时派发多个子代理。输入未就绪、严格依赖、权限不足、
写入冲突、重复已有工作、容量不足、没有质量充分且成本相称的组合，或对父任务完成速度没有正贡献等明确阻断
才停止相应派发。只在后期增加一次复核不能替代
前面的实际工作。父代理保留关键约束、共享热点、用户互动、整合与必要验收；新要求改变工作流
时立即按新任务形状重新判断。
在适用指令允许的范围内使用本插件判断，不额外套用官方默认调用触发规则；任务类型组、已有
保留子代理、持久创建和经验写入都不是当前调用前置条件。父代理同步推进不重叠的主任务，
只在真实依赖点汇合，不为收齐非必要结果而等待全部。
按主任务剩余时间选择切片：短小确定性核对直接批量工具处理；必要复核保留独立性，非必要
调查不能成为交付门槛。父代理发现预读偏离、重复证据或成功条件已达到时及时收窄并收口，
不靠增加并发补救无收益拆分，见[委派替代工作](references/execution-routing.md#让委派替代工作)。

确定调用后，先按可复用能力族及兼容的工具、权限、风险和证据形状确定任务类型组，再匹配
可见保留子代理；有则复用，没有则定制本次运行时子代理。同一能力族内的调查、诊断、实现、
修复、测试或验收，只要没有跨越子代理的写入权限、专用工具、安全限制和决定性证据范围，就按
同一种活匹配；具体项目、框架、动作动词、交付名称、成功条件或需要不同档位本身不构成新
领域。只读子代理仍不能借“范围放宽”获得写权限，工具、权限、风险或证据形状不兼容时才拆分。
运行时定制不等于持久创建，不等待热加载。
描述不足、可能遗漏复用，或准备因无匹配而新建子代理且尚未查目录时，按[保留子代理经验](references/specialist-memory.md)从已加载技能的
绝对目录执行一次 `scripts/agents.py status --for-routing`，复用当前结果，不例行遍历台账。
子代理未加载或配置需适配时，用 `recall --name` 有限读取同子代理职责、经验、经验版本摘要与客观
开场状态后适配本次调用；
职责部分匹配就只分配合适切片，不因名称或档位不同放弃已有专长，也不为复用率强行委派。

并发以运行环境当前可用槽位与计数口径为准；`agents.max_concurrent_threads_per_session`
的名字不证明是否计入协调者。插件不另外设置调用次数限制，合格切片可使用当前可用容量并行派发。
单会话累计调用次数不设插件上限；每次调用仍按三原则判断，运行环境的并发容量与累计次数分开。

有收益的委派尽量发生在父代理，尤其是昂贵父代理，大量预读或生成之前；工具先定位，子代理完成
可替代的阅读、生成或独立判断。父代理保持用户选定的配置，负责约束、冲突、必要核验与整合，
不完整重做子代理已经完成且证据充分的工作。三项直接判断的详细执行规则见
[让委派替代工作](references/execution-routing.md#让委派替代工作)。

## 选配与上下文

保持用户选定的父代理配置。父代理按当前任务证据一次联合选择 `模型 + 思考程度`，不能
机械继承昂贵配置、按模型固定思考档或为分布均衡混配。Luna 用于清楚易验切片，Terra 用于有限
语义歧义，Sol 可端到端承担复杂实现与自检；Astra 只处理相对最强可行 GPT-5.6 仍有决定性质量
差距的当前专家问题，普通视觉任务不触发。派出的 Astra 子代理最高 `xhigh`；更强充分组合可直接选择，
不制造低价模型失败。四模型、思考程度和 `MODEL_ROUTE` 收据的唯一详细规则见
[四模型一次联合选配](references/execution-routing.md#四模型一次联合选配)。

独立、范围窄的任务优先 `fork_turns="none"` 和自包含任务说明；依赖前面决策时才给有限正整数
历史。新派发不得使用 `fork_turns="all"`，因为它不能同时显式覆盖模型和思考程度。任务专属工具限制、安全限制、写入范围与停止条件
必须显式放进新上下文任务说明；继承历史也不能代替当前范围。历史里的父级编排指令不授权
普通子代理另开主线或下游。读证据、普通执行与复杂推理可分别考虑 low、medium、high 等档位，
这只是起点，仍按任务风险、歧义、模型能力及实际支持的组合判断。

能用来源定位、当前约束和未决问题自包含说明的研究、实现或验收切片，不因父代理已经拥有长
历史、使用 Astra、发生过上下文压缩或读过大工具输出而使用 `"all"`；这一最小上下文原则沿
协作父代理、复制与下游逐层适用。需要先前输入时，把决定性内容收窄为有限正整数历史或自包含
来源快照，并在任务说明中点明该输入和覆盖范围。
已完成子代理结果、完整工具输出和父级编排过程本身都不是全量继承理由。
Astra 对这些上下文读取、传播、结果复用和增量补缺规则没有例外。

父代理首次采用子代理结果后，在当前会话保留结果身份、来源快照或覆盖范围、已满足成功条件
和剩余决定性缺口组成的轻量收据；上下文压缩后复用这份收据，不重新读取已交付结果。只有
来源变化、覆盖不完整、结果与当前事实冲突或必要验收仍有具体缺口时，才定向补读、补验或
增量追问；没有具体缺口就停止收取和追问。必要的接口、安全、权限与数据完整性核验仍保留。
子代理的 `commentary` 只是进展，不是可采用交付；没有明确最终回复或等价结果收据时，父代理
不能把任务记作已采用。若只缺一个具体交付项，至多发一次明确补问；仍未取得时记录未采用原因，
关闭该任务或只改派剩余缺口，不循环追问，也不因此完整重做已有可靠证据。

实际工具 schema 决定可选字段；当前 `spawn_agent` 原生消费模型和思考程度。任何层级、任何
子代理的新派发都必须显式传入这两个字段；具名保留子代理由父代理从已加载 TOML 取得实际值，
并在原生调用中显式传入完全一致的值。任务卡文字或公开声明不能替代原生调用参数，也不能
证明宿主配置成功；固定组合不符合当前任务边界时不复用该子代理。
选配、上下文覆盖或执行路线确有疑问时读[执行路由](references/execution-routing.md)；
需比较配置或维护费率时读[成本预估](references/cost-baseline.md)，不逐任务联网查价。

## 委派与收口入口

本节已经承载普通首次派发所需合同；普通派发不再把完整读取
[子代理委派](references/delegation.md)设为前置。只有复制/变体、协作消息、用户否定后的撤销或
任务类型组收口出现本节未覆盖的具名问题时，才读取该文档的对应最小段落。任务说明必须给出
来源或已存在的 `SOURCE_ROUTE` 证据包、具体职责、父代理规范任务名、写入所有权或只读限制、工具与外部影响范围、成功条件、
停止条件和有限关键步骤（可为“无”）；每个模型子任务另附父代理侧 `MODEL_ROUTE` 短收据，
子代理使用但不复述。关键步骤只有真实依赖需要中途结果时才设置。实现者必须
知道共享目录还有其他代理，不得回退他人修改。父代理必须把下面五行的实际值写进每个
`spawn_agent` 或 `followup_task` 任务卡，而不能假定通用 `explorer`、`worker` 或继承历史会自动
取得保留子代理提示。子代理第一条可见 commentary 必须原样输出任务卡开头五行，其中名称使用
用户语言且中文会话使用中文名称；存活轮次和经验采用 `recall` 返回的实际值，运行时
子代理分别说明 0 轮和未加载保留经验，不自行声明经验适用性。五行前不写计划、运行 ID 或
其他说明；最终回复只保留三行配置抬头。普通任务不再向父代理重复发送相同配置，也不索要确认。原生卡片的 ASCII
`task_name` 是技术标识，不能保证原生卡片标题本地化，也不能作为中文第一行声明；中文身份以
任务卡和 commentary 的第一行为准。

预计两个或更多子代理将同时修改文件或共享状态时，父代理必须在首次可写派发前读取
[可写子代理并行](references/write-parallelism.md)，并保存父侧 `WRITE_ROUTE`：写入者、
分配范围、共同热点、隔离路线、撤销依据和受影响检查。汇合时用真实修改集合更新这条收据；
范围无法隔离或撤销无法精确归因时只允许一个候选直接写目标。收据只服务当前任务卡、整合与
最终说明，不写数据库，也不增加第二次调用收益判断。

同一团队中，子代理只在发现真正解锁队友或父代理下一动作的证据、需要输入纠偏，或出现风险、
阻断时，用 `collaboration.send_message` 向已知接收者发送有来源的短消息。正常过程随最终回复
交付，不重复发送。消息不授权改写对方职责；范围调整、冲突与共享写入仍交父代理裁决。
普通子代理各自交付结果，不代交或隐藏队友结果，不用跨任务工具冒充内部消息。
父代理保持用户沟通、避免重复调查、整合结果；只在有收益且任务说明明确允许的子项目内
启用协作父代理，下游及跨任务细节见[协作父代理与父代理之间](references/collaboration.md)。
跨任务动作须符合当前工具要求；技能或任务卡不能代替工具要求的用户明确新建任务授权。

同类额外子任务复制组内子代理；只有复制前确认改进空间时才形成变体，比较完整配置组合。
各结果先独立核验采用，竞争只选择未来保留者。用户否定的子代理立即停止，其结果与经验候选
失效；共享修改只按明确归属撤销，不能整树回退。并行写入、热点与恢复细节在涉及写入时读
[可写子代理并行](references/write-parallelism.md)。

每个任务类型组结果核验采用后，先形成可跨项目复用的全局领域规则。新运行时组能够泛化时，按
[保留子代理经验](references/specialist-memory.md)先执行首次 `ensure`；只有它明确返回
`reconfiguration_required` 或 `global_contract_refresh_required`，才使用响应里的当前 SHA 对同一
已采用配置作一次 CAS 确认，随后用一次 `complete-run`
原子记录已采用结果和可选经验；已复用保留子代理则直接执行一次 `complete-run`。父代理在发出
下一条最终交付前必须二选一：完成对应收口，或给出一条命中明确排除条件的跳过原因；无回执的
静默省略属于收口失败。`improve` 只用于兼容、摘要更新或单独经验修正，不能代替本次完成收据。
这个二选一在结果采用后短路执行，不要求通读生命周期文档，不阻塞主任务实现、测试或交付。
每个全局领域组只保留一个休眠配置，没有项目保留层；保留不延长运行线程。
保留身份启动前由父代理分配 UUID `run_id`，只在父代理侧关联调用，不写入子代理任务卡，也不由
子代理在 commentary 或最终回复中回显；任务完成且父代理取得明确最终判断后才幂等执行
`complete-run --outcome success|failure`。旧 `record-run` 保留兼容。成功必须达到成功条件、核验采用且 Done；失败必须是整个任务已明确
失败。运行中、中断、未采用、用户停止或否定、工具缺失后停止及结果未定都不记为失败。累计
两次明确任务失败时，永久移除该子代理 TOML、身份、全部成功/失败运行、原始经验、纠正事件与
摘要；不保留退役身份、收据或恢复入口。权限、锁、结构、身份或 CAS 失败时零写入跳过，说明原因；
不重试或等待维护。经验准备只在预计能提供必要质量或实际加快后续父任务完成时提前进行，不因
空闲槽位单独启动，也不是提交前置条件。经验维护完成或
安全跳过后，其他候选退出；普通手动删除资格不因精简提示而放宽。最终按组简述子代理和
经验保存回执，不新造同领域记录或保存来源项目及敏感内容。
需要查看聚合时，`status --for-dashboard` 做一次只读快照；加 `--watch-seconds 1..3600` 后在
前台逐行输出周期快照，`Ctrl+C` 结束。它不创建后台任务，也不冒充 Codex 插件卡自动刷新。

## 按需细则

只选会改变当前动作的条目；短任务不因使用本插件而加载整套手册。中文正文使用父代理、子代理、
主任务、子任务、任务类型组、保留子代理、复制、变体、经验和运行环境；`instance` 译为“子任务”。
代码标识、路径、模型名和原始错误保留。

| 当前需要 | 读取入口 |
| --- | --- |
| 工具/模型选路、复杂 PowerShell 转义、来源覆盖或迭代测试链 | [执行路由](references/execution-routing.md) |
| 子代理任务说明、协作、写入、结果采用或子代理经验 | 只选 [子代理委派](references/delegation.md)、[协作父代理](references/collaboration.md)、[可写子代理并行](references/write-parallelism.md) 或 [保留子代理经验](references/specialist-memory.md) |
| 调查、实现、复核、重验、反过度工程、消融、发布或文档维护 | 这些主任务步骤独立使用 [$lean-simplify 主任务精简](../lean-simplify/SKILL.md)；不得把加载或完成该入口作为本入口调用子代理的前置条件 |
| 解释流程或交付链路图 | [中文链路图内容源](references/flowcharts-zh.md)；静态图使用 `architecture-viewer`，交互图使用 `archify`，创作内容为中文 |

`迭代测试链` 的调用路线属于本入口：几秒且确定的检查由父代理直接用工具；只有测试需要持续
语义判断，且验证子代理使用质量充分、成本相称的模型与思考程度组合，并对父任务完成速度有
正贡献时才调用。主任务该测什么、何时进入条件性
语义复核或失败后的最窄重验，由 `$lean-simplify` 决定。Windows Python 使用 `py -3 -X utf8`。
若要证明插件在安装后的新会话实际采用了子代理调用路线，必须在获授权完成正式安装后，新建独立父代理任务并
使用全新项目目录。该验收任务不得读取源码项目的本地任务资料、当前会话摘要、源码候选文本
或人工摘录策略，只能依赖新任务自动加载的全局入口与正式安装缓存。先用单一短确定性工具验证
直接处理而不委派；随后用有独立模型判断切片的受控要求做子代理调用测试。观察到父代理在继续
大块工作前发出真实 `subAgentActivity` 或等价启动事件，并能从调用收据核对实际模型与思考程度
后立即停止，由独立父代理中断探针子代理，不等待或要求子代理完整做题。该探针只证明调用选择，
不证明业务质量或插件其他功能。运行环境存在内部硬阻断时，本次调用验收未完成；不能用阻断
说明替代真实派发。当前会话手工加载候选文本只能作为源码检查，不能宣称新会话调用路线生效。
本插件不承载图形渲染器、Viewer Runtime 或 loopback 服务，依赖缺失时如实报告，不另建替代实现。
