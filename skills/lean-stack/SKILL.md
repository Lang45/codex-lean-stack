# Codex 子代理调用

## 何时使用

本入口负责判断是否委派、选择模型与思考程度、复用子代理、限定上下文和采用结果。首次准备
`collaboration.spawn_agent`，或准备让现有子代理承担新的相关子任务时读取；本轮已经读取且文件
未变化时直接复用。`$lean-stack` 与 `$lean-simplify` 平行、独立，互不构成前置条件。

确定性短工作直接使用工具；已确定需要界面操作的 Computer Use 按[父代理指导、Terra 操作](#computer-use父代理指导terra-操作)执行。
未触发下述持续并行提速状态时，切片就绪、边界清楚且可独立推进，按场景使用三项原则：

1. 高价值工作质量优先，守住正确性；当遇到困难时派遣专家协助。
2. 普通工作可靠性相当后，总成本优先。
3. 总成本处于可接受成本带时，为加快父任务完成速度，增加或并发派遣子代理来节省时间是可取的。

三项不是每次调用必须同时获益的硬门槛，提速也不是每次委派的必要条件；必要质量或真实总成本
收益可以支持较慢的路线，但必须对照整项主任务判断。总成本同时计入父代理独做与委派后的
启动、上下文、交流、等待、整合和核验，不能只比较子模型单价或父代理减少的工作。
调用数量本身不是目标，也不是错误；多个互不冲突的切片各有真实收益时可按上述原则并发。
安全、权限、数据完整性和诚实证据始终优先。

## 先判断是否委派，再选模型与复用

父代理在分工时先比较自己直接完成、父子共同推进和全交子代理的最短完整路径，考虑从用户提出
要求到可采用交付的总完成时间。把适合父代理的实现、研究或关键路径工作留在主线，再派出有收益的
独立切片；不要先把实质工作全部外包，再用轮询、转述、整理和维护填充父代理时间。确实需要集中
整合或监督时可以由父代理专门协调，但须有实际依赖或必要质量收益，不重复子代理工作来证明参与。

- 平均值、汇总、格式转换、哈希比较、已定义公式的计算和现有脚本可完成的核对，由父代理直接
  用工具完成并批量处理。同一规则下的多轮原始事件可以集中解析；“独立重算”“补核”“审核”
  等名称不自动产生调用另一模型的必要性。用户明确指定某项交给子代理或 Computer Use 分工除外；
  泛指“多派”不等于指定这些计算也要委派。
- 只有当前切片仍需要持续模型判断、输入已就绪且可独立交付，并相对父代理参与的方案有具名
  质量、父子合计总成本或整项完成时间收益时，才进入模型和执行者选择。公共接口、安全、迁移、
  数据完整性等必要独立复核保留；不把常规正确性检查升级成默认的逐轮、逐样本模型复核。
- 新的计算、核对或已完成结果的补充同样适用本判断，包括通过 `followup_task` 交给已有子代理的
  工作。已有熟悉代理不是委派理由；同一未完语义切片的纠偏和解锁直接续用，不为每次消息、点击
  或工具步骤重新评估模型。决定确需委派后，才按下文选择模型、读取保留状态和复用线程。

这是入口的快速判断，不生成评分表、计时器、固定路线收据或调用配额。

## 用户要求持续并行提速

用户在会话中说“多开子代理”，或明确表达“在质量前提下持续增加并行、以更快完成当前主任务”等
同义要求时，当前主任务进入持续并行提速状态：质量要求不降低，成本不再作为增加并行的否决条件。
该状态仍先执行上节必要性与整项收益判断，父代理继续承担适合自己的实质工作；可派范围是此后剩余的
合格独立切片。父代理尽早真实派发所有已就绪、可独立交付、互不冲突且通过上述判断的切片；后续出现
新切片或可用容量释放时继续派发，不能只临时增加一两个、固定四路，或因偏好复用当前线程而把
可并行切片串行排队。同一能力族的独立切片可复用同一保留 `agent_type` 启动多个独立线程。

安全、权限、实际工具容量、依赖、写入冲突和必要质量继续约束派发；不为空转或填满槽位制造工作，
不因成本放宽自动全部采用 Astra 或 `xhigh`。模型与思考程度仍按当前切片的必要质量选择。
该状态持续到用户明确撤回持续多派、恢复成本约束、提出与该状态冲突的新要求或明确停止，
或当前主任务交付完毕或被替换；普通顺序调整和局部要求变化不自动终止，不扩展到无关未来任务；
不新增机械人数、时限、脚本调度器、后台状态机或全局持久模式。各分支中的默认成本与线程复用
条款须服从本节当前状态，未触发时仍按原三项原则执行。

## 模型与思考程度

| 模型 | 适用任务 |
| --- | --- |
| `gpt-6.1-terra` | 速度优先、范围明确且验收直接的简单工作：有界读取、结构化提取、事实总结、文字整理和局部小修改；以及由父代理指导的 Computer Use 执行 |
| `gpt-6.1-sol` | 有限歧义、跨来源或模块因果，以及常规复杂实现、审查与验证 |
| `gpt-6-astra` | 相对最强可行 `gpt-6.1-sol` 仍有决定性质量收益的专家问题 |

前两档都是常规子代理路线；只有 `gpt-6-astra` 是专家路线。三项原则中的“派遣专家”只指
这条 Astra 路线，并仍须满足上述决定性质量差距。

上表是本插件按任务分工的路线，不是所有任务的通用能力排名，也不保证各型号都能作为当前宿主的运行时覆盖值。运行时 `model` 必须存在于当前
公开覆盖目录；所需 Terra 不在该目录时，普通任务选择当前可用且质量足够的 Sol，不猜别名、不发错误调用试探。
Computer Use 的执行者按下节核对，不能用普通任务回退代替用户指定的 Terra 操作。
固定保留角色仅按其已加载固定配置调用；某角色的型号可用，不证明通用运行时角色也能覆盖为该型号，
不得为此擅自修改角色 TOML。

思考程度从 `medium` 起，按任务选 `high` 或 `xhigh`；Astra 的 `xhigh` 是上限，不是默认值。
Sol 的 `max`、`ultra` 仅按[首次派发](references/dispatch-start.md#模型与思考程度)
中的质量条件选用；普通任务不因模型名称或任务标签升级。
Terra 通常使用 `medium`，仅有少量局部歧义时可用 `high`；以输入清楚、风险低、有直接验收点为前提，
不为简单工作追求最高质量而增加推理。复杂取舍、跨模块因果、合规或安全判断、高风险修改及最终审查结论
至少使用合适的 Sol；出现这些条件时重新选路，不仅提高 Terra 的思考程度。已保留身份也不能绕过这条质量下限。
旧 Luna 保留资料可读取，但新建或显式重配使用本表型号；需要继续该能力族时按 CAS 重配同一身份，
保留权限与经验，并在新任务核对宿主加载；已加载的旧 Luna 配置不能冒充 Terra。

## Computer Use：父代理指导，Terra 操作

已经确定需要通过桌面或浏览器界面操作的 Computer Use 任务，由父代理指导 `gpt-6.1-terra`
实际执行；即使整体业务复杂，也将复杂分析、取舍和最终审查留给父代理或合适的 Sol/Astra，
再把明确的界面步骤交给 Terra。此分工同样覆盖只读界面观察，不因操作很短就由父代理自行代操。
已有适用连接器、API 或 CLI 的任务继续按对应工具规则处理，不为套用此分工改成界面操作。

- **父代理指导与验收：**任务卡给出目标应用或页面、已知当前状态、已授权操作范围、当前阶段
  的目标、可观察完成条件及必要的停止或恢复要求；父代理负责整体判断、具名纠偏与最终验收。
- **Terra 执行与反馈：**先核对自己的工具可用性；有对应且适用的 Computer Use 技能时读取或复用，
  并遵守实际工具说明，以当前返回的界面对象和观察为依据执行。按可验证阶段反馈实际操作、结果和剩余状态；出现范围外决定、
  权限缺口或界面偏离时返回父代理，不自行扩大目标。父代理用 `followup_task` 发送增量指导，
  不要求每次点击往返，也不把发出点击命令当作已保存或已完成。
- **操作所有权：**同一桌面、窗口或标签页保持一个操作者；父代理不与 Terra 交错输入。
  只有界面和会话状态确实隔离、工具支持且互不冲突时，才并行其他界面操作。
- **能力与权限：**模型和工具须在执行子代理中真实可用，父会话的工具句柄不等于子会话可用对象。
  委派不扩大现有授权，确认要求仍按当前用户授权和工具技能执行。Terra 或所需工具不可用时，
  报告具体缺口并继续不依赖界面的工作；不得把父代理代操、其他模型操作或文字方案说成 Terra 已操作。

## 同一能力族优先复用

决定委派后，同一任务的小补充直接继续使用兼容的当前子代理，只发送新增目标、证据或纠偏；完成
状态本身不妨碍续用。这指仍需模型判断的增量；新增确定性计算先按上节由父代理直接处理，不因
已有线程跳过是否委派的判断。决定为一个新的能力类型调用子代理且没有适合继续使用的当前子代理时，只做
一次快速、有界台账查询。满足以下条件的保留子代理会被复用：

- 当前会话已经加载；
- 属于同一能力族；
- 质量兼容。

符合条件的保留子代理优先于通用角色或最小运行时角色。目录查询失败但当前会话已加载类型中已有
符合三项条件的明确候选时，仍只读取该候选一次；读取成功就复用，不要求所有无关保留身份都健康。
只有没有可核对候选或读取保留子代理失败时，本次才改用最小运行时角色继续。不得把查询失败当成
空台账用于新建保留身份。查询结果和候选条件未变化时复用本轮结果，不重复查。能力族按职责和预期交付判断；输入形式与证据使用规则
写进任务卡，模型档位按本次任务的质量、成本和时间选择，不另设复用条件。当前子代理与台账保留
子代理都可用时，未触发[持续并行提速](#用户要求持续并行提速)则在质量达到要求后比较父子合计
总成本，选择更低成本的一条；触发时按该节派发，不为统计台账复用强制换线程。模型与思考程度由本次任务的质量条件
统一决定，不另设为复用门槛。同身份配置可经核验用 CAS 安全
重配，当前宿主已加载的旧配置须由新任务验证。执行者选择、一次有界
读取保留子代理、失败改派与任务卡细节见[首次派发](references/dispatch-start.md#选择同一能力族的执行者)。
台账复用只指调用现有 `lean_*` 保留 `agent_type`；当前子代理的 `followup_task` 是当前会话上下文
复用，不得计入台账复用。

只有用户优先级、并行需求、任务类型、质量门槛、权限或证据边界、专家必要性、预计成本发生实质变化时才重新选路；同一
任务的小补充直接继续，不重复评估。历史使用的模型不锁定未来模型。需要重新选路时，先按当前
质量要求判断是否仍需 Astra；仍需时再独立选择旧线程或另一条兼容
Astra 路线，旧线程上下文无边际价值不能触发降级。已完成且采用、验收满足的 Astra 在没有新要求、新证据、未满足验收或明确
纠错时停止，详细停止与续用条件见[首次派发](references/dispatch-start.md#增量切片与-astra-停止条件)。

## 原生调用与任务卡

当前宿主所有 `spawn_agent` 调用显式传 `fork_turns="none"`，不得省略历史参数而采用默认全量继承；禁止 `fork_turns="all"`。
通用运行时角色显式传实际 `model`、`reasoning_effort`，型号取当前公开覆盖目录；固定保留角色沿用工具
已加载固定配置，不传模型或思考程度覆盖参数，任务卡核对实际配置。TOML 和任务卡不能代替原生参数，
不得通过错误调用试探或擅改 TOML 绕过工具合同。五行真实开场与最终回复三行的唯一详细规则见
[首次派发](references/dispatch-start.md#任务卡上下文与所有权)；缺少实际状态先内部补齐，
不向用户显示占位语。复用当前子代理但没有已核验的保留子代理读取状态时，经验行只写
“经验：复用当前线程上下文”；不得显示“未核验持久化经验”。保留 TOML 的经验已在
`developer_instructions` 原生注入，读取保留子代理成功后
任务卡只传五行状态，不复制经验正文；子代理读已注入经验一次即开始任务。
任务卡须直接传递[条件性经验候选合同](references/agent-results.md#最终结果)：将本次已验证、可跨任务复用且
当前身份尚未承载的具体做法、反例或证据边界随最终结果返回；无价值或已承载则省略。

## 执行、结果和保留

派发后父代理继续未分配主线，以最终回复或等价结果收据采用结果；进展说明不构成交付。
子代理执行期间正常提供用户可见进展说明，任务卡不得要求默认静默；减少重复的父子内部消息不限制途中说明。进展、内部消息和父代理汇合的具体边界见[子代理结果与汇合](references/agent-results.md)。
核验采用结果时，按[父代理采用](references/agent-results.md#父代理采用)自动完成能力族与新增经验的两项判断，
符合条件即执行现有命令并回读，再继续主任务；采用触发与失败处理以该节为唯一说明。
身份保留无新增经验也无需 `run_id`；成功结果只有新增可复用经验才 `complete-run`，已核验保留身份的明确
失败可不带 `--lesson` 记录。普通派发不进行成本、迁移或摘要巡检。身份、CAS、经验与
第二次明确失败的写入边界见[保留子代理经验](references/specialist-memory.md)。

## 正式宿主证据边界

静态文案、模板测试、源码读取、安装成功或缓存相等不能证明真实宿主采用了本路线。正式验收需要
在安装后的新任务中观察原生调用参数、子线程开场和最终结果；子代理进展说明是否显示还需单独用
用户实际界面确认。辅助脚本维护身份和经验，不启动子代理，也不证明宿主加载了经验。
