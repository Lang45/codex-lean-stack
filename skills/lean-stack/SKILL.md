# Codex 子代理调用

## 何时使用

本入口负责判断是否委派、选择模型与思考程度、复用子代理、限定上下文和采用结果。首次准备
`collaboration.spawn_agent`，或准备让现有子代理承担新的相关子任务时读取；本轮已经读取且文件
未变化时直接复用。`$lean-stack` 与 `$lean-simplify` 平行、独立，互不构成前置条件。

确定性短工作直接使用工具。只有切片已经就绪、边界清楚、可独立推进，并同时满足以下条件时才
调用子代理：

1. **质量：**模型与思考程度足以给出当前任务需要的可靠结果和证据；
2. **成本：**在质量充分的选择中使用与任务相称的组合；
3. **时间：**委派能并行推进或替代父代理尚未完成的模型工作，实际缩短完成时间。

调用数量本身不是目标，也不是错误。多个互不冲突的切片分别满足三项条件时可以并发；没有收益
时父代理直接完成。安全、权限、数据完整性和诚实证据始终优先。

## 模型与思考程度

| 模型 | 适用任务 |
| --- | --- |
| `gpt-6-luna` | 规格清楚、证据已定位、推理直接、输出短且容易核验 |
| `gpt-6-sol` | 有限语义歧义到跨来源、跨模块因果，以及复杂实现、测试和自检 |
| `gpt-6-astra` | 相对最强可行 `gpt-6-sol` 仍存在会改变决定的质量差距，并且已有实际输入与验收点 |

思考程度独立按当前切片选择：直接事实、少量依赖或局部歧义用 `medium`，多层因果、
竞争假设、接口或安全边界用 `high`，只有密集冲突且高价值的未决关系才用 `xhigh`。Astra 可以
使用 `medium`、`high` 或 `xhigh`；`xhigh` 是上限，不是默认值。Sol 的 `max` 可按必要
质量选择；`ultra` 只用于高价值复杂边界，且须有 `xhigh` 与 `max` 都不足的具体依据。

普通视觉、简单审计、提示文档编写或只提到某个模型都不自动升级。需要展开选择边界时读取
[首次派发](references/dispatch-start.md#模型与思考程度)。

## 同一能力族优先复用

已经决定委派后，按下面的短路径选择执行者：

1. 当前 live child 属于同一能力族，实际模型属于上述三款且思考程度不低于 `medium`，开场状态已确认，权限和证据边界兼容，保留上下文能提高质量、成本或速度：
   直接 `followup_task`，只发送新增目标、证据或纠偏；完成状态本身不妨碍续用。
2. 没有合适 live child，但原生工具目录已有同能力族且实际模型、思考程度及权限兼容的 `agent_type`：直接复用该类型。
3. 两者都没有：创建满足当前切片的最小运行时子代理。

能力族按职责、输入形状、可验证交付、权限、安全风险和证据要求判断。项目名、框架名、动作词、
中文展示名或模型档位不同，不能单独成为拆分新角色的理由。原生工具目录已经提供足够信息时不查
`status --for-routing`；旧保留角色模型或思考程度不合规时，确需跨任务复用且适合当前能力族才经已核验的 CAS 安全重配为 GPT-6 类型；当前宿主已加载的旧固定配置不能视作立即生效，须由新任务验证。当前调用可用运行时子代理。命中已加载 `agent_type` 时，只对该身份做一次有界 `recall`，取得五行开场与已有经验；成功后立即原生派发，让子代理读一遍已提供的经验并开始任务。旧经验与当前技能冲突时按当前技能执行，纠正放在后续按需维护，不插入状态全表、旧经验收据、成本或身份维护。召回失败改派最小合规运行时子代理，不重试、不修库、不延迟主任务，不声称复用了保留类型。

同一能力族同时出现多个独立、已就绪切片时，可以创建相互隔离的运行时复制；只有真实选配疑问
需要可比较结果时才使用配置变体。该既有能力的完整触发、写入隔离、结果和保留边界由
[任务类型组、复制与变体](references/agent-groups.md)承载。

## 原生调用与任务卡

每次 `spawn_agent` 都显式传入：

- 当前实际选择的 `model`；
- 当前实际选择的 `reasoning_effort`；
- `fork_turns="none"` 或有限正整数，禁止 `fork_turns="all"`。

TOML、任务卡或“继承”不能代替原生参数。复用保留 `agent_type` 时，传入值须与工具目录中的固定
配置一致。`followup_task` 沿用该 live child 的配置，不重新选模。

新建子代理的任务卡以三行真实配置开头，接两行状态供首次进展说明使用：

```text
子代理名称：<已按实际路线附（复用）或（新建）的名称>
模型：<实际模型>
思考程度：<实际等级>
存活轮次：<保留召回状态或运行时 0>
经验：<保留召回状态或运行时未加载保留经验>
```

每张新任务卡在五行后直接携带这一执行句，不能只在父入口外部概述：

```text
第一条用户可见进展说明顶部必须原样展示以上五行，最终回复顶部重复前三行实际配置；五行前不写计划、父代理开场模板或内部标识。
```

随后写唯一目标、必要输入或来源、只读限制或写入所有权、禁止的外部影响、成功条件、停止条件和
回复语言。第一行只按实际派发路线在名称末尾显示一次 `（复用）` 或 `（新建）`：当前可复用子代理和已选中且召回成功的保留 `agent_type` 为复用，最小运行时新角色为新建；不能仅凭候选匹配就标复用。保留类型的前三行取自原生目录实际配置并与该身份 `recall.opening_declaration` 核对，后两行原样取自 `recall.opening_status`。召回失败时改派最小合规运行时子代理，其后两行写“存活轮次：0”“经验：未加载保留经验”。当前可复用子代理承担新任务时只沿用已确认状态；状态无法确认就改派运行时子代理；同任务补问不重复开场。任务卡若缺少实际状态，先向父代理内部报告并补齐，不向用户展示占位语。不得把保留身份的历史计数冒充 live child 的线程存活时长。

子代理在自己的第一条用户可见**进展说明**中原样展示五行，然后开始任务；最终回复顶部再次
展示含相同名称标记的前三行。若宿主没有向用户显示子代理的进展说明，父代理可以依据原生调用回执和已核验召回状态简短说明实际配置与状态，
不得猜测或使用计划值冒充调用结果。`run_id`、SHA 和经验摘要属于内部持久化字段，不进入开场。

完整任务卡、上下文和所有权规则见[首次派发](references/dispatch-start.md)。

## 执行、结果和可选保留

派发后父代理继续未分配主线，只在真实依赖点汇合。子代理的进展说明和内部消息不构成交付；采用
结果需要明确 final 或等价结果收据。来源完整且快照未变时直接复用，只对具名缺口补问一次。

结果核验采用后，主任务立即继续。新能力族已核验具有跨任务价值且身份、权限可安全绑定时，可按需 `ensure` 保留身份，即便没有新增 `--lesson`；这一步无需 `run_id`。有新增跨任务经验，或已核验并采用的保留身份有明确失败，而且身份与 CAS 快照能安全核对时，才按需进入[保留子代理经验](references/specialist-memory.md)的完成记账。没有新增可复用经验的成功结果不生成 UUID，也不执行 `complete-run`；普通临时调用和同任务补问不做身份维护。保留身份的明确失败可不带 `--lesson` 记录，以维持第二次明确失败删除。运行中、中断或结果未定不记失败。持久化失败不阻塞主任务交付；父代理保留具名未完成写入，随后修复实际阻断并回读验收，不能只报告原因。

旧经验的数据库签发收据只在声称该版本参与并发完成时使用；`ensure` 不依赖旧经验、收据或完成记账。健康结构下新增经验直接按需记账，不等待版本维护或旧摘要纠错；结构不合规时由脚本安全跳过本次写入，父代理保留原已核验结果，后续按备份和显式迁移流程修复再核验保存，不声称已经写入。CAS、事务和 TOML 文件竞争由 `agents.py` 执行并以回执判定。成本基线只在独立维护动作明确触发时核对，不随每次子代理调用查询。

## 条件路由

只在下一动作真正需要时读取对应最小分支：

| 下一动作 | 权威入口 |
| --- | --- |
| 选择执行者、模型、思考程度、任务卡或调用参数 | [首次派发](references/dispatch-start.md) |
| 分配长来源、复用证据包或补具名缺口 | [来源所有权与结果收据](references/source-results.md) |
| 准备运行时复制、配置变体、结果比较或处理用户否定 | [任务类型组、复制与变体](references/agent-groups.md) |
| 接收中间消息、最终结果、等待或停止 | [子代理结果与汇合](references/agent-results.md) |
| 两个或更多执行者写入文件或共享状态 | [可写子代理并行](references/write-parallelism.md) |
| 当前子代理将再派下游，或与其他 Codex 任务协作 | [协作父代理](references/collaboration.md) |
| 创建或重配保留身份、读取经验、记录结果、迁移或删除 | [保留子代理经验](references/specialist-memory.md) |
| 选择直接工具或验证子代理，或失败后最窄重验 | [条件性验证](references/verification.md) |
| 维护官方费率或插件成本基线 | [成本预估](references/cost-baseline.md) |
| 用户明确调用流程图并要求检查或解释 | [中文链路图](references/flowcharts-zh.md) |

下一步属于主任务调查、实现、复核、消融或发布时，独立使用
[$lean-simplify](../lean-simplify/SKILL.md)。未命中分支不读取，不把 reference 变成普通调用前置。

## 正式宿主证据边界

静态文案、模板测试、源码读取、安装成功或缓存相等不能证明真实宿主采用了本路线。正式验收需要
在安装后的新任务中观察原生调用参数、子线程开场和最终结果；子代理进展说明是否显示还需单独用
用户实际界面确认。辅助脚本维护身份和经验，不启动子代理，也不证明宿主加载了经验。
