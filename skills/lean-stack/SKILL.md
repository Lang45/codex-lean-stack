# Codex 子代理调用

## 职责与触发

本入口负责工具/子代理调用判断、模型与思考程度选配、最小上下文、结果采用及必要收口。安装本
插件的项目和新会话保持主动委派：出现符合质量、成本、时间三项原则且能独立推进的切片时立即
调用，不等待用户逐次重申，也不设机械调用配额。代理管理和经验只能服务主任务，不能拖延交付。

新项目或新会话不因进入会话而预读本入口。首次准备调用 `collaboration.spawn_agent`，或用
`followup_task` 启动新当前子任务时，才实际读取已加载目录中的本 `SKILL.md`；已读且入口未变化
时直接复用。只读取并应用当前实际动作命中的入口，不预读 `$lean-simplify` 或完整 `references`。本入口与
其他适用技能的用途说明合并到唯一启动说明；读取后的下一次工具调用立即开始实际任务。

普通子代理从任务卡和指定证据开始，不自行扩读未分配的项目资料、整套技能或插件缓存。首次派发
只识别技能名称、口头声明、项目交接或猜测路径都不算已读；工具明确截断时只补缺失段。

## 每次原生调用的派发硬门

每次 `collaboration.spawn_agent` 调用前都重新检查，且原生参数必须同时包含：

- 当前切片实际选择的 `model`；
- 当前切片实际选择的 `reasoning_effort`；
- `fork_turns="none"` 或有限正整数，禁止 `fork_turns="all"`。

任何层级和任何 `agent_type` 都不得用任务卡文字、TOML 或“继承”占位替代原生参数。具名保留
子代理的模型与思考程度必须与已加载 TOML 完全一致；不合规时换用合规子代理，不覆盖 TOML。
`followup_task` 没有选模参数，但任务卡仍写现有子代理的真实模型、思考程度和 `MODEL_ROUTE`。

每个 `spawn_agent` 或新当前子任务的 `followup_task` 内部任务卡必须以下列五行实际值开头：

1. 子代理名称；
2. 模型；
3. 思考程度；
4. 存活轮次；
5. 经验。

名称使用用户语言；中文会话不能用技术 `task_name` 代替中文名称。五行只由子代理本人在自己的
第一条可见 commentary 原样宣读，五行前不写计划、运行 ID 或其他说明；父代理仅写内部任务卡，
不得在父代理自己的用户可见 commentary 或最终回复中代为展示或重复。该硬门沿 parent → child → grandchild
递归；缺字段、占位值或错误可见所有权时不得调用。

普通 UI、视觉和简单审计不得使用 Sol `ultra`。Sol `ultra` 只用于高价值复杂边界，且须说明
`xhigh` 与 `max` 为何都不足；Astra 仅在最强可行 GPT-5.6 仍有决定性质量差距时使用，最高 `xhigh`。
完整选配规则按需读取[四模型一次联合选配](references/execution-routing.md#四模型一次联合选配)。

## 两个独立入口

插件只提供 `$lean-stack` 与 `$lean-simplify` 两个并行技能入口，二者平行、独立且互不前置：本入口命中时直接完成调用判断与派发，
不等待主任务精简；主任务精简也不得阻断、延后或减少符合三项原则的委派。两边共同保留用户
要求、当前授权、安全、权限、数据完整性和匹配结论的证据，并共同遵守工具与 PowerShell 路径精简及
[Windows exec 稳健性契约](references/execution-routing.md)。

调用子代理不能证明主任务已经精简，静态精简规则也不能证明子代理实际运行。`scripts/agents.py`
只维护子代理、运行和经验，不启动子代理，也不是主任务精简执行器；两项功能分别验收。

## 三项原则与一次判断

选路固定按 **质量 → 成本 → 时间** 执行：

1. **质量。** 模型与思考程度联合达到必要质量并能给出决定性证据；质量不足的组合不合格。
2. **成本。** 在质量充分的组合中选择与任务相称的总成本，不只计算子代理启动成本。
3. **时间。** 委派必须并行推进或替代父代理尚未完成的模型工作，实际加快父任务完成。

确定性短工作直接用工具；独立短命令做工具级并发。需要持续模型判断时，只问是否已有就绪、范围
明确、可安全独立推进且通过三项原则的切片；有则立即调用，多个互不冲突的合格切片可并发。

只有具体阻断才直接处理或停止相应派发：真实前置未就绪或严格依赖、重复工作、无法隔离的写入
冲突、能力/工具/权限不足、运行容量不足、没有质量充分且成本相称的组合，或不能加快父任务。
不使用评分表、固定百分比或机械配额，也不为证明插件能委派而制造任务。

任务形状、来源范围或困难变化并出现新独立切片时重新判断；否则复用当前决定。安全、权限、数据
完整性、明确验收与诚实证据始终是底线，委派不扩大权限。

## 选配与上下文底线

先确定具体任务类型和兼容的任务类型组，再匹配可见保留子代理；有则复用，没有则定制运行时
子代理。任务类型组、保留或经验写入都不是当前调用的前置条件。详细路线见
[当前调用快路](references/delegation.md#当前调用快路)。

独立窄任务优先 `fork_turns="none"` 和自包含任务卡；确需先前决策时才给有限历史。
`followup_task` 不以旧上下文不可替代为前提；持续对话、澄清、纠偏、迭代验证或父代理遥控
能具体改善质量、速度或总成本时，可以继续使用 `followup_task`。无关、已经结束或能自包含的新切片
则新建 `spawn_agent(fork_turns="none")`。任务卡明确职责、来源、写入所有权或只读限制、外部影响、
成功/停止条件和必要关键步骤。父代理同步推进不重叠主线，只在真实依赖点汇合，不完整重做已核验证据。

子代理 commentary 只是进展，不是可采用交付；必须取得其明确最终回复或等价结果收据。只在来源
变化、冲突或具名缺口时定向补读或补问一次，不循环索取全文。结果采用、生命周期和经验收口按需
读取对应 reference，不能阻塞已经就绪的主任务动作。

## 正式宿主证据边界

静态合同、当前源码读取、手工加载候选、安装成功或缓存相等都不能证明新会话真实采用本路线。
若要证明，必须在获授权正式安装后，用全新项目目录创建独立父代理任务，只依赖自动加载的全局
入口和正式缓存；观察真实 `subAgentActivity` 或等价事件，并从原生调用记录核对实际 `model`、
`reasoning_effort`、非全量 `fork_turns` 及子线程首条五行后立即停止探针。内部阻断只能说明验收
未完成，不能替代真实派发；该探针也不证明业务质量或插件其他功能。
