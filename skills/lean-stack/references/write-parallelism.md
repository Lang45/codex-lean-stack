# 可写子代理并行

仅在两个或更多子代理将同时修改文件或共享状态时读取。这是“工具、子代理与安全并行”
合并链路的写入保护分支，不增加第二次调用收益判断。目标不是把所有写入串行化，而是让
多个可写子代理在不会相互覆盖的边界内并行。

## 快速选路

```text
存在多个可写任务类型
→ 写入范围能否天然分开
  → 能：在同一检出目录并行写不同范围
  → 不能：运行环境是否提供独立检出目录，而且隔离与整合成本值得
    → 是：各自在独立检出目录写入，最后比较或整合
    → 否：一个候选直接写目标，其他候选只返回方案或补丁，选定后只应用一次
```

这不是“单写入者”规则。不同任务类型组可以有多个可写子代理同时工作；只有同一个物理
文件或同一份不可拆分状态不能在没有隔离时接受多个直接写入路线。

## 同一检出目录

这是可逆、低风险、边界清楚的普通任务最快路线。高价值工作涉及公共接口、迁移、数据库
结构、安全边界或难以恢复的共享文件时，没有强制写入范围就改用独立检出目录或只读候选。
父代理在调用前只做一次轻量划分：

1. 为每个可写子代理给出精确文件、目录或模块范围。
2. 把清单文件、依赖锁文件、数据库结构、公共接口和生成入口等共同热点单独标出。
3. 写入范围没有交集时立即并行；不要建立锁服务、认领数据库、轮询或后台协调器。
4. 子代理不得切换分支、暂存或丢弃其他改动，也不得修改范围外文件；发现必须跨界时停止
   写入并返回缺口。
5. 共同热点在并行结果回来后集中整合一次；其他范围不因此停止并行。

如果运行环境实际支持可写目录限制，使用 `workspace-write` 和最窄的 `writable_roots`
强化范围；没有这项能力时，不能声称文字任务说明等同强制隔离。

## 同一任务类型的复制与变体

复制的是已有任务类型组里的子代理，用于并行处理多个独立子任务。如果每个子任务天然对应
不同文件、目录或状态范围，就按这些不重叠范围直接并行；父代理为每个子任务分别指定成功
条件，每个子代理完成并自检后在自己的线程用最终回复提交自己的精炼结果。例如三个同类型
文件各由一个组内子代理或其复制处理，不需要从三个结果中只选一个，也不由一个子代理汇总。

只有多个复制会触碰同一个物理目标时，才进入竞争写入保护：

- 运行环境明确提供独立检出目录，且质量、速度或可归因变体收益足以覆盖建立和整合成本
  时，可以让不同复制分别直接写入。
- 没有独立检出目录时，只让一个复制直接写实际目标；其他复制保持只读，返回完整方案、
  补丁或证据。若它们是同一子任务的竞争方案，比较后只应用最佳方案一次。
- 不把共享检出目录里的不同分支当成写入隔离；文件仍然是同一份。

变体只在复制前确认保留子代理确有进步空间时出现。普通复制沿用保留子代理的配置和经验；
变体由父代理根据同一任务类型联合选择完整的模型、思考程度和速度组合，可以因相互制约而
同时变化，子代理不能自行改配置。单轴变化只在明确需要识别因果时作为可选实验。

独立检出目录只在运行环境真实提供且净收益成立时使用。不要为了形式自动创建工作树，
也不要把工作树成本放进普通小任务。

工作树隔离的是文件副本，不会自动消除公共接口或产品决策冲突。父代理仍需按依赖顺序
比较、整合和验证；不能把多个候选无条件合并。

## 收口检查

父代理只在结果汇合时做一次窄检查：

- 查看真实修改文件集合是否落在所有已分配范围的并集内；
- 检查共同热点是否只在集中整合阶段修改；
- 发现越界、重叠或基线变化时停止覆盖，读取当前差异后重新整合；
- 只运行受这些修改影响的测试。

子代理回报保持简短：已修改文件、未修改的共同热点、测试证据、越界或冲突。不要增加
进度数据库、锁租约、心跳或状态机。

## 用户不满意时的精确撤销

可能被用户否定的竞争候选优先使用只读补丁或独立检出目录，使丢弃不需要修改实际目标。
若被否定子代理已经写入共享目录：

1. 立即停止它，禁止继续写入。
2. 对照调用前记录的写入范围、文件基线和当前哈希，列出能精确归因的修改。
3. 当前内容仍只包含该子代理的修改时，恢复调用前的精确内容。
4. 文件已被用户或其他代理继续修改时，不使用 `git reset --hard`、整树检出或按旧快照
   覆盖；父代理读取当前差异，保留可信修改并重建被否定范围。
5. 撤销后只运行受影响检查，再从最后可信状态重做。

无法精确归因时，宁可由父代理重建目标范围，也不能用“立即抹去”为理由破坏其他改动。

OpenAI 官方文档说明可写权限可以限制在工作区或指定目录，工作树为并行任务提供独立文件
副本；官方文档没有说明普通子代理会自动获得独立工作树。因此只有运行环境真实暴露隔离
时才采用隔离路线，否则使用不重叠写入范围或只读候选。
