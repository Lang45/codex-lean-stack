# 子代理结果与汇合

只在子代理已经启动后，需要关键步骤消息、最终提交、父代理采用、等待或停止时读取。普通首次
派发使用[首次派发执行分支](dispatch-start.md)，长来源覆盖和结果补缺使用
[来源所有权与结果收据](source-results.md)。

## 有界关键步骤消息

默认让操作过程随最终回复一次交付。只有中间结果会真正解锁父代理或已知队友的下一动作时，
才在任务卡预先列为关键步骤，并在完成后发送一条短消息后继续：

```text
关键步骤：<预设步骤或新风险>
情况：<决定性结果、证据或方向问题>
下一步：<立即继续的动作>
```

每个真实依赖步骤最多一条消息；方向、权限、安全、数据完整性、外部副作用或停止条件出现新风险
时可额外报告一次，同一风险只有实质变化后再报告。不按时间发心跳，不发送“收到”“是否继续”
等纯确认，也不为父代理答复暂停。父代理无异议时沉默；纠偏只能在当前授权内细化范围、证据、
优先级或成功条件，不得扩权、增加外部副作用或移除停止条件。

队友之间只有在已知规范任务名且发现会解锁对方当前职责的证据时，才用真实内部消息直接传递
依赖、来源快照、发现及验证程度；未核验线索标为假设。不得广播、索要确认、互相分派新任务，
也不得用跨任务消息、共享文件或外部通信冒充内部协作。影响主任务方向、职责或共享写入范围的
发现同时交父代理裁决。

## 最终提交与父代理继续工作

子代理达到成功条件或停止条件并自检后，在自己的线程提交精炼最终结果；commentary、内部进度
和运行中状态不算交付。每个子代理都独立提交，不建共享中转文件；不由一个子代理汇总其他子代理。
协作父代理可核验整合自己下游已独立提交的结果，但不能冒充或替换这些结果。

最终回复至少包含：

```text
子代理名称：<本地化名称>
模型：<具体模型>
思考程度：<具体等级>
子任务：<当前切片>
状态：完成 | 部分完成 | 受阻
结果：<可直接采用的精炼结果>
证据或缺口：<决定性证据、覆盖范围或剩余缺口>
```

父代理在派发后立即推进未分配主线、共享热点或集成；只在下一动作真正依赖某项结果时汇合，
统一收口确实依赖全部必要结果时才等待全部，不主动反复轮询。工具返回运行句柄时沿原句柄等待，
不把“尚未返回”当作失败重新派发。新用户要求先更新范围与授权，再采用迟到结果。

父代理核对关键差异、接口、安全边界和必要验收，但不全面重做证据充分的子任务。非必要结果
未赶上不阻塞主任务；必要验收只补决定性缺口，不能以慢为由丢弃。结果已足够时不再为经验准备、
重复审查或收尾报告启动额外模型。已有完整覆盖且来源未变时直接复用，具体补缺遵循
[来源所有权与结果收据](source-results.md#结果采用与增量补缺)。

用户否定结果时转到[用户不满意时立即移除并重做](agent-groups.md#用户不满意时立即移除并重做)。
每个结果经必要核验并被父代理采用后，必须进入一次
[全局领域保留子代理经验](specialist-memory.md)收口判断：已有专家记录本次完成；临时子代理能形成
全局领域规则时，先保存为专家再记录完成；只有该分支列出的明确排除项才跳过并留下保存回执。
具体命令由保留分支唯一承载；该确定性侧支失败时立即辅助跳过，不能延迟当前主任务动作或交付。
