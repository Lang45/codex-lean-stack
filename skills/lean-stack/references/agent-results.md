# 子代理结果与汇合

只在子代理已经启动，准备处理中间消息、最终结果、等待、补问或停止时读取。

## 进展说明和内部消息

子代理第一条用户可见进展说明以任务卡提供的五行开头，第一行名称带实际路线 `（复用）` 或 `（新建）`；保留类型的状态来自成功的有界召回，召回失败则由运行时子代理使用自身真实状态开场。任务卡缺少实际状态时先向父代理内部报告，不向用户展示占位语。之后的进展说明用于报告已确认进展、方向变化、风险或下一动作，不构成交付。普通
过程不按时间发心跳，也不发送纯确认。只有中间结果会解锁父代理或队友的下一动作、需要纠偏，
或出现新的权限、安全、来源和写入风险时，才发送一条短内部消息并继续工作。

队友之间只有已知真实目标且证据会解锁对方职责时才直接传递；未核验线索标为假设。不得广播、
索要确认、互相扩派任务、共享凭据或用跨任务消息冒充同一任务内部协作。

## 最终结果

子代理达到成功条件或停止条件后，在自己的线程提交 final；进展说明、内部消息和运行中状态不能
替代。最终回复顶部保留三行实际配置，第一行沿用开场的同一名称标记：

```text
子代理名称：<已按实际路线附（复用）或（新建）的名称>
模型：<实际模型>
思考程度：<实际等级>
```

随后至少说明当前子任务、完成/部分完成/受阻状态、可直接采用的结果，以及决定性证据或剩余
缺口。来源读取任务附 `SOURCE_COVERAGE`。每个子代理独立交付，不建立共享中转文件，也不由一个
子代理冒充其他子代理的结果。

## 父代理采用

父代理派发后立即推进未分配主线、共享热点或集成，只在下一动作真实依赖结果时汇合。工具返回
运行句柄时沿原句柄等待，不把尚未返回当作失败重新派发。新用户要求先更新范围与授权，再处理
迟到结果。

父代理核对关键差异、接口、安全边界和必要验收，不全面重做证据充分的职责。完整来源覆盖且
快照未变时直接复用；只缺一个决定性交付项时补问一次，仍不足则说明未采用原因并处理剩余缺口。

结果被采用后立即继续主任务。只有确有跨任务复用价值时才按需进入
[保留子代理身份与经验](specialist-memory.md)；普通结果不执行固定收口，也不为经验维护启动额外
模型或延迟交付。用户否定结果时停止采用；已写入的经验按保留分支追加纠正，不能回流到后续任务。
