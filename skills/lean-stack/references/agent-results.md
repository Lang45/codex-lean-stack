# 子代理结果与汇合

只在子代理已经启动，准备处理中间消息、最终结果、等待、补问或停止时读取。

## 进展说明和内部消息

子代理第一条用户可见进展说明以任务卡提供的五行开头，第一行名称带实际路线 `（复用）` 或 `（新建）`；保留类型的状态来自成功读取保留子代理，读取失败则由运行时子代理使用自身真实状态开场。任务卡缺少实际状态时先向父代理内部报告，不向用户展示占位语。

子代理执行期间正常说明已确认的进展、当前工作、方向变化、问题及下一动作；持续实现、调查和调试也要及时说明，不能只开场和最终交付。任务卡、阶段或内部消息规则不得要求执行期默认静默，也不能把“父代理尚未询问”当作不说明的理由。相同状态不反复叙述，不用定时心跳或逐条工具流水替代实际进展；这些去重要求不限制正常的途中说明。进展说明不构成交付。

发给父代理或队友的内部消息与用户可见说明分别处理。只有中间结果会解锁对方的下一动作、需要纠偏，或出现新的权限、安全、来源和写入风险时，才发送一条短内部消息并继续工作；普通进展留在子代理自己的可见说明中，不逐条复制到内部消息。

同一活跃切片只补事实或解锁条件时用 `send_message`；确有新增任务需要启动执行时才用
`followup_task`。新增任务先按[委派必要性](../SKILL.md#先判断是否委派再选模型与复用)处理，父工具能直接
完成的统计或核对不因已有子代理而补派。不为纯通知唤醒新任务，也不以发送次数、到达事件或触发请求数推算实际新轮次；
运行回执与 `task_started` 分别核对。消息携带新增结论、接口差异、具名风险及下一消费者，
相同状态不重复抄送，必要风险与协作依赖不受机械次数配额限制。

队友之间只有已知真实目标且证据会解锁对方职责时才直接传递；未核验线索标为假设。不得广播、
索要确认、互相扩派任务、共享凭据或用跨任务消息冒充同一任务内部协作。

## 最终结果

子代理达到成功条件或停止条件后，在自己的线程提交最终回复；进展说明、内部消息和运行中状态不能
替代。最终回复顶部保留三行实际配置，第一行沿用开场的同一名称标记：

```text
子代理名称：<已按实际路线附（复用）或（新建）的名称>
模型：<实际模型>
思考程度：<实际等级>
```

随后至少说明当前子任务、完成/部分完成/受阻状态、可直接采用的结果，以及决定性证据或剩余
缺口。来源读取任务附 `SOURCE_COVERAGE`。每个子代理独立交付，不建立共享中转文件，也不由一个
子代理冒充其他子代理的结果。

内部最终结果优先回传新增结论、精确接口、验证状态、制品定位和剩余缺口；已有工件可承载长
报告时只给必要摘要，消费者按具名缺口读取。只读任务无可写工件时直接给最小充分证据。
用户要求的完整最终交付仍完整保留，不将内部长稿每次整份粘回父线程或再复制给所有队友。

本次验证了可跨任务复用且当前身份尚未承载的具体做法、反例或证据边界时，子代理在同一最终结果中
附一条简短经验候选，写明具体内容、适用范围和证据限制，不要求首次发明算法；“新增”的完整定义与
去重比较以[保留子代理身份与经验](specialist-memory.md)为准。无价值或已承载则省略，不编造、不留空模板、
不为候选另发内部消息，也不自行争写台账。
候选不代表已合格、已采用或已保存，由父代理在下述同一结果采用点消费。

## 父代理采用

父代理派发后立即推进未分配主线、共享热点或集成，只在下一动作真实依赖结果时汇合。工具返回
运行句柄时沿原句柄等待，不把尚未返回当作失败重新派发。新用户要求先更新范围与授权，再处理
迟到结果。

用户取消或收窄会影响既有子任务的外部动作时，先把新边界定向传给受影响执行者，停止尚未开始的
旧动作，并按可恢复方式处理在途工作，再做普通汇总。消息已发送不等于动作已停止；核对实际
停止范围与剩余影响，不据此中止无关工作或破坏必要恢复。

父代理不为普通进度逐条确认、复述或停下主线；需处理的新依赖、纠偏和风险及时处理。父代理自己的用户进展说明继续正常提供，不能以减少父子内部消息为由停止汇报。

父代理核对关键差异、接口、安全边界和必要验收，不全面重做证据充分的职责。完整来源覆盖且
快照未变时直接复用；只缺一个决定性交付项时补问一次，仍不足则说明未采用原因并处理剩余缺口。

父代理同样按增量消费：结果已定位且条件未变时，不整稿复读或重新传完整会话；只核关键差异
与具名缺口。按本次真实接口和风险判断通信收益，不能把总研发用量全部归为消息成本。

核验并采用一个已完成切片或续用增量的最终结果（最终回复或等价结果收据）时，父代理在这个采用点自动完成两项判断，
不等待用户提醒、保留线程结束或整个主任务结束。同一结果已处理后不重复；`followup_task` 调用次数不触发记账：

1. **是否保留能力族。** 本次为运行时角色，且预计以后确实还会遇到同类任务、预计复用收益高于维护和查找负担、没有兼容的现有能力族时，执行现有建档命令；已有兼容身份则复用，不重复建档。
2. **是否保存新增经验。** 消费本次结果附带的经验候选；没有候选也不免除父代理判断。按[保留子代理身份与经验](specialist-memory.md)的新增定义与去重规则核对具体内容，符合条件时写入兼容的已核验身份，必要时接续本次符合条件的建档。对实际候选给出已保存、已有覆盖、不成立或受阻的结论；已保存须经下述回读确认，不以泛化目标代替具体做法。没有合格新增经验则不写，不重复保存旧经验。

符合条件时按[保留子代理身份与经验](specialist-memory.md)的既有权限、身份和 CAS 合同，实际执行相应命令并回读身份或经验结果；只作判断、写建议或声称稍后保存不能代替执行，命令返回也不能代替回读确认。
不符合条件时直接继续主任务，不设固定建档率或配额。写入或回读失败时，在当前可恢复上下文中具名保留失败动作、原因和未确认结果，不声称已保存；故障不阻塞无关主任务，也不建立后台队列、轮询或调度器。
这两项判断是既有结果采用的一部分；完成所需动作或明确失败后继续主任务，不为维护额外启动模型、延长已结束的子任务或重复生成经验，正常用户可见进展和最终交付继续提供。

已完成且采用、验收满足的 Astra
在没有新的要求、证据、未满足验收或明确纠错时停止。只有任务类型、质量门槛、权限或证据边界、
专家必要性、预计成本发生实质变化时才重新选模；同一任务的小补充直接继续，不重复评估。用户否定
结果时停止采用。重新选模先判断当前质量是否仍需 Astra；仍需时再决定续用旧线程或改派兼容 Astra，旧线程
上下文无边际价值不能触发模型降级。已写入的经验按保留分支追加纠正，不能回流到后续任务。
