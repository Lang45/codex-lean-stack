# 成本预估

本文件是维护参考，不是每次主任务重新计算的运行时强制规则。只有 OpenAI 官方模型或费率
发生变化时才更新；没有变化时保持不动。普通主任务直接使用固定预估，维护检查
不是主任务前置条件。

## 当前基线

核对日期：2026-09-05。来源为文末官方页面；这是标准 Codex credits 口径，不是 API 美元账单。

当前选路不把 `gpt-5.6-sol` / `max` 或 `gpt-6-astra` / `ultra` 当成所有子任务的默认值，先按工作价值和任务形状
比较完整可行组合：高价值工作先看决定性质量，普通工作达到质量底线后先看总完成时间，
结果相当时再选总成本更低的路线。当前模型名用于维护基线，不是永久白名单。

复用保留子代理及普通复制时沿用其已有具体配置的前提，是该组合仍适合当前任务；明确的
当前偏好或任务深度变化时允许本次调用覆盖，不为此先持久重配。定制运行时新子代理或变体时，
父代理根据任务类型、工作价值、风险、证据形状、时延要求和总成本，联合选择完整配置。

OpenAI 官方当前每一百万令牌消耗的 credits（标准速度）：

```text
模型             输入    缓存输入    输出
GPT-6 Astra      250     25         1250
GPT-5.6 Sol       100     10          500
GPT-5.6 Terra      50      5          300
GPT-5.6 Luna        5      0.5         30
```

相似令牌形状下可使用的固定快速估计：

```text
Sol：相对成本基线（不规定父代理模型）
Astra：相同令牌形状为 Sol 的二点五倍
Terra：约为 Sol 的一半到六成
Luna：约为 Sol 的百分之五到百分之六
```

这只是调用前判断“新增子代理是否会使总成本大幅增加”的维护估计，不证明任何具体任务
已经省钱，也不要求父代理在运行时重新计算令牌。上下文更小、输出更短或减少返工会降低
实际成本；重复阅读、无效复制、汇合和重试会增加实际成本。

GPT-6 的单价较高不等于整项任务必然更贵；更少输出、调用和返工也可能降低总成本。
`ultra` 是本次 Codex 工具暴露的思考档，不是 Fast；未找到独立的 ultra/MAX 固定费率倍率，
不得把二点五倍写成 ultra 比 MAX 的任务总费用。官方 API 模型页与 Codex 工具暴露的档位
可能不同，运行配置只请求当前运行环境明确支持的组合。本插件不修改用户选择的父代理档位。

OpenAI 当前说明，快速速度档在支持模型上约提高一点五倍速度；GPT-5.6 和 GPT-5.5 在
ChatGPT 额度模式下消耗标准速度档的二点五倍。Astra Fast 在可用时也为标准 credits 的
二点五倍；不能把 5.6 的速度收益外推给 Astra，也不能把 API Priority 费率混入此表。
当前用户指定 Luna 默认快速（高速）；其他模型默认标准速度，只有真实关键路径缩短收益
足以覆盖加价时才选择快速。Luna 默认快速不表示更高思考程度，也不自动升级模型。

## 当前联合配置基线

以下是帮助选路的候选示例，不是实测排名或固定映射；斜线分隔的三个值始终作为整体比较。
表中 Luna、Terra、Sol、Astra 分别指 `gpt-5.6-luna`、`gpt-5.6-terra`、`gpt-5.6-sol`、
`gpt-6-astra`，思考档和速度必须由当前运行环境支持。

| 工作形状 | 可考虑的完整组合与取舍 |
| --- | --- |
| 规格清楚、证据已选定，仍需要短判断 | Luna / low / 快速；仍有局部歧义时可考虑 Luna / medium / 快速，比较核验与返工后的总时间。 |
| 窄范围语义差异或容易核验的局部修复 | Luna / high / 快速与 Terra / medium / 标准均可作为候选；更强模型不必搭配更高思考档。 |
| 多文件因果链、隐含不变量、集成实现 | Terra / high / 标准或 Sol / medium / 标准；按当前未决问题选择，必要时联动调整整个组合。 |
| 多个根因竞争、证据冲突、复杂协议或迁移边界 | Sol / xhigh / 标准或 Astra / high / 标准；先比较决定性证据，再看等待、返工和整合成本。 |
| 额外深层推理可能改变高价值决定 | Sol / max / 标准或 Astra / ultra / 标准等可行组合；需要关键路径加速时，把快速组合与标准组合整体比较。 |

任何路线仍要满足该子任务自己的成功条件。模型能力、思考深度和速度档互相影响，父代理
比较完整组合，允许三个字段同时变化；不能分别按三列分布选择，也不按顺序逐项锁定。
只有明确需要识别某个参数的因果作用时才做单轴受控实验；普通配置选择不强制实验或穷举。
`max` / `ultra` 只在完整任务组合确实需要时选择，不能作为普通工作的比较起点。
用户已经指定 GPT-6 ultra 父代理时，保留该选择，把它用于目标、架构、证据冲突和集成判断；
是否委派仍比较整个任务的质量、时间和成本，不能为少用父代理而过度拆分。

思考程度不能按模型名或角色名固定：高能力模型完成已明确的局部工作仍可以用较低档；便宜
模型面对更多推理链不应只因便宜而固定低档。先根据“尚未解决的问题需要几层关联、是否有
竞争假设、证据能否直接核验”选择完整组合，不要求打分、计算令牌或人为分散档位。
不确定性来自缺失输入、工具不可用或等待编译时，先取得证据，不靠提高思考程度反复猜测。
路线失败后先查明未达标原因，再重新比较完整组合；补证据、换模型、调整思考程度和速度
可以同时发生，不把原因机械绑定到一个参数。只调整受影响子任务，不能把整批升级。
高价值风险已明确时直接选足够配置，不必逐级试错。

Luna 默认快速适用于新选配和省略速度参数的新配置；显式选择标准仍有效，已保存角色的真实
字段保持其原意，修改持久配置必须走 CAS。运行环境不能表达快速时如实说明配置与实际差异，
不得声称仅在任务卡写“高速”就已生效，也不擅自开启全局 Fast。

当前工具的实际边界：`spawn_agent` 提供模型和思考程度参数，没有单次速度参数；自定义角色
是配置层，可以通过 `service_tier = "fast"` 选择快速，该配置映射为请求档位 `priority`。
因此优先复用速度配置匹配的角色；不能把所有临时子代理都说成可在生成参数中独立选速。
配置声明直接列所选值，不反复附请求值/回执括注；配置与实测延迟或计费仍是不同证据。

## 调用前的快速使用方法

- 普通任务在达到质量底线的完整组合中优先总完成时间，结果相当再选更低成本；清晰窄任务
  可先考虑 Luna 快速组合，需要更可靠语义判断时同时比较 Terra 等组合，不强制逐级试错。
- 多个独立普通子任务已经就绪、边界清楚、提交与核验成本轻时，更倾向使用低成本子代理
  并行。第二个及后续调用只需证明能缩短整批完成时间并覆盖轻量额外成本，不要求重复证明
  高价值质量收益。
- 某个低成本子任务未达到自己的成功条件时，只升级或重做该子任务；不预先把整批升级到
  `gpt-5.6-sol`，也不重跑已经通过核验的结果。
- 高价值任务允许为了决定性质量或证据使用更强子代理，但不能仅为重复意见增加成本。
- 复制只用于复制已有任务类型组里的子代理，以并行处理第二个及以后的同类型子任务；先确认
  确有整批加速收益。每个子任务的成功条件由父代理分别指定。
- 每次复制前先判断保留子代理是否确有进步空间；没有就普通复制。确有空间时，父代理按任务
  类型选择完整可行的模型、思考程度和速度组合，可以因相互制约而同时变化。真实结果达到
  自己的成功条件后，再按质量、耗时、返工和总成本判断该完整配置是否值得未来保留。只有
  明确需要识别因果时才使用单轴实验，不能把它当作普通选配规则。
- 出现复制或变体时，主任务接近结束必须先选出组内唯一子代理，再维护经验并结束其他子代理；
  这项收口不能为了省少量成本而省略，也不能在主任务完成后继续等待。
- 可用并发容量不是调用目标；没有边际收益时立即停止下一次调用。
- 预计新增调用会使总成本大幅增加，且没有相应质量或速度收益时，不调用。

## 插件内部每周检查

检查代码位于 `scripts/cost_check.py`。它不是 Codex 自动化、系统定时任务或外部守护
进程，不联网、不计算令牌，也不直接修改插件文件。默认只在
`<CODEX_HOME>/lean-stack/cost-check-v1.json` 保存上次核对时间；状态文件不属于成本预估。

只有维护侧链不会延长主任务关键路径、不会争用必要并发槽位或共享写入时，才做一次本地
到期查询：

```text
py -3 -X utf8 <插件技能目录>/scripts/cost_check.py status
```

- 返回 `fixed_baseline_current`：七天未到，立即停止；不联网、不重新计算。
- 返回 `official_check_due`：只在官方核对能与主任务并行时继续，否则保持到期并延后。
- 不为这项维护单独调用子代理，主任务也不等待状态查询或官方核对。

到期后只核对本文件末尾列出的 OpenAI 官方页面：

- 官方事实没有变化：不修改本文件，只用 `record` 写入新的检查时间。
- 官方模型或费率有变化：先更新本文件中的固定预估，再用 `record` 写入状态。
- 官方页面无法确认、网络不可用或检查失败：不写入状态，保持到期，直接结束维护侧链。

已有状态再次写入时必须把 `status` 返回的当前状态哈希传给
`--expected-state-sha256`；状态已经变化就立即跳过，不能覆盖较新的检查结果。示例：

```text
py -3 -X utf8 <插件技能目录>/scripts/cost_check.py record \
  --expected-state-sha256 <当前状态哈希>
```

首次不存在状态文件时省略 `--expected-state-sha256`。官方来源固定列在下方，不由状态
文件重复保存。状态文件异常、链接到别处、并发变化或写入失败时安全跳过，不阻塞主任务。
旧版插件已经写入的官方指纹和来源字段只按旧版精确结构兼容读取；下一次合法 `record`
会自然归一为当前的版本号和核对时间两个字段，不需要手工删除状态文件。
