# 成本预估

本文件是维护参考，不是每次主任务重新计算的运行时强制规则。只有 OpenAI 官方模型或费率
发生变化，或用户明确更改成本策略时才更新；没有变化时保持不动。普通主任务直接使用固定预估，维护检查
不是主任务前置条件。

## 当前基线

核对日期：2026-09-12。来源为文末官方页面；下面原有表是标准 Codex credits 口径，
API 美元价格单独列出，不混用两种账单或把单价比例当作整项任务节省。

### API 美元基线

用户指定的官方 API pricing 页面当前 Standard / Short context 每百万 token 价格：

| 模型 | 输入 | 缓存输入 | 缓存写入 | 输出 |
| --- | ---: | ---: | ---: | ---: |
| gpt-6-astra | $10 | $1 | $12.50 | $50 |
| gpt-5.6-sol | $4 | $0.40 | $5 | $20 |
| gpt-5.6-terra | $2 | $0.20 | $2.50 | $12 |
| gpt-5.6-luna | $0.20 | $0.02 | $0.25 | $1.20 |

相同档位、上下文类别与 token 形状下，Sol 为 Astra 的 40%（单价降低 60%）；
Terra 约为 20%–24%，Luna 约为 2%–2.4%。Long context 的输入、缓存输入及缓存写入为短上下文
两倍，输出为一点五倍；
不据此猜测当前任务计费类别、token 用量或账户实际结算。
Sol 的促销价格官方注明至少持续到 2026-11-21，之后维护核对再更新。

### 模型与思考程度的价格参考

四模型选择、专家例外和任务级 `MODEL_ROUTE` 的唯一规则见
[四模型一次联合选配](execution-routing.md#四模型一次联合选配)；本文件只维护价差和配置候选。
本表只比较模型与思考程度可见的价格证据，帮助在质量充分的组合中选择与任务相称的成本。其他
执行细节按各自规则处理，不形成新增调用的第二套判断轴。是否调用仍直接回答：模型与思考程度
是否联合达到必要质量、质量充分组合的成本是否相称、委派是否对父任务实际完成速度有正贡献。

单价只支持选配，不证明某次任务已经省钱或加快。调用数量本身也不是成本结论；多个调用只要
分别通过三项原则就可同时成立，不能把“调用更多”直接标成浪费。

### Codex credits 基线

当前选路不把 `gpt-5.6-sol` / `max` 或 `gpt-6-astra` / `xhigh` 当成所有子任务的默认值；当前
模型名用于维护基线，不是永久白名单。父代理按任务形状从完整可行组合中执行
**质量 → 成本 → 时间** 的联合选择。

复用保留子代理及普通复制时，以其 TOML 中的已有具体配置作为选择值的前提，是该组合仍适合
当前任务；父代理仍在每次 `spawn_agent` 显式传入模型与思考程度。若当前偏好或任务深度变化，
不临时覆盖保留 TOML，改用合规保留子代理或显式配置运行时子代理。定制运行时新子代理或变体时，
父代理根据任务类型、工作价值、风险、证据形状和推理深度，联合选择模型与思考程度。

OpenAI 官方当前每一百万令牌消耗的 credits 基线：

```text
模型             输入    缓存输入    输出
GPT-6 Astra      250     25         1250
GPT-5.6 Sol       100     10          500
GPT-5.6 Terra      50      5          300
GPT-5.6 Luna        5      0.5         30
```

相似令牌形状下可使用的固定快速估计：

```text
Sol：相对成本基线（不规定父代理模型）
Astra：相同令牌形状为 Sol 的二点五倍
Terra：约为 Sol 的一半到六成
Luna：约为 Sol 的百分之五到百分之六
```

这只是模型与思考程度选配的维护估计，不证明任何具体任务已经省钱，也不要求父代理在运行时
重新计算令牌。

GPT-6 单价较高；只有相对最强可行 GPT-5.6 存在决定性质量差距时选择 Astra。
`ultra` 是本次 Codex 工具暴露的思考档；未找到独立的 ultra/MAX 固定费率倍率，
不得把二点五倍写成 ultra 比 MAX 的任务总费用。官方 API 模型页与 Codex 工具暴露的档位
可能不同，运行配置只请求当前运行环境明确支持的组合。本插件不修改用户选择的父代理档位。

## 当前联合配置基线

以下是帮助选路的候选示例，不是实测排名或固定映射；斜线分隔的两个值始终作为整体比较。
表中 Luna、Terra、Sol、Astra 分别指 `gpt-5.6-luna`、`gpt-5.6-terra`、`gpt-5.6-sol`、
`gpt-6-astra`，模型和思考档必须由当前运行环境支持。

| 工作形状 | 可考虑的完整组合与取舍 |
| --- | --- |
| 规格清楚、证据已选定，仍需要短判断 | Luna / low；仍有局部歧义时可考虑 Luna / medium，以能守住质量的相称思考程度为准。 |
| 窄范围语义差异或容易核验的局部修复 | Luna / high 与 Terra / medium 均可作为候选；更强模型不必搭配更高思考档。 |
| 多文件因果链、隐含不变量、集成实现 | Terra / high 或 Sol / medium；按当前未决问题选择，必要时联动调整整个组合。 |
| 多个根因竞争、证据冲突、复杂协议或迁移范围 | Sol / xhigh 或 Astra / xhigh；选择能守住决定性质量的合适模型和相称思考程度。 |
| Sol 执行中遇到有实际输入、困难点和验收点的专家难题 | 在 Astra 相对最强可行 GPT-5.6 能提供决定性质量时，可把范围明确的困难切片交给 Astra / xhigh 等可行组合协助解决或验证；不限于视觉领域，也不以笼统的“很难”自动升级。 |
| UI 设计、图片、三维模型、渲染或其他视觉工作出现需要专家帮助的难题 | Sol 父代理可把明确视觉难题交给 Astra / xhigh 等可行组合；传入实际材料和验收点，只处理该切片。最终评审或验收是常见辅助场景，视觉任务本身不触发。 |
| 额外深层推理可能改变高价值决定 | Sol / max 或 Astra / xhigh 等可行组合；只有 Astra 相对最强可行 GPT-5.6 有决定性质量差距时才用 Astra，Astra 子代理不超过 xhigh。 |

任何路线仍要满足该子任务自己的成功条件。父代理比较模型与思考程度的完整组合，允许两个
字段同时变化；不能分别按两列分布选择，也不按顺序逐项锁定。
只有明确需要识别某个参数的因果作用时才做单轴受控实验；单轴实验不能取代联合选配，普通
配置选择不强制实验或穷举。
Sol `max` 可按完整任务组合的实际需要选择；Sol `ultra` 只用于高价值复杂边界，且必须具体说明
`xhigh` 与 `max` 都不足，不能作为普通工作的比较起点。Astra 子代理仍最高 `xhigh`。
用户已经指定 GPT-6 ultra 父代理时，保留该选择，把它用于目标、架构、证据冲突和集成判断；
是否委派仍按质量、成本、时间判断，不能为少用父代理而过度拆分。

思考程度不能按模型名或子代理名固定：高能力模型完成已明确的局部工作仍可以用较低档；便宜
模型面对更多推理链不应只因便宜而固定低档。先根据“尚未解决的问题需要几层关联、是否有
竞争假设、证据能否直接核验”选择完整组合，不要求打分、计算令牌或人为分散档位。
不确定性来自缺失输入、工具不可用或等待编译时，先取得证据，不靠提高思考程度反复猜测。
路线失败后先查明未达标原因，再重新比较完整组合；补证据、换模型和调整思考程度可以
同时发生，不把原因机械绑定到一个参数。只调整受影响子任务，不能把整批升级。
高价值风险已明确时直接选足够配置，不必逐级试错。

## 调用前的快速使用方法

- 普通任务选择能达到质量底线的模型，并让思考程度与实际推理深度相称。清晰窄任务可先考虑
  Luna 标准组合，需要更可靠语义判断时同时比较 Terra 等组合，不强制逐级试错。
- 多个独立普通子任务已经就绪、范围清楚时，逐个判断其模型能否守住质量、思考程度是否相称，
  以及是否实际加快父任务完成。符合时可以并行，不因调用数量增加而否定。
- 某个低成本子任务未达到自己的成功条件时，只升级或重做该子任务；不预先把整批升级到
  `gpt-5.6-sol`，也不重跑已经通过核验的结果。
- 高价值任务允许为了决定性质量或证据使用更强子代理，但不能仅为重复意见增加成本。
- 复制只用于复制已有任务类型组里的子代理，以并行处理第二个及以后的同类型子任务；先确认
  确有整批加速收益。每个子任务的成功条件由父代理分别指定。
- 每次复制前先判断保留子代理是否确有进步空间；没有就普通复制。确有空间时，父代理按任务
  类型选择完整可行的模型与思考程度组合，可以因相互制约而同时变化。真实结果达到
  自己的成功条件后，再按模型适合性、思考程度相称性和实际提速判断该完整配置是否值得未来保留。只有
  明确需要识别因果时才使用单轴实验，不能把它当作普通选配规则。
- 出现复制或变体时，主任务接近结束必须先选出组内唯一子代理，再维护经验并结束其他子代理；
  这项收口不能为了省少量成本而省略，也不能在主任务完成后继续等待。
- 三项原则成立时，为提高父任务完成速度，可使用实际并发容量多派子代理；每次新增调用仍须
  有对应的质量、成本和时间收益依据。
- 子代理不能实际加快父任务完成时不调用。

## 执行效率边界

下面规则用于已经选择路线后的高效执行，不参与新增调用的三项根判断。工具结果字符数和日志中
的估计 token 不等于账户结算，重复记录也不等于重复推理，不为每次调用重新估账。
优先在工具侧提取字段、限制输出，相关读取合批；状态问题先用紧凑状态接口，不能默认读取
大段任务历史。实体名称先与身份逐项对应，再下结论，避免错误归因引发二次全量调查。
普通子代理无需发送重复内部配置声明或再把最终结果发一遍；内部交流只服务真实依赖、
必要纠偏、风险和阻断。用户可见开场、进展与最终交付仍保留，不能以内部节省为由静默工作。
commentary-only 的中间进展不构成可采用交付，必须有明确最终回复或收据；若只剩具体缺口，
只做一次明确补问，否则关闭或改路，不全面重做。父代理仍保留用户互动、共享热点、整合和必要验收。

## 插件内部每周检查

检查代码位于 `scripts/cost_check.py`。它不是 Codex 自动化、系统定时任务或外部守护
进程，不联网、不计算令牌，也不直接修改插件文件。默认只在
`<CODEX_HOME>/lean-stack/cost-check-v1.json` 保存上次核对时间；状态文件不属于成本预估。

只有维护侧链通过三项原则、不会争用必要并发槽位或共享写入时，才做一次本地
到期查询：

```text
py -3 -X utf8 <插件技能目录>/scripts/cost_check.py status
```

- 返回 `fixed_baseline_current`：七天未到，立即停止；不联网、不重新计算。
- 返回 `official_check_due`：只在官方核对能与主任务并行时继续，否则保持到期并延后。
- 不为这项维护单独调用子代理，主任务也不等待状态查询或官方核对。

到期后只核对本文件末尾列出的 OpenAI 官方页面：

- 官方事实没有变化：不修改本文件，只用 `record` 写入新的检查时间。
- 官方模型或费率有变化：先更新本文件中的固定预估，再用 `record` 写入状态。
- 官方页面无法确认、网络不可用或检查失败：不写入状态，保持到期，直接结束维护侧链。

已有状态再次写入时必须把 `status` 返回的当前状态哈希传给
`--expected-state-sha256`；状态已经变化就立即跳过，不能覆盖较新的检查结果。示例：

```text
py -3 -X utf8 <插件技能目录>/scripts/cost_check.py record \
  --expected-state-sha256 <当前状态哈希>
```

首次不存在状态文件时省略 `--expected-state-sha256`。官方来源固定列在下方，不由状态
文件重复保存。状态文件异常、链接到别处、并发变化或写入失败时安全跳过，不阻塞主任务。
旧版插件已经写入的官方指纹和来源字段只按旧版精确结构兼容读取；下一次合法 `record`
会自然归一为当前的版本号和核对时间两个字段，不需要手工删除状态文件。

成本记录持有非阻塞内核锁，空载体保持不变且不在释放后删除。POSIX 额外锁定已验证的包含
目录，因此仅 rename/替换锁载体不能让第二个新版记录者进入比较写入区。Windows 仍使用
字节范围锁。正常异常退出均释放内核锁，但释放锁不等于未完成状态写入具备断电恢复能力。
并发写入者必须使用相同协议；包含目录必须保持稳定。目录替换、网络文件系统和同时运行的
旧版写入器不在本保证内。持有锁的外部进程不能被本插件按 PID 或超时猜测后强杀。
