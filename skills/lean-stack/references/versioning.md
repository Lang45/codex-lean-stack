# 插件版本

仅在插件公共行为变化，或本地安装确需新缓存身份时使用。版本工作不属于普通分派。

- 向后兼容的新行为：提升次版本。
- 向后兼容的缺陷修复：提升修订版本。
- 删除或破坏公共兼容性：提升主版本。
- 文档、测试、格式化和不改变公共行为的内部重构：默认保留数字版本。

`+codex.<标识>` 只标识一次安装构建，不能替代数字语义版本决定。

每次提交并推送新版本前，先用一至三条简短说明记录该版本新增或改变的用户可见行为，不用
测试数量、提交过程或泛化宣传代替行为结果：

- `CHANGELOG.md` 顶部新增数字版本和日期，保留本版摘要；不为补齐历史重建长日志。
- `README.md` 的“当前版本”只保留最新摘要，并与插件清单
  `description`、`interface.shortDescription` 和 `interface.longDescription` 同步。
- `interface.shortDescription` 改变时同步技能 `agents/openai.yaml` 的
  `short_description`；稳定入口提示和无关元数据不随版本说明改写。

完成版本写入后，核对 `CHANGELOG.md` 首个版本、README 当前版本和插件清单可见说明中的
数字版本均与 manifest 的数字版本一致；任何一处仍为旧版本时，不提交或推送。没有新的用户
可见行为时如实写明文档或内部变化，不编造功能。

## 型号更新与专属纠错退出

维护父代理在更新可调用型号、默认操作者或受管身份时执行；实际消费者是本发布流程、
`agents.py ensure` 的兼容规范化与同身份 CAS，以及 SKILL、派发任务卡、结果采用和内置提示。

- 先核对当前宿主真实支持的型号、思考档和已加载类型。旧调用参数规范化到经核验的可用配置后
  继续处理；保留身份、权限、速度、经验和历史，不能把拒绝旧调用或留下不可调用台账当成更新完成。
  已加载旧线程不冒充新配置，涉及身份变更时用新进程回读，并按受影响路线取得实际调用及完成回执。
- 型号移出当前路线时，同一更新清理该型号的专属纠错及全部直接消费者，不只改型号字符串。
  对 6.2，清单由[6.2 调用防错](dispatch-start.md#62-调用防错)承载：入口触发及完整附加句、
  派发专属节与任务卡引用、结果返回与父采用引用、内置提示与 README 摘要及专属合同断言一起退出；
  通用证据、安全和数据保护回归保留。历史记录和迁移来源仍可读取，不因此清除用户经验或身份。
  最后一款 6.2 退出后，本流程中的 6.2 清单与链接也移除，包含下条单款/末款退出分支和补偿说明等
  本节全部 6.2 专属句；保留本节通用更新要求。
- 后继型号只按其当前证据建立必要纠错，不自动继承 6.2 的停等、表达、审查或视觉补偿；
  仅移除一款 6.2 时缩小适用集合，最后一款退出时移除整套 6.2 专属附加指令。
- 发布前沿上述实际消费者核对无失效引用、无过期触发，验证非目标型号不会收到退役的专属载荷，
  通用保护仍有现行消费者；正式安装后用独立新任务验证受影响的自然调用路线。

这是一项随模型更新执行的维护合同，不新增全局调度器、Hook 或后台迁移，也不因一次模型失败
永久限制后继型号。Computer Use 的父代理指导、单操作者和权限边界是通用分工；更新执行型号时
保留分工并同步切换全部入口，不能把旧型号的专属纠错继续套用到新操作者。

## 正式宿主行为验收

若本版改变子代理调用决策，而且要声明正式安装后的新会话调用路线已经生效，则源码与静态规则通过后仍须：

- 先完成获授权的正式安装，再在全新项目目录创建独立父代理任务；
- 核对隔离宿主实际可用的协作工具代际与主动委派条件，使其匹配待验入口；默认模型、思考档或
  只返回固定值的已弃用字段不证明等价。用当前二进制公开协议和有效配置取证，不为达到人数擅改
  用户全局设置，也不把不具备主动委派条件的零派发归因为插件或容量限制。
- 不向验收任务传入或让其读取源码项目的本地任务资料、原会话摘要、源码候选规则或人工策略
  摘录，只允许它使用自动加载的全局入口和正式安装缓存；
- 先以一个短确定性工具任务观察父代理直接处理且不委派，再以改变任务形状、包含多个互不依赖且
  需要持续模型判断切片的新要求，观察大块工作前的真实 `subAgentActivity` 或等价原生调用记录；
- 子代理调用探针必须从原生调用记录核对显式 `fork_turns="none"`；运行时角色另核实际 `model`、
  `reasoning_effort`，固定保留角色核对 `agent_type` 和宿主已加载配置且未传禁止的覆盖参数。模型选配先服从用户明确指定，其余符合当前任务的 Astra 与 Sol `ultra` 边界。核对子线程第一条用户可见
  进展说明在首个业务工具前独立发出、以任务卡五行开头，最终回复顶部完整展示五行配置与状态；读取保留子代理失败时改派运行时子代理，以“存活轮次：0”“经验：本次任务上下文”开场。宿主未显示进展说明时单独记录 UI 缺口，并用原生调用回执
  核对实际配置。参数不符即判定调用验收失败。全部符合后立即停止，不等待或要求子代理
  完整做题；控制者只通知独立父任务，由父代理用 `collaboration.interrupt_agent` 停止自己的子代理，不直接向 multi-agent v2
  子代理发送 `send_message_to_thread` 输入；
- 环境硬阻断只把该次行为验收记为未完成，不能用阻断说明、静态关键词或当前会话手工加载候选
  文本替代真实派发；该探针只证明调用选择和调用面可用，不证明业务质量、完整交付或其他功能，
  静态发布一致性与调用验收分别记录。

没有用户明确授权创建独立任务或正式安装时，只交付已完成的源码与静态证据，并明确新会话行为
尚未验收；不能为满足这条规则自行扩权。

公共行为确定、当前风险所需的语义复核和相关检查完成后，使用完整旧版本作为比较并
交换前置条件，只运行一次版本写入器：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\bump_plugin_version.py <plugin-root> `
  --change feature `
  --expected-version "1.1.0+codex.previous"
```

前置条件防止重试时重复升版。运行后不得再调用第二个缓存刷新工具。

父代理直接运行受影响测试、官方技能校验、插件校验和差异检查；多个短检查可在一次
工具调用中并发。本地重装需要当前用户明确授权；只有获准后才只重装一次，再核对安装状态、
版本、源文件集合和哈希。仅授权升版、提交或推送时不自动重装，交付时注明缓存尚未刷新。
用户已明确授权修改全局默认调用指令时，才使用本插件的辅助安装入口完成重装和单行激活：

用户明确给出项目内逐轮升版、推送和重装的持续授权时，在交接记录适用范围，并于每轮有改动
且验证完成后执行；同轮已交付发布或纯查询不重复操作。持续授权不自动扩大到其他项目、
全局用户文件或应用重启。用户明确要求每轮升版时，纯文档改动也升修订版本。

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\install_plugin.py --marketplace personal
```

它先核对市场名、唯一插件条目、当前源码根和实际生效全局指令文件的安全前置条件，并在同一把文件锁内
执行正式 `codex plugin add` 与成功后的幂等单行写入；已知前置错误不会先安装插件，安装失败
也不触碰全局指令文件。辅助安装器把显式 `--codex-home` 同时传给安装子进程，优先更新非空
`AGENTS.override.md`，否则更新 `AGENTS.md`；保留未选中文件、原有编码和换行，不把围栏代码或
注释中的示例认作激活指令。安装过程中生效文件改变时报告未完成激活，不伪报成功。
只授权更新插件时使用普通安装命令，不修改全局文件。新任务负责
加载新技能和专门代理表面，不需要重启 ChatGPT。

安装器只允许补写下列默认调用指令；现有用户文件已含下列句子或用户明确的
“必须调用已安装的 `codex-lean-stack` 插件。”时视为满足，不重复追加、不改写原句：

```text
所有模型和思考程度的父代理必须使用已安装的 `codex-lean-stack`；两个入口按需读取，入口保留快速判断，确认命中后才读取对应功能分支，选配与协作细节由插件维护。
```

安装与版本写入器使用与成本维护相同的非阻塞进程锁。新协议的空锁载体有意保留；正常退出、
异常退出或进程被终止后由内核释放锁，不以文件存在判断忙，也不按 PID、年龄自动删除载体。
旧版留下的非空占用标记继续安全拒绝，必须在确认旧维护进程已停止后按明确授权处理，不能自动
抢占；混用旧新写入器不在并发保证内。POSIX 同时锁定保持稳定的包含目录，防止仅替换锁文件
导致多个锁身份；目录本身被外部替换、网络文件系统和安装子进程的中断恢复需要单独验证。
三个独立脚本通过同目录的 `_maintenance_lock.py` 共享实现，分发时须保留该文件。

安装和升版写入已有文件时共同使用 [`_atomic_file_update.py`](../scripts/_atomic_file_update.py)，
分发两个脚本时也须保留它。Windows 本地卷通过原生替换捕获上一对象，Linux 本地卷通过原生
交换保留上一对象；成功回执的 `previous_path` 指向该恢复制品，升版恢复目录位于源码根的父目录，
不进入源码包。当前检查覆盖 Windows NTFS 与 Linux 本地文件系统；原生捕获能力不支持时明确
保留原件并拒绝，不降级为可能静默覆盖的普通替换。

这不是通用的字节比较交换。捕获的旧对象若与预检内容、身份或受保护权限不同，目标可能已经
发布；错误会明确说明该状态与恢复路径，不自动回滚覆盖后来的第三方保存。原生部分失败或进程
中止后按 `operation.json` 中的目标及摘要核对原件、候选和当前文件，再决定恢复，不能原样盲重试。
用户指令文件缺失且对应恢复目录仍有原件与未发布候选时，安装器会在选择 base/override 或安装
之前报告恢复缺口，不把它当首次创建。正式辅助安装仍须当前用户对准确全局指令变更的授权。

辅助安装器识别段落内跨行代码跨度，示例不算有效规则，补入位置不进入原文的代码或注释块；
原有编码、换行和 YAML 前置区字节继续保留。已知的单链接或平台阻断在调用安装命令前预检，
真正发布前再次核对。恢复制品按准确对象保留或走既有回收合同，不把它们作为源码或自动清理。

Windows 上本插件脚本和官方校验器都必须由 `py -3 -X utf8` 启动。即使当前 PowerShell、
Codex 或父 Python 进程使用 GBK，也不能让子进程依赖默认编码读取 UTF-8 中文 `SKILL.md`；
由 Python 包装启动时还应给子进程设置 `PYTHONUTF8=1`。这条限制不能用切换控制台代码页代替。

提交、推送、公开发布或外部消息仍需要用户授权；版本提升不提供这些权限。
