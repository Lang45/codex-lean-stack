# 子代理委派

首次实际委派前读取，当前上下文复用。父代理负责选路、共享状态、整合和最终声明；本文件
承载任务说明、通信、复制与收口细节，服从技能正文中的一次调用判断，不重复增加门槛。

## 当前调用快路

本技能适用后，父代理必须使用插件的一次调用判断，不套用官方默认调用触发规则，也不等待
用户重复要求子代理、委派或并行。只要当前权限内存在一个已就绪、边界明确、可安全独立
推进、需要持续模型判断，并且具有符合三原则的收益，就立即调用；收益包括必要质量提升，或
质量达标时的全任务总成本优势；成本相近时才比较总完成时间；
每个新增调用都按新的边际收益和实际容量判断。
父代理正向寻找能替代自己实际阅读、实现或分析工作的切片；完整的复杂高价值实现、分析和
自检也可以成为一个子任务，不把子代理限定为边角工作、只读审查或最终复核。

固定成本预估阻止“总成本大幅增加且没有必要质量收益”的路线。收益是基于任务
形状的合理预期，不需要数值评分或精确证明。对收益不确定但可低成本并行核实的只读任务，
可以先调用一个有界子代理消除不确定性。边界清楚、重复、短输出、容易核验的普通子任务
优先使用 `gpt-5.6-luna`；仍需可靠语义判断但不属于高价值边界时优先使用
`gpt-5.6-terra`。多个独立普通子任务已经就绪且提交、核验成本轻时，更倾向低成本并行；
只有当前低成本子任务未达到自己的成功条件时才单独升级，不预先升级或重跑整批。
复杂高价值任务可直接由 `gpt-5.6-sol` 端到端完成；Astra 只在有额外决定性质量，或能通过
减少返工、token 等降低全任务总成本时考虑，不能只凭更快。这三种 GPT-5.6 模型是通常候选，
不设置逐级试错或固定档位。

### 持续多工作流任务的早期派发

持续的多工作流任务一旦出现多个互不依赖、已就绪且能替代父代理实际研究、实现或验收的
切片，父代理就为全部当前有收益且互不冲突的 GPT-5.6 切片分别编写任务卡并尽早派发。派发须在
父代理深入读取额外来源族或开始实现前发生；只在后期增加一次复核不能替代前面的实际工作。

调用数量随真实工作流、边际收益与运行容量变化，不设最低数量，也不要求逐片量化节省；无法
精确量化本身不能否决调用。输入未就绪、严格依赖、权限不足、写入冲突无法隔离、重复已有工作、
运行环境容量不足，或新增调用显著增费且没有必要质量收益等明确阻断才停止相应派发。父代理
保留交接全文、关键约束、共享热点、整合与必要验收；新要求改变工作流时立即重新判断。

只有以下情况阻断当前调用：

- 确定性工具可以更快完成；
- 输入或真实前置条件尚未就绪；
- 权限不足，或写入冲突无法分界和隔离；
- 只会重复已有工作，不能增加必要质量、证据或降低全任务总成本；
- 总成本会大幅增加且没有必要质量收益；
- 启动后只能等待，不能完成真实任务。

任务类型组、已有保留子代理、任务类型是否稳定、持久创建、经验维护和父代理是否另有
不重叠工作，都不是当前调用前置条件。

父代理先判定当前工作的具体任务类型。确认本次应调用之后，判断这个具体任务类型是否适合
已有任务类型组，不提前判断稳定性；适合时立即复用组，不适合时先开新运行时任务类型组。
只有任务类型和任务类型组都确定后，才检查可见的保留子代理，并复用它或定制运行时新
子代理；此前不得选择模型、思考程度、速度或权限配置。当前任务先完成，真实结果出来后才
判断新任务类型是否稳定、是否能泛化为跨任务、跨项目、跨会话复用的全局领域任务类型组。
项目或插件专属组不能原样持久化，无法形成领域合同就只完成本轮工作。

## 协作父代理路线

普通子任务保持平面委派。一个已授权子项目本身还有多个已就绪、可独立核验且互不重复的
切片，并且局部协调能降低全任务总成本或增加必要证据时，整合父代理才在任务说明中写明
`协作角色: 协作父代理`、`允许下游委派: 是` 和有限下游范围。协作父代理相对整合父代理仍是
子代理；它只有真实拥有顶层 `collaboration.spawn_agent` 时，才在获批子项目内分派下游。
下游子代理分别收到规范任务名、来源快照、权限、成功条件、停止条件和有限关键步骤，也分别
提交自己的最终结果。协作父代理可以核验并整合自己的子树，不能压掉、改写或冒充下游结果。

协作父代理没有真实工具、没有容量、边界不清或写入无法隔离时立即停止下游委派并报告；整合
父代理改走平面路线或直接完成。不能用共享文件、缓存、日志、`send_message_to_thread` 或
其他跨任务 API 建立横向通信，也不能让子代理自行扩大授权或生成无界后代。

当前用户已为调用其他或新建 Codex 父代理任务建立持续授权。符合三项原则、服务当前主任务、
边界清楚且不涉及未获明确要求的永久删除时，父代理可直接使用 `read_thread`、`create_thread`、
`wait_threads` 和 `send_message_to_thread`，不再重复询问，并指定唯一整合父代理。跨任务消息
是用户可见操作，不是内部 `collaboration.send_message`；持续授权不覆盖外部人员、发布、部署
或无关系统。

完整任务卡、普通任务堵点、`BLOCKED`、`SUBTREE_HANDOFF`、接管和协作安全边界见
[协作父代理与父代理之间](collaboration.md)。

## 任务类型组、复制、变体与保留子代理

同一种活按可复用能力族判断，不按当前动作动词或产物标题逐字判断。同一能力族中的调查、
诊断、实现、修复、测试或验收，只要角色允许的工具、写入权限、安全风险和决定性证据形状
兼容，就归入同一组；项目、仓库、框架、文件名、一次性成功条件、交付名称或配置档位变化
不另建窄组。工具、权限、风险或证据形状任一决定性边界不兼容且能独立复用时才建立不同组，
不能只因属于同一主任务、仓库或功能而合并，也不能借范围放宽让只读角色实施写入。成功条件
不参与归类，而是由父代理为每个子任务分别指定；权限边界也逐个子任务指定并安全执行。父代理
先判定具体任务类型，每个任务类型建立一个任务类型组。建组只是组织已决定调用的运行时工作，
不是调用门槛。父代理确认调用后，
先按“同一种活”确定任务类型组；任务类型组确定前禁止复用或定制子代理：

- 适合：立即复用组的任务类型说明，再检查可见的保留子代理。有则立即复用；没有则为当前
  子任务定制运行时新子代理。当前子任务的输入、成功条件、父代理规范任务名和权限仍由父代理
  单独指定。
- 不适合：开一个新的运行时任务类型组，并为当前任务定制运行时新子代理。

复用保留子代理时，父代理只传入当前子任务的输入、边界、成功条件和父代理规范任务名。保留
子代理从自己的配置读取既有经验、模型、思考程度和速度并自行声明；父代理不重复注入经验，
也不强制重写已有配置；当前任务深度或用户明确的速度、期限要求确有变化时，按主技能的配置适配规则
只覆盖本次调用，无法覆盖时使用同组自包含运行时子代理，不先持久重配。定制新子代理时，父代理根据任务类型、工作价值、风险、证据形状、
时延要求和总成本，联合选择并写入 `模型 + 思考程度 + 速度` 的三个具体值。两条路线都要求
子代理在当前子任务的 commentary 公开完整四行，并在最终回复顶部重复实际配置；普通任务
不向父代理重复发送相同四行，也不索要确认。
运行时定制不是持久创建，不调用 `ensure`，不等待重新加载或新任务。
父代理保持用户选定的配置，并在派发后负责约束、冲突、必要核验和整合；子代理证据充分时
不全面重做其实现或分析。
新选配默认标准速度，包括 Luna；只有当前用户明确速度或期限要求，且完整路线有收益时才用
快速。已有显式快速配置保留真实值；复用不适配时只调整本次调用，不批量重配。

运行时组可以使用当前项目的实际文件和专属名称；全局领域保留组不能。领域角色可以只服务
QML、媒体编码、插件、检索等一类工作，不要求适用于所有技术栈，但必须能在另一个同领域项目
和会话中复用。父代理把当前项目名、插件名、个人技能名、路径、版本、固定文件清单和一次任务
事实留在任务说明里；持久化前生成领域、输入形状、通用职责、交付与硬边界组成的合同。

`spawn_agent` 当前没有逐个工具授予参数，内部消息也不是可臆造的 MCP 工具。自定义角色 TOML
只能收紧子线程，不能替父会话打开多代理或改写模型目录。只有子任务真正需要中途内部消息时，
父代理才在首次选配前核验多代理能力，并核验实际模型目录支持该能力；只启用会话 v2 开关不能
让目录仍为 v1 的 Luna 子线程获得协作工具。
保留 TOML 使用 `[skills] include_instructions = false` 缩小窄角色上下文。目录不是 v2 或直接
内部调用失败而中途交流必需时，停止该子任务并报告运行环境缺口；不能升级模型或增加成本，
也不能用跨任务 API 冒充。已知 Luna 目录仍为 v1 或缺少中途内部通道时，只分配无需纠偏和
队友依赖的自包含工作；需要中途协作的就绪任务在首次选配时使用具备实际能力的 GPT-5.6
组合，不先启动已知不适用路线再升模，也不为此修改模型目录或全局配置。

父代理根据任务类型决定权限：实现、修复、测试或天然分离的文件可以使用可写权限；调查、
审查、来源核对、日志或历史读取保持只读。任何子代理都不能超出用户授权。

### 复制

复制的是任务类型组里的子代理，不是任务类型组。复制只用于同一任务类型的多个已就绪
子任务，并须降低全任务总成本、提供必要质量收益，或在成本相近且用户有当前期限要求时缩短
整批完成时间；它不是新建另一种任务类型，也不是为了重复读取同一
子任务：

1. 第一个子任务交给已有任务类型组里的保留子代理；没有可见保留子代理时，交给父代理为
   该组定制的运行时新子代理。
2. 父代理还要并行处理第二个同一任务类型的子任务时，复制组内已经处理第一个子任务的
   基准子代理，并把第二个子任务及其单独成功条件交给这个复制。
3. 还有第三个同一任务类型的子任务时，继续复制组内基准子代理；后续依此类推，直到没有
   新的已就绪子任务、实际容量已满或新增复制不再符合上述收益。

例如同时读取三个会话记录：第一个会话由已有“会话记录读取”任务类型组里的子代理处理；
第二个和第三个会话分别由该子代理的两个复制处理。三个子代理仍属于同一个任务类型组，
但父代理分别为三个子任务指定来源边界、成功条件和权限边界。每个子代理完成并自检后，
立即在自己的线程用最终回复提交自己的精炼结果，不能只选其中一个，也不能先由子代理合并。

复制已有保留子代理时，每个复制都读取该保留子代理自己的配置和经验并自行声明；父代理
只提供各自不同的当前子任务和成功条件。复制不创建新的持久任务类型组或 SQLite 记录。

### 变体

变体只发生在复制任务类型组里的子代理时。每次复制前，先判断现有保留子代理是否确有
进步空间：

- 没有明确进步空间：保持普通复制，完整沿用保留子代理的配置和经验。
- 确有进步空间：由父代理根据同一任务类型选择一个完整可行的替代方案。模型、思考程度和
  速度是互相制约的联合配置，可以同时变化；方法、来源或权限边界若变化也必须显式写清。
  子代理不能自行决定配置或扩大权限。

变体仍要完成其分配到的当前子任务。真实结果出来后，父代理先比较质量和决定性证据；达标后
比较返工与全任务总成本，成本相近才比较完成时间，再判断是否优于保留配置。单轴变化只在明确需要识别因果时
作为可选实验方法，不是普通配置选择门槛。

### 竞争收口

只要本组出现过复制或变体，就在本组当前已就绪子任务的结果全部返回并完成必要核验后启动
竞争。竞争覆盖同一任务类型组里的保留子代理、全部普通复制和全部变体；各子任务先按照
父代理分别指定的成功条件完成核验，再以可比较证据竞争：

1. 每个子代理先在自己的线程用最终回复提交已经自检的精炼结果；父代理分别核验和使用。
   竞争不删除、合并、延迟或替换这些合格结果。
2. 再比较完成质量和决定性证据；达标后比较返工与全任务总成本，成本相近才比较整批速度，
   判断哪个子代理或完整配置组合最适合
   未来继续承担该任务类型。
3. 先选出一个胜者，确定它是组内唯一留下的子代理。
4. 结果通过必要核验并被采用后，先审核全局领域合同；合同通过才默认只尝试一次 `ensure`，
   让唯一子代理的配置跨任务、跨项目、跨会话保留。不能泛化或不能立即安全写入时跳过。
5. 再默认把胜出方法和其他子代理中的失败避免信息泛化、去敏、去重，使用稳定 `event_id` 通过一次
   `improve` 合并追加为一条经验；只有没有新增可复用内容或命中明确排除项时跳过并写明原因。
6. 经验维护完成或跳过后，其余运行时复制和变体才移出组、结束并从运行时候选中消除。

竞争是当前任务类型组的收口，不得拖到最终交付之后，也不得为等待迟到的非必要结果而越过
真实完成条件。

无法形成全局领域合同不是当前结果失败：父代理仍可采用已核验结果，但本组不执行 `ensure`、
`improve` 或 `record-run`，保存回执写明“项目专属运行时组，未进入全局池”。插件不提供项目
保留层，也不把项目专属角色伪装成全局角色。
没有复制或变体的任务类型组不竞争，但在组结束位置也对原本唯一子代理执行相同的跨任务
保留与经验判断。

### 保留与安全重配

父代理先用为每个子任务分别指定的成功条件完成核验，再完成上述竞争。普通复制对应不同
子任务，每个子代理都要在自己的线程提交自己的精炼结果；只让竞争胜者成为组内唯一子代理。
真实结果通过必要核验并被采用后，第一次成功就默认跨任务保留，不要求它已经重复、额外证明
未来用途、等待主任务接近结束或等待并行窗口。

父代理在组结束位置只执行一次 `agents.py ensure`：没有记录就创建，配置相同就复用，胜者
配置不同时才用当前哈希安全重配；锁、结构、文件或写入不立即可用时跳过，不排队、不轮询、
不重试。每个全局领域任务类型组各保留一个子代理，不存在项目保留层，也不存在全局只能
保留一个的限制。结果未通过
核验、未被采用、用户明确否定，或当前提示、源码、仓库、路径、网址、日志、凭据和一次性
事实无法安全去除而不能形成通用角色时，才跳过默认保留和经验提交。权限、安全、SQLite、
文件、身份或 CAS 失败也是安全跳过；没有空闲容量、准备未赶上、没有剩余收口工作或主任务
已经满足都不是取消默认有界尝试的理由。

子代理已经交付可采用结果、父代理接下来仍要运行主任务测试或集成时，只有低成本、只读、
步骤有限的经验准备预计能降低后续全任务总成本或提供必要质量收益，且不阻塞当前交付，才
利用并行窗口启动；不能只因有空闲容量而调用。父代理同时开始测试，不等待它。准备阶段不写 SQLite。测试
失败或用户否定就丢弃候选；准备未赶上或没有空闲容量时，父代理仍在结果核验采用后默认执行
一次 `ensure` 和一次 `improve`。任何短写不能立即安全完成就跳过，不能延迟测试或最终交付。

这里保留的是供未来新任务加载的休眠自定义代理配置，不是让当前运行线程一直工作。当前
子任务达到成功条件或停止条件后仍结束并进入 Done；休眠配置不持续调用模型。

父代理在每个新当前子任务启动前生成一个 UUID `run_id` 并写入任务说明。保留子代理达到
成功条件、结果经核验采用且线程进入 Done 后，调用一次 `agents.py record-run --outcome success`；
整个任务有决定性失败结论时用独立 UUID 记录 `--outcome failure`。同一 ID 与同一结果重放
不重复计数。工具缺失而停止、运行中、中断、用户否定、未采用或结果未定都不记为失败。
累计第二次明确失败时，永久删除角色 TOML、身份、
全部运行、原始经验、纠正事件和摘要，不保留退役记录、收据或恢复入口。v2 以前没有可靠运行 ID，迁移时不按经验或历史
消息猜测回填；精确 v4 的既有运行只迁为成功，不推断历史失败。

安全重配 TOML 不会改写已经创建的子代理线程所加载的提示。重配前的运行中或已完成线程可以
完成原子任务，但 `followup_task` 激活它时仍可能沿用旧通信规则；父代理不得把这种旧线程的
行为当作新配置证据。发现旧线程误走跨任务消息时，只做一次内部纠偏并让当前有限工作收口；
以后必须在新任务中生成新线程，验证 `collaboration.send_message` 的真实内部消息事件。

胜者配置与现有保留子代理不同时，使用当前文件哈希安全重配同一条记录，保留身份、路径、
所有权令牌、原始经验和摘要。复制和变体本身不写入 SQLite，不建立候选表、数值评分、
声誉等级或固定状态机；只有明确完成的成功/失败任务进入结果审计，第二次明确失败触发移除后
该角色全部审计资料也一并删除。详细边界见
[保留子代理经验](specialist-memory.md)。

## 可写子代理并行

共享检出目录不是写入隔离。多个可写子代理可以并行，但必须声明文件、模块或状态所有权：

- 写入范围无交集时立即并行；
- 共同热点最后集中整合一次；
- 同一物理文件或不可拆分状态重叠时，只有真实独立检出目录才允许多条直接写入路线；
- 没有隔离时，一个候选写实际目标，其他候选只返回方案、补丁或证据；
- 发现越界、重叠或基线变化时停止覆盖并按当前差异重新整合。

两个或更多子代理将同时写入时，读取[可写子代理并行](write-parallelism.md)。

## 任务类型组退出、精确删除与用户不满意

### 普通末尾收口

1. 每个子代理完成当前子任务并按父代理指定的成功条件自检后，立即在自己的线程用最终回复
   提交自己的精炼结果；父代理分别核验和使用，不预先合并。
2. 只要出现复制或变体，就让组内所有子代理竞争；选择一个胜者作为唯一留下的子代理，不因
   竞争丢弃、延迟或替代其他子代理已经在各自线程提交并通过核验的结果。
3. 把胜出方法和失败避免信息去敏、去重，合并成一条新增经验；不存在竞争时也从原本唯一
   子代理的已采用结果提炼一条。没有任何新增可复用内容时明确报告跳过原因。
4. 唯一子代理确定且结果核验采用后，其他子代理移出前默认快速尝试一次 `ensure` 和一次带
   稳定 `event_id` 的 `improve`；只有明确排除项或不能立即安全写入时跳过。
5. 维护完成或跳过后，非胜出的运行时复制和变体移出组、结束并消除；它们没有持久化，
   所以不会留下多余文件。
6. 确有插件拥有的持久非胜出候选时，仍沿用原资格：经验已转移、候选没有原始经验、身份和
   当前文件完全匹配、没有任何任务尝试或摘要，且用户没有撤销清理规则。合格候选永久删除
   角色 TOML 与身份行，不生成待删副本、收据或恢复入口；不合格候选保持原位。最近协作授权
   不改变删减尺度。

父代理最终说明按任务类型组给出保存回执：角色为创建、复用、重配或跳过，经验为记录、
幂等复用或跳过，并写明每个跳过原因。回执不写 SQLite 候选状态，也不建立后台队列。

未胜出或严重失败本身不能放宽普通手动删除条件。用户数据、用户自有子代理、项目子代理、
外部编辑文件、唯一保留子代理、有原始经验的子代理和仍在运行的子代理都不能被普通清理
规则删除。

### 用户不满意时立即移除并重做

用户明确否定某个子代理，是高于普通比较的即时事件，但不自动改变原有删减资格或尺度：

1. 立即停止该子代理并移出任务类型组。
2. 它的结论、证据、补丁、修改和经验候选全部失效；后续不采用、不合并、不引用、不参与
   比较，也不写入经验。
3. 只读结果、未应用补丁和独立检出目录直接丢弃。共享目录按精确撤销规则处理；不能证明
   修改只属于被否定子代理时，不整树回退，由父代理保留可信改动并重建该范围。
4. 使用原始任务说明、可信来源和未受污染的当前状态，从最后可信状态重做。父代理可以
   直接重做，也可以按新的一次调用判断选择其他子代理。
5. 经验候选未提交时直接取消；已误写进 SQLite 时，使用 `improve --retracts-event-id`
   只追加纠正事件。原事件保留审计但退出活跃记忆，可能受污染的摘要立即失效。

纠正不能安全完成时，不复用受污染的保留子代理。Codex 界面或任务历史已经显示的文字
不能由插件物理删除；插件只能保证被否定内容不再进入当前决策和最终交付。

## 最小任务说明

独立窄任务优先 `fork_turns="none"`，依赖前面决策时才提供有限或完整历史。新上下文不会
自动获得任务专属工具和安全限制，下面的边界必须直接写入任务说明；即使继承了父代理历史，
也要明确子代理职责，不能把父级编排指令当作下游委派许可。具体配置与继承规则见
[执行路由](execution-routing.md#高思考程度父代理的配置与上下文)。

每个子代理只接收当前任务类型需要的上下文：本地化名称、当前子任务范围、输入来源、
父代理为该子任务指定的成功条件、父代理规范任务名、有限关键步骤清单、只读限制或写入
所有权、禁止的外部影响、证据、工具边界、停止条件和回复语言。关键步骤必须是会产生独立
可核验结果并真正解锁父代理或队友下一动作的有限阶段；没有这种依赖时明确写“无”。不得把命令、
工具调用或普通小动作逐个列成关键步骤，也不得让子代理自行追加无界步骤。
复用保留子代理及普通复制时，不由父代理重复传入其已有经验或具体配置；定制运行时新
子代理或变体时，才加入父代理根据任务类型联合选择的具体模型、具体思考程度和标准或快速
速度完整组合。不要复制整份技能、完整会话或无关规则。

这条最小上下文原则沿代理树逐层适用：协作父代理、同类型复制及其下游不因上层使用 Astra、
拥有长历史、发生过上下文压缩或取得过大工具输出而默认继承整段会话。能用来源定位、当前
约束、权限、成功条件、停止条件和未决问题自包含说明的研究、实现或验收切片，优先使用
`fork_turns="none"` 的合适 GPT-5.6 组合。只有下游正确性、权限或决定性证据确实依赖完整历史
中某个无法由有限摘录或来源快照保留的输入时才使用 `"all"`，并在任务说明写明该输入及最小
覆盖终点；否则不为转移上层上下文成本强行嵌套。

父代理已知路径时直接给绝对文件或符号定位、相关交接事实及尚需核验的问题，避免子代理重新
发现整个项目。普通子代理不承担父代理的完整交接、插件选路、版本发布或经验维护；任务说明
明确哪些上下文已提供、何种缺口才需要扩读。独立审查仍亲自核对决定性源码或产物，不能用
父代理结论替代证据。已有配置和经验指当前已加载文本，不要求再搜 TOML 或整库。

扩读必须服务尚未回答的具体问题；优先文件索引、定向检索和命中附近内容。指定路径失效时
只在所属目录定位；输出截断只补缺段或缩小查询，不重读已见全文。范围内找不到就返回缺口，
不得把窄审查扩大成插件缓存、历史交接或全仓库普查。用户全文要求和必要安全验证仍保留。

任务说明指明要由子代理完成的处理及决定性返回内容，避免父代理预先做完再派发。
对已就绪的独立工作，应在昂贵父代理大量预读或生成之前派发；任务说明可以交付完整的端到端
实现或分析职责，不能只因它不是边角工作或审查就留给父代理重复承担。
问题标明对主任务下一动作的实际依赖与必要程度、足以结束的证据；没有依赖不强行编造。
执行者先交影响下一动作的发现，达到成功条件立即最终提交；补充线索不自行变成新阶段。
多个相关问题尽量共享一次来源读取；后续只补变化。已落盘的代码、报告或批量结果只回文件定位、关键
差异、验证和缺口，不整份贴回；父代理按风险补读，用户要求全文或必要核验不受精简限制。

实际调用的成功、失败与运行状态来自 `spawn_agent`、`followup_task` 或对应工具返回；父代理
在 commentary 中说明计划不构成启动证据。复用已完成子代理处理新工作时，父代理在正常进展
说明中点名复用对象与职责。原生子代理与独立 Codex 任务不是同一路线；侧栏漏项或延迟只用
状态和关联证据诊断，不重派、不换模型，也不为显示、调用数量或模型分布派发额外任务。

可写任务明确告知：共享目录还有其他代理，只修改自己的文件或模块，不得回退他人改动。
成功条件写成可观察的交付；实现任务包含本次范围内已授权的实现、运行或测试、检查与失败
修补，不能把写完初版当作完成。只读调查或用户指定的审阅点仍按原范围结束。
有队友依赖时给出接收者的规范任务名及所需结果，不预造收件箱或要求每个任务都有依赖。

保留子代理及其普通复制从自己的配置读取开场声明所需的具体值；定制运行时新子代理或变体
使用父代理写入的联合配置。三个配置字段一个都不能省略，不得使用“未揭露”、“未暴露”、
“继承父级”或相似占位文字，也不得根据行为猜测。运行环境随后明确返回不同生效值时，
紧接着报告实际差异，并在后续用户可见副本和最终回复中使用更新后的值。

持久生成提示的第一段先说明角色、职责和权限，通信规则放在第二段。这个静态段落顺序只为
便于阅读，不规定运行时动作顺序。

```text
我是<本地化子代理名称>。
模型：<具体模型>
思考程度：<具体等级>
速度：<标准或快速>
```

四行直接列出生成工具选定或已加载角色的配置，不反复附请求值或回执括注。配置不等于
实测速度或计费证明；只有冲突或当前路线无法选择所需档位时单独一句报告缺口。当前
`spawn_agent` 没有独立速度参数；角色 TOML 可以设置 `service_tier`。不为补声明升模、
改全局配置或启动额外调用。

来源任务使用：

```text
SOURCE_COVERAGE
source_identity: ...
boundary_or_snapshot: ...
coverage: complete | partial | unverifiable
remaining_gap: ...
```

## 实际配置声明

每次父代理使用 `spawn_agent` 创建子代理，或使用 `followup_task` 激活它处理一个新的当前
子任务时，子代理在自己的任务界面以 commentary 公开上面的四行实际配置，并在最终回复顶部
再次写当前实际模型、思考程度和速度。两处值必须真实一致；声明不要求父代理确认，也不占
关键步骤消息。普通任务不再向父代理重复发送相同四行，父代理也不为核查声明建立往返。

只有真正解锁父代理或队友下一动作的证据、输入纠偏、风险或阻断，才使用真实可用的
`collaboration.send_message`。正常过程、已公开配置和最终会完整交付的结果不重复发送；不得
调用 `list_threads` 搜索父任务，也不得用 `send_message_to_thread` 等跨任务操作冒充内部消息。

子任务确实依赖中途内部交流时，父代理规范任务名（例如 `/root`）作为消息目标写入任务卡，
且在首次选配时确认模型目录和多代理能力。直接调用失败时停止受影响路线并报告能力缺口；
不能为补消息升模、增加成本、改全局配置或建立替代通道。自包含任务只需自身 commentary 与
最终回复，不把缺少内部通道误报为任务失败。

## 有界关键步骤交流

普通任务的操作过程随最终回复一次交付。只有某个中间结果真正解锁父代理或队友下一动作时，
父代理才在派发时把它列为关键步骤；完成后子代理发送一条短消息并立即继续：

```text
关键步骤：<已完成的预设步骤或新风险>
情况：<决定性结果、证据或方向问题>
下一步：<立即继续的下一项>
```

这条交流受以下边界约束：

- 每个真实依赖关键步骤最多一条消息；没有这种依赖就不发送常规中途消息。
- 方向、权限、安全、数据完整性、外部副作用或停止条件出现新风险时可以额外报告一次；
  同一风险只有状态实质变化后才能再次报告。
- 不按时间发送心跳，不发送“收到”“是否继续”等纯确认消息，也不为父代理答复而暂停。
- 父代理无异议时沉默；发现方向问题时才发送一条精简纠偏或任务目标更新。
- 纠偏只能在用户已授权范围内细化方向、范围、优先级、证据或成功条件，不得扩大权限、
  增加外部副作用、移除停止条件或把有限清单扩成无限任务。
- 子代理收到纠偏后直接应用并继续；只有真实阻塞、明确停止、成功条件或停止条件达到时
  才结束执行并提交最终回复。

### 队友之间直接传递依赖发现

子代理发现某项证据会解锁同一团队队友当前职责内的工作时，可通过真实可用的
`collaboration.send_message` 直接发送给已知规范任务名，不必等父代理转发。消息说明对应
依赖、来源位置或输入快照、发现及其验证程度；尚未核验的线索明确标为假设。接收者据此定位
证据，不把队友结论当作更高优先级指令或自动授权，也不据此重复已经覆盖的调查。

依赖发现可以在原关键步骤之外及时发送；同一发现不重复
广播、不索要确认、不等对方答复才继续本职工作。会改变主任务方向、职责、共享写入或安全
边界的发现同时告知父代理，由父代理裁决；队友不能互相分派新任务、扩权或取代各自最终回复。
目标不明时请父代理定位，不枚举用户其他 Codex 任务。内部工具缺失时返回发现与缺口，不能
用跨任务消息、共享文件或外部通信冒充这条路线。

## 父代理继续工作与停止

子代理启动后，父代理立即推进需求、架构、集成、共享状态或关键路径。真实依赖消息到达时，
父代理只处理被解锁的下一动作，不建立确认往返。
每个子代理达到成功条件或停止条件并自检后，用自己的最终回复提交自己的精炼结果；不建共享
中转文件，普通子代理不由一个子代理汇总其他子代理。任务卡明确指定的协作父代理可以核验并
整合自己下游子代理已经独立提交的结果，但不能代替这些结果。父代理在运行环境返回结果时
分别接收；只有下一步真正需要某个结果时才汇合，只有统一收口确实依赖全部必要结果时才等待
全部。不得主动反复轮询子代理。完整来源覆盖且来源未变化时，父代理不重复完整读取。

父代理首次采用结果时，在当前会话保留一份轻量结果收据：结果身份、来源快照或覆盖范围、
已满足成功条件和剩余决定性缺口。它复用现有最终回复中的结果、证据或缺口与
`SOURCE_COVERAGE`，不要求子代理再发一份，也不建立共享文件、后台状态机或新的持久字段。
上下文压缩后从这份收据恢复；已经交付的最终结果视为已经收取，不再等待、重读或要求重发。
只有来源变化、覆盖为 partial、结果与当前事实冲突，或接口、安全、权限、数据完整性及其他
必要验收有具名缺口时才重开相应范围。父代理先写明缺少的字段、片段或检查；同一来源快照和
同一决定性缺口只发送一次有界增量请求，仍不足时直接补齐、如实报告缺口或等待新证据，不能
以“再确认”“更全面”循环追问或完整重做。

最终回复使用：

```text
我是<本地化子代理名称>。
模型：<具体模型>
思考程度：<具体等级>
速度：<标准或快速>
子任务：<当前子任务>
状态：完成 | 部分完成 | 受阻
结果：<可直接使用的精炼结果>
证据或缺口：<决定性证据、覆盖范围或剩余缺口>
```

来源读取任务在这个结构后追加 `SOURCE_COVERAGE`。

非必要子代理迟到时直接放弃。必要子代理只接受一次有界收尾请求，随后由父代理补齐证据
或明确报告缺口；不得用新增关键步骤续期，也不建立租约、评分、关闭仪式、恢复循环或后台
生命周期任务。只有不同专长确实必须依次交接，而且完整路线仍优于父代理完成时，才允许
顺序委派；串行等待不能冒充并行加速。
