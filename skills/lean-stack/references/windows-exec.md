# Windows exec 与 PowerShell

只在当前实际动作需要 Windows exec、PowerShell、跨语言脚本或普通原生程序时读取。本分支只改变
命令的表达和验收方式，不增加第二套任务规划，不写入用户全局文件，也不声称存在宿主调用前 Hook。

<!-- codex-exec-robustness:begin -->
Windows exec 已是 PowerShell 时，简单命令直接执行，不额外套 Shell。
复杂或跨语言代码优先用文件工具落盘，再调用脚本文件，避免层层内联转义。
分离可执行文件、参数和数据，不拼接命令后用 Invoke-Expression 执行。
按各层语法处理引用；路径优先使用变量及 LiteralPath，避免反引号续行。
复杂 PowerShell 脚本执行前做语法预检，执行后检查实际结果与退出码。
转义错误优先减少解析层，不连续盲试引号。
复用已知环境，定向读取；完整日志留本地，回传关键错误，不为省 token 跳过验证。
<!-- codex-exec-robustness:end -->

按下面的最小表达方式执行，不能把一次参数边界错误扩成多轮长命令重写：

1. 简单、短小且只有一层普通参数的命令直接用当前 Windows exec 外层执行，不额外嵌套
   `pwsh`、`powershell` 或 `cmd`。
2. 命令含多层引号、嵌套 JSON、正则表达式、反引号、多行脚本、复杂变量插值，或是跨语言代码时，
   首次执行前优先用 `apply_patch` 等文件工具写成任务专属临时 `.ps1` 脚本，再通过脚本文件或
   `-File` 调用；只有确有进程隔离理由时才启动一层当前运行时的 `pwsh -File`。
3. 新生成的复杂 `.ps1` 在执行前使用 `Parser.ParseFile` 做语法预检；预检有错误时只修脚本文件，
   不继续执行。预检通过不代表逻辑正确，脚本仍须检查实际内容、结果和外部程序退出码；不能用
   最后一句“成功”掩盖前面失败。
4. 调用普通原生程序优先使用 `& $exe @argList`。可执行文件、参数和数据分别保存，不能先用空格
   拼接参数，也不能用 `Invoke-Expression` 执行拼出的命令；不把 `Start-Process -ArgumentList`
   数组当作无损参数数组接口。`.cmd`、`.bat` 和 `cmd.exe` 单独按其解析规则处理。
5. PowerShell 脚本或函数的具名参数使用直接命名传参或哈希表 splatting；不能把
   `@("-Name", "value")` 当成具名参数字典。路径放入变量并在支持时使用 `-LiteralPath`；复杂
   脚本把外部值放在 `param()`，复杂数据使用数据文件或标准输入。原生参数边界按当前
   `$PSNativeCommandArgumentPassing` 和目标程序实测，不能假设跨版本行为相同。凭据、令牌或秘密
   沿用已有安全通道，不写入脚本或命令行参数。
6. 第一次内联失败明确属于 PowerShell 解析或转义问题时，立即停止继续改写长 one-liner；后续只编辑
   同一个临时脚本本体再重跑。业务逻辑、路径、权限或被调用程序失败按真实原因处理，不能误判为
   转义问题，也不连续增加反斜杠、引号、Base64 包装或换 Shell。
7. 临时 `.ps1` 是任务执行制品，不进入仓库或提交。需要清理时，普通脚本移入 Windows 回收站；
   重要诊断脚本或证据移入任务专属 `待删文件`。完整日志留在本地，只回传脱敏后的关键错误、
   位置和判断依据。
8. 不为这条规则建立 PowerShell 包装框架、通用执行器、后台服务、自动重试器或新状态机。

读完本分支后立即执行当前命令；不再读取其他执行分支，除非当前结果产生了新的具名条件。
