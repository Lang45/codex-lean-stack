# 执行路由

仅在“父代理直接做、工具并发、后台命令或模型子代理”之间难以判断，或者需要安排
条件性验证时读取。本文件展开执行细节，不增加第二套调用门槛。

## 一、插件强制调用限制

本技能适用后，父代理必须使用插件规则完成一次调用判断和后续选路，不再读取、引用或
套用官方默认调用触发规则，也不等待用户重复提出委派要求。只有运行环境没有可调用的
子代理能力，或者权限、安全和真实前置条件不允许时，才按能力缺口结束该调用路线。

`agents.max_concurrent_threads_per_session` 只作为可见并发容量上限，不是调用触发条件。
是否计入协调者以及还剩多少槽位，以当前运行环境说明为准，不能从字段名推断。当前工具明确
给出包含父代理的团队容量时按该口径使用；配置与工具说明不一致时按可用槽位收敛，不改配置
或臆造额外容量。容量是上限而不是调用目标。

### 未完成要求锚点

锚点是活动清单中最早一个尚未完成，或已经完成但尚未通过用户可见回复交付的要求。完成且
已经交付的要求立即退出，不等待用户再次确认；纠正只重新打开真正受影响的项，“继续”只恢复
剩余项。最终说明只报告上一次用户可见交付后新完成的结果和当前剩余范围，不重述已经交付的
历史事项，除非用户明确要求回顾或当前结论确实依赖它。

## 二、三项原则

安全、权限、数据完整性、明确验收条件和诚实证据始终是底线。

1. 高价值工作：质量优先，守住正确性和决定性证据。
2. 质量达标后：先比较父子输入输出、分派、交流、核验、返工和新增服务费用组成的全任务总成本。
3. 总成本相近时：再比较总完成时间；只有当前用户明确速度或期限要求时才提高速度权重。没有
   相应质量收益时，不为单纯提速大幅增费。

高价值不等于自动多派子代理。独立复核能增加新证据时可以接受更多时间和成本；重复阅读、
多人猜同一个修法和没有新证据的共识不会提高质量。

兼容、跨版本回迁、机制替换、镜像文档、测试矩阵或发布闭环可能扩大维护面时，先读
[反 AI 过度工程](anti-overengineering.md)。这属于构建范围判断，不是增加子代理的理由；没有
现实消费者或当前来源证据时先删除多余工作项，再对剩余真实任务做一次调用判断。

消融是另一条显式反馈循环：只有用户明确要求对当前制品“进行消融实验”、精简代码或设计、
去掉不必要抽象或同义操作时，才在当前设计或实现形成可验收基线后读取
[消融反馈循环](ablation-loop.md)。普通完成、重构、语义复核和最终验证不自动触发，也不例行
追问用户是否要做。正式消融的独立上下文仍按本文件的一次调用判断与协作范围选择。

## 三、一次选路、立即并行

每条新用户消息先判断是新要求、对活动项的调整、使已交付结果失效的纠正，还是取消、替换、
状态询问或“继续”。只更新对应项并重新判断受影响的任务形状、依赖、风险和可用能力；未变化
的活动项继续，已经交付且未受影响的历史项不复活。

进入工具或代理路线前，先按 `SKILL.md` 的“首条快速说明”给出当前理解、立即动作和必要限制，
随后继续而不建立确认往返；能直接答完的请求由最终答案本身完成，不重复发两份前言。

```text
当前任务类型需要持续模型判断吗
├─ 否：父代理短命令 / 一次工具并发 / 持续终端或后台
└─ 是：是否存在已就绪、范围明确、可安全独立、预计达到必要质量且能替代父代理实际工作的低成本 GPT-5.6 切片
   ├─ 否：父代理完成或等待真实前置条件
   └─ 是：依据维护后的模型价格/收益基线及完整反事实路线取得正向收益判定；是否命中内部硬条件
      ├─ 是：父代理完成；若处于新会话行为验收则记为未完成
      └─ 否：立即调用，父代理同步推进，在真实依赖点汇合
```

上述资格是一次整体判断，不拆成连续多道否决门槛。必要质量收益仍可承担成本；质量达标后先
比较全任务总成本，成本相近时再比较总完成时间。只有当前用户明确速度或期限要求时才提高速度
权重。质量底线、安全、权限或真实前置条件不满足时，按内部硬条件处理；其余合格切片直接依照
维护后的模型价格/收益基线作正向判定并立即派发。
判断时正向寻找能替代父代理实际阅读、实现、诊断或验收的切片；可独立端到端完成并自检的任务
同样合格，不把委派限定为边角工作、只读审查或最终复核。判断“不派发”时，也要把父代理接下来
独立承担这些工作所需的上下文、生成、调试和验证消耗计入该路线总成本，不能只计算子代理增量。
收益依据任务形状、维护后的模型价格/收益基线及完整反事实路线判定，不建立临时评分表。对于昂贵
父代理与低价 GPT-5.6 的明显价差，范围清楚、输出短、容易增量核验且能替代父代理真实工作的
模型判断切片直接取得正向全任务总成本收益判定。需要更可靠语义判断但不属于
高价值工作时优先 `gpt-5.6-terra`。多个独立普通
子任务已经就绪、范围清楚且提交和核验成本轻时，更倾向用低成本子代理并行；每个新增调用
适用同一维护基线判定或提供必要质量收益。低成本路线不达标时只升级当前
子任务。高价值、复杂、模糊或高风险工作才优先 `gpt-5.6-sol` 和必要的更高思考程度。

内部硬条件只有：确定性短工具；输入或真实前置未就绪；切片之间严格依赖；
重复已有工作；写入冲突无法隔离；能力或权限缺失（包括缺少所需真实工具）；交接加增量核验
明显超过切片本身；运行环境容量不足；或新增成本显著且没有必要质量收益。这些条件只约束内部
选路，不产生向用户说明阻断的义务。

### 持续多工作流任务的积极派发

持续的多工作流任务一旦满足以下条件，普通的一次正向判断就尽早派发当前合格切片：

- 已有多个互不依赖、输入就绪、范围明确且需要持续模型判断的工作流；
- 主任务预计跨研究、实现、真实验收等多个阶段持续推进；
- 子代理能替代父代理实际研究、实现或验收，而非只旁观或在末尾复核；
- 每个调用分别符合当前成本优先的三项原则和权限限制。

父代理在深入读取额外来源族或开始实现之前，派发全部当前取得正向收益判定且互不冲突的
GPT-5.6 切片。
调用数量随真实工作流、边际收益与运行容量变化，不设最低数量；各切片直接沿用维护后的模型价格
与收益基线。只在后期增加一次只读复核不能替代前面的实际工作。父代理仍亲自
读取项目交接全文，并保留关键约束、共享热点、用户互动、整合和必要验收。

输入未就绪、剩余工作全是确定性短工具、切片之间严格依赖、权限或写入冲突无法隔离、重复
已有工作、运行环境容量不足，或新增调用会显著增费且没有必要质量收益等内部硬条件才停止相应
派发。新要求改变工作流时，立即
按新的任务形状重新判断；这是输入变化后的判断，不是逐级试错或调用配额。

一次直接处理或派发决定只对作出决定时的任务形状有效。新要求引入不同系统或证据范围、具体
困难暴露出新的已就绪切片，或上下文切换、压缩后剩余任务形成多个已就绪工作流时，父代理立即重新
做上面的正向判断，并在继续大规模读取、实现或长链诊断前派发当前合格切片。没有这些变化时
复用原决定，不按固定时间、文件数量或轮次机械重判。

### 安装后新会话生效验收

只有以下隔离验收可以证明新会话实际采用了本策略：在用户授权正式安装后，新建独立父代理任务，
并让它在全新项目目录中运行。该任务不得读取本项目 Jiao-Jie 交接文件（`Jiao-Jie.md`）、当前会话摘要、源码候选文本
或人工摘录策略，只能依赖新任务自动加载的全局入口与正式安装缓存；否则只能算源码或当前会话
模拟，不能宣称“新会话生效”。

同一验收先给一个单一短确定性工具任务，确认父代理直接用工具且不委派；再用新要求改变任务
形状，形成多个互不依赖、已就绪且需要持续模型判断的工作流。第二阶段须观察到父代理在继续
大块阅读、实现或诊断前真实派发合格切片，并取得真实 `subAgentActivity` 或等价原生调用记录及
至少一个可采用结果。运行环境硬阻断使测试未完成；不能用阻断说明、静态关键词、
当前会话手工加载候选文本或只派末尾复核替代真实派发与可采用结果。

确定性工具路线：

- 几秒的命令由父代理直接运行；
- 多个独立短命令在一次工具调用中并发运行；
- 长但步骤确定的工作进入持续终端或后台，父代理继续其他工作；
- 不让模型子代理只运行命令并回报退出码。

### 让委派替代工作

以下方法只服务三原则，不以文件行数、固定节省比例或必须使用廉价模型决定委派：

- 大输入先用工具定位和筛选；独立读取在同一工具调用中批量进行，工具侧先筛选并限制输出预算。
  尤其在昂贵父代理大量预读前，确需语义理解、能压缩成可核验答案的材料，交给合适角色读取。
  父代理无需为写任务说明先通读同批材料，但仍亲自读取用户要求的全文和影响关键决定的片段。
  纯计数、过滤或格式转换由工具完成，不能另开模型只搬运文本。
- 长来源只筛选一次并沿代理树复用：拥有原始来源的执行者先返回来源或制品定位、必要字段、
  覆盖范围和剩余缺口；父代理、同类型复制、协作父代理与下游只取得各自问题需要的摘要或
  原始来源定向片段。完整线程、完整工具输出、完整父历史或完整子树结果不得作为默认输入继续
  向下复制；后续确需原文时只补能区分当前未决问题的缺段。用户明确要求全文和不可替代的
  原始证据仍按要求读取。
- 输出量大、已有可靠参照的生成工作，或范围明确的复杂高价值实现与分析，给子代理参考、目标
  文件和验收条件，让它在授权范围内端到端完成及自检。回传实际文件、差异要点、决定性证据
  与缺口；已落盘内容不整份重贴给父代理。父代理保留用户配置，负责约束、冲突与整合；
  父代理仍核对关键差异、接口和安全限制，不把“避免重做”当作免检，也不全面重做证据充分的结果。
- 同一材料上的相关问题合并交给一个子代理；同一任务的追问只补问题和变化部分，相关上下文
  仍有效时可复用线程。独立新任务用窄上下文，不把无关长历史带过去，也不假设缓存或保留身份免费。
- 拆分只用于真实独立切片，启动后父代理推进不重叠工作。不为占满容量细碎拆分；子代理已经
  完成的处理和未变的通过证据直接复用，核验失败只补受影响部分，必要独立复核继续保留。

父代理根据剩余工作判断委派是否仍有收益，不用“独立”或“审查”标签替代这个判断：

- 核对几个已知版本字段、文件是否存在或未变文件哈希，直接合并成工具检查。存在需要独立
  判断的发布或安全风险时，才把具体未决问题交给审核者，不让它重新做全项目接手。
- 派发时说明哪项下一动作需要此结果、哪些问题只是补充，以及取得什么证据即可结束；没有
  真实依赖不虚构等待点。相关问题合在一次范围明确的读取中，避免多个角色各自初始化同一材料。
- 首次采用结果时，父代理在当前会话保留“结果身份、来源快照或覆盖范围、已满足成功条件、
  剩余决定性缺口”的轻量结果收据；不建立共享文件、后台状态机或重复报告。上下文压缩后从
  收据恢复，已交付最终结果视为已经收取，不再等待、重读或要求重发。同一来源快照和同一
  决定性缺口只发一次范围明确的增量请求；仍不足时由父代理补齐、明确缺口或等待新的来源变化，
  不能以“再确认”“更全面”为由循环追问。
- 只有子代理线程自己的明确最终回复及其中可采用的结果收据才算已交付；commentary、内部进度
  或“正在处理”状态不能被父代理当成采用结果。最终回复若只缺一个具名字段、片段或检查，父代理
  只发一次明确补问；缺口不具体、路线已经失配或补问仍不足时，说明原因并关闭或改路，不让父代理
  和另一个子代理从头重复整项工作。
- 观察到读规则多于处理目标、重复已覆盖证据、无关扩查或同类静态意见已无法推进时，父代理
  立即用一次消息指定剩余问题和必要来源。满足成功条件就要求最终提交，不继续补“全面审查”。
  这是根据实际行为纠偏，不设置固定秒数、编辑次数或文件数量作为质量门槛。
- 非必要结果未赶上时不阻挡主任务交付，停止其余工作并说明未采用范围；必要验收不能以慢为由
  丢弃，汇合处只补尚缺的决定性证据。顺序依赖无法消除且交接更贵时，由父代理直接完成。
- 结果已足够时不再启动模型做经验准备、重复审查或写收尾报告；必要的有限台账操作按既有
  规则用短工具处理。角色声明、配置核对或维护回执不成为等待执行者确认的往返门槛。

总成本包含并必须比较两条完整反事实路线：父代理独立路线的阅读、生成、上下文膨胀、调试、等待
和返工，对比低价子代理输入输出、启动与分派、过程交流、整合、增量核验和返工。不能只计子代理
新增成本而把它替代的父代理成本算零。质量和决定性证据达标后先比较这个合计，成本相近才比较等待和总完成时间；当前用户明确速度
或期限要求时按该要求调整权重。实际比较考虑输入/输出与缓存差别，不把主代理 token 降幅当总费用或
Codex 额度降幅。运行时用已有预估做一次判断，不逐次计算账单、建评分表或收集全量日志。
明显模型价差是范围清楚、短输出、易增量核验切片的合理推定依据，并直接形成正向收益判定；无需逐项现场重新估账。父代理
只核对关键差异、接口和安全限制，不完整重做证据充分的结果。没有可比实测就只报告实际减少的
读取、重复生成或返工，不声称节省比例。提示约定不是运行时
强制拦截，不能假定其他客户端的 Hook 能在本环境生效。

### PowerShell 复杂转义止损

PowerShell 使用以下止损规则，避免把一次解析问题扩成多轮长命令重写：

1. 简单、短小且只有一层普通参数的命令仍内联执行。
2. 命令含多层引号、嵌套 JSON、正则表达式、反引号、多行脚本或复杂变量插值时，首次执行前
   优先写成任务专属临时 `.ps1`，再通过 `-File` 调用。
3. 如果第一次内联失败明确属于 PowerShell 解析或转义问题，立即停止继续改写长 one-liner；
   后续修复只编辑同一个临时脚本本体再重跑。失败来自业务逻辑、路径不存在、权限或被调用
   程序时，按真实原因处理，不能误判为转义问题。
4. 脚本用 `param()` 接收路径和普通参数，路径操作优先 `-LiteralPath`；外部输入作为参数传入，
   不再拼接成可执行代码。凭据、令牌或秘密沿用已有安全通道，不写入脚本或命令行参数。
5. 临时 `.ps1` 是任务执行制品，不进入仓库或提交。需要清理时，普通脚本移入 Windows
   回收站；重要诊断脚本或证据移入任务专属 `待删文件`。
6. 不为这条规则建立 PowerShell 包装框架、通用执行器、后台服务、自动重试器或新的状态机。

模型子代理路线：

- 父代理先判定具体任务类型；一次调用判断通过后，再判断该任务类型是否适合已有任务类型组，
  不提前判断稳定性；任务类型组确定前禁止复用或定制子代理，也不得选择具体配置；
- 适合已有组时立即复用组，再检查可见的保留子代理：有则复用；没有则由父代理定制运行时
  新子代理；不适合已有组时先开新组，再定制运行时新子代理；
- 复用保留子代理时，父代理只传入当前子任务及为它单独指定的成功条件；保留子代理读取
  自己的经验和已有配置并自行声明。定制运行时新子代理或变体时，父代理根据任务类型、工作
  价值、风险、证据形状、时延要求和总成本，联合选择并写入完整的模型、思考程度和速度组合；
- 默认使用平面子代理。只有一个获批子项目本身还有多个已就绪、互不重复的独立切片，而且
  局部拆分、纠偏和汇合能降低全任务总成本或增加必要证据时，任务卡才指定 `协作角色: 协作父代理`、
  `允许下游委派: 是` 和有限下游范围；
- 协作父代理只有在真实拥有顶层 `collaboration.spawn_agent` 且仍有可用容量时才委派下游。
  工具缺失、直接调用失败、范围不清或写入无法隔离时停止协作父代理路线，由整合父代理改走
  平面路线；不能用 `ALL_TOOLS`、角色 TOML、模型目录、共享文件或跨任务 API 猜测或冒充；
- 现有其他 Codex 父代理任务、`create_thread` 新任务、`read_thread`、`wait_threads` 和
  `send_message_to_thread` 属于用户可见的跨任务编排。当前用户已为本插件持续授权；只要符合
  三项原则、服务主任务、范围清楚且不涉及未获明确要求的永久删除，就可直接进入并指定唯一
  整合父代理，不再重复询问；这条路线不是内部委派；
- 父代理同时给出父代理规范任务名、有限关键步骤清单和停止条件；规范任务名不是 Codex
  线程 ID。没有值得中途报告的步骤时明确写“无”，不把命令、工具调用或普通小动作逐个列为
  关键步骤；只有真实依赖需要在最终回复前取得结果时才设置关键步骤消息；
- 每次 `spawn_agent` 或 `followup_task` 启动新的当前子任务时，子代理在自己的任务界面以
  commentary 公开固定四行实际配置，最终回复顶部再次写实际模型、思考程度和速度。两处值
  必须真实一致；普通任务不再向父代理重复发送同一四行，也不索要确认；
- 内部消息只用于真正解锁父代理或队友下一动作的证据、输入纠偏、风险或阻断。正常过程自动
  随最终回复交付，不重复发送；
- 不得用 `list_threads` 搜索父代理所在任务，或用 `send_message_to_thread` 跨任务发送来替代
  内部父子消息；按本技能三项原则直接授权的父代理跨任务协作不受影响，但仍是另一条用户
  可见路线。自身界面的公开副本不能冒充内部消息；
- 中途内部交流是成功条件而工具不可用时停止受影响的真实任务；完全自包含、无需纠偏或队友
  依赖的有限任务只使用自身 commentary 和最终回复即可继续；
- 父代理工具表不代表子代理工具表；只有任务确实需要中途交流时，才用真实内部消息确认该
  路线可用，不为普通任务额外探测；
- `spawn_agent` 没有逐个工具授予参数，内部消息也不是可臆造的 MCP 工具。角色 TOML 不能
  替父会话启用协作；保留 TOML 只用 `[skills] include_instructions = false` 缩小窄角色上下文。
  需要中途交流时，父代理在首次选配前确认实际模型目录和多代理能力；已知 Luna 目录为 v1
  或缺少内部通道时，只分配自包含工作，中途协作任务直接选具备能力的合适 GPT-5.6 组合。
  直接调用失败时停止受影响路线，不能为补消息升模、增加成本或用跨任务 API 冒充；
- 配置声明不计入关键步骤消息；父代理不轮询或等待，也不要求内部确认；
- 父代理继续需求、架构、集成、共享状态或关键路径；独立证据本身是目标时可以等待证据；
- 只有预设关键步骤涉及真实依赖时，子代理才发一条简短消息并立即继续；其余过程由最终回复
  一次交付。同一方向风险只在状态实质变化后再次报告，不发送定时心跳或纯确认消息；
- 父代理无异议时沉默；发现问题立即纠偏或更新当前任务目标，但不得扩大用户
  授权、移除停止条件或把有限任务扩成无限任务；
- 每个子代理达到成功条件或停止条件并自检后，在自己的线程用最终回复各自提交精炼结果；
  不建共享中转文件，普通子代理不由一个子代理汇总其他子代理。任务卡明确指定的协作父代理
  只核验并整合自己下游子代理已经独立提交的结果，不能压掉、改写或冒充这些结果；
- 子代理结果可采用而父代理仍要运行测试或集成时，只有只读经验准备预计能降低后续全任务
  总成本或提供必要质量收益，且不阻塞当前交付，才可并行启动；不能只因有空闲容量而调用。
  父代理立即继续测试且不等待，准备阶段不写 SQLite；准备未赶上不取消核验采用后的默认保留和经验提交；
- 父代理在结果返回时分别接收；只在下一步真正依赖某个结果时汇合，不主动反复轮询，只有
  统一收口确实依赖全部必要结果时才等待全部；
- 任务类型组、稳定性、保留子代理和经验侧链都不参与当前是否调用的判断。

协作父代理、父代理之间的显式任务编排、任务卡、`BLOCKED` 和子树交接细节见
[协作父代理与父代理之间](collaboration.md)。协作只服务必要质量或降低全任务总成本；成本相近
且用户有当前期限要求时才用速度收益判断。它不能另立主线、增加权限、
建立非授权留言板或让代理共识替代权威来源和真实验证。

### 高思考程度父代理的配置与上下文

这条规则细化已有选路，不改变用户选定的父代理配置，也不新增模型路由器或自动调档脚本。

`gpt-5.6-luna`、`gpt-5.6-terra` 与 `gpt-5.6-sol` 是通常候选；Sol 可端到端承担复杂高价值
实现、分析与自检。Astra 只在相对这些候选有额外决定性质量，或能通过减少返工、token 等使
全任务总成本更低时使用；不能只因更快、父代理昂贵、任务标签为高价值或希望逐级试错而选择。
Sol 本身为父代理时有一条明确允许路线，其主要判断是出现 Sol 难以可靠解决的具体困难，而且
确实需要专家协助；困难一旦形成范围明确、输入就绪且可独立核验的专家切片，就立即路由给匹配
该问题的专家，不先让低价模型失败，也不让父代理继续不限范围地摸索。只有该切片确需更高决定性质量时，
才把它作为范围明确的 Astra 子任务。UI 设计、图片、三维建模、
渲染及其他视觉工作只要出现这种专家需求也可以调用；最终评审或验收核对只是辅助使用场景，
不是前置门槛。视觉任务本身以及普通设计、制作或迭代不触发。该路线不要求先制造一次 Sol 或
低价模型失败。任务卡传入实际材料或可访问路径、视觉目标、需要判断的差异和验收点；普通阻塞、
任务标签或单纯求快不能替代该理由，只路由当前困难，不批量升级已经通过的切片和无关批次。
用户已经选择 Astra 父代理时不擅自改其配置，但它对上下文读取、传播、结果复用和增量补缺
规则没有例外；父代理本身也只处理当前决定需要的来源片段。能自包含的独立切片优先交给
`fork_turns="none"` 的合适 GPT-5.6 子代理。长历史、上下文压缩和大工具输出既不是选择 Astra
子代理的理由，也不是把父历史复制给下游的理由；Astra 子任务同样只接收最小充分输入。

- 运行时新子代理通过当前工具的模型与思考程度参数显式配置；只在任务说明里写“用便宜模型”
  不等于生效。保留角色沿用其配置。若 `fork_turns="all"` 会强制继承且拒绝覆盖，需单独选配的
  子任务使用 `fork_turns="none"` 或工具允许的有限历史，并传入自包含任务卡；只有任务确实
  依赖完整历史且继承组合本身合理时才全量复制。工具字段以实际 schema 为准，不臆造参数。
- `fork_turns="all"` 同时复制父历史、其中的长工具输出和既有子代理或嵌套代理编排痕迹，
  因此只在任务说明点明某个无法由有限摘录、来源定位与当前约束重述的决定性输入，并给出最小
  覆盖终点时使用。已完成子代理结果、父代理编排过程、压缩后曾重读或“可能相关”都不是理由。
- 范围窄、输入可完整描述的独立只读侦察优先 `fork_turns="none"`，避免带入父代理无关推理；
  需要此前决策时才增加有限历史。无历史任务说明显式携带当前工具限制、安全限制、只读或
  写入所有权、成功条件与停止条件，不能假设这些任务专属约束会自动继承。继承历史的子代理
  可能看到父代理编排指令，任务说明仍须明确其普通子代理或协作父代理职责，不能自行扩权。
  只读调查可从低档、普通执行从中档、复杂推理从高档考虑，但这些是可调整的候选，不按角色
  名称强制固定 reasoning_effort，也不覆盖已有模型、思考程度、速度联合选配。
- 新选配默认标准速度，包括 Luna。只有当前用户明确速度或期限要求，且完整路线有收益时才用
  快速；工具没有速度参数时，不把文字声明冒充成功设置，不擅自改全局配置。已有显式快速
  角色保留真实值；不适配时只调整本次调用，不批量重配。四行直接报告生成工具选定或已加载配置。
  只有配置冲突或当前路线无法选择所需档位时，一句说明缺口，不为补声明另开昂贵调用。
- 贵价父代理需要的是影响决定的证据。大结果先在工具侧存放或解析，只返回所需字段、定位和
  来源覆盖；工具发现只输出匹配工具的名称与必要 schema，不展开整个工具目录。会话读取即使
  限制了轮数也可能返回超长单轮，先筛用户消息、最终交付和相关事件，再按缺口补读。
- 查询运行状态时先用紧凑状态接口；实体标签先对应到真实子代理或任务身份，再对缺失、延迟、
  完成或失败定性。读取按当前工具 schema 和下一动作所需字段设置预算，不写死跨工具通用轮数；
  返回超限或截断时只补决定性缺口，不建立新的结果索引或后台状态机。
- 同一来源完整覆盖且未变时复用结果；截断或部分覆盖必须标明缺口，不能当全文证据。
  分页终点只证明工具返回结束；空轮次、条目上限或原句缺失时仍要核对覆盖。用户要求全文时，
  按已知来源补齐缺段，不能把 `hasMore=false` 直接写成全文已读。
  项目交接的新会话与工作上下文重置后（包括压缩或切换上下文窗口），父代理只恢复当前用户
  要求和会改变下一动作的重要片段；插件规则只读一次 `SKILL.md` 入口。reference 只在当前
  操作真正路由到它、尚未加载或已经变化时定向读取，实际调用时不重复读取入口或未变细则。
- 工具返回运行句柄或子代理尚未完成时，先推进无依赖的工作；在真实依赖处按原句柄取得结果，
  不把“尚未返回”当作失败再启动同一操作。用户中途纠正时，先应用最新范围与授权，再采用
  迟到结果；不可撤回的外部影响如实报告，不伪称已取消。
- 总成本判断沿用上面的“让委派替代工作”；不能只用子代理单价推断省钱，也不宣称未经实测的
  ultra 倍率或某模型必然更快。质量达标后成本先于速度。

官方指南中的 `async: true`、`configuration_update` 和缓存参数属于 API 请求与执行环境能力。
本插件没有 Responses 请求发送器，不能把这些字段塞进不支持它们的 Codex 工具或角色 TOML，
也不为适配模型新增 API 客户端、等待工具或后台服务。当前可调用的并行与等待工具足够时沿用。
API 文档中的思考档和速度限制不改写用户已选的 Codex 父代理配置；只按实际运行环境支持的
完整组合选配子任务。以后用户确实要求 API 集成时，再按对应文档核对端点、参数和兼容条件。

## 四、可写并行保护

多个可写子代理可以并行，这不是单写入者规则：

- 写入范围能天然分开时，在同一检出目录分配不重叠文件、目录或模块；
- 清单、锁文件、公共接口、数据库结构和生成入口等共同热点最后集中整合一次；
- 同一物理文件或不可拆分状态重叠时，只有运行环境真实提供独立检出目录才允许多条直接
  写入路线；否则一个候选写实际目标，其他候选只返回方案、补丁或证据；
- 汇合时检查真实修改范围、越界、重叠和基线变化，只运行受影响检查；
- 不增加认领数据库、锁租约、心跳或后台协调器。

需要撤销被否定子代理的共享写入时，必须能用所有权范围、调用前基线和当前哈希精确归因；
禁止整树回退。完整规则见[可写子代理并行](write-parallelism.md)。

## 五、容量与成本快判

插件不设置同时调用数字，也不设置主任务累计调用数字。一次选路通过的任务类型按当前
运行环境实际可用的全部并发槽位启动；容量不是调用目标，也不要求占满。

固定成本预估先给普通工作一个正向选择：窄、清晰、重复、易核验时优先
`gpt-5.6-luna`；需要可靠判断但不是高价值工作时优先 `gpt-5.6-terra`；复杂高价值工作可由
`gpt-5.6-sol` 端到端完成。Astra 只在额外决定性质量，或能以更少返工、token 等降低全任务
总成本时选择，不能仅凭更快。Sol 为父代理时，难以可靠解决且需要专家协助的具体困难可作为
范围明确的 Astra 子任务；需要专家帮助的 UI 设计、图片、三维建模、渲染或其他视觉效果也适用，
最终评审或验收只是辅助场景。视觉任务本身不触发，也不自动升级整批。
模型、思考程度和速度不是三个独立选择；父代理按任务类型一次确定完整组合，
并把过程交流、核验、返工与父子输入输出纳入全任务总成本。它再回答一个停止问题：新增调用
是否会使总成本大幅增加且没有必要质量收益？如果是就停止该调用；否则使用已有容量。运行时
不重新搜索费率、不逐项计算令牌，也不把调用次数直接当成本。新选配全部默认标准速度；只有
当前用户明确速度或期限要求，且完整路线有收益时才使用快速。详细思考程度
与配置复用例外统一见[联合配置基线](cost-baseline.md)，不能给同一模型固定一种思考档。

成本预估维护位于[成本预估](cost-baseline.md)。每周状态由 `scripts/cost_check.py` 在真正
不阻塞主任务时检查；七天未到不联网，到期但不能非阻塞核对就延后。它不参与每次调用，
不创建 Codex 自动化、系统定时任务或外部守护进程。

以下做法错误：

- 为占满容量制造任务；
- 重复读取同一个子任务却没有新的证据或可归因收益；
- 父代理已经完成时继续启动下一轮；
- 把保留子代理创建或经验维护当作当前调用前置条件；
- 忽略维护后的价格与收益基线，把合格低价切片继续留给昂贵父代理；
- 忽略启动、汇合、验证或写入冲突造成的真实成本。

## 六、任务类型组与保留子代理

任务类型组组织已经决定调用的运行时候选，不决定是否调用。按可复用能力族匹配：同一能力族
中的调查、诊断、实现、修复、测试或验收，只要工具、写入权限、安全风险和决定性证据形状
兼容就归入同一组；项目、仓库、框架、动作动词、交付名称、一次性成功条件或配置档位不另建
窄组。工具、权限、风险或证据形状不兼容且能形成独立可复用职责时才建立不同组，不能只因
属于同一主任务、仓库或功能而合并，也不能借范围放宽让只读角色实施写入：

```text
父代理判定具体任务类型 → 确认应该调用 → 判断是否适合已有任务类型组
适合 → 立即复用组 → 检查可见保留子代理
可见 → 复用保留子代理 → 子代理读取自己经验和配置并自行声明
不可见 → 父代理定制运行时新子代理并联合选择三个具体配置值
不适合 → 开新运行时任务类型组 → 父代理定制运行时新子代理并联合选择三个具体配置值
父代理为每个子任务给出成功条件和停止条件；只有真实依赖才列关键步骤，规范任务名不是线程 ID
spawn_agent 或 followup_task 启动新子任务 → 子代理在自己的任务界面公开四行实际配置
→ 最终回复顶部再次写实际模型、思考程度和速度；普通任务不内部重复四行或索要确认
真正解锁下一动作的证据、输入纠偏、风险或阻断 → 使用真实内部消息；正常过程随最终回复交付
同一种活 = 同一可复用能力族，动作动词与项目名称不单独划组
每个子任务的成功条件由父代理分别指定，不参与任务类型归类
已有组内子代理正在处理第一个子任务，另有第二个同类型子任务 → 复制组内子代理并行处理
还有第三个同类型子任务 → 继续复制组内基准子代理，依此类推
复制的是任务类型组里的子代理，不是任务类型组
复制须提供必要质量、降低全任务总成本，或在成本相近且用户有当前期限时缩短完成时间
每次复制前判断保留子代理是否确有进步空间
没有 → 普通复制，沿用已有配置和经验
有 → 父代理按任务类型联合选择完整可行配置组合，本次复制成为变体
真实依赖关键步骤完成 → 子代理发送一条短消息后立即继续；其余过程不重复发送
父代理无异议 → 沉默；发现问题 → 立即纠偏，仍守住权限和停止条件
```

## 七、条件性验证

### 迭代阶段

- 每次改动只运行最窄、最可能失败的检查；
- 父代理直接调用工具，默认使用简短输出；
- 失败后只展开失败项，修复后只重跑受影响检查；
- 相关实现仍会变化时，不启动最终验证子代理。

新增测试应能发现实际行为错误或保护重要不变量；低风险可逆改动不添加仅重复实现、逐字
匹配文案或证明助手自设流程的测试。既有公共约定和安全、数据、权限限制所需检查仍执行。
验收预期来自用户要求、已有公共约定、可信样例或独立计算，不能仅从当前实现或实际输出倒推。
模型可以编写测试；实现失败本身不能成为放宽断言、删除场景、跳过测试或将实际输出改为预期的
理由。需求变化或测试确实错误时可修正，但须指出对应要求和证据，并保留仍有效的回归保护。
小改动由父代理核对预期来源；公共接口、持久状态或复杂交互的独立验收有必要收益时，审核者
从原始要求与可信基线确定用例，再检查实现，不以作者解释替代依据。换模型或隐藏用例都不自动
证明独立性、覆盖充分或真实入口可用，也不要求每次改动都增加独立代理。
提示或技能语义变化需要行为证据时，用少量真实任务或有限情景检查决定与交付，不用更多
关键词断言冒充真实表现，也不重新测试未受影响的代码。

### 需要语义复核时

- 只有代码、配置、公共行为或高风险范围变化时，才做会推动修改的语义复核；
- 高价值且可独立阅读的复核可以交给子代理；
- 调查、解释、简单工具工作和纯只读任务不固定进入冻结步骤。

一次复核返回问题后，先集中修复，再对改动、失败项和受影响风险做增量复核。只有新证据、
依赖、公共约定或风险范围发生变化，才扩大范围；换了模型或开启 `ultra` 不构成新理由。
如果剩余疑问只能通过编译、运行或用户操作确认，停止追加同类静态意见，执行已授权的最窄
决定性验证。复用通过证据不能跳过仍在活动清单中的未完成验收；无关历史中的未验证项则
不能借此复活。尚未获准的外部动作保留为明确缺口；不把“不能整包编译”自行扩大为禁止所有
窄检查，也不把窄验证授权扩大为发布。高风险的必要独立复核仍保留，不设机械轮数上限。

### 最终条件

- 只运行当前改动和风险需要的最终检查；
- 多个短命令优先工具级并发；
- 验证需要持续语义判断或能与父代理真实并行时才调用子代理；
- 代码再次变化后只补跑受影响检查，未受影响证据继续复用。

## 八、禁止的伪并行

- 提前启动没有真实任务、只负责等待的子代理；
- 派子代理审批是否应该再派子代理；
- 父代理读完全部内容后，再让子代理重复读取；
- 把严格前后依赖伪装成并发；
- 多个子代理在没有所有权范围时覆盖同一文件或状态；
- 主任务完成后等待经验、比较、清理或版本维护；
- 把子代理自报、编译或模拟结果冒充真实运行证据；
- 建立共享中转文件，或让一个子代理代交、汇总其他子代理的结果；
- 没有真实统一依赖时反复轮询或等待全部子代理。
