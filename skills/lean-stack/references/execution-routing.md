# 执行路由

仅在“父代理直接做、工具并发、后台命令或模型子代理”之间难以判断，或者需要安排
条件性验证时读取。本文件展开执行细节，不增加第二套调用门槛。

## 一、插件强制调用边界

本技能适用后，父代理必须使用插件规则完成一次调用判断和后续选路，不再读取、引用或
套用官方默认调用触发规则，也不等待用户重复提出委派要求。只有运行环境没有可调用的
子代理能力，或者权限、安全和真实前置条件不允许时，才按能力缺口结束该调用路线。

`agents.max_concurrent_threads_per_session` 只作为可见并发容量上限，不是调用触发条件；
它不包含父代理。没有可见配置时读取运行环境实际容量，容量是上限而不是调用目标。

### 未完成要求锚点

锚点是活动清单中最早一个尚未完成，或已经完成但尚未通过用户可见回复交付的要求。完成且
已经交付的要求立即退出，不等待用户再次确认；纠正只重新打开真正受影响的项，“继续”只恢复
剩余项。最终说明只报告上一次用户可见交付后新完成的结果和当前剩余边界，不重述已经交付的
历史事项，除非用户明确要求回顾或当前结论确实依赖它。

## 二、三项原则

安全、权限、数据完整性、明确验收条件和诚实证据始终是底线。

1. 高价值工作：质量优先，同时提高正确性和决定性证据；可靠性相当时再比较完成时间。
2. 普通工作：达到质量底线后速度优先，选择总完成时间更短的路线。
3. 成本：没有相应质量或速度收益时，不得让新增调用使总成本大幅增加；结果相当时选择
   成本更低的路线。

高价值不等于自动多派子代理。独立复核能增加新证据时可以接受更多时间和成本；重复阅读、
多人猜同一个修法和没有新证据的共识不会提高质量。

兼容、跨版本回迁、机制替换、镜像文档、测试矩阵或发布闭环可能扩大维护面时，先读
[反 AI 过度工程](anti-overengineering.md)。这属于构建范围判断，不是增加子代理的理由；没有
现实消费者或当前来源证据时先删除多余工作项，再对剩余真实任务做一次调用判断。

消融是另一条显式反馈循环：只有用户明确要求对当前制品“进行消融实验”、精简代码或设计、
去掉不必要抽象或同义操作时，才在当前设计或实现形成可验收基线后读取
[消融反馈循环](ablation-loop.md)。普通完成、重构、语义复核和最终验证不自动触发，也不例行
追问用户是否要做。正式消融的独立上下文仍按本文件的一次调用判断与协作边界选择。

## 三、一次选路、立即并行

每条新用户消息先判断是新要求、对活动项的调整、使已交付结果失效的纠正，还是取消、替换、
状态询问或“继续”。只更新对应项并重新判断受影响的任务形状、依赖、风险和可用能力；未变化
的活动项继续，已经交付且未受影响的历史项不复活。

进入工具或代理路线前，先按 `SKILL.md` 的“首条快速说明”给出当前理解、立即动作和必要边界，
随后继续而不建立确认往返；能直接答完的请求由最终答案本身完成，不重复发两份前言。

```text
当前任务类型需要持续模型判断吗
├─ 否：父代理短命令 / 一次工具并发 / 持续终端或后台
└─ 是：是否已就绪、边界明确、可安全独立推进，并有质量或速度收益
   ├─ 否：父代理完成或等待真实前置条件
   └─ 是：新增调用是否大幅增费且没有相应收益
      ├─ 是：父代理完成
      └─ 否：立即调用，父代理同步推进，在真实依赖点汇合
```

“已就绪、边界明确、可安全独立推进且有收益”是一次整体判断，不拆成连续多道否决门槛。
收益只需基于任务形状形成合理预期，不要求量化证明、令牌估算或评分表。对收益不确定、
但可用低成本有界只读任务并行核实的情况，可以先调用一个 `gpt-5.6-luna` 子代理消除
不确定性；需要更可靠语义判断但不属于高价值边界时优先 `gpt-5.6-terra`。多个独立普通
子任务已经就绪、边界清楚且提交和核验成本轻时，更倾向用低成本子代理并行；第二个及后续
调用只需证明能缩短整批完成时间并覆盖其轻量额外成本。低成本路线不达标时只升级当前
子任务。高价值、复杂、模糊或高风险工作才优先 `gpt-5.6-sol` 和必要的更高思考程度。

确定性工具路线：

- 几秒的命令由父代理直接运行；
- 多个独立短命令在一次工具调用中并发运行；
- 长但步骤确定的工作进入持续终端或后台，父代理继续其他工作；
- 不让模型子代理只运行命令并回报退出码。

### PowerShell 复杂转义止损

PowerShell 使用以下止损规则，避免把一次解析问题扩成多轮长命令重写：

1. 简单、短小且只有一层普通参数的命令仍内联执行。
2. 命令含多层引号、嵌套 JSON、正则表达式、反引号、多行脚本或复杂变量插值时，首次执行前
   优先写成任务专属临时 `.ps1`，再通过 `-File` 调用。
3. 如果第一次内联失败明确属于 PowerShell 解析或转义问题，立即停止继续改写长 one-liner；
   后续修复只编辑同一个临时脚本本体再重跑。失败来自业务逻辑、路径不存在、权限或被调用
   程序时，按真实原因处理，不能误判为转义问题。
4. 脚本用 `param()` 接收路径和普通参数，路径操作优先 `-LiteralPath`；外部输入作为参数传入，
   不再拼接成可执行代码。凭据、令牌或秘密沿用已有安全通道，不写入脚本或命令行参数。
5. 临时 `.ps1` 是任务执行制品，不进入仓库或提交。需要清理时，普通脚本移入 Windows
   回收站；重要诊断脚本或证据移入任务专属 `待删文件`。
6. 不为这条规则建立 PowerShell 包装框架、通用执行器、后台服务、自动重试器或新的状态机。

模型子代理路线：

- 父代理先判定具体任务类型；一次调用判断通过后，再判断该任务类型是否适合已有任务类型组，
  不提前判断稳定性；任务类型组确定前禁止复用或定制子代理，也不得选择具体配置；
- 适合已有组时立即复用组，再检查可见的保留子代理：有则复用；没有则由父代理定制运行时
  新子代理；不适合已有组时先开新组，再定制运行时新子代理；
- 复用保留子代理时，父代理只传入当前子任务及为它单独指定的成功条件；保留子代理读取
  自己的经验和已有配置并自行声明。定制运行时新子代理或变体时，父代理根据任务类型、工作
  价值、风险、证据形状、时延要求和总成本，联合选择并写入完整的模型、思考程度和速度组合；
- 默认使用平面子代理。只有一个获批子项目本身还有多个已就绪、互不重复的独立切片，而且
  局部拆分、纠偏和汇合能减少父代理堵点时，任务卡才指定 `协作角色: 协作父代理`、
  `允许下游委派: 是` 和有限下游范围；
- 协作父代理只有在真实拥有顶层 `collaboration.spawn_agent` 且仍有可用容量时才委派下游。
  工具缺失、直接调用失败、边界不清或写入无法隔离时停止协作父代理路线，由整合父代理改走
  平面路线；不能用 `ALL_TOOLS`、角色 TOML、模型目录、共享文件或跨任务 API 猜测或冒充；
- 现有其他 Codex 父代理任务、`create_thread` 新任务、`read_thread`、`wait_threads` 和
  `send_message_to_thread` 属于用户可见的跨任务编排。当前用户已为本插件持续授权；只要符合
  三项原则、服务主任务、边界清楚且不涉及未获明确要求的永久删除，就可直接进入并指定唯一
  整合父代理，不再重复询问；这条路线不是内部委派；
- 父代理同时给出父代理规范任务名、有限关键步骤清单和停止条件；规范任务名不是 Codex
  线程 ID。没有值得中途报告的步骤时明确写“无”，不把命令、工具调用或普通小动作逐个列为
  关键步骤；
- 每次 `spawn_agent` 或 `followup_task` 启动新的当前子任务时，两条路线的子代理都在该子任务
  中声明固定四行实际配置。当前工具表确实有 `collaboration.send_message` 时，直接用它向
  父代理规范任务名单独发送；同时在自己的任务界面以 commentary 公开同一四行，最终回复
  顶部再次写实际模型、思考程度和速度。三处值必须真实一致，但内部消息、用户可见公开、
  reasoning、读取、分析、其他工具调用和真实工作之间不规定具体先后；
- 不得用 `list_threads` 搜索父代理所在任务，或用 `send_message_to_thread` 跨任务发送来替代
  内部父子消息；按本技能三项原则直接授权的父代理跨任务协作不受影响，但仍是另一条用户
  可见路线。自身界面的公开副本不能冒充内部消息；
- 内部父子消息工具不可用时，子代理仍在自己的代理线程输出声明并在最终回复报告能力缺口；
  中途可见交流是成功条件时停止真实任务，只有完全自包含、无需中途纠偏的有限任务才继续；
- 父代理工具表不代表子代理工具表；只有真实收到当前子代理的内部 `agent_message`，才确认
  这条运行路线内部交流可用。新任务或新的生成路线重新核验，不永久缓存能力；
- `spawn_agent` 没有逐个工具授予参数，内部消息也不是可臆造的 MCP 工具。角色 TOML 不能
  替父会话启用协作；保留 TOML 只用 `[skills] include_instructions = false` 缩小窄角色上下文。
  新会话第一次启动 Luna 子代理前，父代理确认 `agents.enabled` 没有关闭，并确认实际 Luna
  模型目录为 `multi_agent_version=v2`。目录仍为 v1 时即使会话显示 v2，子线程也没有内部工具；
  中途交流必需时停止该子任务，不能升级模型、增加成本或用跨任务 API 冒充；
- 配置声明不计入关键步骤消息；父代理不轮询或等待，只核对消息渠道、内容和实际值，不校验
  它与其他运行事件的 ordinal 或时间顺序；
- 父代理继续需求、架构、集成、共享状态或关键路径；独立证据本身是目标时可以等待证据；
- 子代理每完成一个预设关键步骤就发一条简短概述并立即继续，不等待父代理；每个步骤最多
  一条常规进度，同一方向风险只在状态实质变化后再次报告，不发送定时心跳或纯确认消息；
- 父代理无异议时沉默或只回一行；发现问题立即纠偏或更新当前任务目标，但不得扩大用户
  授权、移除停止条件或把有限任务扩成无限任务；
- 每个子代理达到成功条件或停止条件并自检后，在自己的线程用最终回复各自提交精炼结果；
  不建共享中转文件，普通子代理不由一个子代理汇总其他子代理。任务卡明确指定的协作父代理
  只核验并整合自己下游子代理已经独立提交的结果，不能压掉、改写或冒充这些结果；
- 子代理结果可采用而父代理仍要运行测试或集成时，有空闲容量可同时启动只读经验准备子代理，
  整理跨任务角色和经验候选；父代理立即继续测试，不等待，准备阶段不写 SQLite。准备只是
  提前优化，没有容量或没有赶上都不取消核验采用后的默认保留和经验提交；
- 父代理在结果返回时分别接收；只在下一步真正依赖某个结果时汇合，不主动反复轮询，只有
  统一收口确实依赖全部必要结果时才等待全部；
- 任务类型组、稳定性、保留子代理和经验侧链都不参与当前是否调用的判断。

协作父代理、父代理之间的显式任务编排、任务卡、`BLOCKED` 和子树交接细节见
[协作父代理与父代理之间](collaboration.md)。协作只缩短局部工作，不能另立主线、增加权限、
建立非授权留言板或让代理共识替代权威来源和真实验证。

## 四、可写并行保护

多个可写子代理可以并行，这不是单写入者规则：

- 写入范围能天然分开时，在同一检出目录分配不重叠文件、目录或模块；
- 清单、锁文件、公共接口、数据库结构和生成入口等共同热点最后集中整合一次；
- 同一物理文件或不可拆分状态重叠时，只有运行环境真实提供独立检出目录才允许多条直接
  写入路线；否则一个候选写实际目标，其他候选只返回方案、补丁或证据；
- 汇合时检查真实修改范围、越界、重叠和基线变化，只运行受影响检查；
- 不增加认领数据库、锁租约、心跳或后台协调器。

需要撤销被否定子代理的共享写入时，必须能用所有权范围、调用前基线和当前哈希精确归因；
禁止整树回退。完整边界见[可写子代理并行](write-parallelism.md)。

## 五、容量与成本快判

插件不设置同时调用数字，也不设置主任务累计调用数字。一次选路通过的任务类型按当前
运行环境实际可用的全部并发槽位启动；容量不是调用目标，也不要求占满。

固定成本预估先给普通工作一个正向选择：窄、清晰、重复、易核验时优先
`gpt-5.6-luna`；需要可靠判断但不是高价值边界时优先 `gpt-5.6-terra`；高价值工作才优先
`gpt-5.6-sol`。模型、思考程度和速度不是三个独立选择；父代理按任务类型一次确定完整组合，
并把快速速度带来的时延收益与额外成本一起计算。它再回答一个停止问题：新增调用是否会使总成本大幅增加，而且质量或速度
收益不足以覆盖？如果是就停止该调用；否则使用已有容量。运行时不重新搜索费率、不逐项
计算令牌，也不把调用次数直接当成本。默认使用标准速度；快速速度只用于真实关键路径收益
足以覆盖加价时。

成本预估维护位于[成本预估](cost-baseline.md)。每周状态由 `scripts/cost_check.py` 在真正
不阻塞主任务时检查；七天未到不联网，到期但不能非阻塞核对就延后。它不参与每次调用，
不创建 Codex 自动化、系统定时任务或外部守护进程。

以下做法错误：

- 为占满容量制造任务；
- 重复读取同一个子任务却没有新的证据或可归因收益；
- 父代理已经完成时继续启动下一轮；
- 把保留子代理创建或经验维护当作当前调用前置条件；
- 因为收益不能精确量化就默认不调用；
- 忽略启动、汇合、验证或写入冲突造成的真实成本。

## 六、任务类型组与保留子代理

任务类型组组织已经决定调用的运行时候选，不决定是否调用。只有核心职责、主要来源或工具、
证据形状都相同才归入同一组；决定性边界不同且能形成独立可复用职责时就建立不同组，不能
只因属于同一主任务、仓库或功能而合并：

```text
父代理判定具体任务类型 → 确认应该调用 → 判断是否适合已有任务类型组
适合 → 立即复用组 → 检查可见保留子代理
可见 → 复用保留子代理 → 子代理读取自己经验和配置并自行声明
不可见 → 父代理定制运行时新子代理并联合选择三个具体配置值
不适合 → 开新运行时任务类型组 → 父代理定制运行时新子代理并联合选择三个具体配置值
父代理为每个子任务给出父代理规范任务名、有限关键步骤清单和停止条件；规范任务名不是线程 ID
spawn_agent 或 followup_task 启动新子任务 → 子代理通过内部 collaboration.send_message 发送完整四行声明
→ 在自己的任务界面公开同一四行，最终回复顶部再次写实际模型、思考程度和速度
→ 三处使用实际值；不规定声明、reasoning、读取、分析、工具调用和真实工作的具体顺序
→ 声明不计入关键步骤消息，也不等待确认
同一种活 = 同一任务类型
每个子任务的成功条件由父代理分别指定，不参与任务类型归类
已有组内子代理正在处理第一个子任务，另有第二个同类型子任务 → 复制组内子代理并行处理
还有第三个同类型子任务 → 继续复制组内基准子代理，依此类推
复制的是任务类型组里的子代理，不是任务类型组
每次复制前判断保留子代理是否确有进步空间
没有 → 普通复制，沿用已有配置和经验
有 → 父代理按任务类型联合选择完整可行配置组合，本次复制成为变体
每完成一个预设关键步骤 → 子代理简短概述后立即继续，不等待父代理
父代理无异议 → 沉默或一行答复；发现问题 → 立即纠偏，仍守住权限和停止条件
达到成功条件或停止条件并自检 → 在自己的线程用最终回复各自提交精炼结果
父代理仍要测试或集成且有空闲容量 → 同时启动有限只读经验准备；父代理不等待
测试失败或用户否定 → 丢弃候选；准备未赶上 → 不影响核验采用后的默认 ensure/improve
父代理分别核验和使用 → 只在真实依赖点等待，不主动轮询或为收齐而等待全部
变体比较完整配置组合是否值得替换；单轴变化仅是可选因果实验
只要出现复制或变体 → 本组当前已就绪结果全部核验后启动竞争
→ 同一任务类型组全部子代理竞争 → 选出唯一留下的子代理
→ 结果核验采用 → 先形成领域、输入形状、通用职责、交付与硬边界的全局合同
→ 合同可跨任务、跨项目、跨会话复用 → 第一次成功默认只尝试一次 ensure 全局领域保留
→ 仍绑定当前项目、插件、个人技能或一次任务 → 使用本轮结果，但跳过全部持久写入
→ 启动前给出 UUID run_id；成功条件达到、结果核验采用且线程 Done → 一次 record-run
→ 失败、停止、否定、未采用或仍在运行 → 不计存活轮次
→ 泛化、去敏、去重并用稳定 event_id 默认一次 improve 追加一条全局领域经验
→ 只有没有新增经验或明确排除项才跳过并写明原因
→ 其他运行子代理移出组、结束并进入 Done
没有竞争 → 结果核验采用后也对原本唯一子代理执行相同的默认提交
每个合格全局领域任务类型组各保留一个休眠配置；不同领域可同时保留多个，当前线程不会无限运行
```

定制运行时新子代理不等于先持久创建配置。复制的是组内子代理，只处理同一任务类型的额外
已就绪子任务；变体只能由复制组内子代理产生，其模型、思考程度和速度按任务类型联合选配，
允许形成完整可行组合而同时变化。两者都不写 SQLite 候选状态。每个不同任务
类型组的唯一结果通过核验并被采用后，先判断能否泛化成整个 Codex 跨任务、跨项目、跨会话
复用的领域职责；通过合同后，第一次成功就在组结束位置尝试持久保留并追加一条泛化、去敏、
非重复的经验。不要求重复、接近结束或并行窗口。结果未验证或未采用、用户否定、仍含来源
项目身份，或权限、安全、SQLite、文件、身份、CAS 失败时安全跳过。插件只有全局领域保留池，
没有项目保留层；领域角色可以只覆盖特定技术领域，不要求处理所有项目类型。
这只保留休眠配置，不延长当前子任务。父代理最终按组报告角色和经验保存回执。详细边界见
[子代理委派](delegation.md)和[保留子代理经验](specialist-memory.md)。

## 七、条件性验证

### 迭代阶段

- 每次改动只运行最窄、最可能失败的检查；
- 父代理直接调用工具，默认使用简短输出；
- 失败后只展开失败项，修复后只重跑受影响检查；
- 相关实现仍会变化时，不启动最终验证子代理。

### 需要语义复核时

- 只有代码、配置、公共行为或高风险边界变化时，才做会推动修改的语义复核；
- 高价值且可独立阅读的复核可以交给子代理；
- 调查、解释、简单工具工作和纯只读任务不固定进入冻结步骤。

### 最终边界

- 只运行当前改动和风险需要的最终检查；
- 多个短命令优先工具级并发；
- 验证需要持续语义判断或能与父代理真实并行时才调用子代理；
- 代码再次变化后只补跑受影响检查，未受影响证据继续复用。

## 八、禁止的伪并行

- 提前启动没有真实任务、只负责等待的子代理；
- 派子代理审批是否应该再派子代理；
- 父代理读完全部内容后，再让子代理重复读取；
- 把严格前后依赖伪装成并发；
- 多个子代理在没有所有权边界时覆盖同一文件或状态；
- 主任务完成后等待经验、比较、清理或版本维护；
- 把子代理自报、编译或模拟结果冒充真实运行证据；
- 建立共享中转文件，或让一个子代理代交、汇总其他子代理的结果；
- 没有真实统一依赖时反复轮询或等待全部子代理。
