# 全局领域保留子代理经验

专门代理记忆就是经验。仅在有限范围内发现仍可能复用的子代理、读取命中子代理的必要经验，或
已验证并被采用的任务类型组已经能泛化成全局领域职责，需要创建
或安全重配保留子代理、追加跨项目可复用经验，或者一个插件精确拥有的子代理需要按严格规则
永久移除时读取。运行时先复用适合的任务类型组和可见保留子代理；没有可见保留子代理或需要新组
时，由父代理定制运行时新子代理完成真实任务。创建、安全重配和经验维护只是结果出来后的
非阻塞持久侧支，任何一项都不能进入普通分派热路径或成为当前调用门槛。

只有全局领域保留，没有项目保留。全局领域子代理可以只覆盖 QML、媒体编码、插件、检索、发布、
协作或生命周期等某一类工作；它不需要处理所有技术栈，但必须能在整个 Codex 中跨任务、跨项目、
跨会话复用。当前项目、插件、个人技能或一次任务专属的运行时组只有先去除来源身份、形成可审计
领域规则后才可持久化；无法泛化时只使用本轮结果，跳过全部持久写入。

每个不同任务类型组的唯一子代理或唯一胜者，其结果通过必要核验并被父代理采用后，父代理先
形成全局领域规则：领域键、跨项目输入形状、通用职责、可验证交付和硬性限制。规则按可复用
能力族定义，不把当前项目、框架、动作动词、交付名称或一次性成功条件固化成领域；同一能力
族中兼容的调查、诊断、实现、修复、测试或验收可由同一子代理承接。工具、写入权限、安全风险
或决定性证据形状不兼容时仍分开，范围放宽不得把只读子代理改成写入子代理。规则通过后第一次
成功就默认跨任务、跨项目、跨会话保留，不要求此前已经重复、等待主任务接近结束或等待并行
窗口。这个事实自动授权插件拥有的非破坏性创建、安全重配、一次泛化经验追加和经验摘要压缩；
用户明确否决时不得执行。上述自动持久化授权本身不覆盖不可恢复的物理销毁；永久移除只由
用户已明确指定的累计第二次任务失败规则，或下文严格的零经验、零尝试手动删除规则触发。不得保存当前提示、源码、
仓库、项目名、插件名、个人技能名、路径、网址、日志、凭据、固定版本/文件清单或一次任务事实。

默认提交只有明确排除项：结果未通过核验或未被采用；用户明确否定；子代理或经验无法安全
去除来源项目身份、上述一次性或敏感内容，因而不能形成全局领域规则；权限、安全、SQLite、
文件结构、忙锁、损坏、身份或 CAS 使本次
短写不能立即安全完成。没有空闲容量、准备未赶上、没有剩余收口工作或主任务已经满足，不是
取消默认单次尝试的理由。每次失败都立即辅助跳过，不排队、不轮询、不重试，主任务继续。

跨任务保留与经验维护使用两个不同范围：

- 子代理交付可采用结果、父代理仍要运行主任务测试或集成时，有空闲容量且经验准备子代理
  本身通过三项原则，才可启动一个低成本、
  只读、步骤有限的经验准备子代理，整理通用子代理和去敏经验候选；父代理同时继续测试，不等
  它。准备子代理不写 SQLite，只是提前优化；没有准备或准备未赶上不影响正式提交。
- 全局领域保留在唯一子代理确定、结果核验采用并通过规则检查后先执行首次 `ensure`。这是
  确定性的短本地写入；只有响应明确为 `reconfiguration_required` 或
  `global_contract_refresh_required` 时，才使用响应返回的当前 SHA 对同一已采用配置作一次 CAS
  确认。该确认不是锁或普通失败重试；锁、CAS、结构、文件或写入不能立即满足时跳过，不排队、
  不轮询、不再次尝试。
- 已采用结果有新增经验时，默认只尝试一次 `complete-run`，在同一短事务中幂等记录明确结果与
  一条去敏、去重经验。父代理只需提前生成稳定的 UUID `run_id`；脚本在事务前由 `run_id` 和
  调用方 CAS 快照确定有效的经验事件 UUID。相同请求可直接重放，事件、文件或提交失败时结果与
  经验整体回滚。没有新增可复用内容时只记录明确结果，并报告未写经验的原因。
- 摘要压缩仍只在能与真实工作并行且不争用时执行；不能并行时只推迟摘要，不能取消已经完成
  的原始经验追加，也不能延迟主任务交付。

内部消息不是 SQLite 字段或可臆造的 MCP 工具。自定义子代理 TOML 不能替父会话启用协作；
保留 TOML 使用 `[skills] include_instructions = false`，只缩小窄子代理上下文。父代理在启动前
验证配置、身份、哈希、父会话 `agents.enabled` 和实际 Luna 模型目录的
`multi_agent_version=v2`。内部通道以真实业务消息证明，不额外发送配置副本或无业务探针。
自包含任务不以内部消息作为成功前提。目录仍为 v1 或直接调用失败时，
中途交流依赖型子任务立即停止；不能升级模型、增加成本或用跨任务 API 冒充。成功轮次仍归
原保留身份，不另建子代理。

主任务不依赖任何持久写入成功。

复制、变体、配置比较和经验转移直接决定 SQLite 归属，但不扩张数据库对象，也不决定
当前是否调用子代理：

1. 复制的是任务类型组里的子代理，只处理同一任务类型的额外子任务；普通复制和变体都是
   运行时调用，本身不写入 SQLite 台账。复用保留子代理及普通复制时，父代理从 TOML/recall
   取得已有经验、实际模型和思考程度，并在每次 `spawn_agent` 显式传入后两项；TOML 不代替
   原生参数。
2. 每个子代理完成当前子任务并按父代理指定的成功条件自检后，立即在自己的线程用最终回复
   提交自己的精炼结果；父代理分别核验和使用，不由子代理预先合并，也不是只选一个。
3. 只有复制前确认保留子代理确有进步空间时，父代理才根据任务类型联合选择模型与
   思考程度组合形成变体；两个字段可以因相互制约而同时变化。只要出现复制或变体，
   组内当前已就绪结果完成必要核验后就竞争，先选出唯一留下的胜者；竞争不让子代理自行决定
   配置，也不删除、延迟或替换已经各自提交的合格结果。单轴变化只在明确需要识别因果时作为
   可选实验。没有复制或变体时，原本唯一子代理直接进入下一步跨任务保留判断。
4. 不同运行时任务类型组第一次成功且结果核验采用后，只有全局领域规则通过才默认创建记录；
   已有同一全局领域记录且胜出配置不同时，用当前哈希保护重配同一条记录，不为胜者新增第二条
   同领域记录。
5. 跨任务保留完成或安全跳过后，把胜出方法和其他调用中的失败避免信息去敏、去重，默认合并为
   一条新增经验，只追加给
   保留子代理。
6. 经验维护完成或跳过后，其他运行时调用才移出组、结束并从运行时候选中消除；同一任务
   类型组和 SQLite 中都只剩一个保留子代理。

辅助脚本是 [agents.py](../scripts/agents.py)。`status`、`recall`、`ensure`、`complete-run`、`record-run`、`improve`
和 `delete` 是普通按需能力，不构成固定后台生命周期。结果已经核验并被采用时，父代理必须用
对应的 `complete-run` 记录完成；新运行时组能够泛化时先 `ensure`，只有命中明确排除项才跳过并
记录原因。普通状态查询、迁移、删除、摘要维护和单独经验修正仍按需使用，旧 `record-run` 保留
兼容，`improve` 不能代替本次完成收据。`migrate-global` 只把结构精确匹配、现实存在的 v1/v2/v3 台账
通过完整计划显式收敛到当前全局领域结构；`migrate-attempts` 只把精确 v4 或 v5 台账显式升级为
当前尝试与经验结果关联结构，不推断历史失败或历史经验复用。任何数据库、文件、结构、锁或运行环境可见性失败都返回
`auxiliary_skipped`，不能拖延真实任务。

## 保留子代理 TOML 的宿主预配置

`agents.py ensure` 的 `--speed` 只配置插件拥有的保留 custom-agent TOML，并会影响宿主以后如何
调用该具名子代理：`--speed standard` 不写 `service_tier`，`--speed fast` 写入
`service_tier = "fast"`。这个字段必须在创建、安全重配、旧台账迁移、经验刷新和摘要改写中保留并
校验，不能因为整理模型路由文档而删除或重置。

当前 `spawn_agent` 接口只显式接收模型与思考程度，没有逐次速度、`service_tier` 或 `priority`
参数。因此，保留 TOML 的该项宿主预配置不参与模型与思考程度联合选配，也不进入 `MODEL_ROUTE`、
任务卡或五行开场；模型与思考程度路线不能修改它。`status --for-routing` 与 `recall` 可以返回实际
预配置，供父代理复用已加载配置时保持事实一致，但返回值不是新的选配轴。通用子代理仅使用宿主
会话已有配置，插件不声明未观察到的具体值。

相关官方边界见 [Codex 速度](https://learn.chatgpt.com/docs/agent-configuration/speed)、
[Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)和
[Codex 子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents?surface=app)。

## 在其他项目发现与复用

优先按当前可见子代理的职责、输入形状和证据匹配；描述不足、可能遗漏复用时，才读取一次精简
目录；准备以“没有合适保留子代理”为由新建运行时子代理前，尚未查过目录就查这一次。先比较职责、
输入和证据，名称、来源项目或配置差异不能单独证明无匹配。当前工具已提供足够匹配信息时直接
复用，不为复用率增加无用调用。把下面的占位路径替换为当前已加载 `SKILL.md` 所在绝对目录，Windows 示例：

```powershell
$leanScript = '<已加载技能的绝对目录>/scripts/agents.py'
py -3 -X utf8 -B $leanScript status --for-routing
```

本节以下命令中的 `./skills/lean-stack/scripts/agents.py` 是源码仓库示例；在其他项目统一换成
`$leanScript`。不要为了调用插件切换项目、拷贝脚本或扫描安装目录猜版本。

目录核对已登记子代理的文件身份与全局规则，只返回名称、中文职责、领域、规则、模型、思考
程度、具名子代理的 `service_tier` 预配置（如有）和权限形状，不返回经验正文、路径、令牌、哈希或
生命周期统计。该预配置不是路由输入；父代理比较任务规则，模型与项目名不决定子代理是否匹配。
结果在当前上下文复用，相关配置变化才刷新。

目录存在不等于当前生成工具已经加载子代理。可调用且配置适配就直接复用；仅部分职责匹配时，
把匹配的已就绪切片交给它，剩余部分由父代理或其他合适子代理承担，不扩大子代理硬性限制。
需要适配而工具不能覆盖配置，或目录中的子代理未加载为可调用类型时，用单子代理入口取得职责与经验：

```powershell
py -3 -X utf8 -B $leanScript recall --name <目录中的精确子代理名>
```

该入口只核验命中子代理的所有权、规则、文件身份和哈希，返回职责规则、模型/思考程度、具名子代理的
`service_tier` 预配置（如有）、权限形状、当前 SHA-256、有限经验正文、当前经验版本摘要，以及可直接放入开场的“存活轮次”和
“经验”两行客观状态；不返回令牌、路径、整段执行提示或其他子代理。
可选 `--expected-sha256` 锁定已取得的快照。读取失败不绕过身份保护。将适用职责、必要经验和
当前任务范围交给运行时适配子代理，不注入无关经验；经验的适用范围服从当前事实与用户要求。
临时调用不记作原保留身份的成功运行，也不新造同领域记录；
结果采用后再按同一身份的 CAS 规则决定是否更新未来配置。读取失败即报告缺口并继续可安全
独立完成的任务，不加重试、后台目录或热加载等待。

## 每个全局领域任务类型组只保留一个，多个领域可以同时保留

各子任务的真实结果和必要核验完成并选出唯一子代理后，只要结果已被父代理采用、完成全局领域
规则且未命中明确排除项，第一次成功就默认执行首次 `ensure`；该事实即提供这项非破坏性自动
授权。只有首次响应明确要求配置重配或全局合同刷新时，才按下方 CAS 规则确认一次同一请求。
一次性或来源项目语义无法安全去除、未通过、未采用和被用户否定的子代理不保留。不得
写入当前提示、源码、仓库、项目/插件/个人技能名、路径、网址、日志、凭据或一次性任务：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py ensure `
  --role-key qml-binding-diagnostics `
  --global-domain-key qml `
  --global-contract '{"domain":"QML 绑定诊断","input_shapes":["绑定依赖与运行警告"],"responsibilities":["定位可复核根因"],"deliverables":["最小处理与证据"],"hard_boundaries":["不固化来源项目"]}' `
  --origin-term <当前项目名> `
  --display-name "绑定诊断员" `
  --description "重复诊断绑定循环、依赖失效和运行时警告。" `
  --instructions "追踪实际绑定依赖，返回可复核根因和最小处理。" `
  --model gpt-5.6-terra `
  --reasoning-effort high `
  --speed standard `
  --authority read
```

`ensure`、`improve --lesson`、`improve --summary` 和迁移计划中的每个子代理都必须至少提供一个
非空 `origin-term`。来源词只用于拒绝把当前项目、插件或个人技能语义写入长期子代理和经验；
它不进入 SQLite、TOML、全局规则或完成收据。调用者必须提供当前任务的真实来源词，不能用
无关占位词绕过语义检查。

行为如下：

- 没有匹配任务类型：创建一个插件拥有的保留子代理配置，供未来新任务使用；
- 配置完全相同：复用；
- 配置不同：不写入，返回 `reconfiguration_required`；
- `--speed` 按“保留子代理 TOML 的宿主预配置”小节处理，既有配置无需迁移；
- 已验证胜出配置：使用返回的 `--expected-sha256 <当前哈希>` 再执行同一命令；
- 安全重配保留子代理身份、路径、所有权令牌、原始经验和压缩摘要，并返回
  `host_visibility=requires_new_task`；
- 看似受管但没有可信台账记录的同任务类型文件会阻止创建，不能擅自接管、删除或复制。

新建或重配的持久代理不假定能在当前任务热加载。当前任务已经使用复用的可见保留子代理
或父代理定制的运行时新子代理完成，不轮询、不重新加载、不重启。跨任务保留只让 TOML
配置和 SQLite 所有权记录休眠存在；当前运行线程照常结束并进入 Done，不持续调用模型。
重配前已经创建的子代理线程不会因 TOML 改变而刷新提示；不得用 `followup_task` 复用旧线程
冒充新配置验证。新通信规则必须在以后新任务生成的新线程中核验。

## 显式迁移现实旧台账

普通 `status`、`ensure`、`improve`、`record-run` 和 `delete` 只接受当前 v6 全局
领域、尝试审计与经验结果关联结构，不会把 v1、v2、v3、v4 或 v5 子代理静默解释成当前子代理。只有精确匹配已发布结构的现实旧台账
才能使用：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py migrate-global `
  --plan <完整 UTF-8 JSON 迁移计划>
```

计划必须覆盖全部旧子代理，并逐项给出旧名称、旧子代理键、当前 SHA-256、新子代理键、中文显示名、
通用描述和职责、全局领域键、五字段全局规则、至少一个来源词，以及需要泛化纠正的旧经验。
迁移整体预检身份、令牌、路径、哈希、规则、目标冲突和活跃经验；任一项
不合格就零写入停止，不自动合并、不自动猜测职责，也不增加项目保留层。

迁移保留同一 `agent_id`、所有权令牌、创建时间、全部 `agent_runs` 和原始经验事件。项目化旧
经验只通过确定性追加纠正退出活跃提示，原事件仍可审计。成功提交后，旧重要 TOML 以同卷
no-replace 移入 `<CODEX_HOME>/lean-stack/待删文件/全局领域迁移备份`；根目录只保留无令牌、
无经验正文和无绝对路径的完成收据。同一计划重跑只核验完成收据和当前 v6 状态，不依赖旧备份。

生成的 `developer_instructions` 第一段先写子代理、职责和权限，第二段才写通信规则。这个静态
结构只服务可读性；新生成线程须通过内部通道并在自身任务界面声明实际模型与思考程度，但不规定它们与
reasoning、读取、分析、工具调用或真实工作之间的先后顺序。

## 任务尝试、存活轮次与状态查询

“任务尝试”只记录已完成且由父代理取得明确最终判断的正式保留身份调用；“存活轮次”不是
模型消息数、经验事件序号或线程心跳。一次成功存活轮次定义为：一个正式保留
子代理，或承载其同一身份与配置的内置路线，完成一个新的当前子任务，达到父代理为本次单独
指定的成功条件，结果经父代理核验采用，并正常进入 Done。父代理在启动前于父侧生成 UUID
`run_id`，不把它写进子代理任务说明或可见回复；上述条件全部满足且有新增经验时，用一个入口
原子记录成功与经验：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py complete-run `
  --name <代理名称> `
  --expected-sha256 <当前哈希> `
  --run-id <父代理侧 UUID> `
  --invocation-kind spawn_agent `
  --outcome success `
  --loaded-experience-digest <调用前 recall 返回的 experience_digest，可选> `
  --origin-term <当前项目或插件名> `
  --lesson "可复用且有证据支持的经验"
```

`complete-run` 不接受失败结果携带经验；没有新增经验时省略 `--lesson`，即使调用方保留了
`--origin-term` 也会忽略该字段并只登记结果，避免为无经验结果形成失败重试；也可继续使用兼容
的 `record-run`。整个任务有决定性证据表明失败时，用独立 UUID 和 `--outcome failure` 记录。运行中、
中断、结果未采用、用户停止或否定、工具缺失后停止及结果未定都不属于明确任务失败，不提交
任何结果。`--invocation-kind` 只接受 `spawn_agent` 或 `followup_task`；`run_id` 同时绑定身份、
调用类型、结果和经验版本证据，同一组合重放幂等，任一项变化均安全拒绝。省略
`--loaded-experience-digest` 保持原有运行记录语义，但不产生经验版本与后续结果的关联证据；
提供时必须与同一 SHA-256 子代理的当前经验完全匹配。该关联只证明父代理声明用于本次调用的经验
版本与记录时的已验证子代理内存一致，不是宿主实际加载回执，也不证明经验造成结果。

新写入的带经验完成记录按 `run_id` 派生稳定事件身份，不再把会随经验更新而变化的 TOML 哈希
混入事件身份。首次完成仍严格校验 `--expected-sha256`；已完成运行的重复请求可以使用原请求
或返回的哈希，只核对同一身份、调用类型、结果、加载经验摘要、经验正文和纠正目标，并验证
磁盘文件仍与所有权台账一致，不重复写入结果或经验。已有记录不是允许新写入绕过 CAS 的理由。
旧版按首次 CAS 派生的事件继续支持原请求精确重放；没有保存首次哈希时明确拒绝，不按相同
正文或时间戳猜测关联，也不自动重写旧台账。重放历史记录不代表当前内容仍建议采用该旧经验。

`recall` 用两行客观状态显示总尝试、成功存活轮次、失败数、当前配置的活跃经验数，以及当前经验
版本后来关联记录的成功和失败。它不要求子代理判断经验是否适用于本次任务。这个反馈环把
“保存过文字”推进为“知道哪一版经验之后出现过什么结果”，但仍是可审计的提示记忆，不是模型
参数训练，也不能仅凭相关结果证明经验造成了成败。

同一身份累计第二次明确 `failure` 时，短事务永久删除该身份、全局规则、全部成功/失败运行、
原始经验、纠正事件和摘要，同时移除子代理 TOML；不生成退役身份、收据、待删副本或恢复入口。
响应可以返回本次删除前的累计数用于确认触发原因，但后续状态与路由中不再存在该子代理或这些
聚合。忙锁、CAS、文件或事务失败时，数据库与 TOML 共同回滚，不重试、不等待。

当前保留子代理数量、总尝试、成功、失败、磁盘 `lean_*.toml`、未登记文件和每名子代理的
存活轮次由状态命令统一报告：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py status
```

只需有限聚合时使用只读 dashboard 模式；它不返回子代理明细、路径、所有权令牌或经验正文：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py status --for-dashboard
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py status --for-dashboard --watch-seconds 2
```

第一条输出一次 JSON 快照。第二条是前台周期模式，每 1–3600 秒逐行输出一条 NDJSON，按
`Ctrl+C` 结束并返回 130；每轮重新用只读连接核验身份与聚合，不写数据库或状态目录。
这不是后台守护进程、定时任务或 Codex 插件卡动态扩展；当前宿主没有已验证的插件卡刷新规则，
因此不能把 `refreshed_at` 外推成界面自动更新。

SQLite v2 以前没有稳定运行 ID；显式迁移时保留全部代理与经验，但不猜测旧版历史次数，
所以从未有可审计成功记录的子代理会显示 0 成功轮次。0 只说明没有成功记录；用总尝试与失败数
可区分“从未调用”和“调用后失败”。精确 v4 或 v5 台账升级前必须显式运行：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py migrate-attempts
```

v4 中的既有 `agent_runs` 按其原规则只迁为成功；v5 保留既有成功和失败。两者的历史运行都不
回填经验版本摘要，也不从中断、未采用或其他状态猜测结果。成功与失败记录在子代理仍保留时追加；累计第二次明确失败触发永久移除后，
该子代理的全部运行与经验资料一并删除。

## 只保留有用经验

经验正文仍用 `lesson` 与 `summary` 提炼；只增加运行记录上的经验版本摘要以关联后续结果，不增加
优化器或训练任务：

1. **先分清原因。** `SKILL_DEFECT`（规则错误、缺失或歧义）才考虑修正规则；
   `EXECUTION_LAPSE`（已有正确规则未执行）记录有效纠正做法，不再堆同义提醒。工具、模型或
   环境问题单独说明；证据不足写“原因未明”，不强行归类，也不因失败自动改提示。
2. **经验保留适用范围。** 简写“适用情境 → 已验证做法 → 证据范围 → 例外或反例”。原始经验
   仍须去除来源身份；可以记录仅在一种情境核验的通用观察，但不得把“本次成立”提升成普遍规则。
3. **扩大范围需要不同样本。** 同任务重跑只证明可重复性；推广到其他输入或项目须有独立变体
   或另一任务证据，生成候选所用样本不能是推广的唯一依据。没有这种证据就保留窄范围，
   不为收口额外启动实验；摘要压缩可以照常合并文字，但不能把压缩当验证、丢掉例外或提升置信度。
4. **拒绝路线留下短避坑记录。** 只记录可复用的“候选做法及情境 → 核验后不采用的原因 →
   重开条件”，沿用原始事件与纠正机制；输入和环境未变不再试同一候选。方案未通过可以成为
   经父代理核验采用的失败避免结论，但用户否定的子代理及其结果仍不得作为经验来源，不能
   改称失败记录后回流；需要结论时从可信输入独立核验。失败记录不计成功存活轮次。

任务类型组的唯一子代理已经确定、结果通过必要核验并被采用后，自动授权为保留子代理默认
通过 `complete-run` 原子记录结果并追加一条提炼、去敏、非重复且可复用的经验。来自复制和
变体的多条观察先由父代理合并，只写入一个新的原始事件；没有复制或变体的组也从自己的已采用
结果提炼一条。只有没有任何新增可复用内容或命中明确排除项时才跳过经验并写明原因。
独立的 `improve` 保留给后续纠正、摘要以及旧调用兼容：

用户已经表示不满意的子代理及其结果永远不能进入经验候选、原始经验或摘要。经验写入前
收到否定时立即取消本次辅助动作。若原始经验已经误提交，SQLite 的只追加约束意味着不能
伪称物理删除；使用同一 `improve` 动作追加一个指向原事件的纠正事件：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py improve `
  --name <代理名称> `
  --expected-sha256 <当前哈希> `
  --origin-term <当前项目或插件名> `
  --event-id <纠正事件唯一标识> `
  --retracts-event-id <被否定原事件唯一标识> `
  --lesson "经过重新核验、可安全复用的纠正经验"
```

纠正事件和被否定原事件都只追加保留，不能更新或删除。脚本立即从保留子代理的活跃记忆
排除被否定原事件；若现有摘要可能已经覆盖它，就使该派生摘要失效，从未受污染的活跃
事件重新形成有限窗口并返回新的压缩需要。纠正不能安全提交时，不得复用受污染的保留
子代理；主任务由父代理或新的子代理从可信输入重做，不等待经验维护。

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py improve `
  --name <代理名称> `
  --expected-sha256 <当前哈希> `
  --origin-term <当前项目或插件名> `
  --event-id <唯一标识> `
  --lesson "可复用且有证据支持的经验"
```

原始事件和纠正事件都只追加；单条经验最多 4096 个字符，但事件总数量没有上限。一个原事件
最多只能有一个纠正事件，
纠正只能指向同一保留子代理的普通原事件，不能纠正另一个纠正事件。不得记录坏结果、
原始提示、源码、仓库路径、网址、日志、凭据或模型思维过程。每次更新只读取一个有限
活跃窗口，较早原始记录保留在数据库中等待以后增量压缩。摘要同时受字符数和 UTF-8
字节数限制；完整提示和完整子代理文件不设置 KiB 上限。当前提示中的经验窗口最多 4 KiB，子代理
说明、领域合同、单条经验、迁移计划和扫描数量仍分别由输入校验限制；生成后使用真实 TOML
序列化和回读验证结构。经验窗口数值只是插件自身的提示成本限制，不是用户要求或官方限制；
窗口放不下的事件仍留在 SQLite 等待摘要压缩，不截断或删除原始经验。
合法长事件可能使当前窗口尚未加载任何经验；此时 `recall`、路由目录和结果记录仍可使用，
`experience_loaded=false` 且经验版本摘要为空，开场明确报告已保存但待摘要压缩。旧版空窗口
同样可只读识别，不自动改写原文件。压缩触发计算摘要、标签和增量事件的完整 UTF-8 字节预算，
摘要任务同时携带字符与字节限制，不能把保存记录误记成实际加载证据。

返回 `compaction.needed=true` 时，只有摘要压缩能与仍需完成的真实工作并行且不争用时，才让
合格且成本较低的子代理并行压缩旧摘要和增量事件；否则推迟摘要，但不撤销已经追加的原始
经验。提交摘要：

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py improve `
  --name <代理名称> `
  --expected-sha256 <当前哈希> `
  --origin-term <当前项目或插件名> `
  --summary "压缩后的可复用摘要" `
  --covered-through <序号> `
  --source-digest <摘要来源哈希>
```

来源哈希和序号是比较并交换保护。摘要保留原因分类的不确定性、适用范围、证据程度、例外及
失败路线重开条件；相同证据的重复记录不算独立样本。刷新摘要永不删除或截断原始事件。若压缩会拖慢主
任务，直接推迟。

## 永久移除与严格手动删除

运行时复制和变体在唯一子代理确定、经验维护完成或跳过后移出任务类型组并结束，通常不留下
持久文件。若插件确实持久化了同组非胜出候选，普通手动删除仍沿用严格资格：经验已经转移、
候选本身没有原始经验或摘要、没有任何任务尝试、候选明确属于插件、文件身份全部匹配且用户
没有撤销清理规则。唯一保留子代理、用户自有、项目自有、来源不明，或已有任何经验、纠正、
摘要、成功或失败运行的子代理，都不属于普通手动删除候选。严重失败、用户否定结果、未授权影响
或伪造证据只触发停止采用、阻止继续使用和报告风险；只有累计第二次明确任务失败才触发独立
的永久移除规则。

```powershell
py -3 -X utf8 .\skills\lean-stack\scripts\agents.py delete `
  --name <代理名称> `
  --expected-sha256 <当前哈希> `
  --owner-token <所有权令牌>
```

手动删除要求 SQLite 台账、直接普通配置路径、单一硬链接、受管标记、名称、所有权令牌和文件
哈希全部匹配；经验、纠正、摘要与任务尝试都必须为零。缺失 TOML 的孤儿台账清理仍要求同一
哈希和令牌。符合条件时永久删除 TOML 与身份行，返回
`action=permanently_removed`、`recoverable=false` 和
`all_persisted_agent_data_removed=true`；不生成待删副本或收据，也没有 `restore` 命令。
目标在操作间隙发生变化时零写入停止，不能覆盖并发结果。

累计第二次明确失败的自动移除允许子代理已有运行、经验、纠正和摘要，因为这些正是需要一起
清除的资料。实现先在短事务中重新核对当前受管 TOML 的路径、身份和哈希，再删除摘要、纠正
事件、原始经验、全部运行与身份行，并移除 TOML。任一步在提交前失败时回滚 SQLite，并且只在
目标仍为空时按调用前精确字节重建 TOML；这是操作失败时的数据一致性回滚，不是移除成功后的
可恢复退役。成功提交后没有退役子代理记录、待删 TOML、收据或恢复入口。

v5 的 `retired_at` 列只为读取已发布结构保留；新操作从不写入退役身份。现实旧数据库若已有
非空 `retired_at` 行，普通命令会明确拒绝复用或恢复，不能把旧收据路线重新引入当前规则；
需在另一次有精确目标、证据和授权的迁移中处理。当前正式台账没有这种旧行。

## 数据库操作范围

独立数据库位于：

```text
<CODEX_HOME>/lean-stack/specialist-memory-v1.sqlite3
```

它只保存当前全局领域保留子代理所有权、幂等追加的成功或失败任务结果、只追加经验和压缩
摘要；子代理一旦因累计第二次明确失败永久移除，这些关联资料也全部删除，不另存退役记录。
它从不打开、迁移或删除旧生命周期数据库或旧隔离数据。只有版本为零且没有
用户对象时才初始化当前 v6。精确匹配的 v1/v2/v3 只能通过上文显式 `migrate-global` 收敛，
精确 v4/v5 只通过 `migrate-attempts` 升级；普通命令拒绝继续使用旧结构。v1/v2 没有可靠运行 ID
的历史轮次不猜测回填，v4 既有运行只保留为成功，v5 保留原结果；两者都不推断历史经验复用。

结构核对维护当前规范建表定义，并直接与 SQLite 保存的结构比较，不再分别维护重复的列、
索引和外键清单。未知版本、意外表、视图、触发器、命名索引、列结构、主键或唯一索引、
外键、忙锁、损坏或不可用文件都让辅助命令关闭，主任务继续。迁移使用单个
`BEGIN IMMEDIATE` 和极短忙锁等待；拿不到写锁就跳过。SQLite 只服务经验侧链，不用于
认领源码文件或协调可写子代理；可写并行使用[可写子代理并行](write-parallelism.md)中的
范围或独立检出目录路线。
