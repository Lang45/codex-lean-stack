# 保留子代理身份与经验

为新的能力类型选择子代理且没有适合继续使用的当前子代理时，只做一次快速、有界台账查询；命中
当前可调用的兼容保留类型后，仅读取该保留子代理。每个已完成切片的结果被核验采用时，按
[父代理采用](agent-results.md#父代理采用)进入能力族与经验的自动收口；本文件承载具体写入合同。
同任务 `followup_task` 只复用当前子代理线程，不算台账复用；身份维护
不能成为派发前置，也不能延迟主任务动作或交付。普通派发无需成本、迁移或摘要巡检。[agents.py](../scripts/agents.py) 只管理受管
TOML 与 SQLite，没有派发钩子，不启动子代理，亦不能证明宿主加载了身份或经验。

下列相对脚本路径示例只适用于本插件源码仓库根。跨项目调用时，从当前已加载的
`lean-stack/SKILL.md` 的绝对路径取得技能目录：`$leanStackScript = Join-Path (Split-Path -Parent $leanStackSkillPath) 'scripts/agents.py'`，
再以 `py -3 -X utf8 -B $leanStackScript` 调用，不按当前工作目录猜路径。

## 读取保留子代理

当前子代理是当前会话的线程；保留 `agent_type` 是跨任务身份；经验在采用后按新增可复用方法的实际条件自动记录，没有新方法时不追加。
台账复用只指调用现有 `lean_*` 保留 `agent_type`，不把 `followup_task` 计入。没有合适的当前子代理
且决定为一个新的能力类型调用子代理时，只读一次 `status --for-routing`，完成一次快速、有界台账
查询。查询结果只是候选短名单；当前会话已经加载，并经单个保留子代理读取取得完整合同后确认
同能力族、质量兼容的保留类型，才可本次使用。具体条件如下：

`status --for-routing` 返回对象，候选数组的真实字段是 `registered_agents`，数量为
`registered_count`。消费者读取该字段并核对数量；字段缺失、类型错误或数量不符属于返回合同
不符，不能猜测 `agents` 等别名后用 `[]` 当作“没有候选”。只有合法空数组才表示候选为空。

- 当前会话已经加载；
- 属于同一能力族；
- 质量兼容。

目录查询失败但当前会话已加载类型中已有符合三项条件的明确候选时，仍只读取该候选一次；读取成功
就复用，不要求所有无关保留身份都健康。只有没有可核对候选或读取保留子代理失败时，本次才改用
最小运行时子代理。查询失败不得当成空台账，也不得据此新建保留身份。查询结果和候选条件未变化时
复用本轮结果，不重复查。未加载身份不能冒充当前可调用，但仍
用于避免以后重复建档。当前子代理与台账保留子代理都可用时，在质量达到要求后比较父子
合计总成本，选择更低成本的一条，不为统计台账复用强制换线程。

命中已加载类型后，只读取该保留子代理一次。对应命令为：

```powershell
py -3 -X utf8 -B .\skills\lean-stack\scripts\agents.py recall --agent-ref <lean_* 机器身份>
```

`agent_ref` 是稳定机器身份，`display_name` 只用于用户界面；不得把中文展示名或子线程
路径传给 `--agent-ref`。`opening_declaration` 三行须与原生目录实际配置核对，
`opening_status` 两行原样进入[五行任务卡](dispatch-start.md#任务卡上下文与所有权)。
其中“存活轮次”是该身份已记录并采用的成功任务数，不是当前子代理的线程寿命。
已成功读取的保留状态在续用时仍沿用该回执；真实记账改变后才采用新进程读回的新值，
不能用当前线程或切片完成次数替换。零条有效经验直接显示“零经验”；读取失败不能伪装成零。
读取成功后立即派发；受管 TOML 的 `developer_instructions` 已包含经验，任务卡只传五行
状态，不再复制经验正文，子代理读原生注入经验一次即开工。旧经验与当前技能冲突时按当前技能。
读取失败时改派最小合规运行时子代理，名称标 `（新建）`，使用“存活轮次：0”和
“经验：本次任务上下文”，不猜测状态、不重试或修库。

经验状态按实际承载读取：`active_experience_count` 是已保存的有效事件总数；
`experience_summary_count`、`experience_raw_count` 分别是摘要承载和本次配置提供的原文数，
`experience_pending_count` 是本次尚未承载的数量，`experience_complete` 才表示全部已承载。
`experience_loaded=true` 只证明本次有可用内容，不能据此声称全部经验都已提供。

## 三个观察指标

- `retained-spawn share` 只是描述性比例：实际以保留 `agent_type` 发起的新启动次数除以全部新启动
  次数；它混入了没有保留复用机会的调用，不能据此推断真实机会复用率。
- `真实机会复用率` 是实际调用兼容已加载保留身份的次数，除以确需新调用且存在当前会话已加载、
  同能力族、质量兼容并读取成功的保留子代理机会数。
- `合格建档率` 是成功建档的独立新能力族数，除以预计以后确实还会遇到同类任务、预计复用收益
  高于维护和查找负担且没有兼容现有能力族的运行时子代理数。

三者都只作为观察结果，不设固定百分比；分母只使用实际可核验事件，不能伪造分母。任何
`retained-spawn share`，包括单次观察到的低比例，都不能替代真实机会复用率。不能为提高数字过度
保留、重复建档或制造调用，也不回填历史运行。这些是合同口径，不得虚构宿主指标；只有正式运行
证据能填入实际分子与分母。

合格建档指标按独立能力族去重。同一身份的首次 `ensure` 与后续 CAS 确认属于一个尝试单位，CAS
确认不是第二次尝试单位；返回 `reused` 或 `reconfigured` 不能算成功创建新身份。它们分别证明
已有身份复用或重配，不能抬高合格新身份的成功创建数。

## 创建或重配身份

采用节点的触发、去重与失败处理见[父代理采用](agent-results.md#父代理采用)。按职责、交付及权限/证据边界归能力族，同一族的不同
平台分支由任务卡限定，不按项目、平台名或任务名逐个建档。一次有界查询结果仍有效时复用。
有兼容身份就沿原身份处理；没有兼容身份且下列条件成立时，由父代理直接执行现有 `ensure`，
身份建立后，有可复用经验但没有对应的保留调用时，用 `improve --lesson` 保存；当前实际保留
调用产生的新经验用 `complete-run`。以真实回执和一次回读完成闭环。子代理只提供可核验
结果与经验候选，不自行争写共享台账；未采用、条件不足或写入被拒时明确跳过原因。

本分支的实际消费者是父代理和 `agents.py`；自动执行依赖父代理的采用与语义判断，未注册
无模型后台保存Hook。宿主结束事件或子最终文本本身不证明父已采用、符合保留条件或明确失败，
不能将每个结束事件机械转换为新增身份或失败记账。

运行时子代理在以下条件成立时选择性建档：

- 预计以后确实还会遇到同类任务；
- 预计复用收益高于维护和查找负担；
- 没有兼容的现有能力族。

不满足任一项时记录对应原因并跳过新建。同族已存在就复用或按 CAS 重配，绝不新建；不设固定
建档率、配额或强制百分比，不回填历史运行，也不建立后台队列。安全写入、去敏、权限和身份核验
仍由脚本执行；安全拒绝不能伪报为成功建档，但不另增上述选择性条件。

进入创建或重配时：

- **新建：**没有兼容的现有能力族。复用派发阶段的一次有界查询结果；
  只有候选条件实质变化或本轮没有有效结果时，才只读一次 `status --for-routing` 并按需定向
  读取最相关的保留子代理，避免未加载同族重复建档；未加载身份不能冒充当前可调用。确认没有兼容身份后，才
  `ensure` 一个最小权限身份；查询失败时不能确认“没有兼容身份”，本轮跳过 `ensure` 并保留台账
  不可核对的具体原因。项目名、框架或模型档位不同不另建。
- **重配：**已有同身份且能力族、权限、证据边界兼容，但固定配置需要更新时，先核验并采用
  配置胜者，再以该身份当前可用 SHA 执行 `--expected-sha256` CAS；权限不扩大。
  当前宿主已加载的旧配置不会热刷新，新任务才可验证新配置。

能力族键沿用已有身份的 `global_domain_key`，由职责、交付和安全／证据边界确定；具体项目、
一次操作或审查切片名称不构成新的能力族。已有兼容职责时先复用或在同身份上 CAS 扩充合同，
不换一个角色键再建档。脚本对同领域、同权限且规范职责合同相等的别名请求返回现有身份，
不创建第二份；合同措辞不同的语义重叠仍由父代理核对，不能把脚本未拦截当作允许新建。

选择性条件成立并决定新建时，即便没有新增经验也可执行 `ensure`。保留身份本身无需旧经验、数据库签发
收据或 `run_id`，不因此执行 `complete-run`。`ensure` 不依赖旧经验、收据或完成记账。
命令最小输入如下，`global_contract` 只含示例五字段：

```powershell
py -3 -X utf8 -B .\skills\lean-stack\scripts\agents.py ensure `
  --role-key <能力族键> --global-domain-key <领域键> `
  --global-contract '{"domain":"...","input_shapes":["..."],"responsibilities":["..."],"deliverables":["..."],"hard_boundaries":["..."]}' `
  --origin-term <当前来源词> --display-name "<中文名>" `
  --description "<可复用职责>" --instructions "<执行边界>" `
  --model <模型> --reasoning-effort <等级> --speed <standard|fast> `
  --authority <read|write>
```

`origin-term` 仅供去敏拒绝，不进入受管存储。首次 `ensure` 返回
`reconfiguration_required` 或 `global_contract_refresh_required` 时，只有已核验并采用
该配置且响应给出当前可用 SHA，才对同一身份、同一请求做一次 CAS 确认；若已有竞争变更，
重新判断胜者，不拿旧 SHA 强写。父代理按 `ensure` 返回的成功或冲突回执记录实际结果；
锁、结构、身份、权限或 CAS 失败时 `auxiliary_skipped`，不轮询、不让身份维护阻塞主线。
写入失败按现有安全回执保留具名缺口，能安全修复时回读，并继续主任务；不得把失败尝试计作成功
持久化，也不得因辅助维护失败阻断已采用结果。
`service_tier` 是宿主预配置，不进入逐次派发任务卡。

## 按需记录完成与经验

“新增”以当前兼容身份已保存、已承载的职责指令和经验为比较基准，不要求首次发明算法。
本次已核验且会改变后续动作的可复用做法、反例或证据边界，尚未承载时可以保存；职责目标或
泛化质量要求不等于已保存具体做法。单纯完成结果、项目事实、无后续动作价值的常识与已承载
的方法不追加；一次采用结果内可合并为一条，不拆碎凑数。

采用的成功结果只有新增一条去敏、带适用范围和证据限制的跨任务经验时才调用
`complete-run`；无新增经验的成功结果跳过完成记账。
当前实际调用了该保留 `agent_type` 且有已核验的新经验时，父代理在同一采用节点自动生成稳定 `run_id` 并执行
一次 `complete-run`，只记录当前实际调用种类与结果；不回填历史运行。只有补存既有已核验经验、
没有可对应的当前保留调用时，用 `improve` 保存经验，不虚构成功轮次。相同经验已保存则不再
追加，无新增经验不是存储故障；脚本回执和新进程读取才证明写入成功，口头说已保存不算。
已核验并采用的保留身份发生明确失败时，可用 `--outcome failure` 且不附 `--lesson` 记账，以维持累计
第二次明确失败删除；运行中、中断、未采用或结果未定均不算失败。运行时角色不回填保留调用轮次；
其已采用成果符合新建条件时仍执行 `ensure`，有已核验经验时执行 `improve`。身份或 CAS 无法
安全核对时，只跳过需要该核对的写入并保留原因，不将无法记轮次当作身份和经验均无需处理。

需要记录时才生成稳定 UUID `run_id`。只有需要声称某版旧经验参与该次并发完成结果时，
派发前用同一 `run_id` 定向 `recall --agent-ref <lean_*> --expected-sha256 <SHA> --run-id <UUID>`
取得数据库签发的 `experience_digest`、`experience_receipt`，并在完成调用中成对传入
`--loaded-experience-digest` 与 `--experience-receipt`。普通读取只读；收据只证明该版本
曾对同一机器身份和 `run_id` 签发，不证明宿主加载或经验导致结果。不得依据相同正文或历史
摘要猜测关联。

```powershell
py -3 -X utf8 -B .\skills\lean-stack\scripts\agents.py complete-run `
  --agent-ref <lean_* 机器身份> --expected-sha256 <调用方 CAS 快照> `
  --run-id <UUID> --invocation-kind spawn_agent --outcome success `
  --origin-term <用于去敏检查的来源词> `
  --lesson "适用范围：<可复用情境>；证据限制：<已核验依据与未覆盖边界>"
```

经验不含项目名、路径、URL、日志、凭据、原始提示、源码或思维过程。失败教训只写
“情境、停止依据、重开条件”，不作为失败记录的 `--lesson`。用户否定已写结果时只追加
具名纠正事件并使受污染摘要失效；完整纠正、压缩及兼容命令见脚本 `--help` 和行为测试。
健康结构下新增经验直接按需保存，不等待历史摘要纠错；结构不合规时安全跳过，保留已核验
结果和失败回执，后续备份、显式修复并回读验收。

保存回执的 `compaction.needed=true` 或回读的 `experience_pending_count>0` 是实际摘要触发，
按回执提供的原摘要、事件、`covered_through`、`source_digest` 和当前SHA使用现有摘要提交接口；
核对新摘要保留适用范围、权限、证据限制、纠正与重开条件，再以新进程回读承载状态。
原始事件继续保留，不扩大窗口掩盖问题，不把只有部分内容提供说成全部已注入；失败保留具名
缺口，不伪报修复，也不阻断无关主任务。普通派发不因此增加全库扫描或后台摘要巡检。

## 旧状态与数据保护

精确 v1/v2/v3 只经 `migrate-global --plan <UTF-8 JSON>` 迁移；计划必须用
`format_version: 1` 覆盖每个旧身份一次，逐项提供身份、旧/新角色键、当前 SHA、描述、
指令、五字段 `global_contract`、`origin_terms` 和 `experience_corrections`（无纠正用空数组）。
精确 v4/v5/v6/v7 只用 `migrate-attempts` 升到 v8。迁移保留原身份、所有权、原始经验和
运行记录；旧运行、读取签发及经验版本关联保持 unknown，不回填签发。结构或哈希不符须零写入
或按原字节恢复；完整计划格式与验证见脚本 `--help` 和迁移行为测试。

安全规则由 `agents.py` 执行并以成功、冲突或跳过回执判定：机器身份、受管目录、普通
文件、单硬链接、owner token、路径边界；精确 SHA-256/CAS；同一 `run_id`、同一摘要与
随机收据的数据库签发；幂等重放；SQLite 事务串行化使用同一台账的写者；TOML 原字节核验，
恢复不完整须显式报错。Windows 上已覆盖的受管 TOML 重配、删除和跨名称迁移持有目标对象与
父目录句柄；归档目录整体搬移仍是路径级保护，POSIX 仍依赖合作写者。SQLite 与文件系统
不是共同原子事务，进程崩溃后的跨存储恢复仍有缺口。身份移除限于累计第二次明确失败，
或用户明确要求并满足零记录、owner token 和 SHA 校验；删除资格不因自动保存而放宽。
Windows 的上述语义移除使用已核验回收站：归档仅含该身份的原配置、准确关联历史及恢复收据，
核验回收路径和内容后才移出正式台账；无永久删除后备路径，不留正式退役副本。
回收拒绝、漂移或事务失败须恢复原配置并回滚登记，恢复不完整明确报告；回收物是离线恢复
材料，不能作为活跃身份或热刷新证据。其他平台沿原平台合同，不冒充Windows回收能力。
这些是现有 `role_key`、CAS、权限和第二次明确失败删除保护，不宣称数据库强制能力族语义唯一。

## 用户可见回执

只在实际持久化后简短报告身份创建、复用、重配或跳过，及结果/经验是否记录。
失败写入保留具名未完成事项、决定性原因和安全修复条件，主线推进后修复并回读；
不展示 owner token、经验正文、内部路径或 SHA 清单。未进入本分支不生成保留报告。
