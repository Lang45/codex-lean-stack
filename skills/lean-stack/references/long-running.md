# 长任务

仅作为真正多阶段或无人值守工作的叠加规则。主工程任务始终优先，代理维护不是阶段。

1. 从用户目标明确完成标准和精确权限限制。实现任务把已授权的实现、运行或测试、检查结果、
   修复本次引起的失败及实际入口交付算在完成范围内，不能在初版实现后默认停下等待审阅。
   区分达到结果的成功条件和必须暂停的权限、安全或用户停止条件；用户只要方案、只读调查
   或明确先审阅时，按该范围结束，不自动扩成实现。可安全独立进行的已授权工作持续推进，
   阻塞只停受影响动作，不逐阶段重新申请同一授权。
   阶段交付后仍有已授权且可安全独立推进的软件实现，就继续该实现；未完成项分别写明软件
   实现、设备部署、真实测量或缺失来源的具体依赖。用户临时延期发布、设备部署或实机验收时，只调整
   该项当前安排；不据此新增“整个目标完成后才可发布”等完成门，也不自动停止其他已授权的软件实现。
   确实不能继续时指出具名阻断和最窄解除条件。
2. 把任务拆成有限、最小且可独立验证的阶段；派发时把真正影响方向、证据或下一依赖的
   阶段列为关键步骤；关键步骤只用于阶段依赖和验收，不决定是否提供任务途中的进展说明。
   多阶段工作开始、完成一个可验证阶段、发生阻断或纠偏时，面向用户的短状态只保留三件事：
   已由什么证据确认的状态、正在执行的当前动作、下一项将产生的可观察证据。只有一个动作能解除
   当前主要缺口时只给这个最窄下一步；存在真实选择时才列有限选项及影响。状态摘要不能把进行中
   写成已完成，也不能取代正式交接、最终交付或所需授权。
3. 每个阶段先区分高价值与普通工作，再排除短命令、确定性工具工作和未就绪工作。
4. 沿用入口[一次快判](../SKILL.md#先判断是否委派再选模型与复用)，将已就绪的可委派独立语义切片立即派出，
   同时安排父代理适合承担的实质工作；不等待完整拆分，按当前运行环境可用容量和三原则调用
   子代理。持续任务中同时出现多个互不依赖、能与父代理共同推进实际研究、实现或真实验收的合格
   工作流时，默认在父代理深入读取或推进这些工作流前尽早派发当前有边际收益的可委派
   切片，父同时推进自己的实质主线；数量随真实工作流、收益和容量决定，不把“所有”解释为全部外包，默认总成本可接受时可为提高父任务完成速度多派子代理。
   触发入口[持续并行提速](../SKILL.md#用户要求持续并行提速)时，按该节在新切片就绪或容量释放后继续派发。
   一个阶段内的获批子项目仍有多个已就绪独立切片，并且下游委派按当前用户优先级满足入口规则时，
   才允许任务卡明确指定协作父代理；不得让下游子代理提前启动后等待。阶段范围若任务类型、
   依赖、风险、可用能力、用户优先级和并行需求未变化，复用原决定。
5. 子代理不能提前启动后等待下一阶段输入。构建器或工装准备完成而集成输入尚未冻结时，先交付准备结果；
   输入清单、版本及来源归属一致后再续派集成或验收，也可预先固定不含未冻结输入的范围。
   执行期间按实际工作正常提供进展说明；阶段划分不能
   要求默认静默或只在关键步骤汇报。发给父代理的内部消息只用于解锁真实依赖、必要纠偏和风险，
   发送后继续工作，不等待确认；不重复发送同一状态。父代理继续关键路径，不逐条确认普通进度，
   有问题及时纠偏，只在真正需要结果时等待；并行写入必须天然分离。父子双方的用户可见说明
   均不受内部消息触发条件限制，具体通信边界见[子代理结果与汇合](agent-results.md)。
6. 记录决定、关键证据、已验证结果和下一风险。下一阶段只能依赖已验证结果。
   遇到长构建、反复失败或上下文接近压缩时，在当前会话保留最后可信状态、当前进程或产物、
   已排除原因、最窄下一动作、仍有效授权、相关定位、已采用结果轻量收据和唯一未决缺口；
   不复制原始工具输出或完整子代理回复。恢复后先复用定位与收据，只有具体缺口、来源变化或
   必要核验才补读。恢复前先确认这些当前事实是否已经可用；已存在就不重复注入，缺失时只恢复
   会改变下一动作的最小状态，且较新的用户覆盖、停止条件和证据优先于旧记录。同一失败若没有
   新证据或输入变化，不重复原动作；优先执行能区分剩余原因
   的小探针，再决定是否重建。扩大重试范围须有新的原因。
7. 收到“可以了”等含混反馈时，先对照仍有效的未完要求；不能确定取消范围时只澄清受影响项，
   不自动取消全部修复，仍可独立推进的已授权工作继续。停止条件满足时立即结束；不能满足时报告精确缺口。
   不得为了等父代理确认、增加交流点
   或自行追加关键步骤而延长任务；父代理更新目标也不得扩大授权或移除停止条件。

不要等待新写入的保留配置在当前任务中可见。同一任务的小补充可直接续用同能力族且上下文有益的
当前子代理。决定调用新的能力类型且没有适合继续使用的当前子代理时，才做一次快速、有界台账查询；
当前会话已经加载、属于同一能力族、质量兼容的保留子代理会被复用，并在单个身份读取成功后优先于
运行时子代理。目录查询失败但当前会话已加载类型中已有符合三项条件的明确候选时，仍只读取该候选
一次；读取成功就复用。只有没有可核对候选或读取失败时，本次才改用最小运行时子代理。不得把查询
失败当成空台账用于建档。当前子代理与
保留类型都可用时，默认在质量满足后选父子合计总成本更低的一条；持续并行提速时按入口该节选择线程。

成功子结果需要核验和整合，不需要关闭仪式。非必要工作迟到就放弃；必要工作超时只
发一次范围明确的收尾请求，随后由父代理继续或报告缺口，不用新增关键步骤反复续期。

经验维护不是阶段。运行时子代理在预计以后确实还会遇到同类任务、预计复用收益高于维护和查找
负担、没有兼容的现有能力族时，满足选择性建档条件。满足选择性
建档条件时才执行 `ensure`，依据脚本的创建、冲突或跳过回执判定；已有身份重配和 `complete-run`
才要求身份及当前 CAS 快照可安全核对。失败只影响记录，
主任务不等待。详见
[保留子代理身份与经验](specialist-memory.md)。不得排队、轮询、重试、等待或遗留后台生命周期工作。

已授权且幂等的外部传输可对一次明确的暂时故障重试。持久化本身不授权部署、删除
用户数据、公开发布或外部发信。只有产品选择、新权限或外部状态真正阻止安全推进时，
才询问用户。
