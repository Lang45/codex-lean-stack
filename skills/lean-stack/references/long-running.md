# 长任务

仅作为真正多阶段或无人值守工作的叠加规则。主工程任务始终优先，代理维护不是阶段。

1. 从用户目标明确完成标准和精确权限限制。实现任务把已授权的实现、运行或测试、检查结果、
   修复本次引起的失败及实际入口交付算在完成范围内，不能在初版实现后默认停下等待审阅。
   区分达到结果的成功条件和必须暂停的权限、安全或用户停止条件；用户只要方案、只读调查
   或明确先审阅时，按该范围结束，不自动扩成实现。可安全独立进行的已授权工作持续推进，
   阻塞只停受影响动作，不逐阶段重新申请同一授权。
2. 把任务拆成有限、最小且可独立验证的阶段；派发时把真正影响方向、证据或下一依赖的
   阶段列为关键步骤，没有值得中途报告的步骤时明确写“无”。
   多阶段工作开始、完成一个可验证阶段、发生阻断或纠偏时，面向用户的短状态只保留三件事：
   已由什么证据确认的状态、正在执行的当前动作、下一项将产生的可观察证据。只有一个动作能解除
   当前主要缺口时只给这个最窄下一步；存在真实选择时才列有限选项及影响。状态摘要不能把进行中
   写成已完成，也不能取代正式交接、最终交付或所需授权。
3. 每个阶段先区分高价值与普通工作，再排除短命令、确定性工具工作和未就绪工作。
4. 只对当前已经就绪的独立语义任务类型，按当前运行环境可用容量和三原则判断调用
   子代理。持续任务中同时出现多个互不依赖、能替代父代理实际研究、实现或真实验收的合格
   工作流时，默认在父代理深入读取或推进这些工作流前尽早派发所有当前有边际收益的 GPT-6
   切片；数量随真实工作流、收益和容量决定，三项原则成立时可为提高父任务完成速度多派子代理。
   一个阶段内的获批子项目仍有多个已就绪独立切片，并且下游委派分别通过三项原则时，
   才允许任务卡明确指定协作父代理；不得让下游子代理提前启动后等待。阶段范围若任务类型、
   依赖、风险和可用能力未变化，复用原决定。
5. 子代理不能提前启动后等待下一阶段输入。只有关键步骤结果会解锁真实依赖时，才发一条简短概述并
   立即继续，不等待父代理；不发送定时心跳、纯确认或同一风险的重复消息。父代理继续关键
   路径，无异议时沉默或一行答复，有问题时立即纠偏，只在真正需要结果时等待；并行写入
   必须天然分离。
   这里的沉默只指对内部子代理消息不逐条确认；面向用户的进展与最终交付仍按主技能
   “首条快速说明”执行，不能把有限内部消息当成整个长任务的用户说明上限。
6. 记录决定、关键证据、已验证结果和下一风险。下一阶段只能依赖已验证结果。
   遇到长构建、反复失败或上下文接近压缩时，在当前会话保留最后可信状态、当前进程或产物、
   已排除原因、最窄下一动作、仍有效授权、相关定位、已采用结果轻量收据和唯一未决缺口；
   不复制原始工具输出或完整子代理回复。恢复后先复用定位与收据，只有具体缺口、来源变化或
   必要核验才补读。恢复前先确认这些当前事实是否已经可用；已存在就不重复注入，缺失时只恢复
   会改变下一动作的最小状态，且较新的用户覆盖、停止条件和证据优先于旧记录。同一失败若没有
   新证据或输入变化，不重复原动作；优先执行能区分剩余原因
   的小探针，再决定是否重建。扩大重试范围须有新的原因。
7. 停止条件满足时立即结束；不能满足时报告精确缺口。不得为了等父代理确认、增加交流点
   或自行追加关键步骤而延长任务；父代理更新目标也不得扩大授权或移除停止条件。

不要等待新写入的保留配置在当前任务中可见。当前任务优先续用同能力族且上下文有益的 live
child，其次使用已加载且边界兼容的 `agent_type`；两者都没有时，由父代理定制最小运行时子代理。

成功子结果需要核验和整合，不需要关闭仪式。非必要工作迟到就放弃；必要工作超时只
发一次范围明确的收尾请求，随后由父代理继续或报告缺口，不用新增关键步骤反复续期。

经验维护不是阶段。只有结果形成跨任务可复用能力或经验，而且身份与 CAS 快照能够安全核对时，
才按需执行 `ensure` 或 `complete-run`；普通调用直接跳过。失败只影响记录，主任务不等待。详见
[保留子代理身份与经验](specialist-memory.md)。不得排队、轮询、重试、等待或遗留后台生命周期工作。

已授权且幂等的外部传输可对一次明确的暂时故障重试。持久化本身不授权部署、删除
用户数据、公开发布或外部发信。只有产品选择、新权限或外部状态真正阻止安全推进时，
才询问用户。
