# 长任务

仅作为真正多阶段或无人值守工作的叠加规则。主工程任务始终优先，代理维护不是阶段。

1. 定义一个停止条件和精确权限边界。
2. 把任务拆成有限、最小且可独立验证的阶段；派发时把真正影响方向、证据或下一依赖的
   阶段列为关键步骤，没有值得中途报告的步骤时明确写“无”。
3. 每个阶段先区分高价值与普通工作，再排除短命令、确定性工具工作和未就绪工作。
4. 只对当前已经就绪的独立语义任务类型，按当前运行环境可用容量和快速收益判断调用
   子代理。一个阶段内的获批子项目仍有多个已就绪独立切片，并且局部协调能缩短关键路径时，
   才允许任务卡明确指定协作父代理；不得让下游子代理提前启动后等待。阶段边界若任务类型、
   依赖、风险和可用能力未变化，复用原决定。
5. 子代理不能提前启动后等待下一阶段输入。每完成一个预设关键步骤，只发一条简短概述并
   立即继续，不等待父代理；不发送定时心跳、纯确认或同一风险的重复消息。父代理继续关键
   路径，无异议时沉默或一行答复，有问题时立即纠偏，只在真正需要结果时等待；并行写入
   必须天然分离。
6. 记录决定、关键证据、已验证结果和下一风险。下一阶段只能依赖已验证结果。
7. 停止条件满足时立即结束；不能满足时报告精确缺口。不得为了等父代理确认、增加交流点
   或自行追加关键步骤而延长任务；父代理更新目标也不得扩大授权或移除停止条件。

不要等待新写入的持久代理配置在当前任务中可见。当前任务先复用适合的任务类型组和可见
保留子代理；没有可见保留子代理或需要新组时，由父代理定制运行时新子代理和最小任务
说明。真实结果出来后，最多为未来持久保留一个胜出者。

成功子结果需要核验和整合，不需要关闭仪式。非必要工作迟到就放弃；必要工作超时只
发一次有界收尾请求，随后由父代理继续或报告缺口，不用新增关键步骤反复续期。

经验侧链不是阶段。任务类型组的唯一结果核验采用并通过全局领域合同后，组结束位置默认各
有界尝试一次 `ensure` 和 `improve`；失败立即跳过，主任务不等待。子代理结果已可采用而父代理
仍要测试或集成时，有空闲容量可以提前并行整理泛化候选，但准备不是正式提交前置条件，详见
[保留子代理经验](specialist-memory.md)。不得排队、轮询、重试、等待或遗留后台生命周期工作。

已授权且幂等的外部传输可对一次明确的暂时故障重试。持久化本身不授权部署、删除
用户数据、公开发布或外部发信。只有产品选择、新权限或外部状态真正阻止安全推进时，
才询问用户。
