# 可执行项目交接

仅在新建、修订 `Jiao-Jie.md`，或接手时发现目标、来源、证据和下一步混淆时读取。
本文件定义交接应保存什么，父代理的读取与更新时机由 `SKILL.md` 规定。
交接应让新父代理能执行下一项已授权工作，不必重新猜测产品目标或重走已失败路线。

## 稳定部分：要求、决定与边界

- 首章只放用户明确要求，必要时保留关键原话及来源定位；助手理解、设计提案、建议和
  待确认假设另列，不得改写成用户准则。用户未明确的内容不靠模板补齐。
- 用户最新明确要求决定当前目标与授权；当前源码和实际运行证据决定事实状态。历史交接、
  截图和助手结论不能覆盖二者。要求与实现不一致时记为缺口，不能把现状倒推成已获准目标。
- 写清目标成品、必须保留的能力和本轮范围；容易误解的核心要求用“入口 → 用户操作 →
  可观察结果 → 持久化或撤销结果”表示，并说明什么证据足以验收。按风险保留必要场景，
  不把所有专业功能或想象的边缘场景展开成强制清单，也不默默收窄用户验收。
- 权威路径区分可编辑源码、构建或生成目录、安装缓存、实际运行入口，以及必要的只读边界。
  路径只记录已知事实，不例行扫描权限。文件、版本和进程未对应时不能把源码修改说成运行生效。
- 已采纳决定只记录当前选项、影响后续选择的简短理由与必要证据。用户否定或实验证伪的
  路线记录“为何停止、什么新事实才允许重开”；保留已有可用能力，不将一次失败泛化为全局禁令。
- 保留通俗中文与必要英文标识的对应，代码标识、路径、模型名和原始错误不翻译。

例如，用户要求“打开菜单后切到编辑态，调整菜单大小”，交接不能只写“有模式切换按钮”。
应记录菜单保持打开、选中真实对象、修改写回及 Undo 的对应验收；截图和静态解析分别只能
证明外观和语法。具体场景是项目要求，不能复制成所有项目的通用功能。

## 动态部分：一个当前快照与恢复入口

把动态状态集中在末尾，更新同一快照，不逐轮追加多个互相矛盾的“当前状态”。

| 必要信息 | 最小内容 |
| --- | --- |
| 来源与新鲜度 | 快照日期、直接来源定位、已核对范围；历史背景或未核对项明确标识 |
| 活动要求 | 最早未完成或已完成未交付项、余下验收；已交付项退出，不从引用任务恢复旧待办 |
| 实现与运行 | 实际改动在哪、当前运行哪个产物、哪些尚未加载或验收 |
| 验证证据 | 对象、命令或操作、结果、覆盖边界与复用前提；大日志只给定位 |
| 失败与下一步 | 最后可信状态、当前阻断、已排除原因、最窄下一动作、成功或停止条件 |
| 授权边界 | 已明确授权且仍有效的动作、明确禁止或仍需另行授权的动作；授权不能被历史禁令覆盖 |

源码完成、静态通过、编译通过、真实运行通过和已对用户交付是不同状态。
只有证据支持对应状态时才能升级；用户例子中的行为未观察到时保留缺口。
受阻项写明依赖或恢复条件；“继续”先恢复剩余活动项，不能重跑已经交付的整个任务。

更新保持最小增量：稳定规则未变就不重写；被新授权或证据覆盖的旧当前状态及时替换，只保留
仍有决策价值的历史原因与来源。无状态变化就复用原快照，不为“本轮更新”新增空记录。
不保存思维过程、凭据、临时日志、可推导的全量清单或整套插件规则。

## 交接的窄验收

父代理收口时用当前用户要求和已取得证据核对：读者能否确定“要交付什么、在哪里改、已经
证明什么、下一步做什么、何时停止”？缺少会改变执行的信息就补齐该项，不要求固定章节数、
逐字段齐全或另派代理重写。纯交接文字变更用读回、链接和语义检查，不运行代码套件。

`AGENTS.md` 属于用户文件。提出增补建议不等于获准写入；本技能和安装辅助器不得借生成
交接扩大对它的写入范围，也不得把另一个项目的路径、产物、权限和失败方案带到当前项目。
