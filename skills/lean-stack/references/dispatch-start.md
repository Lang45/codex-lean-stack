# 首次派发

用户已明确指定是否委派、人数、协作方式或成本优先级时，先执行[用户明确指令优先](../SKILL.md#用户明确指令优先)，
不在此重新以成本、收益或复用偏好缩减人数；保留角色只提供执行者，复用不等于已补足并行队伍。
准备按用户明确安排或 `$lean-stack` 已确认的具体切片真实调用 `spawn_agent`，或准备让现有
子代理承担新的相关任务时读取。本分支执行已经作出的决定，不再增加第二套判断或维护步骤。
这里沿用入口的[一次快判](../SKILL.md#先判断是否委派再选模型与复用)，不重新比较路线或论证收益；
语义增量直接续用，新增确定性核算由父工具完成，不把“已有熟悉代理”当作必须继续派发的理由。

## 模型与思考程度

模型和思考程度分别按当前切片选择，然后一起检查是否达到必要质量：

- `gpt-6.1-terra`：用于速度优先、范围明确且验收直接的简单工作，覆盖有界读取、结构化提取、事实总结、文字整理和局部小修改，以及常规、低风险 Computer Use；
- `gpt-6.2-sol`：有限歧义、跨来源或跨模块因果，常规复杂实现、审查与验证，以及复杂或高风险的 Computer Use；
- `gpt-6.2-astra`：有实际输入和验收点，且相对最强可行 `gpt-6.2-sol` 存在会改变决定的质量差距。

前两档都是常规子代理路线；只有 `gpt-6.2-astra` 是专家路线。对用户明确指定由专家执行的切片，
在专家路线选配；其余切片按上面的质量门槛。选用专家时，记录一句用户指定或决定性质量缺口。

运行时覆盖值与固定保留角色配置的可用性按[入口模型规则](../SKILL.md#模型与思考程度)核对，
不能从某个固定角色的型号推断通用运行时覆盖支持。
`ensure` 的旧 Sol/Astra 输入按该入口规范化为当前型号后继续处理；身份 CAS、权限和思考上限保持。

思考程度使用当前任务需要的最低充分档位：

- `medium`：直接事实、少量依赖或局部歧义；
- `high`：多层因果、竞争假设、接口或安全边界；
- `xhigh`：密集冲突且高价值的未决关系。

Astra 可选 `medium`、`high` 和 `xhigh`；不得因为模型是 Astra 就固定选 `xhigh`。
`xhigh` 只用于上面的高难形状，`max` 和 `ultra` 不用于 Astra 子代理。Sol `max` 可按必要质量
正常选择；Sol `ultra` 只在高价值复杂边界且 `xhigh`、`max` 均不足时使用。

普通视觉、简单审计、路由审计、提示文档编写或只提到模型名称都不构成升级依据。按质量选用
Sol `ultra` 时，父代理用一句话记录决定性的质量缺口；普通调用不生成固定格式的路线收据。
Terra 的适用条件、`medium`/`high` 选择和转用 Sol 的质量门槛统一见
[入口模型规则](../SKILL.md#模型与思考程度)。
Computer Use 的界面执行按[父代理指导、按任务选配](../SKILL.md#computer-use父代理指导按任务选配)
处理；复杂业务判断与具体界面操作分别选配，任务卡补齐该节的目标、授权范围、阶段验收与操作所有权。

## 6.2 调用防错

父代理选择 `gpt-6.2-sol` 或 `gpt-6.2-astra` 时，在本节把当前任务的防错要求带入下方任务卡；
执行者完成或遇阻后，由[最终结果与父代理采用](agent-results.md#最终结果)消费对应证据。
这些约束针对已知失效方式降低风险，不保证模型零错误，也不增加固定复核轮数或新的调度层。

**适用与退出：**只对实际执行型号 `gpt-6.2-sol`、`gpt-6.2-astra` 生效；旧别名先按当前兼容映射
规范化，再判断实际型号，不按历史资料或旧请求字符串永久触发。单款 6.2 从当前可调用路线移除时，
在入口和各消费者的触发条件中缩小适用集合，继续保护仍可调用的 6.2 执行型号。
最后一款 6.2 退出时，维护父代理按[型号更新与专属纠错退出](versioning.md#型号更新与专属纠错退出)在同一更新中移除本节、
SKILL 中的 6.2 触发摘要及完整随卡执行句、任务卡引用、结果返回与父采用的 6.2 引用、内置提示与
README 的 6.2 防错摘要、发布流程中的 6.2 清单及链接和相应专属测试；不得只替换型号后把这些调优自动继承给后继模型。
诚实报告、权限、数据完整性、必要验证与证据边界继续由各自通用合同执行；不因移除 6.2 附加指令而删除。

- **先补决定性知识缺口。** 任务卡给出具名关键事实、未知项和最窄成功条件；对会改变实现或结论的
  文件、接口、来源、单位、例外与约束，先读取实际拥有者或用工具核对。不能把猜测的字段、路径、
  API、引用或硬件状态当作事实；缺少决定性输入时只处理不依赖该输入的部分，并报告缺口。
- **节省输出时保持要求完整。** 实现与结果逐项覆盖会改变结论的用户要求、数量、边界和反例；
  不因回答简短而漏掉关键事实。已有任务卡与结果中的简短对应关系足够，不另建打分表或重复全文。
- **按完成条件推进，减少例行停等。** 把用户可观察的成品、行为和最终检查写进最窄成功条件；
  内部文件命名或常规实现选择由执行者在约定内决定，不转成用户的例行阻断。缺少决定性事实、
  权限或范围外决定时仍明确询问；等待时继续不依赖该答案的部分，不用假设补造关键输入。
- **按任务校验结果。** 审查发现附位置、触发条件与影响，核对严重性，不把模型报出的条目数当成
  已确认缺陷数或已完成修复。视觉结果同时检查参考风格、关键姿态、时段、文字和实际交互；
  画面精致或识别总分高不能代替逐项满足用户要求。只检查当前任务相关项，不强制增加另一模型投票。
- **阻断如实报告。** 文件缺失、工具失败、搜索不可用、权限或测试阻断一旦影响结果，明确返回
  失败动作、实际错误、受影响结论和仍可推进部分。工具失败不能写成没有搜索结果；未执行的测试
  不能写成通过；替代来源或方法须说明证据范围，不能静默填补成已完成。
- **循环以新证据推进。** 再做同类尝试前说明哪条新观察、输入或方法能区分当前假设；无新增证据
  且结果不变时停止原样循环，保留当前工件，改做最窄决定性检查或带具体缺口返回父代理。
  不只换措辞、增加思考程度或重复派发同题；必要安全与数据完整性检查继续保留。
- **可理解、可采用的交付。** 先写实际结果、直接原因和证据位置，再给必要技术细节；区分观察、
  推断与未知。代码看似合理、模型自信或另一模型赞同不能代替验证；可计算事实用工具核对，
  交互结果按实际入口操作验收，关键外部事实附原始来源，未覆盖项明确保留。最终说明面向用户独立
  重写，避免照搬内部简称和探索笔记；保留理解结果所需的背景，不靠不断追加“更简短”压掉关键事实。

背景与证据范围：2026-11-18 的 X 公开搜索反馈提出知识缺口、循环和解释难读问题，属于早期
使用者经验；[Artificial Analysis 的原帖](https://x.com/ArtificialAnlys/status/2122750634210529569)及
[可直接读取的原始评测](https://artificialanalysis.ai/articles/openai-has-the-2-model-in-the-intelligence-index-with-the-release-of-gpt-6-2-astra-and-gpt-6-2-sol)
指出其编码评测中 Sol 更易遗漏关键事实，不能外推为所有编码任务退步。
[OpenAI 发布说明的 Alignment 节](https://openai.com/index/introducing-gpt-6-2-astra-sol/#safety-and-alignment)
也披露两项测试更易漏报缺失文件或不可用搜索工具；这些反馈不作为任意任务错误率或零错误保证。

## 选择同一能力族的执行者

1. **继续当前子代理。** 同一会话已经调用的子代理继续完成同一任务、澄清、纠错或紧密相关工作，
   且已有上下文仍有用、质量兼容，并仍需模型判断时，可以直接使用 `followup_task`。模型、思考程度、输入形式、
   职责领域、权限和证据边界未变化的普通补问，不重复核验或查询台账。新职责先对照已核验的
   `global_contract`：同领域消费者延伸可续用，已经变为另一项专业任务则重新选路，旧线程只交
   已有证据；不能只因上下文有用就继续使用原身份，也不因框架或文件名不同机械拆族。新切片再判断权限形状是否变化：
   只读职责转为产品、测试或报告等持久写入时，直接另派具备兼容写入权限的角色并明确文件所有权，
   或让原只读角色回传事实/文本，由父代理落盘；任务卡不能扩大固定身份权限，不能让只读身份先尝试、
   失败后再补派。子代理显示为完成不妨碍兼容续用；独立并行切片按入口
   [默认增派快判](../SKILL.md#先判断是否委派再选模型与复用)及当前明确安排选择线程，不因本条串行排队。
2. **快速查询台账。** 决定为一个新的能力类型调用子代理，且没有适合继续使用的当前子代理时，
   只做一次快速、有界台账查询：只读一次 `status --for-routing`。该结果只用于候选短名单，不能单独
   证明当前可调用。满足以下条件的保留子代理会被复用：

   - 当前会话已经加载；
   - 属于同一能力族；
   - 质量兼容。

   不能因项目名不同跳过保留类型；有符合条件的候选就只读取最相关的保留子代理，以完整合同核验
   后使用；读取成功后，将该机器身份真实传入 `spawn_agent.agent_type` 调用，不能因为通用角色更顺手
   而跳过。未加载身份不能冒充当前可调用；
   查询结果和候选条件未变化时复用本轮结果，不重复查。目录查询失败但当前会话已加载类型中已有
   符合三项条件的明确候选时，仍只读取该候选一次；读取成功就复用，不要求所有无关保留身份都健康。
3. **比较两条可用复用路线。** 当前子代理与台账保留子代理都可用时，先确认两者质量均达到要求，
   再按[当前用户优先级](../SKILL.md#用户明确指令优先)和[持续并行提速](../SKILL.md#用户要求持续并行提速)选路。
   默认比较父子合计总成本，选择更低成本的一条；不为统计台账复用强制换线程。
4. **选择运行时路线。** 当前会话已加载类型中没有可核对候选、质量不兼容，或读取保留子代理
   明确失败时，再考虑通用角色或任务定制运行时角色，并记录对应
   原因。候选实际固定配置与用户明确指定的模型或思考程度冲突时，按原生调用选择能满足要求的路线；
   “没想到”、“名称不同”或“未查”都不是理由。查询失败不得解释为台账为空，也不得据此
   新建保留身份。符合上述三项的保留子代理优先于通用角色和运行时路线。

能力族由职责和预期交付决定。输入形式与证据使用规则写进任务卡，模型档位按本次任务的质量和
当前用户优先级选择，不另设复用条件。项目、框架、动作名称、展示名或模型档位不单独拆分能力族。当前工具
目录决定当前可调用性；上述新能力类型的单次查询只负责发现候选，不扩张宿主当前可调用类型。命中
已加载类型后只读取该保留子代理一次，取得五行开场的客观状态和已有经验，成功后立即派发。机器身份或当前 CAS 快照
需要时也复用这次结果，无需批量查库。旧保留角色只有适合当前能力族时，才经已核验的 CAS 安全
重配为上述三款之一；当前宿主已加载的旧固定配置不能视作立即生效，须由新任务验证。本次调用可
直接走运行时角色。读取保留子代理失败时改派最小合规运行时子代理，用运行时真实状态开场，不声称复用了
保留类型，不重试、不修库。保留 TOML 的 `developer_instructions` 已原生注入经验；成功后任务卡
只传五行真实状态，不复制经验正文，子代理读已注入经验一次即开始任务。

台账复用只指成功调用现有 `lean_*` 保留 `agent_type`。复用当前子代理的 `followup_task` 仍是
同一会话上下文复用，但不得计入台账复用；通用角色或任务定制运行时角色也不冒充台账复用。
台账复用可减少角色提示重建和重复交接，因此在可靠性相当时优先；但注入经验与新调用仍有
成本，默认按当前增量输入判断；用户要求持续并行或不计成本时沿用入口优先级。全局权限、安全、数据完整性和诚实证据规则继续适用，但不重复
列入上述三项复用条件。

`followup_task` 开头明确“续做同一任务”或“开始新子任务”，只发送新增目标、证据、纠偏、成功
条件或停止条件。开始新子任务时给完整五行任务卡并重新开场；续做同一任务沿用已确认状态，
不因宿主工具名含 task 或父只给增量就重新索要完整卡、重查台账或停工。真正恢复执行后的首条
实质进展附最近已确认的存活轮次与经验，不为普通内部消息重开场；最终回复仍完整展示五行。
真正缺少会改变权限或当前动作的状态时才内部补齐。任务已经无关、需要隔离上下文、权限边界
不同或需独立并行时，新建子代理。

## 增量切片与 Astra 停止条件

只有用户优先级、并行需求、任务类型、质量门槛、权限或证据边界、专家必要性、预计成本发生实质变化时，才重新选路。
同一任务的小补充直接继续，不重复评估。已完成且采用、验收满足的 Astra，在无新要求、新证据、
未满足验收或明确纠错时停止；完成状态本身不能成为继续占用专家路线的理由。

出现新切片时使用两阶段判断。第一阶段落实用户明确指定的专家切片，其余切片按当前质量要求是否仍需 Astra 决定能力档位。第二阶段在
仍需 Astra 时，独立判断续用旧 Astra 线程还是新建或改派另一条兼容 Astra 路线；复用独有上下文
有边际价值才支持续用旧线程。旧线程上下文无边际价值时停止旧线程，但不能因此降到 Sol/Terra，
而应选择兼容保留 Astra 或新的 Astra 路线。

只有当前切片没有指定专家且不再需要 Astra，才按当前用户优先级选另一条路线。默认可考虑工具、兼容保留身份或满足质量的更便宜路线。历史使用 Astra
不锁定未来模型；父代理比较的是新增切片的边际投入，不回算或摊销已完成调用，也不逐调用查询价格。

## 任务卡、上下文与所有权

新建子代理的任务卡开头写五行，前三行是真实配置，后两行是有来源的状态：

父代理在实际调用前直接带入已核验的配置和状态，缺少字段时先补齐，不把缺卡任务派出后等待
子代理拒绝再补派。同一当前子代理的已确认状态未变时直接复用；有真实记账变化时采用既有写入
回读的新值，不为重复填写五行重新扫描台账。首次状态未知时仍按上节读取，不猜测或取消真实声明。

```text
子代理名称：<已按实际路线附（复用）或（新建）的名称>
模型：<具体模型>
思考程度：<具体等级>
存活轮次：<保留子代理读取状态或运行时 0>
经验：<保留子代理读取状态、复用当前线程上下文或本次任务上下文>
```

五行之后直接写入下面这句执行合同，使默认、内置或运行时角色在零历史调用中也能执行：

```text
真实新子任务先发送独立的用户可见进展说明，顶部原样展示以上五行，再调用首个业务工具；最终回复顶部完整展示五行，次数与经验沿用最近已确认快照，不自行加一。五行前不写计划、父代理开场模板或内部标识。
执行期间正常说明实际进展、变化和问题，不得默认静默或只在最终回复时说明；普通进展不逐条发送给父代理，内部消息仅用于解锁依赖、必要纠偏或风险。
本次验证了可跨任务复用且当前身份尚未承载的具体做法、反例或证据边界时，随最终结果附一条简短经验候选（适用范围、证据限制），不要求首次发明算法；无价值或已承载则省略，不编造、不留空模板、不另发内部消息、不自行写台账。
```

选择 6.2 时另附本节[调用防错](#62-调用防错)中与当前切片有关的具名关键事实、未知项和最窄
成功条件，并直接带入[入口“原生调用与任务卡”的完整执行句](../SKILL.md#原生调用与任务卡)。
执行句只在必读入口维护；关键词检索或链接存在不能代替把实际句子交给执行者。

随后只写当前调用真正需要的内容：

- 当前切片的唯一目标；
- 会影响当前动作的用户明确安排及持续并行状态；
- 输入来源或已有证据定位；
- 运行工件依赖的消费者身份及就绪证据；已有日志中的格式、窗口或接口标识直接传递，
  使用时核对当前对象，不靠猜测重新构造；准备工装与运行验收分别给成功条件，未就绪的
  包或接口不写成已具备，也不反复派发只会等输入的验收任务；
- 只读限制或精确写入所有权；
- 禁止的外部影响；
- 成功条件和停止条件；
- 必要时写回复语言和真实依赖消息对象。

第一行名称末尾只出现一个与实际路线一致的标记：复用当前子代理或已选中且读取成功的保留子代理用 `（复用）`，最小运行时新角色用 `（新建）`；候选匹配但未成功派发不得预标复用。已加载保留类型的开场通过读取同一保留子代理取得并核对；`opening_declaration` 是前三行，`opening_status` 是以下两行，状态原样写入任务卡：

```text
存活轮次：<已记录任务与失败状态>
经验：<当前配置数量与版本关联状态>
```

当前可复用子代理开始新的相关子任务时，前三行沿用已确认配置；若它此前使用经读取保留子代理核验的
保留状态，后两行沿用该状态。若它只复用当前线程而没有已核验的保留子代理读取状态，存活轮次只写父代理
已观察到的完成次数，经验行固定写“经验：复用当前线程上下文”。这句话不声称存在持久化经验；
不得写“未核验持久化经验”“任务卡未提供”或任何同类占位语。原状态无法确认时先在父子内部
补齐，仍无法确认就改派最小合规运行时子代理。

读取保留子代理失败时改派最小合规运行时子代理并标 `（新建）`；运行时新建或读取失败回退都写
“存活轮次：0”“经验：本次任务上下文”，不声称复用了保留类型，也不把保留身份记录误作
当前子代理线程寿命。
任务卡缺少实际状态时先在父子内部报告并补齐，不向用户展示占位语。用户可见说明使用中文展示名，
必要代码标识紧邻中文解释；机器名只在命令或核验证据中出现。中文展示名与机器 `agent_type` 分开；
持久化命令只使用脚本返回的 `agent_ref`。

开场与最终抬头都完整展示五行，是输出合同，不是宿主显示拦截器。若宿主没有向用户显示子代理开场，或
用户已反馈本轮显示不完整，父代理依据原生调用回执和已核验的保留子代理读取状态补显完整五项，
运行时角色使用本次已确认的实际状态；同批可用
每名一行的五列表格，不只说“已派几名”。同一状态不重复补显，不能据原始消息存在就声称界面
已经显示，也不能因截图未见就断言子代理未输出。不得猜测或使用计划值替代回执，不能声称调用没有发生。

当前宿主每次显式使用 `fork_turns="none"` 和自包含任务卡；决定性输入依赖此前对话时，将必要历史
整理进任务卡。禁止复制完整会话、整份技能、无关交接、缓存或台账。指定路径失效时只在所属目录定位；
输出截断只补缺段。

每次派发指定唯一来源所有者或不重叠写入范围。父代理随后只推进未分配主线、整合或真实依赖；
来源快照变化、覆盖不完整、结果冲突或必要高风险核验时，才定向重开具名缺口。

复用或派发前不核验旧经验签发收据、文件句柄或成本基线到期状态；只有实际声称某版旧经验参与并发完成时，才按保留经验分支使用数据库签发收据。

## 原生调用

每次 `collaboration.spawn_agent` 显式传 `fork_turns="none"`，不得省略参数而采用默认全量继承，禁止 `fork_turns="all"`。
通用运行时角色显式传入实际 `model`、`reasoning_effort`，型号取当前公开覆盖目录；固定保留角色沿用工具
已加载固定配置，不传模型或思考程度覆盖参数，任务卡核对实际配置。任何 `agent_type` 都不能用 TOML、任务卡
或继承占位替代所需原生参数，也不通过错误调用试探或擅改 TOML 绕过工具合同。

准备工作完成后立即调用。子代理进展说明不是结果；父代理以明确最终回复或等价结果收据采用结果。
结果采用时先进入[父代理采用](agent-results.md#父代理采用)的同一双判断节点，消费经验候选（如有），
完成该节规定的动作或失败记录后继续主任务；不另设建档判断流程。普通调用不
预生成 `run_id`，也不在派发前执行身份或经验维护。
