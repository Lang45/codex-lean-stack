# 首次派发

只在 `$lean-stack` 已确认一个具体切片值得委派，并准备真实调用 `spawn_agent`，或准备让现有
子代理承担新的相关任务时读取。本分支执行已经作出的决定，不再增加第二套判断或维护步骤。

## 模型与思考程度

模型和思考程度分别按当前切片选择，然后一起检查是否达到必要质量：

- `gpt-6-luna`：事实已定位、推理直接、结果容易核验；
- `gpt-6-sol`：有限歧义、局部实现风险、跨来源或跨模块因果，以及复杂实现与验证；
- `gpt-6-astra`：有实际输入和验收点，且相对最强可行 `gpt-6-sol` 存在会改变决定的质量差距。

思考程度使用当前任务需要的最低充分档位：

- `medium`：直接事实、少量依赖或局部歧义；
- `high`：多层因果、竞争假设、接口或安全边界；
- `xhigh`：密集冲突且高价值的未决关系。

Astra 可选 `medium`、`high` 和 `xhigh`；不得因为模型是 Astra 就固定选 `xhigh`。
`xhigh` 只用于上面的高难形状，`max` 和 `ultra` 不用于 Astra 子代理。Sol `max` 可按必要质量
正常选择；Sol `ultra` 只在高价值复杂边界且 `xhigh`、`max` 均不足时使用。

普通视觉、简单审计、路由审计、提示文档编写或只提到模型名称都不构成升级依据。选择 Astra 或
Sol `ultra` 时，父代理用一句话记录决定性的质量缺口；普通调用不生成固定格式的路线收据。

## 选择同一能力族的执行者

按顺序选择第一个兼容选项：

1. **复用 live child。** 当前已存在子代理属于同一能力族，实际模型属于上述三款且思考程度不低于 `medium`，开场状态已确认，权限和证据边界兼容，而且保留上下文
   能改善质量、成本或速度时，使用 `followup_task`。子代理显示为完成不妨碍再次续用。
2. **复用已加载 `agent_type`。** 没有合适 live child 时，直接使用原生工具目录中同一能力族、
   权限和配置兼容的保留角色；旧配置不合规时不得调用。
3. **创建运行时子代理。** 没有兼容候选时，按当前任务定制最小角色。

能力族由职责、输入形状、交付、权限、安全风险和证据要求决定。项目、框架、动作名称、展示名或
模型档位不单独拆分能力族。原生目录信息足够时不执行 `status --for-routing`；命中已加载 `agent_type` 后只对该身份做一次有界 `recall`，取得五行开场的客观状态和已有经验，成功后立即派发。机器身份或当前 CAS 快照需要时也复用这次结果，无需批量查库。旧保留角色只有确需跨任务复用且适合当前能力族时，才经已核验的 CAS 安全重配为 GPT-6 类型；当前宿主已加载的旧固定配置不能视作立即生效，须由新任务验证。本次调用可直接走运行时角色。召回失败时改派最小合规运行时子代理，用运行时真实状态开场，不声称复用了保留类型，不重试、不修库。保留 TOML 的 `developer_instructions` 已原生注入经验；成功后任务卡只传五行真实状态，不复制经验正文，子代理读已注入经验一次即开始任务。

`followup_task` 只发送新增目标、证据、纠偏、成功条件或停止条件；承担新的相关子任务时补充五行开场要求，且只沿用已确认状态。状态无法确认时改派最小合规运行时子代理。同一任务补问不重复开场声明，
也不重新执行保留身份发现。任务已经无关、需要隔离上下文或权限边界不同，才新建子代理。

## 任务卡、上下文与所有权

新建子代理的任务卡开头写五行，前三行是真实配置，后两行是有来源的状态：

```text
子代理名称：<已按实际路线附（复用）或（新建）的名称>
模型：<具体模型>
思考程度：<具体等级>
存活轮次：<保留召回状态或运行时 0>
经验：<保留召回状态或运行时未加载保留经验>
```

五行之后直接写入下面这句执行合同，使默认、内置或运行时角色在零历史调用中也能执行：

```text
第一条用户可见进展说明顶部必须原样展示以上五行，最终回复顶部重复前三行实际配置；五行前不写计划、父代理开场模板或内部标识。
```

随后只写当前调用真正需要的内容：

- 当前切片的唯一目标；
- 输入来源或已有证据定位；
- 只读限制或精确写入所有权；
- 禁止的外部影响；
- 成功条件和停止条件；
- 必要时写回复语言和真实依赖消息对象。

第一行名称末尾只出现一个与实际路线一致的标记：复用当前 live child 或已选中且召回成功的保留 `agent_type` 用 `（复用）`，最小运行时新角色用 `（新建）`；候选匹配但未成功派发不得预标复用。已加载保留类型的开场从同一身份的 `recall` 取得并核对；`opening_declaration` 是前三行，`opening_status` 是以下两行，状态原样写入任务卡：

```text
存活轮次：<已记录任务与失败状态>
经验：<当前配置数量与版本关联状态>
```

召回失败时改派最小合规运行时子代理并标 `（新建）`；运行时新子代理写“存活轮次：0”“经验：未加载保留经验”。当前可复用子代理承担新任务时只沿用已确认状态，否则也改派运行时子代理，不把保留身份记录误作 live child 线程寿命。任务卡缺少实际状态时先在父子内部报告并补齐，不向用户展示占位语。中文
展示名与机器 `agent_type` 分开；持久化命令只使用脚本返回的 `agent_ref`。

这条随卡执行句是输出合同，不是调用前拦截器。若宿主没有向用户显示子代理的进展说明，父代理依据原生调用回执和已核验召回状态简短说明实际值；不得猜测或使用计划值替代回执。子代理没有按合同展示时记录回退，不能声称调用没有发生。

独立窄任务优先 `fork_turns="none"` 和自包含任务卡；只有决定性输入依赖此前对话时才给有限正
整数历史。禁止复制完整会话、整份技能、无关交接、缓存或台账。指定路径失效时只在所属目录定位；
输出截断只补缺段。

每次派发指定唯一来源所有者或不重叠写入范围。父代理随后只推进未分配主线、整合或真实依赖；
来源快照变化、覆盖不完整、结果冲突或必要高风险核验时，才定向重开具名缺口。

复用或派发前不核验旧经验签发收据、文件句柄或成本基线到期状态；只有实际声称某版旧经验参与并发完成时，才按保留经验分支使用数据库签发收据。

## 原生调用

每次 `collaboration.spawn_agent` 显式传入实际 `model`、`reasoning_effort` 和
`fork_turns="none"` 或有限正整数，禁止 `fork_turns="all"`。任何 `agent_type` 都不能用 TOML、任务卡或继承占位替代
原生参数；保留角色的值须与工具目录一致。

准备工作完成后立即调用。子代理进展说明不是结果；父代理以明确 final 或等价结果收据采用结果。
结果采用后主任务继续，只有确有跨任务复用价值时才按需进入保留经验分支。普通调用不预生成
`run_id`，也不进入身份或经验维护。
