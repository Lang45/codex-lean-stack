# 首次派发

只在 `$lean-stack` 已确认一个具体切片值得委派，并准备真实调用 `spawn_agent`，或准备让现有
子代理承担新的相关任务时读取。本分支执行已经作出的决定，不再增加第二套判断或维护步骤。

## 模型与思考程度

模型和思考程度分别按当前切片选择，然后一起检查是否达到必要质量：

- `gpt-5.6-luna`：只用于有界读取、结构化提取和事实总结；
- `gpt-6-sol`：有限歧义、局部实现风险、跨来源或跨模块因果；
- `gpt-5.6-sol`：需要更强常规能力的复杂实现、审查与验证；
- `gpt-6-astra`：有实际输入和验收点，且相对最强可行 `gpt-5.6-sol` 存在会改变决定的质量差距。

前三档都是常规子代理路线；只有 `gpt-6-astra` 是专家路线。“专家”不得用作前三档或全部
子代理的泛称。

思考程度使用当前任务需要的最低充分档位：

- `medium`：直接事实、少量依赖或局部歧义；
- `high`：多层因果、竞争假设、接口或安全边界；
- `xhigh`：密集冲突且高价值的未决关系。

Astra 可选 `medium`、`high` 和 `xhigh`；不得因为模型是 Astra 就固定选 `xhigh`。
`xhigh` 只用于上面的高难形状，`max` 和 `ultra` 不用于 Astra 子代理。Sol `max` 可按必要质量
正常选择；Sol `ultra` 只在高价值复杂边界且 `xhigh`、`max` 均不足时使用。

普通视觉、简单审计、路由审计、提示文档编写或只提到模型名称都不构成升级依据。选择 Astra 或
Sol `ultra` 时，父代理用一句话记录决定性的质量缺口；普通调用不生成固定格式的路线收据。
建议、取舍、合规判断、审查结论及其他需要持续判断的任务至少使用合适的 Sol；已保留身份也不能
绕过这条限制。专家问题仍按 Astra 的决定性质量差距边界处理。

## 选择同一能力族的执行者

1. **继续当前子代理。** 同一会话已经调用的子代理继续完成同一任务、澄清、纠错或紧密相关工作，
   且已有上下文仍有用、质量兼容时，可以直接使用 `followup_task`。模型、思考程度、输入形式、
   权限和证据使用规则不在每个增量切片重新核对。同一任务的小补充直接继续，不做台账查询或重复评估；子代理显示为完成不妨碍
   再次续用。
2. **快速查询台账。** 决定为一个新的能力类型调用子代理，且没有适合继续使用的当前子代理时，
   只做一次快速、有界台账查询：只读一次 `status --for-routing`。该结果只用于候选短名单，不能单独
   证明当前可调用。满足以下条件的保留子代理会被复用：

   - 当前会话已经加载；
   - 属于同一能力族；
   - 质量兼容。

   不能因项目名不同跳过保留类型；有符合条件的候选就只读取最相关的保留子代理，以完整合同核验
   后使用；读取成功后，将该机器身份真实传入 `spawn_agent.agent_type` 调用，不能因为通用角色更顺手
   而跳过。未加载身份不能冒充当前可调用；
   查询结果和候选条件未变化时复用本轮结果，不重复查。目录查询失败但当前会话已加载类型中已有
   符合三项条件的明确候选时，仍只读取该候选一次；读取成功就复用，不要求所有无关保留身份都健康。
3. **比较两条可用复用路线。** 当前子代理与台账保留子代理都可用时，先确认两者质量均达到要求，
   再比较父子合计总成本，选择更低成本的一条；不为统计台账复用强制换线程。
4. **选择运行时路线。** 当前会话已加载类型中没有可核对候选、质量不兼容，或读取保留子代理
   明确失败时，再考虑通用角色或任务定制运行时角色，并记录对应
   原因；“没想到”、“名称不同”或“未查”都不是理由。查询失败不得解释为台账为空，也不得据此
   新建保留身份。符合上述三项的保留子代理优先于通用角色和运行时路线。

能力族由职责和预期交付决定。输入形式与证据使用规则写进任务卡，模型档位按本次任务的质量、成本
和时间选择，不另设复用条件。项目、框架、动作名称、展示名或模型档位不单独拆分能力族。当前工具
目录决定当前可调用性；上述新能力类型的单次查询只负责发现候选，不扩张宿主当前可调用类型。命中
已加载类型后只读取该保留子代理一次，取得五行开场的客观状态和已有经验，成功后立即派发。机器身份或当前 CAS 快照
需要时也复用这次结果，无需批量查库。旧保留角色只有适合当前能力族时，才经已核验的 CAS 安全
重配为上述四款之一；当前宿主已加载的旧固定配置不能视作立即生效，须由新任务验证。本次调用可
直接走运行时角色。读取保留子代理失败时改派最小合规运行时子代理，用运行时真实状态开场，不声称复用了
保留类型，不重试、不修库。保留 TOML 的 `developer_instructions` 已原生注入经验；成功后任务卡
只传五行真实状态，不复制经验正文，子代理读已注入经验一次即开始任务。

台账复用只指成功调用现有 `lean_*` 保留 `agent_type`。复用当前子代理的 `followup_task` 仍是
同一会话上下文复用，但不得计入台账复用；通用角色或任务定制运行时角色也不冒充台账复用。
台账复用可减少角色提示重建和重复交接，因此在可靠性相当时优先；但注入经验与新调用仍有
成本，实际收益按当前增量输入判断。全局权限、安全、数据完整性和诚实证据规则继续适用，但不重复
列入上述三项复用条件。

`followup_task` 只发送新增目标、证据、纠偏、成功条件或停止条件；承担新的相关子任务时补充五行开场要求，且只沿用已确认状态。状态无法确认时改派最小合规运行时子代理。同一任务补问不重复开场声明，
也不重新执行保留身份发现。任务已经无关、需要隔离上下文或权限边界不同，才新建子代理。

## 增量切片与 Astra 停止条件

只有任务类型、质量门槛、权限或证据边界、专家必要性、预计成本发生实质变化时，才重新选路。
同一任务的小补充直接继续，不重复评估。已完成且采用、验收满足的 Astra，在无新要求、新证据、
未满足验收或明确纠错时停止；完成状态本身不能成为继续占用专家路线的理由。

出现新切片时使用两阶段判断：第一阶段只按当前质量要求是否仍需 Astra 决定能力档位。第二阶段在
仍需 Astra 时，独立判断续用旧 Astra 线程还是新建或改派另一条兼容 Astra 路线；复用独有上下文
有边际价值才支持续用旧线程。旧线程上下文无边际价值时停止旧线程，但不能因此降到 Sol/Luna，
而应选择兼容保留 Astra 或新的 Astra 路线。

只有当前切片不再需要 Astra，才改用工具、兼容保留身份或满足质量的更便宜路线。历史使用 Astra
不锁定未来模型；父代理比较的是新增切片的边际投入，不回算或摊销已完成调用，也不逐调用查询价格。

## 任务卡、上下文与所有权

新建子代理的任务卡开头写五行，前三行是真实配置，后两行是有来源的状态：

```text
子代理名称：<已按实际路线附（复用）或（新建）的名称>
模型：<具体模型>
思考程度：<具体等级>
存活轮次：<保留子代理读取状态或运行时 0>
经验：<保留子代理读取状态、复用当前线程上下文或本次任务上下文>
```

五行之后直接写入下面这句执行合同，使默认、内置或运行时角色在零历史调用中也能执行：

```text
第一条用户可见进展说明顶部必须原样展示以上五行，最终回复顶部重复前三行实际配置；五行前不写计划、父代理开场模板或内部标识。
```

随后只写当前调用真正需要的内容：

- 当前切片的唯一目标；
- 输入来源或已有证据定位；
- 只读限制或精确写入所有权；
- 禁止的外部影响；
- 成功条件和停止条件；
- 必要时写回复语言和真实依赖消息对象。

第一行名称末尾只出现一个与实际路线一致的标记：复用当前子代理或已选中且读取成功的保留子代理用 `（复用）`，最小运行时新角色用 `（新建）`；候选匹配但未成功派发不得预标复用。已加载保留类型的开场通过读取同一保留子代理取得并核对；`opening_declaration` 是前三行，`opening_status` 是以下两行，状态原样写入任务卡：

```text
存活轮次：<已记录任务与失败状态>
经验：<当前配置数量与版本关联状态>
```

当前可复用子代理开始新的相关子任务时，前三行沿用已确认配置；若它此前使用经读取保留子代理核验的
保留状态，后两行沿用该状态。若它只复用当前线程而没有已核验的保留子代理读取状态，存活轮次只写父代理
已观察到的完成次数，经验行固定写“经验：复用当前线程上下文”。这句话不声称存在持久化经验；
不得写“未核验持久化经验”“任务卡未提供”或任何同类占位语。原状态无法确认时先在父子内部
补齐，仍无法确认就改派最小合规运行时子代理。

读取保留子代理失败时改派最小合规运行时子代理并标 `（新建）`；运行时新建或读取失败回退都写
“存活轮次：0”“经验：本次任务上下文”，不声称复用了保留类型，也不把保留身份记录误作
当前子代理线程寿命。
任务卡缺少实际状态时先在父子内部报告并补齐，不向用户展示占位语。用户可见说明使用中文展示名，
必要代码标识紧邻中文解释；机器名只在命令或核验证据中出现。中文展示名与机器 `agent_type` 分开；
持久化命令只使用脚本返回的 `agent_ref`。

这条随卡执行句是输出合同，不是调用前拦截器。若宿主没有向用户显示子代理的进展说明，父代理依据原生调用回执和已核验的保留子代理读取状态简短说明实际值；不得猜测或使用计划值替代回执。子代理没有按合同展示时记录回退，不能声称调用没有发生。

独立窄任务优先 `fork_turns="none"` 和自包含任务卡；只有决定性输入依赖此前对话时才给有限正
整数历史。禁止复制完整会话、整份技能、无关交接、缓存或台账。指定路径失效时只在所属目录定位；
输出截断只补缺段。

每次派发指定唯一来源所有者或不重叠写入范围。父代理随后只推进未分配主线、整合或真实依赖；
来源快照变化、覆盖不完整、结果冲突或必要高风险核验时，才定向重开具名缺口。

复用或派发前不核验旧经验签发收据、文件句柄或成本基线到期状态；只有实际声称某版旧经验参与并发完成时，才按保留经验分支使用数据库签发收据。

## 原生调用

每次 `collaboration.spawn_agent` 显式传入实际 `model`、`reasoning_effort` 和
`fork_turns="none"` 或有限正整数，禁止 `fork_turns="all"`。任何 `agent_type` 都不能用 TOML、任务卡或继承占位替代
原生参数；保留角色的值须与工具目录一致。

准备工作完成后立即调用。子代理进展说明不是结果；父代理以明确最终回复或等价结果收据采用结果。
结果采用后主任务继续。运行时子代理在以下条件成立时选择性建档：预计以后确实还会遇到同类任务、
预计复用收益高于维护和查找负担、没有兼容的现有能力族。建档按
[保留子代理身份与经验](specialist-memory.md#创建或重配身份)执行。普通调用不
预生成 `run_id`，也不在派发前执行身份或经验维护。
