# 首次派发执行分支

只在 `$lean-stack` 入口已经确认一个具体切片通过质量、成本、时间三项原则，准备真实调用
`spawn_agent`，或用 `followup_task` 启动新的当前子任务时读取。本分支执行已经作出的调用决定，
不再建立第二套“是否委派”判断。若当前这次调用同时命中来源所有权、可写并行、协作父代理或
保留发现等派发前分支，依次只读这些已命中分支并补齐必要字段；未命中分支不读。完成这些当前
调用必需的步骤后，下一次工具调用就是对应的 `spawn_agent` 或 `followup_task`。

## 一、一次确定模型与思考程度

入口中的四模型快判是普通选择依据；只有边界歧义、高成本路线或需要完整收据时使用本节展开。
父代理让模型和思考程度联合选择并达到当前切片的必要质量，再在质量充分的组合中比较成本，并确认
委派能实际加快父任务。任务标签、子代理名、父代理型号或希望模型分布均匀都不能代替任务证据。

- `gpt-5.6-luna`：规格清楚、证据已定位、推理链直接、输出短且容易核验的普通切片；也适合把
  多个互不依赖的小切片并行化。
- `gpt-5.6-terra`：存在有限语义歧义、少量关联来源或局部实现风险，Luna 难以达到必要质量，
  但尚不需要复杂端到端统筹。
- `gpt-5.6-sol`：需要跨来源或跨模块因果、竞争假设、隐藏不变量，或负责复杂实现、测试和自检的
  完整切片。控件布局、常规图片处理和普通 UI 实现默认先在三种 GPT-5.6 候选中选充分组合。
- `gpt-6-astra`：四种模型中唯一称为高成本专家的路线，只处理有实际输入与验收点的当前未决专家问题；相对最强可行 GPT-5.6 组合，
  须带来会改变决定的额外质量。普通视觉任务不触发 Astra，不批量升级，也不要求较低模型实际失败；
  派出的 Astra 最高 `xhigh`。

模型路由审计、提示或文档编写，以及任务中提到 Astra、视觉、3D、前端或视频，都不能构成选择
Astra 的证据。Sol 为父代理时也可直接使用专家路线，不先制造一次 GPT-5.6 失败。Sol 在执行中
遇到真实困难时，可把范围明确的困难切片交给 Astra 协助或验证；该切片须有实际输入、困难点、
验收点和停止条件。这条专家协助不限于视觉领域，也不能用笼统的“很难”代替决定性质量差距。

工作中出现影响最终产物的具体视觉质量缺口时，父代理重新选配当前未决专家切片。UI 设计、图片、
三维建模、前端视觉、视频编辑、渲染或其他视觉效果只有实际材料已就绪、存在范围明确的专家判断，
而且最强可行 GPT-5.6 仍有决定性差距时才适用；最终评审或验收核对只是辅助场景，不是前置门槛。
Astra 按同一验收点核验修正结果，“Astra 看过”不能代替可观察证据；Astra 子代理仍最高 `xhigh`，
不升级已经通过的切片或无关批次。

思考程度按推理深度选择：直接事实且无竞争假设可用 `low`；少量依赖和局部歧义可用 `medium`；
多层因果、竞争假设、接口或安全边界可用 `high`；密集冲突且高价值的未决关系可用 `xhigh`。
运行环境支持时，Sol `max` 可按任务复杂度和必要质量正常选择，不要求先证明 `xhigh` 不足。普通 UI、视觉和简单审计不得使用
Sol `ultra`；只有高价值复杂边界可选择，且须具体说明 `xhigh` 与 `max` 都无法可靠处理的竞争
关系、风险或证据缺口。缺输入、工具或权限时停止或补证据，不能靠抬高思考程度猜测。

每个模型子任务在父代理侧形成下面的短收据，并放入任务卡；它不是数值评分，也不要求运行多个
候选。子代理用它理解范围，但不在固定五行开场前复述：

```text
MODEL_ROUTE
selected: <model / reasoning effort and actual tool evidence>
quality: <该模型与思考程度为何联合达到必要质量>
cost: <为何在质量充分组合中成本与任务相称>
parent_speedup: <该委派如何对父任务实际完成速度产生正贡献>
```

## 二、选择运行时或保留子代理

正向委派决定完成后，先确定具体任务类型和兼容任务类型组，再匹配已经加载的轻量路由目录；目录
尚未加载时做一次有界 `status --for-routing`，命中候选后才按需读取
[保留子代理经验](specialist-memory.md)并执行 `recall`。查询失败、没有兼容候选、固定配置不合规
或锁/结构不可用时，立即改用合规运行时子代理，不重试、不修库，也不延后主任务。目录查询只为
选择已经决定调用的执行者，不能反向成为“是否调用”的前置。

具名保留子代理的原生 `model` 和 `reasoning_effort` 必须与已加载 TOML 完全一致；不合规时换用
合规候选或运行时子代理，不覆盖 TOML。当前结果被采用后，才判断是否值得形成跨任务、跨项目、
跨会话复用的领域组；持久化和经验收口不能反向成为本次派发前置。

## 三、任务卡、上下文与所有权

每个 `spawn_agent` 或启动新当前子任务的 `followup_task` 内部任务卡先写五行实际值：

```text
子代理名称：<本地化名称>
模型：<具体模型>
思考程度：<具体等级>
存活轮次：<recall 的客观状态；运行时子代理为 0（运行时子代理）>
经验：<recall 的客观状态；运行时子代理为未加载保留经验>
```

五行之后写 `MODEL_ROUTE`，再写当前切片唯一目标、输入来源或现有 `SOURCE_ROUTE`、只读限制或
写入所有权、禁止的外部影响、成功条件、停止条件、必要关键步骤和回复语言。名称使用用户语言；
技术 `task_name` 不是用户可见身份。只有真实依赖内部消息时才写父代理规范任务名或接收者的
规范任务名；
无内部依赖不制造消息路线。每次 `spawn_agent` 或用 `followup_task` 启动新当前子任务前，父代理
生成并保留一个稳定的唯一编号（UUID `run_id`），供结果采用后的同一次完成记录使用；父代理侧
`run_id` 不进入任务卡，也不得让子代理回显。

最小上下文原则沿代理树逐层适用；贵价父代理和 Astra 子任务对上下文读取、传播、结果复用和
增量补缺没有例外，Astra 子任务同样只接收最小充分输入。独立窄任务优先 `fork_turns="none"`
和自包含任务卡；决定性输入依赖先前决策时才给有限正整数
历史。禁止 `fork_turns="all"`，不复制完整会话、整份技能、插件缓存或无关规则。指定路径失效时
只在所属目录定位；输出截断只补缺段。用户要求全文和必要的高风险独立核验仍保留。

派发前指定唯一来源所有者或不重叠责任范围。子代理负责的来源发现、完整读取、实现或验收范围内，
父代理不得并行重做；父代理下一动作只能是未分配主线、整合或真实依赖。来源快照变化、覆盖不完整、
结果冲突或必要高风险事实复核时，才定向重开具名缺口。

## 四、选择 followup_task 或新 spawn_agent

持续对话、澄清、纠偏、迭代验证或父代理遥控能具体改善质量、速度或总成本时，可以继续使用
`followup_task`，但只发送新增问题、变化、证据或操作目标。无关、已经结束或能自包含的新切片
使用新的 `spawn_agent(fork_turns="none")`。`followup_task` 没有选模参数，任务卡仍写现有子代理
的真实模型、思考程度和 `MODEL_ROUTE`。

## 五、原生调用硬门与可见声明

每次 `collaboration.spawn_agent` 都在原生参数中显式传入：

- 当前切片实际选择的 `model`；
- 当前切片实际选择的 `reasoning_effort`；
- `fork_turns="none"` 或有限正整数。

任何层级和任何 `agent_type` 都不得用任务卡、TOML 或“继承”占位代替原生参数。缺五行、
`MODEL_ROUTE`、原生参数、成功/停止条件或所有权时不得调用。

五行只由子代理本人在自己的第一条可见 commentary 原样宣读，前面不写计划、运行 ID 或其他
说明；父代理只把五行写入内部任务卡，不在自己的用户可见 commentary 或最终回复中代为展示、
复述或预告。子代理自己的最终回复顶部只重复名称、模型、思考程度三行。该合同沿
parent → child → grandchild 递归。

## 六、立即调用并继续主任务

本分支和当前调用已命中的必要派发前分支读取后，不再发送第二段路线前言；下一次工具调用直接
执行选定的 `spawn_agent` 或 `followup_task`。不得读取未命中 reference、查询版本、提前维护经验
或扫描无关来源。这只约束当前派发前的热路径，不取消调用后随来源、写入、汇合或保留动作产生的
后继分支触发。

调用后父代理立即推进未分配主线，只在真实依赖点汇合。子代理 commentary 是进展，不是可采用
交付；父代理以子代理自己的明确 final 或等价结果收据采用结果。完整来源覆盖且快照未变时不重复
读取；只在来源变化、partial 覆盖、冲突或具名必要缺口时补问一次，随后补齐、报告缺口或停止，
不循环索取全文或另派执行者重做整项。
