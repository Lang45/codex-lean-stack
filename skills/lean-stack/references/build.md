# 构建或重构

用于新增功能、行为变化、重构和迁移。

1. 写清用户可见结果、权威数据格式或对外约定，以及明确不应改变的行为。
   动手前确定本次改变的可观察行为、必须保持的行为，以及区分做对和做错的最窄检查；
   简单改动简述即可，不形成额外审批。共享状态、覆盖写入、迁移或公共接口还须核对前置条件、
   操作顺序及失败后的恢复路径。检查范围按行为影响和真实调用方决定，不按修改行数缩减。
2. 涉及跨版本回迁、机制替换、大范围删改、兼容层、测试矩阵或发布面时，先读取
   [反 AI 过度工程](anti-overengineering.md)，核对当前用户原话、当前事实、现实消费者和保留项。
   助手推断的图数、拓扑、固定流程或版本形态没有来源证据时，只交差异清单，不执行回迁。
3. 追踪现有所有权，依次寻找可复用代码、标准库、原生平台行为和已安装依赖。应用最小方案
   阶梯，停在第一个完整方案；安全时先删除负担，再增加替代。
4. 先按工作价值分流。迁移、公共约定、安全、权限、数据完整性和重大架构属于高价值工作，
   质量与证据优先；普通机械改动在验收底线内速度优先。
5. 只有重要公共边界或共享状态没有现有模式和明确最小路径时，才比较两个真正可行的形状。
   不为形式制造第二方案，不为尚未部署的内部功能制造兼容层，也不为已经决定不实现的假想
   功能增加桩、注释、TODO 或测试。
6. 先排除短命令和确定性工具工作，再对独立探索、语义复核或天然分离的文件应用核心分派
   判断。父代理继续架构和集成，耦合代码和共享写入保持一个所有者。一个获批子项目自身还有
   多个已就绪独立切片，而且局部协调能减少父代理堵点时，才按
   [协作父代理与父代理之间](collaboration.md)指定协作父代理；否则保持平面委派。
7. 实现最小完整切片。兼容性没有现实消费者时，在同一验证波次迁移真实调用方并删除已被
   替代的内部接口。现实旧状态需要兼容时只保留一条显式迁移路径。
   大范围外观、交互或架构工作先使一个代表性用户操作贯穿真实入口、核心行为与结果保存，
   取得能否满足目标的证据后再扩展。用户已否定目标路线时停止在该路线继续补丁或编译，
   先把纠正后的结果与验收对齐；不因重新设计外壳而修改本应保留的产品结构来迁就它。
8. 把变更表面分为权威行为、直接说明、可再生展示和发布/缓存；只修改不改就会错误承诺的
   表面。同一规则只设一个权威源，其他表面引用、生成或保留最小摘要。
9. 只有用户明确要求对当前制品执行消融、精简代码或设计、去掉不必要抽象时，才读取并执行
   [消融反馈循环](ablation-loop.md)。普通设计或实现完成不自动启动或建议消融。
10. 在匹配表面验证用户可见结果。迭代中的窄测试由父代理直接运行；负向测试只保护明确禁止、
   安全/权限/数据完整性、公共约定或真实回归。纯说明或展示变化不自动触发升版、重装或运行环境
   运行验收。

完成条件是请求行为可用、相关检查支持既有行为，而且每个新层或依赖都有当前调用方
和具体理由。

## UI 的实际验收

UI 任务从用户参考、现有产品约定和一条代表性操作确定验收，分别核对视觉结果与交互行为。
按本次影响检查真实窗口尺寸下的布局、溢出和可读性，相关的正常、空、加载、失败状态，
操作反馈与保存、撤销或重新打开后的结果；适用时检查键盘焦点与操作顺序，不机械穷举状态。
截图只支持外观判断，编译和接口测试不能证明交互完成；行为须在实际入口操作验证。
实际入口不可用时明确缺口，已有窄证据照常交付，但不能据此宣称 UI 已验收。
