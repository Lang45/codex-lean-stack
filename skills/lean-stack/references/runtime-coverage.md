# 运行期主线覆盖

用户明确要求持续派遣或逐线覆盖时使用。普通一次性任务不建立执行表。原目标清单继续定义
用户要什么；本表只保存可由程序核对的工作包、代理活动和采用状态，恢复与钩子消费同一份表。
不能用已完成子切片或一个硬件缺口自动关闭整条主线。

## 启用与同源状态

插件的 `hooks/hooks.json` 声明运行入口。宿主必须支持这些事件，且该精确版本的钩子已被用户
审阅信任。安装成功、技能已读或脚本能单独执行，不证明钩子已生效；用宿主的 `hooks/list`
及真实触发回执核对。未信任时明确说明并继续可做工作，不自行改写全局信任记录。

钩子在明确持续请求时提供当前 `session_id`、实际数据目录和可执行命令。第一次按现有目标表
登记全部未交付主线，工作包只列当前可执行结果或具体依赖；不另抄一份业务合同或派人等输入。
命令使用正式安装路径及该钩子给出的数据目录：

```powershell
py -3 -X utf8 -B "<插件根>/skills/lean-stack/scripts/coverage_runtime.py" plan `
  --session "<当前会话>" --cwd "<项目根>" --data-dir "<钩子数据目录>" --input "<计划JSON>"
```

计划形状：

```json
{"goals":[{"id":"G01","title":"原主线名","work":[{"id":"W01","title":"当前完整工作包"}]}]}
```

后续计划更新保留未交付主线；新增切片属于原目标，不用删除旧行表示完成。主父负责登记，普通
子代理只完成当前卡，不改父执行表。`status` 使用同一个 `--session` 与 `--data-dir` 查看。

## 实际派发与接续

计划为每个工作包给出结构化 `executor` 路径，例如 `/root/lean_g01_w01`。新派时把末段
`lean_g01_w01` 直接放入原生 `spawn_agent.task_name`；业务 `message` 正常携带任务卡、
身份、权限和完整业务上下文，无需手写关联标记。需要续用已有代理时，在该新工作包的计划中
显式写 `executor: "/root/已有代理"`，然后用同一路径调用 `followup_task.target`。
现有包尚在运行时不把同一执行者重复分给另一个就绪包；先采用返回结果，或选另一个执行者。

首派或续派无法以原生参数唯一对应一个就绪工作包时，在派出前拒绝，给出具体可用的
`task_name` 或 `target` 和修正入口。程序按同一调用和真实成功路径关联当前包，不把计划或
失败调用算作运行。旧的唯一 `[lean-work G01/W01]` 调用仅作为兼容入口，不能越过显式分配。
原生 UUID 没有公开在普通回执中时不猜；成功派发先保留为已派待核对，由父调用原生 `list_agents` 的实际回执
确认对应路径仍在运行或已返回。子代理生命周期钩子属于子会话，不拿它伪造父会话的关联。
核对前不能直接等待，不能让历史线程永久冒充活动覆盖，也不因未知状态盲目重派。

工作包返回后由父核验，使用 `update --session ... --data-dir ... --input <动作JSON>` 采用：

- `{"action":"accept","goal":"G01","work":"W01","evidence":"实际验收收据"}` 只采用该包；
- 有新就绪包则用 `plan` 登记下一包并接续派发；
- `{"action":"block","goal":"G01","work":"W02","blocker":"具体缺口","evidence":"来源"}`
  只阻对应包，核对同条是否仍有独立可做的研究、实现或验收；
- `{"action":"deliver","goal":"G01","evidence":"完整用户结果的交付收据"}` 仅在整条满足后交付；
- 用户明确停止时 `{"action":"pause"}`；明确恢复原安排时 `{"action":"resume"}`。中断也保留表并暂停。

已有缺口解除后可 `retry` 对应包。命令只登记状态，不自行启动模型、操作设备或扩张权限。
宿主已明确返回失败却没有发送后置回执时，可凭该错误用 `retry` 释放在途预占，再修正分配或重试；
尚未收到结果本身不算失败，不能用它解除实际正在执行的工作。
临时阻断可用同命令的 `--json '<动作JSON>'` 直接登记，不必先执行被守卫暂缓的文件写入。
宿主不能自动提供列表回执时，父先核对真实原生状态，再用
`{"action":"verify","goal":"G01","work":"W01","task_path":"/root/实际代理","state":"running","turn_id":"拒绝提示中的当前父轮次","evidence":"核查收据"}`
登记；`state` 也可为 `returned`，此时不需 `turn_id`。该路径必须匹配已经成功派发的工作包，不能用它补造派发或交付。

## 运行检查与边界

登记后的就绪包无人承担时，前置钩子要求先派发，阻止父直接等待或继续受覆盖检查的局部工具；
派发、续做及执行表自身的纠错操作保持可用。子层不受父门约束。代理结束只进入待采用，不能
自动交付主线。父准备结束时仍有就绪缺口，则 `Stop` 钩子要求同轮继续；同一无变化状态不会
无限续烧，仍未解决的缺口须显式呈现。

`SessionStart`（含宿主的压缩恢复入口）从同一执行表给出全部未交付项。真实输入、权限、账户或宿主容量阻断
仍按具体包报告，不能假装在运行，也不能为满足人数空占线程。表由实际消费者维护，不能证明
模型业务结论正确或自动发现所有潜在工作；领域验收仍沿用原消费者。
