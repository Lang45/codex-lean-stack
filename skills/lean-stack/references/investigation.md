# 调查

用于取得回答行为、所有权、原因、风险或方案选择所需的证据。研究目的与操作权限分别判断，
按[多目标推进与逐项交付](../../lean-simplify/SKILL.md#多目标推进与逐项交付)选择实际取证方法；
当前授权内需要运行、调试、逆向或修改隔离工装才能判明的问题，直接执行对应专业操作。
用户明确只读时保持只读；研究结果不自动授权生产修改、设备写入或外部副作用。

运行或逆向遇到异常时，把异常作为当前工作包内待解决的问题，按[缺陷修复](bug-fix.md)继续：
取得失败动作、原始异常、目标版本及必要的模块、依赖或调用证据，做能区分原因的诊断，
在授权副本或工装上修正并验证，再回到原分析目标。异常弹窗、一次工具失败或启动失败不是
任务完成或必须交还用户的条件；原路线确实不通时沿新证据换取证方法。只有具名缺失输入、
权限、安全停止条件或当前工具无法消除的限制才阻住受影响项，并说明实际尝试和最窄解除条件。

用户已明确指定执行者、人数、独立阅读或协作方式时，先按[用户明确指令优先](../SKILL.md#用户明确指令优先)落实；
下述父工具、唯一来源所有者和委派收益判断为未指定时的默认，不排除用户要求的独立核查。

1. 写清问题，以及什么证据足以回答。提速或链路调查先确定用户实际工作流、输入变化与总耗时
   指标，再定位阶段开销；固定输入的重复读取与切换输入的完整序列不能互相替代。已有要求和
   实际消费者能确定对象时直接推进；歧义会改变优化对象时先澄清，并继续不依赖答案的读取。
2. 先标出主运行或数据路径，再标出相互独立的调用方、配置、测试、历史或外部来源。
   每个来源类别第一次用工具定位后，按[来源所有权与结果收据的 `SOURCE_ROUTE`](source-results.md#唯一来源所有者)
   指定唯一完整读取者和消费者；派发时直接传证据包、定位和问题。只有其中列出的重开条件
   成立时才补读，不能让父代理、子代理和工具各自重复同一轮索引与预读。
3. 已明确交给子代理的工作按[明确安排](../SKILL.md#用户明确指令优先)落实；仅未指定的委派先判断是否需要持续模型判断，此时短查询由父代理直接调用工具；只有大于
   工具开销、范围清楚的独立来源或子系统才进入核心分派判断。
4. 父代理追主路径，已选择的子代理覆盖不同来源类别或子系统；任何子代理启动时都要
   立即有真实来源可读，不能预先启动后等待。
5. 汇合真正拥有该行为的运行路径、调用方、配置和测试。只有问题确实依赖时才使用
   历史和外部文档；当前代码与真实行为优先于搜索摘要、评论和旧文档。问题确实依赖外部事实时，
   优先回到拥有该事实的第一方资料，例如官方文档、规格、源码或第一方 API；二手摘要只作为
   定位线索，不能单独把主张升级为已确认事实。交付中的关键外部主张须附精确 URL、章节、段落
   或等价定位；这不要求不依赖外部事实的普通调查联网或生成独立研究报告。
6. 返回带精确位置或链接的证据，明确区分已确认事实、推断和未知项，并指出它满足的用户验收
   或解除的具名依赖。用户目标包含后续操作或实现时，将可采用结果接给该消费者；下一步需要
   动态验证就执行最窄决定性操作，不能用更多同类静态阅读替代。只要报告或方案时按要求交付。

来源覆盖完整且未变化时，父代理不做常规完整重读。不以“继续研究”自行撤销已有操作授权，
也不从研究目的推导新权限；需要范围外操作时只停对应项，说明精确缺口并继续独立工作。
