# 反 AI 过度工程

当构建、重构、迁移、兼容、测试、交接或发布工作可能扩大维护面时读取。本文件是这类决策的
详细权威来源；`SKILL.md` 只保留入口和最小摘要，README、流程图、UI 与交接只承担各自受众
真正需要的说明，不逐字复制本文件。

反过度工程不是少写必要代码。安全、权限、数据完整性、公共约定、真实用户数据、可恢复迁移
和便宜的关键回归仍必须保留。目标是删掉没有现实消费者、来源证据或当前调用方的维护工作。

## 历史删减边界

本插件已经删除的多层数值评分与逐级否决路由、项目保留层、租约/推荐/停滞状态、独立
`variation-plan/stage/verify` 状态链、晋升与退役恢复工作流，以及插件项目交接生命周期，不得
因拆分 `$lean-stack` 与 `$lean-simplify`、重写文档或增加兼容说明而恢复。现有四模型一次选配、
运行时复制与变体、现实旧状态的显式迁移、所有权/CAS 和 SQLite/TOML 数据保护有当前消费者，
不属于被删机制，也不能借“保持精简”移除。

## 一、先证明问题真实存在

开始兼容层、跨版本回迁、机制替换、大范围删改或发布闭环前，先写清：

1. 当前用户原话或当前公共约定；
2. 当前源码、运行状态或真实数据中的决定性事实；
3. 已安装/已发布版本、真实调用方、持久状态或用户数据等现实消费者；
4. 必须保留的现有行为与停止条件。

只有历史助手结论、旧 TODO、旧交接、旧截图、推测的图数/拓扑/固定流程或“以后也许会用”，
不构成迁移目标。证据不足时停在差异清单，不做整面回迁、机制替换或大范围清理。

## 二、兼容只服务现实消费者

只有以下任一事实存在时才实现兼容：

- 已安装或已发布版本仍有调用方；
- 真实用户数据或持久状态需要迁移；
- 公共约定或现有消费者不能在同一变更中同步切换；
- 当前可审计运行面确实会读取旧格式。

尚未部署的新内部功能直接替换。在同一变更中迁移真实调用方并移除被替代接口；不预造
legacy reader、旧新格式双写、永久别名、回退分支、兼容桩或假想消费者测试。现实旧状态只
保留一条显式、有限、可测试的迁移路径，迁移完成后新运行面只写当前格式。

## 三、不维护已经决定不实现的假想功能

“不实现”本身不是功能。默认不为它增加：

- 运行时分支、空接口、占位实现或永久 feature flag；
- TODO、解释“这里为什么没有某功能”的代码注释或未来路线图；
- mock、fixture、迁移桩或专门证明该假想功能不存在的测试；
- 仅为潜在扩展预留的数据库列、配置字段、抽象层或目录。

只有四类负向限制值得最小测试：

1. 用户明确禁止的行为；
2. 安全、权限或数据完整性硬性限制；
3. 公共约定中明确保证不会发生的行为；
4. 真实发生过且容易回退的问题。

这类测试只覆盖能观察到的拒绝或不变量，不为被禁止功能搭建一套实现脚手架。注释只解释当前
存在且反直觉的代码行为；不能用注释和测试把一个已拒绝的想法变成永久维护对象。

## 四、哈希按风险计算一次

哈希用于所有权、CAS、SQLite/TOML 迁移、角色永久移除的操作前核对与失败回滚、真实发布产物和安装缓存最终一致性。
普通阅读、纯文字修改、未变化文件和同一次操作已经取得的摘要不重复散列。

验证策略由实际数据变化决定，不由“迁移”“全面”“回退”或“安全”等标签自动放大。先判断
操作是否真的复制或改写文件内容。同一卷内的 `Move-Item`、改名或重新挂接目录只改变
路径元数据时，不得仅为“迁移安全”建立源端和目标端整树逐文件 `Length` 与 SHA-256 清单。
这类操作先验证解析后的精确源/目标、两者位于同一卷、目标不存在、重解析点边界和预期路径
映射；操作后验证源已消失、目标已存在及预期顶层结构。只有结果确实依赖文件数量时才读取
一次数量或其他便宜元数据，不能用内容散列代替路径与结构断言。

跨卷移动、实际字节复制、正式发布或安装清单、安全关键完整性约定，或用户明确要求逐字节
核验时，可以对预先声明的交付文件集合做完整散列。顺序仍是先看变更集、文件集合和便宜元数据，
再只对变化或安全关键目标散列；同一输入、同一重试和同一次操作已经取得的 manifest 或摘要
必须复用。不得用重复全树哈希制造“全面”感，也不得省掉保护用户数据的必要 CAS。

交接与最终说明记录验证对象、文件集合范围和结论即可；除非它本身是用户要求的交付物，不保存
逐文件长度或散列列表，不把可即时推导的摘要维护成第二事实源。

## 五、一个权威源，四类变更表面

同一行为规则只设一个可审计的权威源。其他位置只有在存在不同运行时消费者、直接用户受众或
真实交付要求时才保留最小摘要、引用或可再生派生物。不要把同一规则逐字手写到多份文档、
提示、UI、图、测试和交接中，再依赖全文扫描维持一致。

每次政策、术语或流程变化先划分：

| 表面 | 何时修改 |
| --- | --- |
| 权威行为面 | 运行决策、公共约定或数据格式确实改变。 |
| 直接说明面 | 不修改就会向用户作出错误承诺。 |
| 可再生展示面 | 展示源确实依赖该语义；优先重生成或引用，不手写镜像。 |
| 发布/缓存面 | 用户明确要求发布/重装，或运行时公共行为与可加载产物确实改变。 |

只修改会因本次变化而错误的表面。纯说明或展示同步不自动授权升版、重装、运行环境验收、提交
或推送。已有多表面结构不因此触发无关的大重构；先指定权威源，后续在受影响范围内逐步收敛。

交接文件记录稳定决定、当前入口、权威路径、未完成范围和会改变下一父代理决策的必要快照。
可由 SQLite、manifest、测试输出或文件清单低成本即时推导的细粒度计数、全量哈希和逐项验证
清单不维护为第二事实源；确需记录时注明来源与快照时间。

## 六、实现与验证停止条件

按以下顺序停在第一个完整方案：不构建；复用现有实现；标准库；原生平台；已安装依赖；
删除或内联；最后才添加最少代码。

新增层、依赖或配置项须解决当前具体问题，说明直接实现在哪个已知重复、行为风险或复杂范围
上不足；“以后扩展方便”本身不构成理由。能隔离真实业务规则、外部副作用或重复逻辑时可以保留，
不为减少层数而破坏必要功能与验证。

以下任一成立就停止扩张：

- 没有现实消费者支持兼容工作；
- 回迁或机制替换缺少当前来源证据；
- 新增抽象没有当前调用方；
- 被决定不实现的功能不属于四类负向限制；
- 说明面已经正确，展示/发布/缓存面不会作出错误承诺；
- 输入未变化，已有验证或摘要仍适用；
- 新层只会增加维护对象，不能提高质量、速度或安全。

验证只覆盖当前改变的行为、真实消费者和必要硬性限制。纯文档改动默认读回、查链接与格式；
不运行代码套件、哈希整树、升版或重装。真实运行面未变化时，不用静态同步制造运行验收。

## 七、消融反馈循环只按明确要求运行

本文件用于日常避免扩大维护面，但不会自动启动消融实验。只有用户明确要求对当前代码或设计
执行“进行消融实验”“精简代码/设计”“去掉不必要抽象”或同义操作时，才进入
[消融反馈循环](ablation-loop.md)。该循环用不含作者辩护历史的独立上下文实际删除、内联或
合并一个候选，并比较同一组前后验收；普通实现完成、一般重构、审查或测试都不隐式触发。

## 例子

- 未部署的新内部 schema：直接替换，不写 legacy reader。
- 已存在的角色台账：v1/v2/v3 只走显式 `migrate-global` 收敛到当前结构，v4/v5 只走显式
  `migrate-attempts` 增加明确结果及经验版本关联审计；累计第二次明确失败后永久移除该角色全部资料。
- 用户明确只允许全局领域保留：可以测试不存在项目作用域字段，因为这是明确禁止的公共限制。
- 只是交接措辞变化：更新权威文字并读回；不跑代码测试、不全树哈希、不重装。
- 同一卷内移动一棵资料目录：核对精确根、目标缺失、重解析点、路径映射和移动后结构；不为
  源端与目标端各建立一份全树长度和 SHA-256 清单。
- 一项规则同时出现在技能、图和 UI：先确定权威行为面；只有图或 UI 会继续误导时才更新相应
  派生面，且只做一次针对性一致性检查。
