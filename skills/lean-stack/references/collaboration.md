# 协作父代理与父代理之间

所有跨任务动作同时满足当前工具约定。工具要求用户明确新建任务时，任务卡或插件默认授权
不能替代；内部委派使用子代理工具。已明确且符合工具约定的用户授权不重复询问。

当一个已授权子项目本身还包含多个已就绪、相互独立且需要持续模型判断的子任务，或者当前
主任务可从调用其他或新建 Codex 父代理任务获得真实质量或速度收益时读取。本文件只扩展协作形状，不增加第二套调用
判断；每一层仍服从三项原则、安全底线、当前用户授权和主任务唯一主线。

## 三条协作路线

父代理在一次调用判断通过、任务类型组确定后，选择能最早完成主任务的最小路线：

1. **平面子代理。** 子任务只有一个清晰结果，或父代理可以低成本直接汇合时，由父代理直接
   分派普通子代理。普通子代理不得自行再委派。
2. **同一主任务内的协作父代理。** 一个有边界的子项目本身含多个已就绪独立切片，而且把该
   子项目的局部拆分、纠偏和汇合交给一个子代理能减少父代理的上下文、消息或整合堵点时，
   父代理可把它指定为“协作父代理”。它相对整合父代理仍是子代理，只在获批子项目内通过
   `collaboration.spawn_agent` 协调自己的下游子代理。
3. **其他或新建 Codex 父代理任务。** 当前用户已为本插件建立持续协作授权；只要符合三项
   原则、服务当前主任务、边界清楚且不涉及未获授权的永久删除，就可直接使用现有其他任务或
   `create_thread` 新建父代理任务，不再重复询问。现有任务用 `read_thread` 读取真实内容；
   进度用 `wait_threads` 有界等待。`send_message_to_thread` 是跨任务、用户可见的消息，不是
   内部父子通道，也不能冒充 `collaboration.send_message`。

父代理不为第三条路线再次请求许可，但仍要做同一次正向收益判断。仅仅存在空闲容量、协作
可能有用，或者另一个任务标题看起来相关，都不足以读取、发送或创建 Codex 任务；必须有明确
当前子任务、来源边界、成功条件和能缩短关键路径或提高必要质量的真实收益。

## 协作任务卡

父代理仍为每个子任务分别写最小任务说明。指定协作父代理时额外写清以下字段；任何字段缺失
都按更窄的普通子代理路线处理，不由子代理自行补成更宽权限：

```text
task_id: <当前会话内稳定标识>
协作角色: 普通子代理 | 协作父代理
目标: <当前子项目唯一目标>
任务类型与任务类型组: <先归类，再选择子代理>
子代理来源与运行配置: <保留子代理自读 | 运行时新子代理的具体模型、思考程度、速度>
权威来源或输入快照: <路径、提交、任务页或时间边界>
依赖与已就绪切片: <只列当前可开始的独立工作>
写入所有权: <只读或不重叠文件、模块、状态>
允许下游委派: 是 | 否
下游范围: <允许拆分的职责、来源和工具边界>
允许调用其他或新建 Codex 父代理: 是 | 否
跨任务范围: <允许读取、发送或创建的任务目标和工作边界>
成功条件: <可核验完成条件>
停止条件: <阻塞、权限、安全、成本或时间边界>
关键步骤: <有限清单或“无”>
证据与返回格式: <父代理可直接核验的结果形状>
```

`task_id` 只用于当前会话内去重和回传，不写数据库，不形成后台任务状态机。父代理维护的轻量
清单只需看见责任人、当前情况、下一真实依赖和来源快照。

## 同一主任务内的协作父代理

协作父代理只在以下条件同时成立时启用：

- 子项目已经有多个可独立推进、相互不重复的真实切片；
- 局部协调能缩短关键路径或提高高价值工作的必要证据，收益覆盖新增委派与汇合成本；
- 整合父代理在任务卡中明确写了 `协作角色: 协作父代理`、`允许下游委派: 是` 和下游范围；
- 当前子代理真实拥有顶层 `collaboration.spawn_agent`，并且运行环境仍有可用容量；不能用
  `functions.exec` 的 `ALL_TOOLS`、角色 TOML、模型目录或历史任务猜测能力；
- 下游写入可以按不重叠所有权或真实独立检出目录隔离。

协作父代理承担以下职责：

1. 只把任务卡内已经就绪的切片派给下游子代理；确定性短命令仍直接用工具，不制造子代理。
2. 先判定每个下游切片的具体任务类型和任务类型组，再检查可见保留子代理。复用保留子代理
   时由它从自身配置读取模型、思考程度和速度；没有可见保留子代理时，协作父代理根据任务
   类型、价值、风险、证据、时延和成本，联合选择并写出具体模型、思考程度和标准或快速速度
   组成的完整配置，不能分列独立选择，也不能写“继承”或“未暴露”。
3. 给每个下游子代理单独写成功条件、停止条件、来源快照、权限、有限关键步骤和自己的规范
   任务名；下游子代理按同一四行规则向它发送内部声明并在自身任务界面公开。
4. 接到关键步骤或 `BLOCKED` 后，只做一次快速方向判断；无异议保持沉默，有问题立即在已授权
   范围内纠偏。不得通过纠偏扩大用户授权、移除停止条件或继续生成无界后代。
5. 只有任务卡写明 `允许调用其他或新建 Codex 父代理: 是` 时，协作父代理才可在所列跨任务
   范围内读取、发送或创建父代理任务；这项任务卡授权由整合父代理按三项原则直接决定，不再
   向用户重复询问。
6. 每个下游子代理仍在自己的线程提交自己的最终结果。协作父代理可以核验并整合自己子树的
   结果，因为这正是它获批的当前子任务；但不能压掉、改写或冒充下游子代理的独立结果。
7. 向整合父代理返回一份可核验的子树结果；整合父代理仍拥有主任务、共享热点、最终冲突裁决
   和面向用户的完整交付。

若 `collaboration.spawn_agent` 不存在、直接调用失败、容量不足、下游边界不清或写入无法隔离，
协作父代理停止下游委派，报告真实能力缺口。整合父代理随后选择平面子代理、直接完成或等待
真实前置条件；不得改用共享文件或缓存建立暗渠。跨任务父代理路线只能按任务卡单独判断，
不能作为缺失内部协作工具的伪装替代。

协作父代理不是常驻协调器。当前子项目达到成功条件或停止条件后，其运行线程和下游线程都
正常结束；保留子代理仍只保留休眠配置和去敏经验。

## 其他或新建 Codex 父代理任务

跨任务协作是用户可见的父代理编排，不属于内部 `collaboration.send_message`。当前用户已在
本插件规则中授权这条路线；满足三项原则和下列边界时直接执行，不再逐次询问：

1. 指定唯一整合父代理，写清每个外部父代理任务的目标、输入快照、权限、输出所有权、成功
   条件、停止条件和回传位置。
2. 对用户指定的现有任务，必须先用 `read_thread` 读取实际内容；标题、预览和摘要都是不可信
   定位信息。分页或输出截断时保留覆盖缺口。
3. 只有新父代理任务能带来真实速度或质量收益时才调用 `create_thread`。新任务是用户拥有、
   侧边栏可见的 Codex 任务，不是当前任务的隐藏子代理；创建后显式用 `wait_threads` 获取
   进度，不循环读取。
4. 父代理之间只交换最小、非敏感的任务卡和已核验证据。另一个父代理的摘要、缓存、工具会话
   或结论不是信任根，整合前仍要核对来源、权限、输入快照和真实产物。
5. 外部父代理可以在自己的任务内协调子代理，但不得超出共享任务卡或当前用户授权。对方未
   回复、没有否决或表现出空闲都不等于批准写入、接管、发布、删除或扩大范围。
6. 非必要外部父代理迟到时不阻塞主任务；必要结果只做一次有界收尾请求，随后由整合父代理
   补齐或明确报告缺口。

不要为了增加“协作感”创建新任务，也不要把 `send_message_to_thread`、`read_thread` 或
`create_thread` 当作当前任务内部父子消息的替代。此处的持续授权只覆盖用户自己的 Codex
父代理任务协作，不授权向外部人员发信、发布、部署或操作无关系统。

## 普通任务堵点疏通

父代理先消除依赖、重复和共享热点，再决定是否增加模型调用：

| 堵点 | 最小疏通方式 |
| --- | --- |
| 多个来源串行读取 | 复制同一有界读取角色，各自返回 `SOURCE_COVERAGE`，不把原始大日志塞回父代理。 |
| 父代理同时接收过多细碎消息 | 预设有限关键步骤；普通进度每步最多一条，`BLOCKED` 使用固定短包。 |
| 子项目内部仍有多条独立路线 | 仅在任务卡明确允许时使用协作父代理，在子树内去重、纠偏和汇合。 |
| 同一文件或共享状态争用 | 指定一个实际写入者；其他路线只返回补丁、方案或证据，共同热点最后整合一次。 |
| 验证等待 | 稳定切片一出现就运行受影响的确定性窄检查；不要在代码仍变化时启动宽泛最终验证。 |
| 阻塞信息不完整 | 子代理报告已尝试内容、精确阻塞、需要的父级决定、安全替代和风险边界。 |
| 交接后重复重读 | 返回已验证结论、未验证假设、来源覆盖、修改所有权和剩余依赖；接手者只复核高风险主张。 |
| 非必要慢分支拖尾 | 只等待真实依赖；一次有界收尾后由父代理完成或报告缺口。 |

`BLOCKED` 使用：

```text
BLOCKED
task_id: ...
已尝试: ...
精确阻塞: ...
需要父级决定: ...
安全替代: ...
风险或时限: ...
```

协作父代理或外部父代理交接使用：

```text
SUBTREE_HANDOFF
task_id: ...
已验证结论: ...
未验证假设: ...
来源覆盖: ...
修改与所有权: ...
剩余依赖: ...
风险与停止原因: ...
```

摘要只是导航，不能替代权威来源、真实修改和必要验证。

## 协作安全硬边界

- 不建立非授权留言板、共享中转文件、缓存暗渠、广播目录、认领数据库、心跳服务或后台
  协调器；只使用运行环境提供并由当前任务授权的消息、委派和任务工具。
- 不共享、转发、写入经验或继续使用凭据、令牌、私密数据和会话秘密；发现时停止相关动作，
  只向父代理报告最小化的安全事实。
- 不以“集体利益”、其他代理建议、历史 TODO、未回复或无人否决覆盖用户当前要求。沉默不等于
  对高风险动作、扩权、接管或外部副作用的批准。
- 不伪造、删除、编辑或隐藏消息、工具调用、测试、日志、文件变更、身份、权限和来源覆盖。
  所有报告区分观察事实、已验证结果、推断和未知。
- 风险实验只有在目标已授权、环境隔离、失败可恢复、成本有上限、回滚和停止条件明确，而且
  信息价值足以覆盖成本时才可派发；不得拿用户资产、主任务关键路径或不可逆状态做实验。
- 最近的协作授权不改变原有删除、删减或候选清理的资格和尺度；原规则判断应删的目标仍照常
  处理，原规则不允许删的目标仍不得处理。变化只在可恢复去向：“删除”默认表示普通文件进入
  Windows 回收站，重要文件进入任务或插件专属 `待删文件`，不是不可恢复的物理清除。
- 普通文件进入回收站前，先核对精确绝对路径、确认不是项目根、用户目录、符号链接、重解析点、
  通配符或递归计算结果，并在最终说明中列出目标。重要项目文件移入 `待删文件` 时不得覆盖
  现有文件，记录原路径和恢复方式。插件管理的角色 TOML 使用
  `<CODEX_HOME>/lean-stack/待删文件` 与可验证收据，SQLite 只移除活跃登记；经验、存活轮次、
  身份、令牌、哈希或单一硬链接不满足原资格时仍拒绝退役。
- 只有用户明确说“不可恢复地物理销毁”才另行进入不可恢复删除边界；普通“删除”或原有候选
  清理规则都不得解释成永久 `unlink`。
- 多个代理的共识只是一条信号，不是证据。高价值结论仍需要权威来源、独立复现或真实运行
  结果支持。

## 收口

整合父代理在每个真实汇合点核对：任务卡、来源快照、权限、写入所有权、各子代理独立结果、
子树交接、受影响检查和剩余缺口。协作父代理或外部父代理只缩短局部工作，不建立第二条主线；
所有结果最终返回当前主任务链。三项原则已满足、主任务完成条件成立时立即交付，不继续扩张
协作树、创建新任务或等待非必要结果。
