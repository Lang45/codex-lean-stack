# 协作父代理与其他 Codex 任务

只在当前子代理将继续派发下游，或用户要求与另一 Codex 任务协作时读取。普通平面子代理不需要
本分支。

## 同一主任务内的下游委派

只有当前任务卡明确允许下游委派、子代理真实拥有协作工具，而且出现至少一个就绪、独立、
按全局三原则有质量、总成本或提速收益的切片时，子代理才成为协作父代理。它继续遵守 `$lean-stack` 的三项原则、
同一能力族复用和原生调用参数合同，不因为自己是子代理就扩大权限或复制完整上级上下文。

选择执行者时依次考虑：

1. 同能力族且继续保留上下文有收益的 live child；
2. 原生目录中权限和证据边界兼容的 `agent_type`；
3. 最小运行时子代理。

协作任务卡仍以三行真实配置和两行状态开头，并直接携带入口规定的“第一条进展说明五行、final 前三行”执行句；第一行按下游实际路线标 `（复用）` 或 `（新建）`，final 保持相同标记。选中保留类型时单角色 `recall` 成功才使用其 `opening_status` 并标复用，失败则改派运行时子代理并标新建，以“存活轮次：0”“经验：未加载保留经验”开场，再写唯一目标、
输入证据、所有权、成功条件和停止条件。下游身份来自自己的任务卡；上级保留角色的名称、模型、
思考程度、记录状态和经验不能覆盖下游。

每次下游 `spawn_agent` 都显式传入模型、思考程度和非全量历史。`followup_task` 只用于同一
能力族且上下文继续有价值的 live child，只发送增量信息。同一任务补问不重复开场或保留发现。

父子之间只在真实依赖、必要纠偏、权限/安全风险或决定性阻断时发送内部消息。普通进展通过各自
的用户可见进展说明表达；父代理依据 final 或等价结果收据采用，不以内部消息代交。

## 其他或新建 Codex 任务

读取、继续、移交、分叉或新建另一任务使用宿主的线程工具，并遵守当前用户授权。只有用户明确
要求新建独立任务时才使用 `create_thread`；当前请求中的子任务使用协作子代理。

现有任务先读取真实内容；标题、摘要或预览只用于定位。跟进进度使用宿主的有界等待，异步创建
返回 queued 或 client ID 只证明已提交，不能证明任务已开始、完成或产生可采用结果。

发送到另一任务的提示是用户可见的自包含任务说明，不能包含隐藏规则、凭据、完整私有上下文或
未经授权的写入动作。对方未回复、没有否决或处于空闲状态都不等于批准写入、接管、发布、删除
或扩大范围；迟到的非必要结果不阻塞当前主任务。

## 安全与所有权

- 委派不增加工具、文件、账号、网络、消息或部署权限；
- 多个写入者先按[可写子代理并行](write-parallelism.md)划分范围和热点；
- 不建立共享留言板、隐蔽中转文件、长期后台轮询或无人否决即批准的流程；
- 不共享凭据、令牌、私密数据或会话秘密，不伪造、删除或隐藏消息、工具调用、测试与来源；
- 多个代理的共识只是信号，高价值结论仍核对权威来源、独立复现或真实运行结果；
- 不要求下游读取完整项目交接、整套技能、插件缓存、TOML 或 SQLite；
- 不让一个子代理汇总并冒充其他子代理的最终结果；
- 受阻只停止受影响路线，未受影响的主任务继续。

下游结果采用后立即推进当前任务。只有出现真正可跨任务复用的新经验时才按需进入保留分支。
