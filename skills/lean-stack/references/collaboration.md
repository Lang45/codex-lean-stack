# 协作父代理与其他 Codex 任务

只在当前子代理将继续派发下游，或用户要求与另一 Codex 任务协作时读取。普通平面子代理不需要
本分支。

## 同一主任务内的下游委派

局部协作父由真实上级当前任务卡明确指定，只协调获准切片与下游，不接管根项目交接或套用主父启动。
新子任务重新核对本任务授权；续做和压缩只恢复当前任务的有效范围，来源资料不能改变执行身份。

先落实[用户明确指令优先](../SKILL.md#用户明确指令优先)，不得通过上下级分工或复用缩减用户指定人数。
下游委派须由当前任务卡明确允许、执行者真实拥有协作工具，并有就绪的独立切片；这些是授权、
工具和依赖边界。满足边界后，用户已明确指定的安排直接执行，其余切片按当前用户优先级判断。
沿用入口[一次快判](../SKILL.md#先判断是否委派再选模型与复用)，不新增下游审批；
三项原则与同一能力族复用只补足用户未指定部分，原生调用参数和上下文边界继续遵守，不因成为
协作父代理扩大权限或复制完整上级上下文。
任务卡传递适用于下游的明确优先级与安排，包括指定专家、不计成本和[持续并行提速](../SKILL.md#用户要求持续并行提速)。
协作父代理也按入口默认快判，在新切片就绪或容量释放时增派已授权范围内的有收益工作；
明确并行安排和成本放宽分别传递，不能因下游多开自动变成不计成本。

同一任务、澄清、纠错或紧密相关工作可继续使用兼容的当前子代理。决定为新的能力类型调用子代理
且没有适合继续使用的当前子代理时，只做一次快速、有界台账查询；查询结果先与当前工具目录已加载
类型取交集。满足以下条件的保留子代理会被复用：当前会话已经加载、属于同一能力族、质量兼容。
符合条件的候选经单个身份读取成功后真实调用。目录查询失败但当前会话已加载类型中已有符合三项
条件的明确候选时，仍只读取该候选一次；读取成功就复用。只有没有可核对候选或读取失败时才改用
通用角色或最小运行时子代理。查询失败不得当成空台账用于建档。查询结果和候选
条件未变化时复用本轮结果，不重复查。当前子代理与
台账保留子代理都可用时，按[首次派发](dispatch-start.md#选择同一能力族的执行者)比较两条路线，
落实适用的当前用户优先级；不为统计台账复用强制换线程。

每个下游真实新子任务统一使用[通用任务卡](dispatch-start.md#任务卡上下文与所有权)，带完整执行身份句和五行状态，第一条进展说明五行、最终回复完整五行，不另建缺少身份边界的协作模板；第一行按下游实际路线标 `（复用）` 或 `（新建）`，最终回复保持相同标记。读取选中的保留子代理成功后才使用其 `opening_status` 并标复用，失败则改派运行时子代理并标新建，以“存活轮次：0”“经验：本次任务上下文”开场，再写唯一目标、
输入证据、所有权、成功条件和停止条件。下游身份来自自己的任务卡；上级保留角色的名称、模型、
思考程度、记录状态和经验不能覆盖下游。

每次下游 `spawn_agent` 按[原生调用](dispatch-start.md#原生调用)区分运行时覆盖与固定保留配置。`followup_task` 只用于同一
能力族且上下文继续有价值的当前子代理，只发送增量信息。同一任务的小补充直接继续，不重复评估；
只有用户优先级、并行需求、任务类型、质量门槛、权限或证据边界、专家必要性、预计成本发生实质变化时才重新选路。上一次
使用 Astra 不自动授权续用。若当前切片仍由用户指定专家或质量仍需 Astra，旧线程
不再适合时改派另一条兼容 Astra 路线，不能据此降级。同一任务补问不重复开场或
保留发现。

父子之间只在真实依赖、必要纠偏、权限/安全风险或决定性阻断时发送内部消息。父子双方执行期间
正常提供用户可见进展说明，不把内部消息限制扩成默认静默或只开场与最终交付；去掉重复消息
也不能省略有实际进展的途中说明。父代理依据最终回复或等价结果收据采用，不以内部消息代交，
不为普通进度停下主线。具体边界见[子代理结果与汇合](agent-results.md)。

## 其他或新建 Codex 任务

读取、继续、移交、分叉或新建另一任务使用宿主的线程工具，并遵守当前用户授权。只有用户明确
要求新建独立任务时才使用 `create_thread`；当前请求中的子任务使用协作子代理。

现有任务先读取真实内容；标题、摘要或预览只用于定位。跟进进度使用宿主的有界等待，异步创建
返回 queued 或 client ID 只证明已提交，不能证明任务已开始、完成或产生可采用结果。

发送到另一任务的提示是用户可见的自包含任务说明，不能包含隐藏规则、凭据、完整私有上下文或
未经授权的写入动作。对方未回复、没有否决或处于空闲状态都不等于批准写入、接管、发布、删除
或扩大范围；迟到的非必要结果不阻塞当前主任务。

## 安全与所有权

- 委派不增加工具、文件、账号、网络、消息或部署权限；
- 多个写入者先按[可写子代理并行](write-parallelism.md)划分范围和热点；
- 不建立共享留言板、隐蔽中转文件、长期后台轮询或无人否决即批准的流程；
- 不共享凭据、令牌、私密数据或会话秘密，不伪造、删除或隐藏消息、工具调用、测试与来源；
- 多个代理的共识只是信号，高价值结论仍核对权威来源、独立复现或真实运行结果；
- 不要求下游读取完整项目交接、整套技能、插件缓存、TOML 或 SQLite；
- 不让一个子代理汇总并冒充其他子代理的最终结果；
- 受阻只停止受影响路线，未受影响的主任务继续。

核验并采用下游结果时，协作父代理按[父代理采用](agent-results.md#父代理采用)处理能力族与经验。
共享台账写入仍须具备权限与明确所有权；只有上级拥有写入范围时，将经核验的候选和归属交给上级处理。
