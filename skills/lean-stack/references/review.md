# 审查或审计

用于差异、分支、文件集或仓库审查。除非用户另行请求修复，本手册保持只读。

1. 确认预期行为和审查范围，与正确基线比较，不猜测分支名称。
   涉及架构或数据路径时，核对用户明确选择、实际调用链和本次差异，检查是否绕过指定机制、
   捆绑无关行为或改变计算位置；按[既定决策](build.md#既定决策与改动范围)处理，不仅看测试结果。
2. 极小差异由父代理直接审查。高价值或范围较大的审查，可按相互独立的风险轴应用
   核心分派判断，同时父代理审查主路径。可用风险轴包括：
   - 正确性、安全、并发和数据丢失；
   - 集成范围、测试和行为回归；
   - 最小性、依赖、无调用方的灵活性和阅读负担。
3. 子代理必须立即有真实代码范围可读，只接收最小上下文。完整覆盖且来源未变化时，
   父代理不重复完整阅读。
4. 每个发现都要包含位置、因果机制、影响、证据或复现路径，以及最小可信处理办法。
5. 合并时去重，并针对代码或运行行为核验高影响主张。多个代理同意只是信号，不是
   证据；拒绝纯风格偏好和依赖虚构要求的发现。
   涉及验收时，按[执行路由](execution-routing.md#七、条件性验证)核对预期来源和测试变更理由，
   特别检查是否用内部成功替代用户结果。UI 按[构建规则](build.md#ui-的实际验收)区分外观与
   实际交互证据；发现须对应本次影响，不把审核扩成无关的全项目整改。
6. 先列按严重度排序的可行动发现，再列假设、验证缺口和简短结论。没有重要发现时
   直接说明，并写清验证范围。

未经用户明确扩展，不应用修复、不发布评论，也不创建外部问题。
