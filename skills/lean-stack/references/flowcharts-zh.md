# 中文链路图

本文件按当前源码中的独立执行链分图。图的数量没有目标或上限；源码出现、合并或删除一条真实
链路时，对应图也随之出现、合并或删除，不合并成一张难以核对的总图，也不为凑总数拆图。若
图文冲突，以两个技能入口、命中的最小 reference、实际脚本和运行证据为准。

## 主任务链路

```mermaid
flowchart TD
    A[收到或更新用户要求] --> B[确认当前剩余目标、授权和停止条件]
    B --> C[$lean-simplify 选择最小完整主任务路径]
    C --> D{确定性工具可以可靠完成吗}
    D -->|是| E[直接工具或一次工具级并发]
    D -->|否| F{有就绪、独立且通过质量、成本、时间判断的切片吗}
    F -->|否| G[父代理直接推进]
    F -->|是| H[选择同能力族执行者并派发]
    H --> I[父代理继续未分配主线]
    I --> J{下一动作依赖子结果吗}
    J -->|否| I
    J -->|是| K[取得 final 或等价结果收据]
    K --> L[父代理核验结果、权限和数据完整性]
    E --> M{代码、配置、公共行为或高风险范围变化吗}
    G --> M
    L --> M
    M -->|是| N[条件性语义复核与必要验证]
    M -->|否| O{达到交付条件吗}
    N --> O
    O -->|否| D
    O -->|是| P[交付结果和真实缺口]

    D -. 从这里开始 .-> AUXTOOLS[工具、子代理与安全并行]
    D -. 复杂 Windows 命令 .-> AUXWINDOWS[Windows exec 与 PowerShell]
    H -. 从这里开始 .-> AUXCAP[能力族复用与运行时创建]
    H -. 同能力族多个切片或真实选配疑问 .-> AUXCOPY[运行时复制与配置变体]
    C -. 从这里开始 .-> AUXWORK[调查与实现]
    L -. 从这里开始 .-> AUXTEST[迭代测试]
    M -. 从这里开始 .-> AUXVERIFY[语义复核与最终验证]
    N -. 验证失败时 .-> AUXRETRY[失败后的最窄重验]
    L -. 确有跨任务复用价值时 .-> AUXMEMORY[按需经验记账]
    O -. 插件发布已获授权时 .-> AUXRELEASE[版本、校验与本地重装]
```

虚线只标记其他链路从主任务链的哪个位置开始。它们完成或跳过后返回主任务，不能成为另一条
取代主任务的主线。经验维护不影响已就绪的主任务动作和交付。

## 工具、子代理与安全并行链路

```mermaid
flowchart TD
    A[当前工作已就绪] --> B{需要持续模型判断吗}
    B -->|否| C{一个还是多个独立确定性动作}
    C -->|一个| D[父代理直接调用工具]
    C -->|多个| E[一次工具调用并发运行]
    B -->|是| F{委派满足质量、成本、时间吗}
    F -->|否| G[父代理直接处理]
    F -->|是| H[进入能力族复用链]
    H --> I[任务卡写目标、来源、所有权、成功和停止条件]
    I --> J{需要写入吗}
    J -->|否| K[只读执行]
    J -->|是| L[按物理目标分配唯一写入者和验证]
    K --> M[子代理以 final 交付]
    L --> M
    M --> N[父代理采用或只补一个具名缺口]
```

短命令和确定性查询不启动只会代跑命令的模型子代理。多写入者必须遵守
[可写子代理并行](write-parallelism.md)；委派不增加权限或外部副作用。

## Windows exec 与 PowerShell 链路

```mermaid
flowchart TD
    A[准备执行 Windows 命令] --> B{短命令且只有一层普通参数吗}
    B -->|是| C[直接使用当前 PowerShell 外层执行]
    B -->|否| D[写入一个任务专属临时 ps1]
    D --> E[用 param 和 LiteralPath 分离代码、参数与数据]
    E --> F[Parser ParseFile 做语法预检]
    F --> G{语法通过吗}
    G -->|否| H[只编辑同一个脚本后重验]
    H --> F
    G -->|是| I[通过 File 或脚本路径执行]
    I --> J[检查真实结果和外部程序退出码]
    J --> K{失败属于解析或转义吗}
    K -->|是| H
    K -->|否| L[按业务、路径、权限或目标程序原因处理]
```

第一次内联失败明确属于解析或转义时，后续只编辑同一个脚本，不连续重写长 one-liner、叠加
转义或换 Shell。完整参数和清理边界见 [Windows exec 与 PowerShell](windows-exec.md)。

## 能力族复用与运行时创建

```mermaid
flowchart TD
    A[已决定委派] --> B{同能力族 live child 的实际配置合规且上下文仍有收益吗}
    B -->|是| C[followup_task 只发送增量目标和证据]
    B -->|否| D{已加载 agent_type 的 GPT-6 配置、职责、权限和证据边界兼容吗}
    D -->|是| E{单角色 recall 成功吗}
    E -->|是| H[复用已加载 agent_type，名称标复用并原样使用 opening_status]
    E -->|否| F[创建最小合规运行时子代理]
    D -->|否| F
    C --> G[沿用 live child 的实际配置，名称标复用]
    H --> K[首条进展五行 final 前三行且名称标记一致]
    F --> I[名称标新建，只选 GPT-6 三模型与 medium 及以上思考程度]
    G --> J{开始新当前子任务且状态已确认吗}
    I --> R[存活轮次 0 经验未加载保留经验]
    R --> K
    J -->|是，状态已确认| K
    J -->|是，状态无法确认| F
    J -->|否，同任务补问| L[执行并独立提交 final]
    K --> L
    L --> M[父代理核验结果、权限和数据完整性]
    M --> N{确有可复用经验且身份可安全核对吗}
    N -->|是| O[按需经验记账]
    N -->|否| P[直接继续主任务]
```

能力族按职责、输入形状、交付、权限、安全风险和证据要求判断。完成状态不妨碍 live child 续用；
项目、框架、动作名称、展示名或模型档位不同不单独创建新角色。

## 运行时复制与配置变体链路

```mermaid
flowchart TD
    A[已经决定委派] --> B{同一能力族有第二个独立已就绪切片吗}
    B -->|否| C[保持单一执行者]
    B -->|是| D{每个复制仍满足质量、成本和时间吗}
    D -->|否| C
    D -->|是| E[为每个切片复制运行时执行者和独立任务卡]
    E --> F{现有配置有真实改进空间且结果可比较吗}
    F -->|否| G[沿用完整配置普通复制]
    F -->|是| H[父代理显式选择完整配置变体]
    G --> I[各自达到成功条件并提交 final]
    H --> I
    I --> J[采用所有已核验结果]
    J --> K{需要选择未来配置吗}
    K -->|否| L[结束本轮运行时复制]
    K -->|是| M[按质量、总成本和完成速度比较]
    M --> N[未来身份和经验仍走保留分支]
```

复制和变体只存在于本轮运行，不创建持久候选表，也不丢弃已经核验的互补结果；写同一物理目标
时还须进入 [可写子代理并行](write-parallelism.md)。完整既有语义见
[任务类型组、复制与变体](agent-groups.md)。

## 来源所有权与结果复用链路

flowchart TD

    G --> E
```

## 可写并行链路

flowchart TD
    A[两个或更多执行者可能写入] --> B[建立 WRITE_ROUTE]
    B --> C{物理目标天然不重叠吗}
    C -->|是| D[分配精确目标并行写入]
    C -->|否| E{存在真实独立检出目录吗}
    E -->|是| F[隔离写入并指定归并所有者]
    E -->|否| G[一个执行者写实际目标，其余返回只读方案]
    D --> H[各自运行受影响检查]

    G --> H
    H --> I[父代理核对共享接口并精确整合]
```

## 协作父代理链路

```mermaid
flowchart TD
    A[当前子代理发现多个下游独立切片] --> B{任务卡允许且真实拥有协作工具吗}
    B -->|否| C[保持平面子代理并报告具名缺口]
    B -->|是| D[按同一能力族复用规则选择下游]
    D --> E[每个下游取得独立任务卡、所有权、成功和停止条件]
    E --> F[下游分别提交自己的 final]
    F --> G[协作父代理核验整合，不冒充下游结果]
```

## 调查与实现链路

```mermaid
flowchart TD
    A[取得当前问题或行为目标] --> B[写下预期、保持项和最窄判别检查]
    B --> C{需要调查还是实现}
    C -->|调查| D[定位真实入口、消费者、来源和竞争假设]
    C -->|实现| E[修改最小权威位置]
    D --> F[执行能区分原因的最小观测]
    F --> G{根因足够明确吗}
    G -->|否| D
    G -->|是| E
    E --> H[运行受影响的必要检查]
    H --> I{原始问题消失且保持项成立吗}
    I -->|否| D
    I -->|是| J[停止并交付证据]
```

没有新证据时不重复同一补丁或同类检查。能由真实入口决定的问题不靠静态同义字符串代证。

## 迭代测试链路

```mermaid
flowchart TD
    A[行为变化或明确缺陷] --> B[先独立写出预期与失败方式]
    B --> C{复杂用户流程还是隔离边界}
    C -->|复杂流程| D[运行可重复的集成或端到端入口]
    C -->|解析、CAS、路径、权限或数据完整性| E[运行最窄隔离测试]
    D --> F{修改前是否捕获原始问题}
    E --> F
    F -->|否| G[修正测试入口或证据，不改弱预期]
    F -->|是| H[实施最小修复]
    G --> B
    H --> I[在同一入口重跑]
    I --> J{问题消失且保持项成立吗}
    J -->|否| H
    J -->|是| K[保留可重复工件或结果收据]
```

## 语义复核与最窄重验链路

```mermaid
flowchart TD
    A[代码、配置、公共行为或高风险范围变化] --> B[复核真实消费者与不变量]
    B --> C{发现影响结论的问题吗}
    C -->|否| D[运行当前风险所需的最窄验证]
    C -->|是| E[集中修复发现]
    E --> D
    D --> F{验证通过吗}
    F -->|是| G[停止扩大检查]
    F -->|否| H[依据新失败重新定位根因]
    H --> E
```

代码、依赖、配置和环境未变化时可复用已通过证据。安全、数据完整性、权限和公共合同所需验证
不得因精简而省略。

## 保留身份创建与重配链路

```mermaid
flowchart TD
    A[采用结果且形成跨任务能力] --> B{原生目录已有同能力族兼容 agent_type 吗}
    B -->|是| C[直接复用，不创建身份]
    B -->|否| D[去除项目、路径和一次任务身份]
    D --> E[身份权限安全绑定后 ensure，无需旧经验收据或 run_id]
    E --> F{需要安全重配或合同刷新吗}
    F -->|否| G[返回未来可加载的 agent_ref]
    F -->|是| H[使用返回 SHA 作一次 CAS 确认]
    H --> I{立即成功吗}
    I -->|是| G
    I -->|否| J[auxiliary_skipped，不重试]
```

## 按需经验记账与摘要压缩链路

```mermaid
flowchart TD
    subgraph PRE[派发前的可选经验归因]
        A{本次调用需要加载并归因既有经验吗}
        A -->|否| B[不创建召回签发关系]
        A -->|是| C[派发前生成稳定 run_id]
        C --> D[recall run-id 短事务持久化随机收据]
        D --> E[保存同身份、同 run_id、同摘要的收据]
    end
    subgraph POST[结果采用后的按需记录]
        F[父代理已核验并采用结果] --> G{新增跨任务经验成功或保留身份明确失败吗}
        G -->|否| H[跳过辅助记录并继续主任务]
        G -->|是| I{身份、权限及必要输入可安全绑定吗}
        I -->|否| U[保留具名未完成写入，继续主任务]
        I -->|是| J{结果为保留身份明确失败吗}
        J -->|是| N[complete-run failure 不附 lesson，保留失败事件]
        J -->|否，成功有新增经验| K{派发前保存了数据库召回签发收据吗}
        K -->|否| L[complete-run success 附 lesson，不附旧经验关联]
        K -->|是| M[complete-run success 附 lesson，精确核对摘要和收据]
        L --> W{脚本写入和回读成功吗}
        M --> W
        N --> W
        W -->|否| U
        W -->|是，新增经验| O[同一事务追加经验并保留原始事件]
        W -->|是，明确失败| Q
        U --> V[主任务推进后修复阻断并安全续写、回读]
        O --> P{摘要窗口需要压缩且不争用吗}
        N --> Q{用户后来否定该结果吗}
        P -->|否| Q
        P -->|是| R[按需压缩摘要并保留原始事件]
        R --> Q
        Q -->|否| S[保持记录]
        Q -->|是| T[停止采用并追加纠正事件]
    end
    B -. 完成后若需要普通记录 .-> F
    E -. 调用结束并核验采用 .-> F
```

召回签发只能在派发前发生；没有当时保存的数据库收据，就不能在完成后补造经验关联。无新增经验的成功结果不执行 `complete-run`；保留身份明确失败可不带 `--lesson` 记录。未采用、用户否定或无法安全去敏时不写经验。运行中、中断、停止或结果未定不记为失败。写入失败由父代理保留具名续做项，主任务推进后修复实际阻断并回读，不把报告原因当成完成。

## 现实旧状态迁移链路

```mermaid
flowchart TD
    A[显式请求迁移既有台账] --> B{精确 schema 版本}
    B -->|v1 v2 v3| C[读取完整 migrate-global JSON 计划]
    B -->|v4 v5 v6 v7| D[执行 migrate-attempts]
    B -->|其他或结构漂移| E[auxiliary_skipped 零写入]
    C --> F[核对每个旧身份、SHA、合同和纠正项]
    F --> G[事务迁移身份、运行和原始经验]
    D --> H[保留既有运行语义并创建空召回签发表]
    G --> I[不推断失败、经验复用或完成与召回收据]
    H --> I
    I --> J{完整性、外键和精确 schema 通过吗}
    J -->|否| K[回滚 SQLite 并按原字节恢复文件]
    J -->|是| L[提交并返回迁移收据]
```

迁移没有普通自动入口。历史运行不能因为当前摘要、相同正文或事件标识而补造调用前签发事实。

## SQLite 结构拒绝链路

```mermaid
flowchart TD
    A[准备访问保留台账] --> B[核对路径、普通文件、链接和 schema]
    B --> C{结构与所有权完全受支持吗}
    C -->|否| D[auxiliary_skipped，不写入、不迁移猜测]
    C -->|是| E[BEGIN IMMEDIATE 与精确 CAS]
    E --> F{TOML、SQLite 和召回签发状态都成功吗}
    F -->|是| G[提交事务并返回收据]
    F -->|否| H[按原字节回滚并报告决定性原因]
```

完整迁移、重放、删除和经验事件语义由 `agents.py` 及其行为测试承载，不复制进普通调用链。

## 版本、安装与正式宿主验收链路

```mermaid
flowchart TD
    A[插件公共行为已改变且必要验证通过] --> B[按语义版本规则升版一次]
    B --> C[同步 manifest、README 和 CHANGELOG 的当前说明]
    C --> D[运行最终受影响检查与完整套件]
    D --> E{用户是否授权更新正式插件}
    E -->|否| F[交付源码，注明安装缓存未更新]
    E -->|是| G[普通安装更新插件，不修改全局文件]
    G --> H[核对版本、源与缓存文件集合和哈希]
    H --> I{需要声明新任务真实行为吗}
    I -->|否| J[记录安装证据并停止]
    I -->|是| K[在全新任务观察原生参数、进展说明与 final]
    K --> L[区分调用行为、UI 显示和业务质量证据]
```

只有用户另行明确批准准确文字时，辅助安装器才修改全局调用入口；更新插件本身不需要改全局
`AGENTS.md`。
