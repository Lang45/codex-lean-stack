# 全部中文链路图

本文件用通俗中文说明插件的完整执行链。三项原则按工作价值改变顺序：

- 高价值工作：质量优先，其次是总时间，最后是总成本。
- 普通工作：达到安全和验收底线后，速度优先；时间接近时再看总成本。
- 安全、权限、数据完整性和诚实证据始终是底线。

## 一、总任务主链路

```mermaid
flowchart TD
    A[每条新消息、继续、方向调整<br/>队列新增、范围或阶段变化] --> B{重新判断工作价值和可分派工作}
    B -->|高价值| C[质量和证据优先]
    B -->|普通工作| D[达到底线后速度优先]
    C --> E[判断工具还是模型工作]
    D --> E
    E --> F{有已就绪且有净收益的<br/>独立语义工作吗}
    F -->|没有| G[父任务直接完成]
    F -->|有| H[一次选择零至三个专门子代理]
    H --> I[子代理交付独立实活]
    H --> J[父任务同步推进关键路径]
    I --> K[在真实依赖点汇合]
    J --> K
    G --> L[完成语义审查]
    K --> L
    L --> M[冻结相关代码边界]
    M --> N[运行一次必要最终验证]
    N --> O{成功条件满足吗}
    O -->|是| P[立即交付]
    O -->|否| Q[只处理真实缺口]
    Q --> L
```

## 二、工具与子代理选择链路

```mermaid
flowchart TD
    A[出现一个候选工作块] --> B{需要持续模型判断吗}
    B -->|不需要| C{确定性工作耗时如何}
    C -->|几秒| D[父任务直接调用工具]
    C -->|多个独立短命令| E[一次工具调用并发运行]
    C -->|长但步骤确定| F[放入持续终端或后台会话]
    F --> G[父任务继续其他工作]
    B -->|需要| H{输入和前置条件已就绪吗}
    H -->|没有| I[不启动子代理]
    H -->|已经就绪| J{扣除启动、传递、汇合和核验后<br/>仍有净收益吗}
    J -->|没有把握| K[父任务完成]
    J -->|高价值质量增益明确| L[进入子代理数量判断]
    J -->|普通工作明显省时| L
    L --> M[从当前宿主模型中选择最合适配置]
    M --> N[未来更强模型自动纳入候选]
    D --> O[不启动模型子代理]
    E --> O
```

经验边界：普通工作大约只能节省十几秒时，要把子代理启动和汇合开销算进去；这只是
快速判断，不是评分表。

## 三、子代理数量选择链路

```mermaid
flowchart TD
    A[列出当前已就绪工作块] --> B[去掉工具工作、串行依赖和重复范围]
    B --> C[去掉无法独立验收或会冲突的写入]
    C --> D[按工作价值核对质量、时间和成本]
    D --> E{剩余多少个真正有净收益的独立工作块}
    E -->|零个| F[使用零个子代理]
    E -->|一个| G[使用一个子代理]
    E -->|两个| H[使用两个子代理]
    E -->|三个或更多| I[优先选择价值最高的三个]
    I --> J[其余留给父任务或下一阶段]
    F --> K[立即执行]
    G --> K
    H --> K
    J --> K
```

数量没有默认值。零个、一个、两个和三个地位相同，不能为了显得并行而凑数。

## 四、父任务与子代理并行链路

```mermaid
flowchart LR
    A[完成一次分派决定] --> B[立即启动有真实工作的子代理]
    B --> C[子代理读取或实现独立工作块]
    B --> D[父任务继续需求、架构、集成或关键路径]
    C --> E{子结果已成为下一步必需输入吗}
    D --> E
    E -->|还不是| F[双方继续推进，不空等]
    F --> E
    E -->|是| G[在第一个真实依赖点汇合]
    G --> H[父任务核验证据和允许写入]
    H --> I[整合并继续主任务]
```

耦合代码和共享状态只有一个写入者；多个可写子代理必须天然拥有互不重叠的目标。

## 五、同类复制与单轴变体链路

```mermaid
flowchart TD
    A[同一类专门工作出现多个项目] --> B{项目彼此独立吗}
    B -->|是| C[复制同一运行时角色]
    C --> D[每个实例领取不同范围和完成条件]
    B -->|否| E{是否有一个明确差异<br/>可消除关键不确定性}
    E -->|没有| F[只保留一个执行路线]
    E -->|有| G[建立只改变一个轴的变体]
    G --> G0{本次只选择哪个升级轴}
    G0 -->|模型| G1[沿当前模型链只升一档<br/>未来更强模型动态接入]
    G0 -->|推理强度| G2[沿宿主真实档位只升一档]
    G0 -->|速度| G3[只比较标准速度档与快速速度档]
    G1 --> H{按工作价值比较真实结果}
    G2 --> H
    G3 --> H
    H -->|高价值| I[先比质量、安全和证据]
    H -->|普通工作| J[达到底线后先比总时间]
    I --> K[选出已验证胜出者]
    J --> K
    D --> K
    K --> L{还有有用的未试单轴且有净收益吗}
    L -->|有| G
    L -->|没有| M[运行时其他实例结束]
    M --> N[最多持久保留一个胜出角色]
```

## 六、调查与实现链路

```mermaid
flowchart TD
    A[收到问题或变更请求] --> B{用户只要求调查吗}
    B -->|是| C[明确问题和所需证据]
    C --> D[父任务追主路径]
    C --> E[按需委派独立来源或子系统]
    D --> F[汇合当前代码、运行行为和相关测试]
    E --> F
    F --> G[区分事实、推断和未知]
    G --> H[只交付结论和可选处理]
    B -->|请求包含修改| I[先确认用户可见结果和权威契约]
    I --> J[复用现有实现并证明根因或设计边界]
    J --> K[实现最小完整切片]
    K --> L[在匹配表面验证结果]
    L --> M[进入语义审查与最终验证]
```

调查子代理完整覆盖且来源未变化时，父任务不做常规完整重读。

## 七、迭代测试链路

```mermaid
flowchart TD
    A[完成一小步代码修改] --> B[找出最可能受影响的最窄检查]
    B --> C[父任务直接调用工具并使用简短输出]
    C --> D{检查通过吗}
    D -->|通过| E{相关代码还会变化吗}
    E -->|会| F[继续实现，不启动最终验证]
    F --> A
    E -->|不会| G[转入语义审查]
    D -->|失败| H[只展开失败项详细输出]
    H --> I[定位并修复真实原因]
    I --> J[只重跑受影响检查]
    J --> D
```

这条链路通常使用零个子代理。几秒的测试由父任务直接运行更快、更省。

## 八、语义审查、代码冻结和最终验证链路

```mermaid
flowchart TD
    A[实现达到预期边界] --> B[先做会推动修改的语义审查]
    B --> C{存在安全、契约、架构或差异问题吗}
    C -->|有| D[修复发现并重做受影响审查]
    D --> B
    C -->|没有| E[声明相关代码边界冻结]
    E --> F{最终检查是否只是确定性命令}
    F -->|是| G[父任务在一次工具调用中并发运行]
    F -->|否| H{是否需要独立语义复核或长时间真实并行}
    H -->|不需要| I[父任务完成]
    H -->|需要且有净收益| J[使用合格验证子代理]
    G --> K[统一收集最终证据]
    I --> K
    J --> K
    K --> L{验证后代码又变化了吗}
    L -->|没有| M[交付]
    L -->|有| N[解除冻结]
    N --> O[只重验受影响边界]
    O --> B
```

验证子代理不能只运行命令并回报退出状态；它必须提供独立语义判断或证据解释。

## 九、失败后的最窄重验链路

```mermaid
flowchart TD
    A[某项检查失败] --> B[记录失败检查、边界和决定性输出]
    B --> C{失败来自代码、依赖、配置还是环境}
    C --> D[只修改与根因相关的部分]
    D --> E[列出被修改影响到的检查]
    E --> F[重跑失败项和受影响项]
    F --> G{此前其他证据的来源和边界变化了吗}
    G -->|没有| H[复用此前通过证据]
    G -->|变化| I[只补跑对应检查]
    H --> J{所有必要证据齐全吗}
    I --> J
    J -->|是| K[收口]
    J -->|否| L[继续处理剩余真实缺口]
```

## 十、专门代理创建与安全重配链路

```mermaid
flowchart TD
    A[发现一种重复性专门工作] --> B{角色是否稳定且值得未来复用}
    B -->|否| C[只使用当前运行时任务说明]
    B -->|是| B0{用户已明确否决持久化吗}
    B0 -->|是| C
    B0 -->|否| B1[自动获得非破坏性<br/>持久创建和重配授权]
    B1 --> D{当前任务已有可见匹配角色吗}
    D -->|有| E[立即复用，不做维护前置]
    D -->|没有| F[当前任务先使用可见通用角色]
    F --> G{父任务仍有真实工作可并行吗}
    G -->|没有| H[推迟持久化]
    G -->|有| I[运行可选创建命令]
    I --> J{同角色配置状态}
    J -->|不存在| K[创建一个供未来任务使用]
    J -->|完全相同| L[复用现有角色]
    J -->|不同| M[返回需要安全重配]
    M --> N[用当前文件哈希做比较并交换]
    N --> O[保留身份、路径和经验]
    K --> P[新任务加载]
    O --> P
    L --> P
```

当前任务不等待新配置可见，也不轮询、不重新加载、不重启。

## 十一、经验追加与摘要压缩链路

```mermaid
flowchart TD
    A[专门代理交付结果] --> B{结果已验证且胜出吗}
    B -->|否| C[不写入推荐经验]
    B -->|是| D{角色和经验是否稳定、去敏<br/>且值得未来复用}
    D -->|否| C
    D -->|是| D0{用户已明确否决持久化吗}
    D0 -->|是| C
    D0 -->|否| E[自动授权并只追加一条原始经验事件]
    E --> F{有界窗口达到压缩条件吗}
    F -->|没有| G[结束辅助动作]
    F -->|有| H{压缩是否会拖慢主任务}
    H -->|会| I[推迟压缩]
    H -->|不会| J[合格子代理压缩旧摘要和增量事件]
    J --> K[用来源哈希和序号安全提交]
    K --> L[保留全部原始经验]
    G --> M{主结果已准备好吗}
    I --> M
    L --> M
    M -->|是| N[立即交付，不等待维护]
    M -->|否| O[父任务继续真实工作]
```

## 十二、数据库结构拒绝链路

```mermaid
flowchart TD
    A[可选维护命令打开专门代理数据库] --> B{文件可用且没有忙锁或损坏吗}
    B -->|否| C[辅助动作跳过]
    B -->|是| D{结构版本是多少}
    D -->|零且没有用户对象| E[初始化唯一受支持结构]
    D -->|受支持版本| F[核对表、列、键、索引和外键]
    D -->|未知版本| C
    F --> G{结构完全一致吗}
    G -->|是| H[允许本次辅助写入]
    G -->|否| C
    C --> I[不迁移、不猜测、不删除]
    I --> J[主任务继续]
    E --> H
    H --> J
```

## 十三、永久删除链路

```mermaid
flowchart TD
    A[出现删除候选] --> B{用户当前明确要求<br/>永久删除吗}
    B -->|否| C[停止采用并可提出删除建议<br/>但不删除]
    B -->|是| D[核对插件台账和精确代理名称]
    D --> E[核对直接普通文件、单一硬链接和受管标记]
    E --> F[核对所有权令牌和文件哈希]
    F --> G{全部完全匹配吗}
    G -->|否| H[停止并要求人工核对]
    G -->|是| I[删除前再次核对路径]
    I --> J[永久删除精确文件和台账记录]
    J --> K[报告已删除且无法恢复]
```

删除不能与另一个代理目录写入者并行，也没有隔离、恢复或状态机。

## 十四、版本提升、单次重装和新任务加载链路

```mermaid
flowchart TD
    A[插件改动完成] --> B{公共行为如何变化}
    B -->|兼容新功能| C[提升次版本]
    B -->|兼容缺陷修复| D[提升修订版本]
    B -->|破坏兼容性| E[提升主版本]
    B -->|仅文档、测试或内部重构| F[保留数字版本]
    C --> G[完成语义审查并冻结代码]
    D --> G
    E --> G
    F --> G
    G --> H[用完整旧版本作为比较并交换前置条件]
    H --> I[只运行一次版本写入器]
    I --> J[父任务运行相关测试和官方校验]
    J --> K{全部通过吗}
    K -->|否| L[修复后只重跑受影响检查]
    L --> J
    K -->|是| M[只执行一次本地重装]
    M --> N[核对启用状态、版本、文件集合和哈希]
    N --> O[用新任务加载新技能和代理表面]
    O --> P[不需要重启应用]
```

提交、推送、公开发布和外部消息不在本链路的默认授权内。

## 系统标识说明

中文正文使用中文术语。必须与宿主或脚本精确交互时，才单独使用这些标识：

```text
worker
explorer
SOURCE_COVERAGE
expected_sha256
ensure
improve
delete
```
